# Web Flow 项目维护约定

继承[仓库 AGENTS.md](../../AGENTS.md)。以下只规定本项目特有的归属与发现入口，不复制框架规则。

## 先恢复当前任务

先读 [README](README.md)、[产品合同](docs/product-contract.zh-CN.md) 和[执行计划](docs/execution-plan.zh-CN.md)。固定检索词为 `OD-AI-WORKFLOW-BRIDGE`。

只有项目内这两份文档维护完整需求和进度；旧根 docs 路径是迁移入口。保留 BR-01–12、AWB-01–08 与历史证据等级，当前步骤变化直接更新原执行计划。

## 新业务在本项目，公共能力在原框架

- Web Flow 新增业务源码、专属测试与文档归 `projects/webflow/`。具体模块按 README 的职责建立，不预建空目录或假安装配置。
- 使用公开 SDK/Task/存储与交付合同，不把沙箱应用直接接到宿主私有模块，不在框架里追加 Web Flow 专用业务分支。
- 必须补框架能力时，先记录实际公开接口、可复现失败和最小通用缺口，再由原 owner 实施；不能因建立本项目就另建 Runner、Host、Authority、安装器或任务数据库。
- `projects/ai-send-queue/` 与计算接力样例保持原 owner。本项目不接管它们的代码、安装身份或内存队列；需要迁移现有 Bridge 业务时，先核对真实消费者及构建/权限/测试影响，完整迁移后只保留一个实现。
- 业务编排通过原执行链推进；五字段协议、单站任务、UNKNOWN 不重放及结果/交付分开验收继续遵守产品合同。

## 当前交付边界

目前是已建立的业务项目与文档入口，尚无本项目可安装包。文档整理只检查内容、链接、编号与差异；不得把目录、预览或组件测试记为真实网页通过。进入实现时在执行计划登记准确写入范围、依赖和当前验证等级。
