> 日期：2026-10-30 ｜状态：DESIGN / RESEARCH；所有网络连通率、播放成功率、节省带宽比例与商业合作均为 NOT_TESTED / NOT_VERIFIED。
>
> 仓库：shopable-ai/opendesk-browser ｜唯一产品：projects/video-svip/ ｜范围：长期方向、路线比较、最小 PoC 与业务边界。**本文件不是上线承诺，不覆盖已有 ROADMAP 或 R0.3.1 实站验收。**

## 1. 不得漂移的原始目标与已有工作

核心用户目标：进入视频网站 → 正确识别平台、作品及当前集 → 找到可合法观看的来源 → 尽量自动选择稳定且成本合理的方式 → 保留原站播放与恢复能力；进而统一找片、会员管理、跨设备观影与合法商业合作。

当前 main 已有 R0.3.0 的只读识别、videoSVIP.inspect/watch/stop、原站观看、会员日期本机登记与同源 preview。R0.3.1 针对腾讯、B站的真实 Mac Chrome 验收由独立任务进行，结果不得预先宣称通过。现有视频下载是另一个独立产品 projects/video-downloader/，其 R0.1 仅下载明确的同源直链 MP4/WebM，HLS 只检测不下载，DRM/加密不下载；不要将其业务重造或把其 Demo 当作会员资源下载成功。

本研究的新问题：能否将**有权存储/提供的媒体**存入用户设备，在局域网、家庭自用远程访问、合法授权的多用户分发场景，通过 P2P 打洞、加密组网或中继减少对中央云端的依赖？答案是有多条技术路线可研究，但内容授权、可达性与成本必须分别判断。

## 2. 先决条件：权利分层，不能由网络能力推导内容权限

必须在所有来源选择前区分：

| 内容与许可类别 | 可用方向 | 禁止做出的推断 |
| --- | --- | --- |
| A. 自制、公共领域、许可明确允许的公开视频 | 按许可范围缓存、跨设备、P2P 分发 | “可观看”自动等于“可改编/可商用”；仍需阅读许可 |
| B. 用户个人合法持有且允许私人跨设备观看的文件 | 本机媒体库、同一用户的局域网或远程访问 | 个人购买自动允许向公众提供 |
| C. 获得明确多用户分发权的合作内容 | 授权 CDN、P2P/CDN 混合、边缘缓存 | 协议未覆盖的地区、期限、并发人数与再分发 |
| D. 流媒体平台账号下的 VIP / 订阅影片 | 官方播放器及平台允许的离线观看 | **订阅 = 拥有可复制的视频文件 / 可转给其他人** |
| E. 官方 App 内的受保护离线缓存 | 严格按平台设备、期限和使用规则播放 | 浏览器扩展可以提取、破解 DRM、重新加密或转供第三人 |

**非目标：**抓取付费内容、绕开 DRM/登录限制、将平台受保护缓存提取成可分享文件、个人会员 Cookie 池、未经授权向陌生人提供影片。技术研究可使用自制视频、Creative Commons 授权样本或有合同的测试资产。权利不明确时拒绝加入分发候选，仍允许官方观看与会员导购。

需要有可验证的 RightsCapability：streamToOwner / download / store / syncBetweenOwnedDevices / householdUse / redistribute / commercialUse / territories / expiry / concurrencyLimit / evidenceRef。没有权利证据的能力一律 UNKNOWN 或 DENIED；法律判断需按地区与合同独立核验。

## 3. 三个不可混淆的工程目标

- **A. 私人远程观看：**同一用户自己的媒体，从家庭电脑/NAS 播到自己的手机或第二台电脑。重点是免配置、私密、可用。
- **B. 多人授权分发：**内容方允许的多用户观看。重点是内容许可、范围、并发和计费；不能用私人 VPN 绕过版权许可。
- **C. 官方 VIP 观看辅助：**用户仍在合法官方 App/网页内看受保护视频，Video SVIP 负责识别、找片、权益及链接，不负责导出或再分发受保护内容。

产品需要先判断是哪一类目标，再选择技术栈。不能把 A 成功当成 B/C 已完成。

**不纳入正式技术选项：**“先下载某平台 VIP 影片，再无授权供所有其他用户播放”的方案。即使可以通过 NAT 打洞传送字节，也不能据此获得向他人分发的权利。

## 4.1 不一定要传输视频字节：另外六种低带宽服务机会

这组方向从用户需求出发，不需要将 VIP 影片下载后再分发，可能比大规模 P2P 更容易验证：

| 方案 | 用户价值 | 网络负担 | 重要边界 | 设计优先级 |
| --- | --- | --- | --- | --- |
| 21. 同步观影房间（Watch Party） | 异地朋友同步播放/暂停/进度与文字交流 | 只传控制消息；各自从原站播放 | 每个人独立拥有观看资格；平台需允许该控制行为 | 高，独立 PoC |
| 22. 一键跨设备续看 | 同一个人从 PC 跳转到手机/TV 官方入口 | 只同步作品与进度元数据 | 官方允许的深链和有限同步；不复制视频内容 | 高 |
| 23. 共用观影清单与选片投票 | 多人决定看什么、在哪个合法平台看 | 很小 | 不代替任何人的会员授权 | 高 |
| 24. 会员费用与观看计划联动 | 减少重复订阅、单片租赁与续费浪费 | 很小 | 商业价格需可核验，不虚报优惠 | 高 |
| 25. 授权内容的字幕/轨道、清晰度与节流建议 | 慢网络下改善用户体验 | 通常只传有限配置 | 不覆盖原平台安全策略、不能读取受保护流 | 中 |
| 26. 内容方授权的设备闲时缓存和预热 | 合法高频内容降低内容方中心流量峰值 | 较大，必须限额 | 明确授权、过期清理、用户上传/存储同意 | 远期 |

**同步观影与共享媒体是两种不同产品。**例如多人分别使用自己的官方播放器，只同步暂停、时间轴和选片，传输的是小量状态消息；不需要将付费视频从 A 的电脑转播给 B。可参考 Chrome Web Store 上各端使用本人访问权限的 Watch Party 扩展，但不能推断第三方平台都允许相同播放器控制。

参考：https://chromewebstore.google.com/detail/watch-party-for-youtube/bhcpabaiehekgikpnhnngojclbiaccdj ；Plex 历史 Watch Together 功能案例：https://support.plex.tv/articles/watch-together/ （Plex 已说明部分新版客户端结束支持，不能把历史功能当作当前全面兼容保证）。

**路线建议：**在证明自有文件双机 P2P 技术之前，Watch Party 和跨设备续看可先做独立的低成本产品可行性评估；它们是商业/体验备选项，不应抢占 R0.3.1 实站识别验收或强制成为 Video SVIP 主界面。

## 5. 用户想要的自动打洞：正确架构与限制

### 私人设备之间的可行路径

1. 设备 A 本地发现授权媒体，设备 B 发出本人授权的播放请求。
2. 控制面进行设备身份认证、会话授权、密钥交换与能力确认。不得暴露本机目录。
3. 优先同一局域网直连；跨网络优先加密 P2P 直连（Tailscale/WireGuard 或 WebRTC ICE/STUN）。
4. 遇到 CGNAT、对称/严格 NAT、企业防火墙、UDP 不可用等情况时，自动评估用户接受的受控 relay/TURN/DERP 或其他已允许的网络路径。
5. 仅对授权媒体发出带到期时间、权限范围、带宽上限的传输请求；响应支持 Range、暂停、取消和错误恢复。
6. 播放证据区分 FOUND / CONNECTED / HTTP_OK / DECODABLE / FIRST_FRAME / PLAYING_15S / UNKNOWN / FAILED，不因连上隧道就报告“播放成功”。
7. 网络变化或 Stop 后旧会话失效，关闭共享、撤权与移除设备须及时终止访问。

### 关于“减少公网 IP 流量”的准确结论

- 同 LAN 观看：视频数据可以不走互联网。
- 跨互联网的**直连 P2P**：通常减少云服务器/中继的出口数据，但双方运营商带宽仍会被使用。
- 经 TURN/DERP/VPS 中继：流量依然经过中继，成本可能更高，且吞吐或延迟可能更差。
- 一台家庭电脑给 N 个观众：家庭**上行总容量**常成为瓶颈；多 peer 分担、授权边缘缓存或 CDN 混合架构才可能扩展。
- 不得承诺“打洞 100% 成功”或“零带宽成本”。AI 能自动判断/配置常规路径，不能改变 NAT、运营商、物理上行和版权限制。

### Chrome Extension 的宿主边界

Video SVIP 是 MV3 Side Panel 应用，不应将 Chrome Service Worker 当作 24×7 视频种子服务器。长期在线、本地文件持有与稳定上传需要一个可选的、有用户明确授权的桌面/家用设备节点；它可以复用已有 Desktop 的受限 HTTP/IPC 通道或独立轻量伴随进程，但**不应侵入桌面自动化 Runtime**。浏览器只负责发现、选择、授权、展示与受控会话。若浏览器本身使用 WebRTC，仍须在标签页/扩展生命周期中正确处理关闭与暂停。

## 6. 可组合的目标架构：不是把所有能力塞进 Browser

- **Video SVIP（产品控制面）**：识别影片、观看方式决策、权益信息、来源选择、状态反馈、用户授权。
- **video-downloader（独立产品）**：只在用户有权下载时保存媒体，现有接口/权限/验收独立；不由 Video SVIP 启动未知跨源下载。
- **Rights / Catalog Adapter**：作品匹配、许可证明、地区与到期、官方来源、可分发能力。
- **Media Library Adapter**：本机/NAS/授权缓存目录的媒体摘要、大小、时长和可用性；默认不索引任意私人目录。
- **Optional Media Node**：在用户明确开启后运行本地服务器、上传配额、速率限制、会话有效期、单设备撤权与日志。
- **Peer Connection Manager**：LAN / direct / peer relay / TURN / licensed origin；选择最小成本可达路径。
- **Licensed Delivery Adapter**：未来商业授权 HLS/DASH、P2P/CDN 与按合同计费、失效清理。
- **Playback Verifier**：独立检查有权限读取的首帧、短时连续播放；无法观测则 UNKNOWN。
- **AI Assistant（未来）**：依据可验证工具结果推荐设置和修复；不得执行未知脚本、静默改路由器端口、自动开放公网目录或自作主张上传影片。

建议抽象两个正交对象：

**WatchOffer** = 作品 + 剧集 + 正规来源 + 地区 + 权益 + 价格/到期 + 权利依据。

**DeliveryPath** = 网络拓扑 + transport + endpoint + peer/relay + 性能 + 费用 + 身份认证 + 失败原因。

“有 WatchOffer”不意味着有 DeliveryPath；“打通了 DeliveryPath”不意味着可以传这个作品。来源选择器必须两个都判定，并尊重原站官方优先。

## 7. 可靠性目标：不是“无论什么片都至少有一路播放”

真实保证的前提是**至少有一个合法授权且在线的内容来源**。如果作品被下架、用户没有权益、节点离线、所有网络路径被封锁或 CDN 故障，就必须如实报无可播放线路。

建议的降级顺序：

1. 原站/官方拥有权益的播放方式。
2. 同一用户自有且允许远程播放的本地/LAN 库。
3. 授权跨设备的 P2P 直连。
4. 经用户允许的有费用上限中继。
5. 合同内的内容方源站或 CDN。
6. 都不可用时显示原因、下一操作和正规的获取/购买方式。

不得悄悄以未授权资源填补空缺；不要将技术兜底变成“万能会员破解”。

## 8. 有意义的 AI 自动化程度

可自动：诊断网络环境、判断直连/中继、生成配置建议、检索授权来源、测延迟与带宽、健康度排序、播放失败切换、生成可复核故障日志、提醒流量超额和节点离线。

须用户明确同意：安装桌面服务、配对设备、开放文件目录、分配上传速率、绑定隧道/中继账号、支付带宽费用、邀请其他身份、变更路由器/防火墙规则。

不能自动：规避 DRM、借他人会员、静默开启公网服务器、绕过第三方收费或服务协议、借内容方账号替其他用户提供未经许可的播放。

## 9. 最小真实 PoC：先证明“自己的文件能从家中传到另一台电脑”

**PoC-1 · 两台电脑 + 自制 30–60 秒视频（技术验证首选）**

- 两台不同网络或至少可模拟 NAT/UDP 受限的设备；电脑 A 是自有合法文件服务器，电脑 B 是观看端。
- 首先基于成熟 Tailscale/WireGuard 类实现做自动配对、身份验证、直连检测、无感路由；记录 direct/relay 与带宽/延迟。
- 验证断开 A、换网、停止、超时、撤销访问、文件错误与无权限访问，禁止本机目录外泄。
- 若实际硬件不足，标 NOT_TESTED，不将 localhost 成功代替跨网成功。
- 不改变 Video SVIP R0.3 的原站播放器、识别宿主和安全边界。

**PoC-2 · WebRTC ICE/STUN/TURN 浏览器 P2P**

- 同一份合法视频，由显式授权的浏览器/伴随节点共享。
- 建立受限信令、设备授权、DataChannel / 有界分片、超时、取消、完整性校验与中继。
- 真实网络记录候选类型 host/srflx/relay，区分连接成功与首帧播放成功。
- 比较 PoC-1 成本、部署和 Chrome 生命周期风险；**两方案是备选，不必同时产品化**。

**PoC-3 · 有合同后的授权 P2P CDN（独立商务准入）**

- 只以版权方允许的自制/签约 HLS/DASH 片段，研究 P2P Media Loader、浏览器同时观看场景与 CDN 回退。
- 测起播时延、卡顿率、上传带宽、来源分布、TURN 回退、成本及可撤销性。
- 未签约前只能在受控样本环境验证技术，不能接入真实 VIP 流、声称版权可分发或对外售卖。

### 独立证据等级

DESIGN / NODE / BUILD / LAN_REAL / TWO_NETWORK_REAL / NAT_HARD_REAL / DIRECT_VERIFIED / RELAY_VERIFIED / FIRST_FRAME / PLAYING_15S / HOST_STOP / AUTH_REVOKE / TRAFFIC_COST / MAC_CHROME / LICENSE_VERIFIED / COMMERCIAL_READY。每一项记录：设备类型、网络条件、时间、来源权利类别、真实日志、失败原因和独立读回。未测不得 PASS。

**关键成本指标**：每 GB 的源站或中继出口费、P2P 直连占比、家庭上行消耗、播前等待、卡顿、节点在线率、授权范围；不能只用某些测试结果声称“节省 80%”。

## 10. 商业方向：区分真正的付款方

| 模式 | 用户/客户 | 可售价值 | 准入 | 探索优先级 |
| --- | --- | --- | --- | --- |
| 官方会员导购与正规渠道分销 | 普通观影者、平台 | 找片、优惠、少重复购买 | 平台/联盟合同、明确披露 | 高 |
| 家庭自有媒体远程访问工具 | 自有文件的个人/家庭 | 免配置、安全跨设备播放 | 自有或允许跨设备使用的文件 | 高 |
| 管理型个人 NAS / 媒体库服务 | 家庭与小团队 | 设置、同步、健康诊断与维护 | 隐私与文件权限 | 中高 |
| 授权 P2P/CDN 降本服务 | 有分发权的视频发行方 | 降低中心带宽支出 | 版权、分发合同、质量 SLA | 高潜力、但后期 |
| 授权边缘缓存节点网络 | 内容方与区域服务商 | 热门内容靠近用户 | 节点同意、计费、清退、版权 | 远期 |
| 影视数据/会员成本决策 API | 内容发现和导购合作方 | 正版渠道、转化、订阅优化 | 商业数据许可与披露 | 中期 |
| 个人 VIP 文件众包给陌生人 | 不应提供 | 技术可传输不代表可经营 | 缺失再分发授权 | 排除 |

会员付费、单片租赁和家庭共享属于**商业权益逻辑**；视频文件能否复制、缓存、远程访问或向多人分发属于**内容权利逻辑**。不要将两者合并。

- **Now · R0.3.1 并行但不覆盖：**腾讯/B站识别实站验收；本文件只记录未来方向，不修改既有 Host、App、版本或预览。

- **PoC · 第一项真实技术闭环：**两台电脑、实际跨网、真实可播授权视频、自动直连/中继切换、独立证据；不以 Node mock 代替。
- **Integration · 可选节点：**把网络状态/有权媒体候选作为 Video SVIP 的来源之一，严格与独立 Video Downloader 分责，不产生第二套 Host。

- **Expansion · 新技术观察：**libp2p、QUIC/WebTransport、IPFS、私有 relay、家庭节点市场等每季度审查一次；不因热门概念重写已稳定运行的链路。

## 12. 主要风险、反方观点及停损条件

- 权利：用户付费观看 ≠ 视频再分发授权。若没有合法内容测试资产，停止分发 PoC，只做网络性能测试。
- 连通：严格 NAT、CGNAT 或屏蔽 UDP 时不可能保证直连。没有可用 relay 则标失败。
- 成本：家用上行、流量费、存储、电费、转码、带宽投诉和商业运维，均需计入。
- 隐私：P2P 可能暴露网络地址或观看行为，必须最小化、取得同意、限制节点发现范围。
- 安全：设备配对、TLS/密钥、目录沙箱、短时令牌、逐文件范围、撤权、日志、速率和并发限制是上线门槛。
- 质量：一个种子节点不能保证大量并发，必要时回到有合同的 origin/CDN。
- 产品：不要把 Video SVIP 变成下载器、VPN 或云存储的集合。优先保留“看视频/找片/会员”用户价值。
- 资源：没有两台真实设备、可控网络、明确许可和证据收集能力时，继续设计优于伪造实测。

## 13. 独立专家设计评分规则

对**推荐的阶段组合**（保留原站 → 个人合法文件跨设备 PoC → 授权来源策略 → 正规商业扩展）进行设计评估，目标每维不低于 95：用户价值、架构边界、安全合规、网络可靠性设计、兼容性、测试可验证性、可持续成本、UI/操作效率。综合分取八项算术平均，不能累加。**评分不是实现结果**：实测没做的必须 NOT_TESTED，许可没取得必须 NOT_AUTHORIZED。对不适合现在采用的候选技术如 IPFS/自托管控制面允许低于 95，不可通过虚报提升排名。
