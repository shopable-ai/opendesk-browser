# 视频会员（Video SVIP）R0.3 · 技术验收与证据矩阵

## 原始目标与本轮边界
打开视频页 → 从已授权活动 Chrome Document 的真实 DOM 读取片名、当前选集 → SPA/同 URL 内容切换自动失效并复查 → 原站观看、重新识别、Stop。
独立产品只有 `projects/video-svip/`。本轮不涉及会员解锁、外部视频解析、播放器替换、Cookie/Token、账号共享或商业售卖。

## 已实现源码（不是实测声明）
- `trusted/policy.js`：固定平台/路径匹配与只读选择器，前五平台 + YouTube + Netflix + loopback fixture；实站选择器均为**待核验**。
- `trusted/host.js`：固定 `pageVideoSVIP` 函数经 ISOLATED + `documentIds` 执行；官方 Host 在前后校验同一活动 Document、安装代际和发行 SHA，最多三轮成对独立读取；有界标题稳态检测、选中集数判断，空值明确 unknown。
- `trusted/admission.js`：发行版本、Package SHA、provenance、已安装实例、启停和撤权代际均须匹配。
- `src/main.js`：显示读取证据与状态；带请求序号的旧结果失效、DOM 事件去抖、Stop；原会员 `memberships` 存储格式及 CAS 未变。
- 共享 Host 新增唯一 `page.videoContext` 能力，`videoSVIP.inspect/watch/stop` 固定操作，有限 DOM MutationObserver 仅传递变更信号、不传标题。
- `preview/index.html`：继续是唯一预览，**只用模拟数据**。

## R0.3.1 真实网站优先测试样例（2026-10-30 用户指定）

**首选不是本地 Fixture，而是以下真实播放页；链接是「待测输入」，并非已经识别成功的证据。**

1. 腾讯视频：`https://v.qq.com/x/cover/mzc00200aaogpgh/c4102y7ahdb.html`
2. B 站番剧：`https://www.bilibili.com/bangumi/play/ep3854821?from_spmid=666.25.episode.0`

优先在用户已经授权的实际 Mac Chrome 活动标签页里查看页面 DOM。必须使用正式 OpenDesk Side Panel → Host → `documentId` → 固定只读 DOM 识别 → Host 读回的链路。网页标题、`og:title`、视频区域标题及当前高亮选集应交叉核对，不能靠 URL 域名或页面标题就判定完整识别成功。

**重要语义防误判：**腾讯的 `mzc00200aaogpgh` / `c4102y7ahdb` 是页面作品/视频标识，不代表第几集；B 站 `ep3854821` 是番剧剧集 ID，不是“第 3854821 集”；查询参数 `from_spmid` 也不是当前选集。只有“共 N 集”“更新至 N 集”时返回 `episode=unknown`。普通 BV 多 P 的 `p=2` 不自动等于电视剧第 2 集。

**允许换视频，但必须保留失败事实和替换证据：**

- 如果首选视频失效、下架、登录/会员/地区限制、平台风控、网络故障或不可加载：记录原 URL、时间、失败层次与错误；**优先换同网站、同类型、合法公开可访问的视频或番剧**，并记录新 URL 与更换原因。不要反复尝试同一失效页面、绕过会员或 DRM。
- 如果页面可访问、DOM 能读取但识别错误：这是待修的产品缺陷，不能简单换视频冒充成功。先保存有限脱敏的 DOM 证据，修复对应站点适配器，继续测试原视频（如可访问）与另一视频回归。
- 如果识别出片名但当前集数无法核实：仅记为片名识别通过、`episode=unknown`；另找确实有当前选集的同平台视频完成集数验证。
- **技术可行性**可由任一真正可访问的真实站点验证 Host、documentId、独立读回；但腾讯与 B 站分别声称“已适配”前，每个平台都必须有自己的真实 DOM 识别证据。其他站点 PASS 不能替代某站点未测结果。
- 测试记录以“站点 + URL + 测试日期 + Chrome/权限状态 + 片名证据 + 当前集证据 + 独立 Host 读回 + SPA/Stop 结果 + 原播放器未被修改”为最小单元，禁止伪造片名/选集预期值。

**参考项目可借鉴范围：**`88lin/video_vip` 3.2.11 的 `video_vip.user.js` 有 `readVideoTitle`（约 367–399 行）、`waitStableTitle`（约 491–519 行）、`curEpNum`（约 538–552 行）等思路，以及腾讯 `.intro-title[title]`、`.video-title[title]`、`.player-title` 和 B 站 `[class*="mediaTitle"][title]` **候选**标题选择器。当前 upstream 根目录和 workflows 未发现现成的独立 DOM/Chrome 自动化测试套件；仅复用思路与独立设计的测试，勿复制 GPL 源码，也勿套用会员解析服务/播放器劫持代码。**原始 `curEpNum` 将 B 站 `/epN` 的 ID 当成集数，并可能把“更新至 N 集”当作当前集，明确禁止继承这些误判。**候选选择器未经过真实页面核对不能标为 VERIFIED。

## Chrome 实测必须先通过，不得以 Node mocks 替代
在本机 /Users/shopme/Documents/workspace/opendesk-browser 的最新 main 上：

1. `node --test tests/environment/video-svip.test.mjs tests/environment/video-svip-ui-r03.test.mjs`
2. `npm run build:sidebar-tool -- projects/video-svip`，再 `npm run build:dev`。若固定源码 SHA 失败，立即停止，不跳过或放宽白名单。
3. 用真实 Chrome 加载 `artifacts` 中的最新扩展构建，经官方扩展中心安装**当前版本 0.3.0**，审阅新增只读权限与网站访问授权。未批准 Chrome 原生网站权限时识别必须失败。
4. **先打开上述腾讯视频与 B 站实际页面**，经正式 Host 读取可核对的片名、当前选集与同一活动 `documentId`；若首选失效，则按前述同平台替换规则选择第二真实视频，不能丢失原失败记录。开发者可在本机证据中使用 tabId，但业务 UI/API 不得接收或暴露 tabId。
5. 在同 URL 改 DOM A→B、改选集、History API 导航与跨 Tab 切换；用慢旧请求制造竞态，结果不能回到 A。Stop 后不得恢复；重新识别才可恢复。关闭 Side Panel 后 Port/Observer 不应持续运行。
6. 禁用工具、撤销网站访问、无权限 iframe、普通网页、只有“共 N 集/更新至 N 集”、多个同名元素：逐项核验明确失败、unknown 或需确认，**不能虚报成功**。确保源站播放器没有被暂停、静音、改速或替换。
7. 读取现有 `memberships`，保存更新、删除；记录旧 `video-pass` 包/数据仍存在且没有隐式迁移。
8. 腾讯视频与 B 站分别记录真实 URL（允许按规则换成同平台可访问视频）、测试时间、实际 DOM 证据、Host 返回、权限、成功/失败和原播放器状态。后续另以 YouTube 或合法可访问的海外流媒体做海外扩展性测试，单独报告 REAL_SITE；暂不能测不虚报。真实视频不必能付费播放，但读取的 DOM 必须是真实页面、已获许可的内容。

## 验收等级（全部独立填写）
- NODE：行为测试命令输出、通过/失败数、Node 版本及 commit SHA
- CHROMIUM：Chromium 中真 DOM 页面截图/日志，不能代替正式 Host
- REAL RUNHOST：正式 Host、官方安装身份、documentId 注入及独立读回证据
- MAC_CHROME：真实 Mac Chrome 视频页面/安装记录及失败原因
- REAL_SITE：至少国内一站和海外一站的实站记录；未实测选择器不标“已验证”
- BUILD：两个构建命令最终退出码、manifest、包 SHA

本文件只是验收规范，不代表任何测试已通过。没有 REAL RUNHOST 的正式只读识别实证，**不能宣布 R0.3 完成，也不能进入 R0.4 的播放故障诊断验收**。
