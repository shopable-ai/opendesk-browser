## 目标

在 ChatGPT 原生输入框粘贴、追加和编辑长文本，或在编辑器扩缩、滚动、节点替换时，完整保留原稿、既有队列及消息；皇冠和 Ctrl + Enter 只转移完整正文一次。取回失败保留原条目；任何不确定状态保留完整副本，阻止自动推进，不覆盖新稿、不重发。

唯一业务 owner 是本项目；复用原 Page USER_SCRIPT、`@opendesk/ui`、site adapter 和 engine。Sidebar 仍只提供说明。本轮不修改框架、Host、权限或发行来源校验，不接管网站 React Root，不替换网站编辑器。

**最新界面约束：** 顶部只保留队列消息行及必要操作，移除「发送队列」「共 N 条」和状态数量汇总，不以新状态条或说明区替代。状态警告继续归属对应消息，保留展开、取回、暂停、删除和完整原文恢复入口。

## 本轮证据与原因

1. **已复现的视觉消失。** 长文编辑器是数千像素高的内容，祖先 scrollport 只显示约 156px。旧 `view` 要求整个编辑器矩形都在圆角输入表面内，因此返回布局失败并隐藏列表、皇冠；四条测试队列正文仍完整。修复改为只读计算被 overflow 祖先裁切后的可见区域，原有缩窄、遮挡及原生控件检查保留。
2. **已复现的回填迟缓。** 在任务自有 ChatGPT 页面，旧 `insertText` 回填 1k 多段文本约 2.5s；8192 字符的多段 `insertText` 和实验性 `insertHTML` 均超过浏览器工具的 15s 界限，结果不能当作成功。网站原有纯文本 paste 处理则在约 68ms 完整接受 8192 字符，两帧后全文仍相等。
3. **真实 DOM 的换行差异。** Chromium 对 `DIV/P + 空段落 + BR` 的 `innerText` 会增加布局换行。现按逻辑段落读取，真实 DOM 夹具的长文清空、取回逐字符相等；不通过 trim 或忽略差异制造成功。
4. **异步交接漏洞由 Node 探针证实。** 同步读回之后，microtask/后续状态回滚可能清掉取回草稿；旧实现已删除唯一队列副本。清空之后恢复旧稿也可能重复入列。没有证据断言用户原现场必然触发了这些回滚。
5. **网站行为须单独识别。** 本次 21k 字符原生粘贴被 ChatGPT 转成文本附件。新增识别实际观察到的可见附件容器，拒绝将附件旁的局部文本当成完整消息入队。
6. **续接复核发现两条重复发送时序。** 独立 poll 确认入队之后，网站无可信编辑地恢复旧稿，旧实现仍允许再次入队；入队确认之前旧稿已被原生发送、输入框又变空时，旧实现也会继续发送队列副本。两条均由真实 main/site/engine 的 Node 探针复现，实际网站发生频率未知。
7. **区分消息交接记录与独立输入意图。** 后续复核证明，第一条发送不能释放第二条的清空保护；用户可信输入并原生发送相同正文，也不能消费原有队列项。已补修复前失败的回归：前者保留第二条和恢复副本、阻止重复入队；后者保留原队列授权，复用同一 engine 的原生入站与回复等待，不按正文合并意图。

上述 ChatGPT 证据是**自有页面的源码诊断**：site 测试使用显式模拟会话路由，view 使用模拟受管 UI；没有安装新版 Page，也没有发送消息。它们不是 USER_SCRIPT 安装、权限、真实队列自动发送或当前用户问题页已修复的证据。

## 交接设计

| 操作 | 完整正文的归属与核对 |
| --- | --- |
| 普通输入、布局与滚动 | 只读测量原生输入；只修改扩展自己的受管节点，不能清空或回写草稿 |
| 入列 | 先检查 8192 UTF-16 长度、20 项容量与会话，再保存完整快照并清空、入列；等待下一次独立 poll 核对原 route/form/editor、历史及空草稿，期间阻止再次转移和自动发送；确认后继续核对未解释的草稿恢复 |
| 取回 | 暂停原条目并保留全文；通过网站纯文本 paste handler 写入，完整同步读回后仍等待独立 poll，成功才移除原条目 |
| 成功取回或回滚恢复 | 保留内存备份，直到未取消的可信 beforeinput 后有可信 input 且正文确实改变、新的安全转移或精确入站证据；网站无用户编辑而清稿、换节点或改变正文时，提供完整复制恢复副本 |
| 未确认、部分接收或异步接收 | 不跟随第二次写入，不自动覆盖新稿；保留原文，复用 unknown/恢复入口，继续必要的只读回执核对 |
| 原生已发送入队正文 | 精确新增用户消息证明入站时，复用 engine 的确认与回复等待；历史变化无法证明时保留队列及完整副本，禁止发送；不得以输入框为空代替入站核对 |
| 可信新草稿的原生发送 | 即使与已排队正文相同，也保留原队列授权；精确核对这条独立新稿的入站并等待回复完成，使用同一 engine 的回复 gate，不新建发送器 |

沿用 650ms 独立 poll，不把任意延时当作网站永久稳定的证明。正常文本相同的新意图仍允许重新入列，不能按正文全局去重；可信、未取消且实际改变正文的编辑更新预期草稿。beforeinput 只是用户编辑的观察信号，不授予额外权限；取消、未实际改动和自己的同步写入不能释放备份。正在进行的原有回复可继续追加其对应 assistant 节点，但不能静默替换已观察的历史。并发移除条目、页面卸载及 owner 销毁均保留原有生命周期边界。

非空 contenteditable 写入只构造 `text/plain` 的 `DataTransfer` / `ClipboardEvent`，走网站处理；不读取或改写系统剪贴板，不传解释性 HTML，不依赖私有编辑器状态或属性。未完整接收时拒绝推进。清空继续使用原生编辑命令。

文本规则：textarea 保留 `value`；contenteditable 的相邻 P/DIV/LI/PRE/BLOCKQUOTE 边界为一个换行，BR 为一个换行；直接空段落的唯一 BR 和 ProseMirror caret 占位 BR 不额外计字。保留空段落、NBSP、首尾空格、代理对及有意的尾换行。浏览器粘贴后的逻辑文本是基准，CSS 软换行和段落间距不进入正文。长度仍按 JS `text.length`，上限不扩大。
