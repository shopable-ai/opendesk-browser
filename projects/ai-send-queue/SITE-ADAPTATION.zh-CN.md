# AI 消息发送队列 · 网站输入区适配工作流

网站改版后，从真实聊天页的原生输入框和发送控件开始排查。队列在输入框上方，皇冠始终在同一个原生输入框的底部操作区；原生发送和皇冠各自可点。窄窗允许底部操作区换行，草稿变长或锚点暂缺时不把皇冠挪到输入框上方。目标不明确时等待下一次确认，不猜测挂载点或发送目标。

## 现有代码怎样适配

| 职责 | 入口 |
| --- | --- |
| 定位原生编辑器、输入容器、发送／停止控件；返回挂载工具栏及可选的外层布局节点 | [`src/page/site.js`](src/page/site.js) 的站点配置与 `createConversationSite().inspect()` |
| 验证工具栏属于当前输入框，创建并复用一枚皇冠，必要时调整原生布局，并检查编辑器和按钮几何 | [`src/page/view.js`](src/page/view.js) 的 `bottomSlot()`、`applyNativeLayout()`、`place()` |
| 草稿、IME、会话、发送结果、暂停和防重 | 现有站点读写与回执逻辑、[`src/page/engine.js`](src/page/engine.js)；布局适配复用它们 |

三站沿用同一个挂载入口。站点负责识别原生控件及其工具栏：ChatGPT 沿用原生发送控件的父容器，Gemini 使用跨状态保留的底部工具栏，DeepSeek 使用包住原生控件的操作栏。共用视图沿控件向上寻找工具栏的直接子节点，并在该节点之前插入队列按钮；中间有几层包装都适用。工具栏必须属于当前输入容器，且不能包含编辑器。

### 共用规则：原生按钮尺寸和独立皇冠

共用视图按当前发送、停止或空框锚点的布局宽高设置队列按钮并垂直居中，触屏也用当前站点的原生尺寸。按钮用 `position: relative` 建立坐标参照，皇冠用 `position: absolute` 居中并上移，脱离文档流，也不拦截指针。若原生祖先会裁切溢出，视图把皇冠移入可见空间，必要时缩小装饰，避免盖住箭头；不为皇冠改原生容器的裁切属性。今后优先复用上述规则；工具栏布局确有差异时，才提供额外的原生网格节点。找不到可信原生控件时等待重识别。

验收时用同视口、同输入状态的官网作对照：按钮宽、高和垂直中心的差值各不超过 1 CSS px；皇冠不撑高按钮所在行，编辑器可用宽度不缩窄。窄窗可让底部操作区换行。皇冠轮廓完整，不遮挡箭头或焦点提示；两个按钮各自可以命中，保持各自的操作。检查桌面、窄窗和触屏输入，以及发送、停止、空框之间的切换。安全几何检查失败时沿用现有隐藏和回退逻辑。

### Gemini：独立底部工具栏与网格

Gemini 的 `placement()` 是现有结构适配的例子。下面摘自站点配置；`one()` 仅在恰有一个匹配时返回节点。

~~~js
placement(_button, form, editor) {
  const toolbar = one([...form.querySelectorAll('.input-buttons-wrapper-bottom')]);
  const trailing = toolbar?.closest('.trailing-actions-wrapper');
  const grid = trailing?.parentElement;
  const field = grid && [...grid.children].find(node => node.contains(editor));
  const leading = grid?.querySelector(':scope > .leading-actions-wrapper');
  return {toolbar, gemini: true,
    ...(field && leading && form.contains(grid) ? {grid, field, leading, trailing} : {})};
}
~~~

`toolbar` 决定皇冠直接插在哪一层；`grid` 及其子区交给视图判断怎样分配编辑器和按钮的空间。Gemini 当前的 `applyNativeLayout()` 会在识别到原生 grid 时重设模板，窄宽时把底部操作区分行。即使 `toolbar` 完全正确，外层网格的轨道、原生子项的 `grid-area`、最小尺寸或裁切仍可能改变整块布局。`place()` 的几何保护失败后会隐藏皇冠并撤回布局改动；因此还应区分失败发生在布局应用前、应用后，还是回退后采样时。

## 排查顺序

1. **锁定原生节点。** 在 Agoo/ego 的任务专用测试会话核对实际 URL、视口、前台标签以及运行中的固定脚本身份。先从空框填一条可辨认的合成短草稿，逐字读回，定位同一输入框中的原生控件。记录空框、发送刚出现、动画结束三个时点的节点和父链。优先依据表单归属、可访问名称、控件角色和稳定属性；在该输入容器内确认唯一匹配，别依赖整页第一个按钮或图标。
2. **比对两层父容器。** 从实际发送控件找到原生底部操作区，再追到同时管理编辑器格、附件格和操作区的布局节点。记录皇冠实际父节点、`toolbar.contains(native)`、插入锚点、以及编辑器是否在独立格。Gemini 先确认 `.input-buttons-wrapper-bottom` 在状态切换中是否仍是同一个有效底部工具栏；若是，再看 `.trailing-actions-wrapper` 的父 grid 和编辑器格，确认 `field`、`leading`、`trailing` 都有正确的原生归属。
3. **分清测量、遮挡和布局。** 查记录脚本是否误把麦克风当发送，或漏掉 `aria-label="Send message"`。分别量皇冠宿主、内部按钮、原生发送和编辑器可见滚动区。两按钮尺寸正常但点不到时，读中心和内部点实际命中的节点（含 Shadow DOM），排除抽屉、动画和裁切。按钮尺寸为零或编辑器变窄时，对比原生与固定脚本加载后的 `display`、网格模板、`grid-area`、flex 收缩／换行、最小宽度、`overflow` 与祖先矩形；同时对照故障帧截图。临时隐藏扩展控件获取原生宽度时，确认视图加到原生节点上的样式也已回退，并把这组证据单独标为对照。
4. **按证据做最小改动。**

   | 观察结果 | 从哪里改 |
   | --- | --- |
   | 编辑器、按钮或工具栏只有属性改名，结构与角色不变 | 改 `site.js` 中该站的选择器或现有角色识别条件。 |
   | 空框与有稿时切换节点，或发送外面多了容器 | 保持识别当前原生控件；如果稳定工具栏的结构也变了，只更新 `placement()` 的定位。共用视图负责推导插入点和重挂载。 |
   | 两个按钮确实同处底部工具栏，但扩展让编辑器变窄或发生裁切 | 比对原生 grid/flex 后，修 `placement()` 返回的布局节点或 `applyNativeLayout()` 写入的最小属性。让编辑器独占可用宽度、按原生规则纵向增长，让底部操作区换行。 |
   | 原生页面也出现同样问题，或命中被站点抽屉挡住 | 记录原生对照和遮挡节点；如果只有取证选择器认错，修取证，不改产品挂载。 |
   | 新站点或发送语义变化 | 复用现有适配器合同，另核实支持路由、会话归属、忙闲／停止和接收回执；新站点范围走原审阅链。 |

普通改名可以只换选择器。当前实现是项目内的站点适配器，不是可从配置填入任意选择器的通用发送器。对新容器结构先复用 `placement()` 的节点合同；如果后续多个站点确实需要不同 grid 策略，再按已经验证的差异整理布局参数。

## 怎样判定修好

- 先在故障视口跑通空框到短草稿；再在受影响的窄窗及 1280 CSS px 跑空框 → 短草稿刚出现和稳定后 → 6,399 字符多行 → 1,400 个连续 `W` → 恢复短稿。记下宽度、控件父区、滚动与矩形、实际命中节点、原生对照宽度和逐字读回结果，保存关键帧原始截图。
- 每个稳定帧只有一枚可见皇冠，它留在原生底部。有发送按钮时，两者同区、轮廓完整，分别命中，不重叠或覆盖编辑器。编辑器可用宽度不低于同稿同视口的原生对照，多行可纵向增长，连续字符不撑宽页面。需要刷新前先核对草稿、在途请求及未知结果。
- 涉及点击验证时，在任务专用会话先读回精确合成草稿，再定向可信点击：原生发送一次，回执只出现一条唯一短消息且未入队；Shift＋皇冠一次，原文只进入一条暂停项且未发送。核对暂停项文本、状态和 ID，只清理本次合成数据；结果未知先查回执。
- [视图定向测试](tests/view.test.mjs)已覆盖草稿变化、工具栏替换与皇冠实例复用；选择器及控件角色改动沿用对应站点测试。真站结论以当前运行的固定脚本为准，源码、开发产物、已审阅安装和实际运行版本分别记录。临时样式和夹具只用于定位，旧版把皇冠移到上方的记录不属于当前通过证据。[UI 验证记录](UI-VERIFICATION.zh-CN.md)单独保存各版本结果。

### Gemini 390 px 已观察到什么

此前 0.1.59 采样中，皇冠宿主落在 `.input-buttons-wrapper-bottom` 内，但有按钮零尺寸和无法命中的帧；旧量测也漏识别过实际存在的原生发送按钮。另有一帧 DOM 命中栈显示 Gemini 抽屉遮罩挡住输入区。关抽屉并将标签切到前台后，390 与 1280 px 的采样中皇冠可命中；这批采样没有建立完整草稿及可信点击回执，也没有隔离原生 grid 与扩展样式的影响。由此不能判定直接父容器错选，也不能排除外层布局在某个状态下出错。本机线索：`artifacts/bottom-crown-20261124/{second-matrix,takeover-dom,r58-foreground-matrix}.json`。
