## 真实订阅与独立取证

- 原生侧栏进入 PC 订阅管理，实际下载原用户授权订阅。识别 Clash、1 个 VMess、0 无效，界面将该节点列为需要本地客户端。独立 Mihomo 实例读取同一授权来源并选中这唯一节点。
- 同一隔离 ego Profile、同一标签页的三个独立 HTTPS 请求均返回 200。应用后 Chrome 读回 `pac_script` 和专用回环端口 `50021`，浏览器响应也记录该端口，客户端在同一次导航中记录见证域名通过选中的 VMess。暂停后 Chrome 回到 `system`。三个阶段出口一致。
- 重开后来源仍在，URL 输入为空，解析结果未恢复，持久数据未发现完整 URL 或秘密路径。删除临时来源和端点，恢复原待应用选择。独立客户端已退出且端口关闭，私有临时输入和比较密钥已清理，任务空间复查已不在。隔离安装仍有这条精确端口的闲置授权，现有 UI 仅支持撤销本工具全部线路，因此保留了原有线路授权及这条记录。该端口当前无监听。原 Clash 和开发服务仍在运行。[S-REAL 脱敏证据](../evidence/s-real-20261119.json)

S-REAL 的隔离 ego 安装登记与唯一正式 0.3.36 逐字节一致，实读同轮已应用开发 revision。旧备份和生命周期使用 Chrome for Testing 155.0.8059.39 固定开发候选及同一正式工具包。ego 测试空间结束后，离线同源预览用同版 Chrome 独立实点，覆盖七栏、内存应用和暂停，记录 0 外部请求、存储不变。原打包器 `PROJECT_PACKAGE_MATCH` 通过。本轮交付验收文档和证据，未修改产品源码或正式包。[运行身份与样本账](UI-FUNCTIONAL-TESTS.zh-CN.md#第二阶段--逐轮运行记录) · [补测证据](../evidence/acceptance-supplement-20261119.json)
