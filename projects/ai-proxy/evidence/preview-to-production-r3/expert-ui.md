## 扣分依据与剩余建议

以下是组件设计质量的扣分依据及优先级，**不计算正式总分，不与其他专家分数平均**。同一原因不按 Surface、宽度或截图张数重复扣分。

### 1. P1 · 当前子页被公共前言挤到首屏之后

证据：`management-320-overview.png` 首屏只能看到前两张完整状态卡及第三张开头；矩阵该状态的“概览”Tab 顶部 y≈1089.85、“测速”Tab y≈1137.85，已超过 900px 取景。`management-390-speed.png` 中测速 Tab 在 y≈883.78，正文尚不可见。侧栏相对紧凑，但 `sidebar-390-speed.png` 的测速正文也到约 y=820 才出现。

扣分点是信息层级：页面标题、解释性 Hero、四张状态卡、子导航和运行提示连续堆叠，使切换后的专属内容失去视觉主导。不是“有纵向滚动就失败”，也不是要求所有长列表塞进首屏。

建议由原 UI owner 压缩窄屏公共摘要，并让当前子页标题和关键内容更早出现。保留控制权、配置应用、HTTP 与 AI 能力的区分；可以合并重复文字，不能通过移除安全边界或伪造可用状态换取空间。320px 管理页四卡全改单列是额外高度来源，应按实际文本容纳能力评估。

### 2. P2 · 同一未接入原因重复占据多个层级

证据：`management-1200-speed-content.png` 和 `sidebar-680-speed-content.png` 中，“尚未接入真实 HTTP 耗时与下载吞吐测速……”在子页说明与下方白色卡内逐字重复，上方另有全局未接入提示。`management-900-top-content.png` 也在全局提示和 Top 空态中重复同一段解释。

扣分点是重复而缺少新信息，导致多个相同视觉权重的说明框竞争注意力。

建议保留一处完整、持续可见的能力原因，子页只补充本页特有信息；沿用现有反馈与状态语义。不能批量删除 `role=status/alert`，也不能隐藏尚未接入的真实限制。此项与第 1 项有关，但这里只评价文案重复，不再重复计算纵向空间损失。

### 3. P2 · AI 网站列表过早变成高卡片，扫描效率下降

证据：`sidebar-1200-ai-content.png` 中名称、状态和操作同排，单项约 70px；到 `sidebar-900-ai-content.png` 时操作整组移到第二行，单项约 119px，右侧仍有大块空白。管理页的 `management-900-ai-content.png` 同样明显；390/320px 内容截图进一步成为名称、状态、操作三层。

源码对应 `options.css` 的 `@media(max-width:900px)`，按视口统一让操作占整行；这能避免挤压，却没有利用不同 Surface 的实际可用宽度。与参考成组紧凑列表相比，逐项独立描边和多行布局也增加了滚动负担。

建议优先按实际内容区宽度调整行内布局；900px 侧栏不必与被管理导航占去宽度的 900px 管理页采用相同密度。窄屏允许换行，保留清楚的名称/域名层级、操作标签和足够点击面积，不用缩小字号硬塞。

### 4. P2 · 可导航按钮的名称承诺了当前没有的结果

证据：`management-1200-overview-content.png`、`sidebar-320-overview-content.png` 中“查看耗时统计”“本地统计与收藏”仍是正常可点外观；对应 `speed-content` 和 `top-content` 实际只有未接入说明。源码 `DiagnosticsPage.tsx` 的 overview 分支也确认它们分别导航到 speed/top。

扣分点是目的地预期不一致，不是禁用检测按钮有错。导航可用不等于统计或收藏能力可用。

建议保留必要入口，但让当前未接入状态在按钮附近或名称中明确，例如指向“测速说明”；不要让用户以为下一页已有统计数据。未来能力接入时再恢复结果型文案，不扩展本轮后端范围。

## 反方核查：不能成立的“一致 / 通过”推论

1. **同样的标题与颜色不等于全页面一致。** 参考概览以当前网站域名、常用 AI 网站摘要及带图标的快捷入口组织内容；正式组件概览改为当前选择和四个均质入口卡。参考 Top 有 Top 5/10 控件与收藏列表，参考测速有三项指标与控制区；当前 production 分支的这两页是说明态。应保留 R2 的 PARTIAL，不能写成完整视觉复刻。也不能为填平差异接入参考中的模拟成功。
2. **50 状态 / 100 PNG 不等于 100 次完整页面验收。** 短页的顶部与内容取景可能高度近似，长页的 `-content` 仍会裁掉上方标题或下方列表项；固定页头上方的裁切不能直接当成产品遮挡故障。补图解决了首遍只有公共区域的证据缺口，但没有证明所有内容同时完整可见。
3. **没有页面横向溢出不等于所有局部导航同时可见。** 管理导航在窄屏横向滚动是明确设计，不将首遍 overflow 计数当成整页破版。680px 管理页的诊断子导航末项贴近/部分超出容器可见边缘，源码有 `overflow-x:auto`；这是滚动可发现性的观察，不是已经证实不可访问。参考在 ≤680px 使用两行子导航，与当前布局存在差异。
4. **`preview=false` 不等于 Chrome 已安装或数据来自真实 Chrome。** 基础诊断中的“读取真实 Chrome API”是产品文案；本 fixture 的 transport 仍在内存中。蓝色“模拟出口探测”也不能作为实际出口证据。没有看到伪造成功截图，不等于完成了真实线路验证。
5. **视觉禁用态正确不等于全部可访问性通过。** 本审阅未执行键盘、焦点恢复、屏幕阅读器、200% 缩放、其他语言或真实 Side Panel 内嵌检查。禁用控件的淡色不机械按正常可用控件扣分；当前截图也不足以宣称全局 WCAG AA。
