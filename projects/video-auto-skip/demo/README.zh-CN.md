## 如何复跑

从仓库根目录运行：

```sh
node projects/video-auto-skip/demo/run-chrome.mjs
```

使用 Node 22+、已有的 `dist/development`、仓库缓存的 macOS Chrome for Testing 155 与带 VP9 编码器的 `ffmpeg`。可用 `--chrome /绝对路径` 指定 Chrome for Testing 二进制。脚本在本机回环地址生成并提供两段真实 WebM，从 Chrome 原生扩展操作打开实际 Side Panel，进入「开发」→ 网页模式 →「运行」，读回草稿再执行。如果临时配置未启用该扩展的 Chrome「允许用户脚本」，用该配置的原生开关启用。使用 Chrome 指针输入回拖测试页控件，控件调用真实媒体 seek。报告写到标准输出。测试结束释放本次的 Chrome 和本地测试服务。

脚本只运行自有临时 Profile，不连接 iYF。合格的复跑应退出 0，且 JSON 的 `status` 为 `passed`、`preview.targetMatched` 与 `candidateUnchanged` 为 `true`；并发负例期望 `UNKNOWN` 且 `rearmRejected: true`。两次连续开发构建指纹不一致时，保留失败报告，待同一现有 writer 稳定后再复跑。

### 为什么选 Page 世界

- R1 试运行：[开发 → Page JS](../../../docs/api/page-userscript.zh-CN.md#developer-page-quickstart) → 原 OpenDesk 预览与权限链 → 绑定当前标签页顶层文档的 `USER_SCRIPT` → 原生 `HTMLMediaElement`。只在本地夹具运行一次；脚本限时并移除监听，不保存用户规则。
- 正式候选：[Sidebar v2 + 同包 Page companion](../../../docs/api/sidebar-tool-page-module.zh-CN.md)。页面端拥有播放器身份、监听、定位、防重和撤权清理；沙箱侧栏保留现有设计，只通过 `page.request` 请求当前文档快照和校准，双方用公开私有存储设备内保存规则，按版本/修订并发校验。网页侧可以在侧栏关闭后继续运行。参照[阅读目录同包先例](../../reading-toc/DYNAMIC-PILOT.zh-CN.md)；R1 尚未验证连播助手的同包安装、回执或撤权。
- 普通 Sidebar iframe 不能直接访问网站 DOM，也不负责常驻监听。Controller 是一次性受控任务，可用来诊断与人工试跑；它不适合作为媒体事件驱动程序。目标站若只提供跨源 iframe、封闭播放器或未公开私有 API，先判定站点适配受限；公开 Page 合同不承诺任意子帧注入。当前结论为 `SDK_GAP_NOT_PROVEN`，暂无依据增加固定 Content、MAIN 桥或平台权限。

## 第一版的最小任务拆分

1. 真人验证完成后，从原 URL 只读观察。给该站建立作品、季、集、线路/版本与唯一主媒体的识别规则；区分广告、不可读 iframe 与播放器替换。身份不确定时给出原因并禁止动作。
2. 把已验证的基本 seek 迁入受管 Page companion。按文档、播放器、来源和内容绑定规则；在自然播放进入区间时才触发。补验主动查看、撤销、换集、SPA、手动换线、用户停用/撤权。暂停只修改配置；回拖和主动查看豁免当前区间。用原有受管生命周期清理监听，校验实际 seek 落点，未知不重试。
3. 用现有预览实现侧栏的两个区间与开关，设置默认不生效。「最后 N 秒」只存 N；保存支持同作品默认及当前集例外，显式关闭覆盖继承。使用共享存储与按需快照验证关闭侧栏后仍运行、重开恢复、草稿不串到其他文档。
4. 从站点公开选集 UI 读取当前集及可验证的正常集序；处理倒序、跨页/分组/加载边界、同集多线路、季末和非正片。确认唯一下一集后只导航一次；分别确认进入目标集及目标视频实际开始播放，若未知只读对账，既不重发也不与站点原生连播竞争。

只有第 1 项和目标站的 T04 核心证据成立，才能确认首个支持网站具备正式开发的技术条件。通用播放器内核与侧栏伴随结构可以先行开发，暂不承诺 iYF 可用。
