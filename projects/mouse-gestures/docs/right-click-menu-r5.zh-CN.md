# OpenDesk Mouse Gestures R5 · 右键菜单与手势时序兼容

任务：OD-MOUSE-GESTURES-RIGHT-CONTEXTMENU-R5
仓库：shopable-ai/opendesk-browser · 唯一分支 main

## 1. 原始目标及问题

用户在 `projects/mouse-gestures/preview/index.html` 看到“右键拖动”，实际按下右键却弹出浏览器默认菜单，不能自然体验手势。

根因分两层：

- **预览缺陷**：练习画布原先的 `pointerdown` 只接受 `event.button===0`，而菜单没有被练习区域专门拦截；界面默认“右键拖动”与实际代码不符。
- **正式浏览器时序限制**：macOS Chrome 等环境可能在 `mousedown` 后、第一次 `mousemove` 前触发 `contextmenu`。想要允许原生菜单与想要阻止早发菜单，不能单靠移动阈值同时保证。真实原生菜单不能用普通网页脚本延迟后再原样恢复。

**不可接受的伪方案**：先无条件 `preventDefault()`，之后合成一个 `contextmenu` 事件“恢复原生菜单”；合成事件无法真正重开浏览器原生菜单。

## 2. 产品决策

### 2.1 预览沙盒

预览页面仍是离线、无权限、无导航的交互演示：

- 选择“右键拖动”时，仅在 **练习画布** 的鼠标右键 `contextmenu` 上阻止默认行为，避免下压时菜单遮挡手势；按下右键、保持右键移动、松开识别一段或两段方向；仍只显示反馈，不执行导航。
- 单纯右击练习画布也不打开原生菜单，这是**演示沙盒的显式牺牲**；练习画布外的页面及键盘菜单不受影响。
- 选择“Option / Alt + 左键拖动”时仅接收 Alt + 左键，不拦截右键菜单。
- Esc、指针丢失、取消、禁用及切换选项都清空本次轨迹；`pointerId` 必须匹配，不得串用其他指针。

### 2.2 正式扩展

新选项 `preferences.menuPolicy` 使用现有 ETag/CAS 保存、读回，不扩充 Chrome 权限：

| 策略 | 默认值 | 菜单先于移动时 | 普通右键 | 适用 |
| --- | --- | --- | --- | --- |
| `native-first`（原生菜单优先） | **是** | 允许原生菜单，放弃该次手势 | 保留 | 保护既有用户行为 |
| `gesture-first`（手势优先） | 否，需用户主动选择 | 已授权网页、可信右键、非排除区域阻止早发菜单，继续等待拖动 | **在可手势区域不弹原生菜单** | Mac 菜单提前弹出者 |
| `alt-left`（替代触发方式） | 否 | 使用 Option / Alt + 左键，无需抢右键 | 保留 | 必须保留原生右键者 |

在手势优先模式下，Shift + 右键、输入框、链接、可编辑区、按钮、选区及原有排除条件不应被抢占，仍使用浏览器菜单。用户随时可切回原生菜单优先。**不能把这种有取舍的模式隐式设为所有用户默认值，也不能声称百分之百兼容网站自身的右键逻辑。**

### 2.3 原有行为不可回退

维持 12px 拖动意图、56px 激活、28px 最大侧偏、12px 反向限制；保留四方向、最多两个互相垂直段、未映射组合不执行、释放后至多执行一次、Esc/失焦/隐藏/授权失效取消；保留释放后精确匹配目标、位置、按键与 450ms 窗口的菜单关联防护；不扩大权限、不改通用 Host、Installer、Page Authority。
