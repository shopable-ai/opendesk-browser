## 添加服务易懂化（2026-10-31，本轮设计决定）

阶段仍为 DESIGN_PREVIEW_ONLY。实际打开添加入口后确认：旧“本机服务／连接这台设备”没有解释连接对象，地址不可见，下一页却要求选登记进程。普通用户无法据此知道该启动什么。

只读核对 `ai-account-usage/README.zh-CN.md` 的“普通 serve 的有界 HTTP 应用接入”和 `app/domain/http-services.js:cookieServiceOrigin`：普通 serve 已提供精确 origin 与一次性应用连接码；管理页“Cookie 同步设置 → 生成新应用连接码”也提供地址。默认端口为随机值，主机名含当次随机标识；不能猜端口、替换成 127.0.0.1 或把一次性管理链接当服务地址。本轮只模拟这一 HTTP 配置路径，不改并行 owner 的正式 HTTP/Native 实现，不宣称真实接入通过。

| 方案 | 取舍 | 本轮决定 |
| --- | --- | --- |
| 两类都显示名称、地址，本机预填固定端口 | 填写形式一致，但当前没有可靠默认地址 | 不预填；显示明确的地址取得方式和示例占位 |
| 本机只填名称，下一页选登记进程 | 适合既有 Native 登记路径，仍难解释且排除普通 serve | 不作为本轮默认添加流程；正式 Native 入口保持原 owner |
| 两类都填名称、地址，再分别审阅连接 | 两个稳定输入框；本机支持普通 serve，公司保留 HTTPS 规则 | 采用；本机下一步填应用连接码，公司授权仍未接入 |

本机命名“此电脑上的服务”，说明连接已在此电脑启动的账号额度服务。名称自定义；地址初始为空，粘贴服务实际给出的完整地址；说明未启动时先启动服务、保持运行并从管理页取得地址／码。公司地址从管理员取得。切换类型分别保留地址草稿，不把本机地址带进公司字段。两类保存都不自动连接、关联或授权。

本机地址只接受 HTTP(S) 的 localhost、*.localhost、127.0.0.1、[::1] 来源；公司只接受非本机 HTTPS 来源。保留严格精确来源检查：不接受路径、尾斜杠、参数、片段、用户密码或控制字符。重复按完整来源判断，允许不同本机服务。已连接配置的地址只读，改地址须先断开；更换接收方清除旧关联与授权。连接码单独在连接页填写、只存草稿内存，不放 URL、截图或回执；离线验证仅用虚构码。未知结果继续只核对原操作，不重发。

验证计划只覆盖本轮添加、切换、校验、保存未连接、返回修改、失败保留、取消／草稿、连接审阅与受影响身份／撤权／unknown 保护，附同候选截图并进行新独立 UI/UX 复评。真实服务、Native、正式 React、安装和完整无障碍验收仍 NOT_TESTED；不启动 Browser 构建或宽度／缩放矩阵。

实施收尾：本机 HTTP 配置与公司配置共享两个字段，名称保留且地址按类型分别缓存；重复按精确来源检测。连接码用默认遮蔽输入与准确的64位十六进制校验，清除旧登记进程选择。未启动时在详情与连接页提供明确下一步和手动核对入口；核对后仍不提交连接。已连接空关联提示按当前状态显示。配置表单收紧间距并保持保存／取消可见；真实截图与断言确认操作区不遮住默认启动帮助。
