## A. Chrome/浏览器进程、自动化协议与扩展边界

| 来源 | 经核查的事实 / 产品落点 |
| --- | --- |
| [Chrome for Testing 官方介绍](https://developer.chrome.com/docs/automation-and-testing/chrome-for-testing) | Chrome for Testing 是面向自动化与可复现测试的版本化发行包，不是某个网页 JS 属性的别名。**产品落点**：发行版信息归启动器诊断，网页读数不冒充二进制身份；另注意它不自动更新，不宜加载不可信内容。 |
| [Chrome Automation and Testing 总览](https://developer.chrome.com/docs/automation-and-testing) | 区分 Chrome for Testing、ChromeDriver、Puppeteer、Headless；**落点**：报告中分清浏览器渠道与自动化控制器。 |
| [MDN `navigator.webdriver`](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/webdriver) | 标准网页层自动化状态信号；Chrome 的一些自动化/无头/调试启动条件可使其为 true。**落点**：只显示实测 true/false/不可用；false 不等于不可被检测。 |
| [Playwright Browsers](https://playwright.dev/docs/browsers) | Playwright 支持本机品牌 Chrome channel，也支持 Chromium/无头实现；使用品牌 Chrome 不是自动化解除证明。**落点**：将启动渠道和有头/无头标为启动器元数据，而不是“隐身模式”。 |
| [Chrome 扩展 Content scripts](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts) | `ISOLATED` 默认与网页 JS 不共享执行世界；`MAIN` 可在共享环境内运行且有暴露/干扰风险。**落点**：读数必须标记执行世界，独立网页验证不依赖扩展内部临时变量。 |
| [Chrome Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) | Chrome 原生支持 MV3 侧栏；**落点**：OpenDesk 已有共享 Side Panel 宿主，新业务产品只需要 Sidebar Tool UI，不再注册平行 Panel。 |
| [Chrome debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger) | 高敏 CDP 附着能力。**落点**：严格复用现有 Browser Fingerprint 受控 Host，拒绝新项目接受任意 CDP 指令。 |
| [Chrome Permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions) | `debugger` 不可声明为运行时 optional permission。**落点**：不得说“首次点击再向 Chrome 申请 debugger”；安装/升级时必须原生审阅。 |
| [Chrome 136 远程调试变更](https://developer.chrome.com/blog/remote-debugging-port) | 默认用户数据目录不接受某些远程调试开关；自动化测试应隔离用户 Profile。**落点**：启动层安全检查，不尝试从现有个人 Chrome 绕过该保护。 |

## B. Cloudflare、测试键及访问控制

| 来源 | 经核查的事实 / 产品落点 |
| --- | --- |
| [Cloudflare Bot Score](https://developers.cloudflare.com/bots/concepts/bot-score/) | 综合请求/会话/浏览器信号及检测引擎，非单一 JS 字段；Bot Score 为站点侧能力，不保证对客户端公开。**落点**：浏览器侧不得声称算出 Cloudflare 真正 Bot Score。 |
| [Cloudflare Bot Detection Engines](https://developers.cloudflare.com/bots/concepts/bot-detection-engines/) | 包含启发式、JavaScript 检测、机器学习等；**落点**：诊断归因必须区分网页层、网络层及服务端策略，不能把 WAF 挑战归因到一个属性。 |
| [Turnstile 自动化测试文档（2026-10）](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) | 自有网站在开发/CI 使用官方测试 sitekey 与 secret，避免测试场景因真实挑战失败；**落点**：提供面向站点拥有者的测试模式说明，而非生产绕过功能。 |
| [Cloudflare WAF Skip 规则](https://developers.cloudflare.com/waf/custom-rules/skip/) | 站点所有者可按自身权限为合法测试流量配置受限规则；某些防护模式不可跳过。**落点**：仅用于授权站点和最小范围，不是第三方站点绕过手段。 |

| 来源 | 用途 | 建议与风险 |

| [CreepJS / GitHub](https://github.com/abrahamjuliot/creepjs) | 浏览器/设备属性和一致性研究 | **参考特征分类和对比 UX**；其 README 声明代码 MIT，但名称及商标有限制，产品不得以 CreepJS 名称公开镜像。 |
| [puppeteer-extra / GitHub](https://github.com/berstend/puppeteer-extra) 和 [stealth 插件说明](https://github.com/berstend/puppeteer-extra/tree/master/packages/puppeteer-extra-plugin-stealth) | 公开存在 Node 自动化特征修改路线 | **竞品/风险研究，不列为默认依赖**。方案依赖持续适配目标网站检测，不能修改 Chrome 原生 UI、服务端 TLS/行为信号，也不能保证访问通过；不据此实现未授权访问控制规避。 |

## D. 技术决策与证据等级

1. **来源优先级**：最新 Chrome / Cloudflare / Playwright 官方文档 > 公开 SDK/浏览器规范 > OSS 项目自身 README > 第三方博客/社区猜测。
2. **观察面分离**：`webpage-js`（网页可见）/ `launcher-attested`（经授权启动器元数据）/ `test-server-echo`（自有测试服务端回显）/ `unknown`。未经证据连接，禁止跨层推断。
3. **技术路径对比**：
   - 只做网页 JS 伪装：可观察表象局部改变，但难以覆盖协议和进程层；**不推荐**单独承载产品目标。
   - 扩展复制一套 debugger/指纹控制：违反 OpenDesk 单 Host/权限架构，维护高；**不推荐**。
   - **独立 Automation Lab UI + 复用 Browser Fingerprint SDK + 自有检测网页 + 可选启动器上报**：用户诊断价值、维护性、权限与独立证据最佳；**推荐**。
4. **验证不能替代**：只读检测页不是启动器真实性证明；`navigator.webdriver === false` 不是“Cloudflare 通过”；`debugger.detach` 不是恢复验证；React 构建不是 Mac Chrome 正式安装验收。
5. **安全边界**：仅面向已获授权的测试系统/浏览器。示例和实现默认不能悄悄读取个人 Cookie、跨站账号数据、重写未授权网站的挑战页面或禁用浏览器安全告警。
