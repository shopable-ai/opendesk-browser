## 1. 原始用户目标

用户在 ChatGPT、Claude、Gemini 等网页进行深度分析时，AI 单条回复往往非常长。用户希望在「网页剪藏」中点击“选择目标区域”，然后回到网页，**仅点击包含完整目标回答的内容区域一次**，就将该 DOM 区域下已经加载的正文转换成 Markdown，呈现在剪藏侧栏，供复制、下载 .md 或明确保存到「我的摘录」。无需拖动鼠标从回答开头选到结尾，也不应把其他回复、输入框、侧栏或整个网页混入。

产品语义必须区分：
- **文章**：原有正文提取。
- **选区**：原有鼠标拖动的文字 Range，保持完整原逻辑与右键路径。
- **引用**：原有文字选区转引用，保持完整原逻辑。
- **链接**：原有 URL Markdown。
- **区域（新增）**：**点选网页 DOM 容器**（例如一条 AI 回答）并提取该容器完整可读取内容，纵向跨度可以超出当前屏幕。

这里的「区域」不是屏幕截图 OCR，也不是 CSS 像素矩形剪切；只读取用户确认的 DOM 目标及其语义内容，最终产出真实 Markdown。

## 3. P0 操作流程与界面

1. 用户在「网页剪藏」选择新增的「区域」模式（推荐在「文章 / 选区 / 引用 / 链接」四个原有入口之外增加第五个；320px、360px、400px、440px 响应式必须实测）。
2. 主按钮显示「点选网页区域」。点击后在**当前已授权的目标网页**启动临时区域点选；侧栏显示「移动鼠标查看范围，点击一处选择整块内容；Esc 取消」。
3. 网页上的候选内容容器随鼠标 hover 显示轻量轮廓。选择器优先定位有意义的正文容器（例如一条回答、一篇文章、section、article、代码块），而不是页头、工具栏、输入框或整个根节点；允许切换上一级/下一级候选容器以修正范围。
4. 用户在目标回答上**点击一次**；此点击用于确认，不得触发网页原有按钮、链接、提交或复制。点击后**自动**获取该容器的一致性快照并转换成 Markdown，不强制再点「转换」。
5. 侧栏显示真实生成的 Markdown 预览、来源、字节数；「重新选择」可重新点选，原有「保存摘录 / 复制 / 下载 .md」按钮继续工作。**保存仍须用户主动确认**，不能自动落库或发送网络请求。
6. 如果没有权限、网页变更、选择取消、内容为空、尚在动态生成、大小超限或目标不支持，明确提示原因及下一步；禁止把上一轮结果当本次成功。

文案建议：
- 模式：`区域`
- 主按钮：`点选网页区域`
- 激活提示：`移动鼠标预览范围，点击选中整块内容；按 Esc 取消`
- 成功：`已提取所选区域的 Markdown`
- 重新操作：`重新选择区域`
- 体积过大：`所选区域超过单条摘录限制，请选择较小范围；内容没有被截断保存`

要做到“一次点选就完成”：**hover 预判 + click 提交自动提取**。可在 hover/选中时提供上一级/下一级范围调整，但不得成为强制二次确认流程。

## 4. P0 架构契约：复用既有框架而不伪装功能

- **正式 UI（工具沙箱）**：只保存当前 UI 模式、操作序号和返回的 Markdown，调用可信 Host；不能直接跨 iframe 读取目标网页 DOM、任意注入脚本或伪造鼠标事件。
- **可信 Host / Browser Framework**：在已有 `page.clip` 与工具安装、启用、包摘要、Chrome 网页授权的安全边界上扩展“网页区域点选”操作；不要新建第二个自动化 Runner、后台服务或存储系统。
- **网页 Content（isolated world）**：负责可见 hover 轮廓、候选选择、真实 click 拦截、Esc/取消、同文档快照；区域转换尽可能复用已有文章/Range 的 HTML→Markdown 转换器，不另建一个质量下降的 `innerText` 拼接器。
- **操作结果**：返回 `{mode:'clip.region',markdown,title,site,source,capturedAt,bytes}` 一类有限、经验证的数据；概念操作可称 `clip.region`，具体启动/等待/取消的 RPC 命名必须先查证现有 Host 事件和异步事务机制，再冻结协议。旧 `clip.article` / `clip.selection` / `clip.link` 合同不改变。
- **绑定与清理**：一次激活仅作用当前工具、当前有权限的 tab/frame/document/URL 与页面代际；导航、tab 关闭、停用/卸载/升级、撤权、超时、Esc 或用户取消时主动卸载 overlay、丢弃旧 ticket，迟到消息不得回填、不得自动重试。
- **内容隐私**：仅在用户明确点选后采集候选 DOM，不跨页面批量扫描/采集，不读取不可见 DOM、输入框、密码、脚本或编辑中的私有内容；结果不上传远程服务。不可访问的 Chrome 内部页、跨源 iframe、封闭 ShadowRoot 应显示不支持，而不是绕过授权。
- **DOM 语义**：按已有转换器能力保留标题、粗斜体、列表、链接、表格、引用、代码栅栏与代码语言；数学公式/脚注/引用标记保留最佳可读表达，不保证网站没有提供原始源码时的逐字节 Markdown 同一性。
- **动态 AI 回复**：一旦用户点击，就生成该时刻的一致快照；如模型仍在流式输出，应明示“内容可能未生成完”，支持完成后重新选择；不谎称最终完整。虚拟列表未装载进 DOM 的内容亦不能宣称已捕获。
- **数据安全**：继续沿用单条 160,000 UTF-8 字节、整库 4 MiB、最多 1000 条、CAS/读回校验；超限拒绝而非截断。较大回复按标题分段/多次剪藏可列为 P1，不擅自扩容所有工具的权限或额度。

3. `preview/mock-host.js` 与 React 同源预览舞台：用模拟长 AI 对话网页演示真实的 hover、单击、范围调整、取消和 Markdown 输出；预览只模拟 Host/页面，不复制一套工具 UI。

6. 添加区域点选专门 Node/Chromium 回归和真实 Chrome 操作记录；补充 README 用户操作说明及当前状态。旧文章/选区/引用/链接和历史保存测试不能删。
