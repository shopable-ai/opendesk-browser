## 3. 修复目标

| 目标 | 优先级 | 用户可观察的结果 |
| --- | --- | --- |
| G1 安装后可打开 | P0 | 拖入合法包、完成原安装审阅后，在「扩展」点击「scrapyjs 采集」进入真实采集界面；不出现文件丢失页或空白页，不增加第二次通用启用步骤 |
| G2 安装内容可持久使用 | P0 | 关闭再打开、在安全条件下重新打开宿主后仍可用；安装成功后不依赖导入包的原路径或临时对象 URL，原配置可读 |
| G3 身份与保护不退化 | P0 | 安装、打开和更新始终绑定真实工具身份；原数据、能力审阅、opaque sandbox、权限、撤权、dirty/busy/unknown 保护保留；打开不自动采集或发送 AI 请求 |
| G4 错误可判断与恢复 | P1；若修复涉及失败分支则必测 | 已知加载失败提供可见原因和适用恢复入口；失败不伪报成功，未知操作不自动重放 |

本问题的修复完成门槛是适用 P0 全部通过，并通过实际改动涉及的 P1；仅隐藏错误页、显示成功 Toast 或让模拟预览打开均不满足 G1。

## 6. 执行顺序与文件归属

1. 从 T01–T03 的真实入口定位首个失败边界，核对用户安装包与仓库正式包的身份。记录实际资源 URL 和加载状态，区分路径丢失、包读取/存储失败、宿主资源缺失与 App 初始化失败；这些目前都是待证假设，不排序为已知根因。
2. 若故障在工具初始化或资源声明，业务修改留在 `projects/scrapyjs/`，先检查[配置](../tool.config.json)、[入口](../src/main.jsx)与[原构建合同](../vite.config.mjs)。若证实是通用导入、安装、打开路由或沙箱资源故障，再由原 UI/Runtime owner 在现有模块最小修复，并补对应公共回归；不在工具内复制 Host/安装器。不足以证明通用缺口时标 `SDK_GAP_NOT_PROVEN`。
3. 先运行能证明该失败修复的定向检查。只有相关源码修复或交付需要才重新编译、准备候选；使用[原打包器](../../../scripts/build-sidebar-tool.mjs)及[打包 Skill](../../../.agents/skills/opendesk-sidebar-tool-package/SKILL.md)的候选 → 定向门禁 → `--promote-from` → `--check-project`。任何失败、来源漂移或未知结果均保留旧正式包。
4. 对同一候选完成适用 T02–T08，再补与实际改动相关的 T09/T10。业务回归归项目 `tests/`，公共导入/Host/身份/撤权回归归根测试；不新增只匹配源码字符串或版本号的业务测试。

后续需要对正式包与当前编译/源码做同源诊断时，已有只读入口为：

```sh
node scripts/build-sidebar-tool.mjs projects/scrapyjs --check-project
```

此命令本轮未执行；本轮已直接观察到 JS 及回执输入漂移，因此其潜在失败只能先判为同源验证未满足，不能自动归因于文件丢失。无需为本轮规划启动构建或修正这些产物。

浏览器实施默认先运行 `ego-browser skill` 并复用单一 TaskSpace；仅在确认 ego 缺少目标 Chrome 扩展/Side Panel 能力时说明具体原因，沿用原受支持专项入口。Browser 开发复用既有 `dist/development` 与原 dev 服务，先核实真实路径、ID、连接和指纹，不覆盖其他 watcher，不通过 `chrome://extensions` 绕路或全局剪贴板输入。无原生访问能力时继续源码工作，安装层保持 `NOT_TESTED`。
