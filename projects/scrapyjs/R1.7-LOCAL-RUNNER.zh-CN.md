## 所有权与调用链

- Sidebar Tool / opaque iframe：原 React `App.jsx` → `AiPanel.jsx` → `local-runner-client.js`，只发声明式 JSON，不获取凭证和服务 URL，不直接访问 localhost。
- 通用可信 Host：`src/platform/host/local-tasks.js`，通过原 `OpenDeskTool.request` 分发，负责有限端点、安装身份、精确目标范围、首次可信配对、短期 session 和下载回执；不理解字段规则或 Scrapling。
- 本机服务：本目录 `local-runner/`，手动启动一次，仅监听 127.0.0.1；Scrapling 解析、SQLite 状态、独立 Worker、JSONL/CSV 均在本机。关闭侧栏不停止任务；服务重启保守标记中断，不重放任务。
- 原 Controller：`controller/` 与固定 Task 的三个 Origin 不变。本地服务权限由新能力独立审阅，不扩大旧 Task。

## 通用桥接缺口记录

公开合同 `docs/api/browser-sdk.zh-CN.md` 的 network.request、`docs/api/sidebar-tools-ai.zh-CN.md` 的 ai.generate 以及 `manifest.json` 的沙箱 CSP 是调查入口。当前 `src/ui/sidebar-tools.js` 对每个 `browser.network.request` 都调用 `requestBrowserClick`；连续读取同一个任务也重复确认。沙箱 `connect-src 'none'` 明确拒绝直接 fetch。普通应用不能通过自身代码解决而不绕过现有保护。

最小通用增量是 v2 能力 `localTasks`、`localTasks.request` 和 `localTasks.export`。本机离线转换、分析、索引等任务可复用相同有界服务端点合同；不增加任意 URL 代理、任意命令或动态 Python 执行。业务配置由服务端验证。

首次创建任务在可信 Host 原审阅区批准精确目标 Origin，并通过可信文件选择器读取服务的配对 JSON；该文件不能交给 iframe。令牌刷新只建立同 owner/scope 会话，不重发任务 POST。Host 在派发前持久记录 requestId→scope，回执未知只允许 by-request 读取；取得 runId 后再保存 runId→scope。最多 20 个范围、128 个请求、每分钟 120 次、并发 2 个通信请求；服务 Worker 并发限制另行执行。

停用、升级、卸载沿原安装锁调用服务撤权，要求 `workerExited:true`。服务离线或回执未知时保留可信凭证及原清理日志，不假称远端已退出。不能因此改写 Native 配对或绕过停用保护。

完整导出在服务流式读取、在可信 Host 内有界接收（32 MiB），只向 iframe 返回 Chrome 下载 ID；不通过小容量 IPC 返回全部记录。实际落盘仍需真实 Chrome 下载后独立读回验证。
