# OpenDesk Task Shop · 商业模式与经济模型（V0.1 方案）

> BUSINESS_HYPOTHESIS / REVENUE_NOT_VERIFIED / NO_LIVE_PAYMENTS。2026-11-02。此文档不是已获收入或法律意见。产品边界参见[产品合同](product-contract.zh-CN.md)。

## 1. 卖的是业务成果，不是账号控制权

需求方为**有授权、可验收的业务结果**付费 → 节点用户在许可范围内领取 → 经身份校验的本地脚本执行 → 返回最小必要证据 → 独立验收 → 结算。AI 可选，既不是接单入口也不是必要的执行引擎。

市场不能交易用户好友关系、群组成员、登录 Cookie、凭据或“代发陌生人广告”的权限。自有账号不代表平台获得自动群发许可；禁止未征得收件人同意的骚扰、欺诈或刷量任务。

## 2. 四方交易与对应价值

| 角色 | 提供 | 获得 | 约束 |
| --- | --- | --- | --- |
| 需求方 | 合法任务、预算、验收规则 | 实际业务成果与费用记录 | 不取得执行者登录态/敏感数据 |
| 执行者 | 已授权设备、时间、脚本、业务环境 | 可查看净额、暂停权与收益 | 可随时撤权；不承担未知任务 |
| 脚本开发者 | 可审核且锁定版本的脚本 | 销售/调用分成 | 维护和版本变更受控 |
| 平台 | 匹配、审查、证据、争议、结算治理 | 订阅或服务费 | 公开规则，不伪报完成 |

## 3. 建议收入线与优先级

| 模式 | 付费方 | 验证顺序 | 风险 |
| --- | --- | --- | --- |
| 企业 SaaS 订阅 | 使用本地自动化的商家 | 第一 | 付费意愿与留存未验证 |
| 脚本授权/分成 | 购买脚本服务的用户 | 第二 | 脚本维护和站点兼容成本 |
| 任务成交服务费 | 需求方、按公开合同扣费 | 第三 | 双边流动性、欺诈、退款与支付资质 |

先有真实采购/电商需求，再邀请供给方；不先大规模招募挂机用户或保证赚钱。AI 聊天是可选辅助，不是商业营收前提。

## 4. 第一批任务类目

**优先**：自有电商商品数据整理、已授权采购报价归档、内部工单核对、可审计的资料结构化。尽可能采用目标网站官方 API，浏览器自动化只用于合法且已许可的场景。

**审慎评估**：订阅会员通知或经过接收者明确同意的服务消息，需适配渠道规则、频率、退订、内容及接收者确认。

**不开放**：出租个人社交账号、批量陌生人私信、群聊广告群发、虚假评论、虚假流量、绕风控/验证码、买卖 Cookie 或隐私数据。

## 5. 单笔订单收益示例（完全假设）

以示意订单 ¥100 为例，假设平台服务费 15%（¥15），剩余 ¥85 在执行者/脚本开发者间按明示协议分配。假设平台每笔通道、验收、客服、争议可变成本分别为 ¥2、¥3、¥2、¥4，则：

`平台单笔贡献毛利 = ¥15 - ¥2 - ¥3 - ¥2 - ¥4 = ¥4`。

还未扣除市场获客、固定技术费用、税费和潜在退款。**此处不是 OpenDesk 的实际价格、收入、用户收益或已可支付能力。**

执行者净收益还应减去其自担的时间、设备、网络、适用税务和合规成本。发布任务时必须透明展示预算、费用、结算规则与退款条件，不能默认保证收益。

## 6. 冷启动策略

1. 找到少量真实商家，围绕 1–2 个高频、可合法执行、数据可验收的任务做访谈/试点。
2. 先用单个已授权节点完成真实业务结果，再扩展到有限多节点。V0.1 仍使用模拟结算。
3. 记录人工作业成本、出错率、可付费上限、验收时间和异常处理成本，测算贡献毛利。
4. 企业重复付费和执行者正向实际净收益成立后，才考虑完全开放任务市场。

## 7. 真实支付上线前的独立合规门槛

支付商和托管资金能力、KYC/反洗钱适用性、反欺诈、税费与发票、劳动/服务关系、跨境数据、退款/争议与用户保护等必须按照目标市场由合适的专业团队审核。V0.1 不建立真钱钱包、代付、托管资金或提现；后台的模拟结算状态不能展示成真实到账。

## 8. 风险指标与待验证假设

观察：有效任务发布数、合格领取率、真实任务完成率、独立验收通过率、重复企业发布率、审查成本、争议率、每单贡献毛利、节点净收益和撤权成功率。

任意出现未经授权发送、跨账号访问、凭据泄露、外部代码执行、UNKNOWN 重放或伪造结果，应停止对应类目的接单并调查。

| 核心假设 | 验证方式 | 当前 |
| --- | --- | --- |
| 企业愿意为结构化商品整理按单付费 | 实际业务报价/成交 | NOT_TESTED |
| 本地执行能减少单位成本 | 人工对照 + 故障审查 | NOT_TESTED |
| 用户愿持续手动/自动接单 | 多轮合规任务试点 | NOT_TESTED |
| 脚本开发者愿维护适配器 | 贡献者试点 | NOT_TESTED |

验证数据必须标明时间、样本和凭据，不能通过内部专家主观评分替代营收证明。
