# OpenDesk Task Shop · 长期产品合同（V0.1 方案）

> **PRODUCT_PROPOSED / NOT_TESTED**。2026-11-02 建立。唯一需求来源；代码实现与验收以[执行计划](execution-plan.zh-CN.md)为准。固定检索词：`OD-TASK-SHOP`。

## 1. 产品目标与边界

让普通用户安装 OpenDesk 后，选择可信任务并交由自己**已授权的本地自动化环境**执行；企业按可核验成果采购服务；开发者可提供已审核的可复用脚本。**不依赖 ChatGPT 或任何 AI 对话**，AI 仅可选帮助理解与审核。

与 [Web Flow](../../webflow/README.md) 分工：Task Shop 拥有任务供需与收益、市场调度策略和任务详情 UI；Web Flow 拥有工作流编排、步骤依赖与交接；Browser/Controller/Native 继续拥有真实执行、权限、安装与运行结果。接口不存在时标记 `PROPOSED`，不宣称能直接调用。

**V0.1 非目标**：大规模跨用户分发、真实资金/提现、长期 7×24 在线、第三方个人社交账号出租、自动发送未请求营销消息、任意远程脚本安装/执行、多 Profile 批量运营。

## 2. 核心参与者

| 角色 | 能做什么 | 不允许隐含获得什么 |
| --- | --- | --- |
| 需求方 | 定义任务、预算、输入范围、验收标准、纠纷规则 | 本地设备、账号凭据或跳过审阅的执行权 |
| 执行者/节点主 | 安装脚本、设授权范围、手动/自动领取、查看证据与收益 | 对第三方账号/受众的未授权访问或营销权 |
| 脚本开发者 | 提交可审核、可复用的脚本和版本 | 通过任务名称替换已批准源码/权限 |
| 平台运营 | 审核任务、匹配、验收结算、治理纠纷 | 隐藏任务成本、私自复制账号数据 |
| AI 助手（可选） | 生成建议、分类、辅助表单或摘要 | 自行授予网站/Native/资金操作许可 |

## 3. 三种用户模式与入口

1. **自用任务**：用户在 OpenDesk 直接执行自己安装的脚本，不经过商业任务市场；现有产品能力仍按真实安装许可。
2. **手动接单**：在任务市场查看任务详情、交付物、报酬、脚本/网站/数据范围，确认后领取；本地执行前仍校验脚本身份与授权。
3. **受限自动接单**：用户提前选择任务类型、站点、已安装脚本、批准的账号/Profile、每日次数/时间/成本、最大风险、结束时间和撤销条件；符合范围才可自动领取与执行；超出范围先待审。

来源可以是平台新任务、用户手动、定时、已授权的企业事件或 AI 建议。**触发不是授权，领取不是执行，执行完成不是商业验收通过。**

## 4. 关键用户体验（稳定 TS-需求 ID）

| ID | 需求 | 用户可见验收 |
| --- | --- | --- |
| TS-01 | 零 AI 依赖 | 不登录/打开 AI 对话，也能进入任务列表和领取入口 |
| TS-02 | 可信任务列表 | 可筛选类别、交付物、报酬、期限、需求方及适用脚本 |
| TS-03 | 本地能力匹配 | 明确显示脚本未安装、权限缺失、节点离线、站点不兼容等原因 |
| TS-04 | 手动接单 | 点击领取产生唯一任务身份，显示租约和执行准备状态，不以请求 ACK 冒充成功 |
| TS-05 | 自动接单规则 | 用户明确选择任务/网站/账号/限额，可预览、暂停、撤销，不在规则外自动接单 |
| TS-06 | 执行前许可 | 每次匹配当前真实脚本版本/哈希/目标/参数/站点许可，新增范围需再次审阅 |
| TS-07 | 任务托管 | 在线任务能查看状态；断网/重启记录 UNKNOWN 并对账，不能盲重试提交/发送 |

| TS-09 | 结果验收 | 区分技术完成、业务交付、验收通过；失败和争议有明确责任与结果 |
| TS-10 | 收益信息 | 任务显示毛报酬、预计平台费、净额、支付条件；试点阶段禁用真实结算 |
| TS-11 | 用户安全 | 显著展示 Stop、暂停接单、撤销授权、删除/导出记录及异常告警 |
| TS-12 | 角色界面 | 普通用户仅见任务/规则/状态/收益；脚本 ID、哈希、诊断日志折叠展示 |
| TS-13 | 任务发布准入 | 发布者定义目的、数据来源、授权依据、验收规则与允许的外部操作 |
| TS-14 | 可追溯性 | 任务发布、领取、执行、验收、结算分别保留来源和时间；不可伪称执行或收益成功 |

## 5. 受限自动接单策略

自动接单是显式、可撤销的*限权计划*，不是“安装插件即默认自动接单”。

授权最小字段：`allowedTaskTypes`、`allowedScriptPins`、`allowedOrigins`、`allowedAccountScopes`、`maxDailyClaims`、`maxConcurrentRuns`、`maxTimePerRun`、`maxSpend`、`validUntil`、`riskyActionsRequireReview`。这些均为**业务方案字段，非已存在的公开 SDK 字段**。

判定顺序：身份有效 → 任务合规 → 需求方/预算可信 → 执行脚本已安装且精确匹配 → 用户规则允许 → 本地站点与权限再次校验 → 原执行入口准入。任一步失败停留在待处理，不扩大范围、绕过同意或替换脚本。

资金转移、对外发送、隐私数据外发、账号权限更改和真实购买/支付默认须独立确认；将来若某站允许受控免确认执行，必须有明确的用户可见收件人/范围、网站规则和可撤销授权，不依靠市场任务文本扩大权限。

## 6. V0.1 最短业务场景

**受控商品资料整理**（自有或正式授权的演示商店，测试订单、虚拟报价）：

- 需求方创建“读取已授权商品列表并导出结构化摘要”的测试任务，明确目标网站、输出字段、最大数量与非敏感数据；
- 执行者在 OpenDesk 看见适用脚本、所需网站许可与报酬为模拟值，点击手动领取；
- 平台发出一次性租约；本地按现有 Task/Authority/RunHost 合同执行已安装脚本；
- 从原持久结果读取 runId/resultId，附最小证据，需求方在模拟验收 UI 中确认；
- 展示“待结算/模拟结算”，**不连接真实资金，不宣称用户已赚取真实收入**。

V0.1 必须实际证明：单任务不重复领取、站点不越权、停止和 UNKNOWN 不盲重试、执行结果来自原任务持久记录、人工看得见验收结论。真实网页测试与模拟服务测试分别记录。

## 7. 风险边界与禁用任务

禁止以平台能力出租账号控制权、出售登录态/Cookie、绕过网站验证码/风控、欺诈访问或假流量、刷量、未经请求的批量广告/骚扰、爬取不应访问的隐私数据、伪造交易/业绩或以任务描述实现远程代码执行。

对合法的客户运营、订阅会员通知、采购询盘，必须具备适当的账号授权、平台规则适配、接收者同意、退订和数据保留限制；发送行为不能因为自动接单而省略必要确认。

对于支付、平台责任、税务、劳动用工、数据保护等跨地区问题，先由合资格专业人士按目标市场审查，不把本合同视为法律结论。

## 8. 产品验证门槛

V0.1：证明一条用户真实可见的端到端链路（或明确记录缺的环节）；至少保留正向、越权拒绝、断连、回执未知、取消、重复接单等关键行为证据。脚本返回 `completed` 仅代表运行结束；只有需求方的独立验收结果才可变成 `ACCEPTED`。真金白银结算阶段需独立支付/反欺诈/争议/合规审查。

审查状态和负责人逐项登记在[执行计划](execution-plan.zh-CN.md)。
