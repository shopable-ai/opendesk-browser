这次验证的问题是：业务后台发出的任务，是否真的被指定浏览器执行，页面是否产生准确结果，执行结束后后台是否收到确认。

## 开始前

- 自动复测和手动测试由一个人负责提交。本次自动复测已结束；你另做一次手动测试时使用新的独有姓名和新请求键，不重发本次已完成的请求。
- 先核实开发服务、43111 观察服务、业务后台连接和原 Chrome 的安装及托管授权。已安装、授权且就绪时，直接使用；不把重新下载、重装或重新配对作为固定步骤。
- 使用原 Chrome 扩展和现有业务账号。业务网页使用账号正常登录；Provider token、管理凭据和配对密钥由原服务端保管，不填到网页，不放进截图或交接包。
- 若提示运行时已变化，先通过原有试运行、验证和确认更新安装恢复，再核对同范围云控批准；未恢复前不发送任务。

## 按这六步操作

1. 打开 [云控表单演示](http://127.0.0.1:38001/public/opendesk-cloud-demo/index.html)，用自己的业务账号登录。
2. 点击「刷新设备」，选择自己的执行设备。本次为 #1288；确认独立状态为 READY，任务目录显示 sample.form-fill@1.0.2。设备名称中历史遗留的“待配对”文字不是实时状态。不是 READY 时先检查具体原因，不靠重复提交恢复。
3. 点击一次「新建请求」，立即保存显示的“当前请求键”。输入本次独有的姓名，例如 Manual-日期-时间；保留实际输入的原样文字。
4. 点击一次「提交一次」。这是唯一触发执行的步骤。之后只点「查询原请求」，直到看见完成状态、回执“已确认（true）”、资源释放 released。queued、assigned、received 等中间状态都不算成功。
5. 点击「独立查看原网页效果」，在观察页输入刚才完全相同的姓名，查询原记录。应看到同一份原文档的事件连续、该姓名只提交一次、完成文字准确为“已提交：你的姓名”。任务页执行结束后会关闭，查看观察记录即可，不需要重新打开表单再点提交。
6. 在扩展「云控 → 请求记录 → 查看详情」核对完成、结果保存、资源释放、回执确认；展开「查看原始请求 / Job / Run 身份」，再使用「在『开发』查看原始 Run / Result」查看本机原结果。归档时把该记录与业务请求、原文档关联。观察页本身只证明页面事件，不能单独证明是哪台设备或哪次任务执行的。

## 怎样判定通过

以下事实必须属于同一个新请求，且全部具备：

| 核对项 | 应看到的结果 |
| --- | --- |
| 页面实际效果 | 姓名准确，提交一次，准确完成文字，原文档事件连续 |
| 浏览器执行记录 | 同一任务有原始运行与已保存结果，页面操作回执关联原文档 |
| 执行资源 | Worker 已退出、任务创建的专用标签页已关闭、执行槽已释放 |
| 业务后台 | completed、receiptConfirmed=true、retirementState=released |

本次保持 allowResult=false，因此业务网页只显示完成状态，不显示结果正文；本机结果仍可查看。
若要像本轮一样严格归档，须在提交前准备原生 document 与观察实例的只读关联；执行结束页面会正常关闭，事后重新打开同一网址不能补证。只看到成功提示、HTTP 200、观察页记录或测试数字时，不能宣布整条业务链通过。

## 超时或看不到结果时

保存原请求键，继续用「查询原请求」或「按请求键恢复」查询。刷新页面后需要重新登录，再恢复原键。
不要为重试点击「新建请求」或再发一条任务。查不到、超时或 UNKNOWN 时，实际执行结果仍可能未知。
本轮默认不测试「请求取消」分支；如误点取消，记录事实并核对停止、释放和回执，不能把取消登记当成已停止。
