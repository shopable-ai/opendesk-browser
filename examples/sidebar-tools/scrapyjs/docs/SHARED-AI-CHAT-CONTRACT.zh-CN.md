## AI 字段规则优先使用字符串简写（2026-11-04）

**关键描述：AI 先根据用户需求和当前真实页面确定采集语义，再在语义等价时优先使用简单的选择器字符串。** 用户提供的配置用于表达“对象可能过于复杂”的问题；其中的字段、标签、属性和站点不是预置答案。Books to Scrape 仅是用户指定的测试地址。

- 记录范围、字段、选择器和读取目标来自当前页面或原有效规则；不按示例固定某个字段、标签或属性，不凭空补出不存在的属性。
- 普通文本或单一属性读取可由字符串完整表达时优先简写；简写不能改变匹配节点、读取内容、缺值行为或单值/多值语义。
- 显式 `cardinality: "one"/"many"` 等约束无法用字符串完整表达时保留对象。已有对象规则仍合法；用户未要求修改的字段不做批量转换。

通用偏好由工具原 `ai-config.js` 提示词维护，不新增 DSL、转换器、抽取器或公共 Chat 业务逻辑。2026-11-04 本轮纠偏已移除上一版提示词中直接引用用户具体字段/选择器的示例，改为以上通用描述。

本轮 Node v24.16.0 的 `ai-config`、`ai-actions`、`extraction-contract` 三个定向测试文件共 38 项通过，覆盖完整属性读取、原提案与意图校验及对象基数兼容。另下载该站真实首页，使用原校验链和序列化 ItemLoader 核对 20 条、60 个字段，全部与独立 DOM 读取一致；其中 10 个可见书名被省略，`::title` 均保留完整值。详情见[本机实测报告](../../../../artifacts/scrapyjs/selector-shorthand-20261104-01a1a26d/report.json)。这是实际 HTML 的引擎验证，输入规则由测试提供；不冒充 AI 生成或已安装 Chrome 的完整操作证据。

上段 38 项与 20 条实测属于纠偏前的执行能力证据，**只证明测试提供的规则能校验并执行，不证明模型会从网页正确生成规则或优先选择简写**。纠偏后语法检查及 `ai-config.test.mjs` 8 项通过；Chat 和 local runner 的实际提示词均不含本轮具体选择器、列表类名或测试站域名，现有 watcher 回执的输入 SHA 与修正源码一致。这些仍不构成新提示词的真实 AI 生成证据。

本轮真实 AI 生成偏好及安装版发送/采集仍 `NOT_TESTED`。相关原生验证须在集中更新后的安装态从空白配置发送普通业务需求，驱动不提供 CSS/JSON，核对模型选择是否有页面依据、表达是否足够简单，再经原业务采集；只按这些条件评价，不要求返回某个固定字段名或选择器。未改版本、正式 JSON 或安装态，不重放其他 owner 尚未确认终态的请求，不恢复已暂停的双站或完整验收。

## AI Panel 默认列表规则与执行方式（2026-11-04）

默认采用**由真实网页结构生成显式记录规则，再由原引擎确定性执行**。对于新的 DOM 列表配置，AI 输出完整 `_listItem` CSS 与相对字段；不强制 `_listContainer`，不新增用户必须选择的模式或公共 `mode` 参数。已有容器 + 列表项规则继续保留直接子项语义；明确的页面摘要/独立多值字段才使用单页对象，不能把列表歧义降级成独立字段数组。

`_listContainer: 'ol.row', _listItem: 'li'` 是合法旧规则；在该结构下也可直接用 `_listItem: 'ol.row > li'`。需要直接子项过滤时保留容器，不自动改写已有配置。字段基数、缺值和记录归属由同一个 ItemLoader 执行，不能在 Chat 中拼接数组或另建抽取器。详细参数语义见[核心 API](../../../../../scrapyJs/docs/api/items-pipelines-exports.md#按目标选择写法独立字段与关联记录)。

当前正式源码 `AiPanel.jsx` 的创建路径为：受控网页观察 → `ai.generate` 返回声明式提案 → 原配置 validator 与意图/身份检查 → `business.config.propose/apply` 更新草稿。`ai-config.js` 已提示记录优先，但 `AiPanel.jsx` **没有调用** `prepareListProposal`。因此默认不是“每次业务运行先 prepareList”，也不能宣称完整字段的确定性准备已接入默认 Chat。仅完整字段输入而无记录边界时，先复用既有范围入口的 `ItemLoader.prepareList` 作者辅助；需要把它接入 Chat 时，必须先复现具体缺口，沿原 adapter 最小接入，不恢复粘贴 HTML 或技术审阅 UI。

明确配置修改可沿现有校验自动同步草稿；歧义以普通问题澄清。保存、运行、停止和下载继续用原业务入口。保存规则与分页执行不请求模型、不重新推断记录。公共 Dock/Frame/session 不解释 `_listItem/_listContainer`，不持有采集业务或获得网页权限。

**证据边界**：2026-11-03 原 Chrome 点选、命名保存/重开和实际翻页在 Books to Scrape 两页共 40 条记录、120 个字段逐值通过；业务字段经过作者明确审阅编辑，记录范围来自真实点选。这是原插件与核心引擎证据，见[原生报告与定向条件](../../../../../scrapyJsChrome/docs/list-selection.md#实际结果与证据2026-11-03)。它不能代替默认 AI Panel 的真实生成闭环。主链随后在同 SHA 1.9.11 完成真空白生成三字段、命名保存、单页 20 条、CSV、关闭重开及无 AI 再采 20 条，见[主链最新实证](../evidence/blank-page-creation-20261103.md#三字段真实闭环结果2026-11-04-0035北京时间)；该实证覆盖下文历史观察阻塞的未测试结论，但不证明多轮修改、同规则两页或随后漂移的源码/正式包。本节不恢复已暂停的双站任务。

下一轮只验证这一默认模式的最短实际链：普通业务语言 → 授权页面观察 → 草稿生成与原界面同步 → 原采集 → 保存重开；第二页复用同一显式记录规则，通过原分页界面明确设置，不能让空白创建静默越过现有单页限制。逐值/顺序/归属、缺值、多值、重复标题、歧义、过期/取消/unknown 与未请求配置保留是关键条件。测试驱动不得代写记录 CSS，也不得把 fake Provider 或预置站点配置记为真实 AI 证据。只修实际失败与受影响保护，正式验收继续延期。

**本轮独立实测（2026-11-04）**：本轮自有 Profile 安装同 SHA 1.9.11 临时候选，从空白配置发送普通图书字段需求。用户授权开启本 Profile 的用户脚本后，原页面观察历史读回 `completed/released`；后续 AI requestId 仍为 `E_AI_UNKNOWN`，原查询/停止尚未确认终态。共享设置显示本机连接关闭，保持 unknown 围栏；仅此 Profile 的配置生成、采集和保存/两页复用仍 NOT_TESTED，不与上述主链成功混同。桌面租约归 Host owner，本对话保留 Profile/未知请求，不并行操作浏览器或版本/正式包。身份、原话、结果下载与资源归属见[独立证据](../evidence/default-ai-panel-20261104.md)。这不恢复下述已暂停的双站任务。

## 当前增量：从空白创建单页列表（2026-11-03，1.9.7）

本轮最新用户目标是“自然语言 → 当前真实网页生成规则 → 原表单/JSON 同步 → 原保存 → 真实采集 → CSV → 关闭重开复用”。先以一个公开英文图书列表完成核心链，不扩到复杂分页、详情批量访问、登录站或电子书文件下载。下方 1.8.x 的“页面推导未实现/需用户明确选择器”仅是当时限制，不能拒绝本轮已授权的空白创建；既有配置的精确修改合同继续保留。
