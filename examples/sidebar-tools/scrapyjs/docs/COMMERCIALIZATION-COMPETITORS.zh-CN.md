# ScrapyJS 商业化、竞品与上下游服务（策略草案）

> 记录日期：2026-10-30｜状态：RESEARCH / PLANNED（未经市场实销、法律审阅和生产验收）
>
> 目标：明确哪些能力值得为未来保留设计接口，避免提前建设完整 SaaS 或将 ScrapyJS 侧栏变成拥挤商城。以下竞品信息是路线定位，价格/功能/条款上线前需重新核实。

## 1. 产品定位与机会

将“单次爬取工具”发展为“可重复使用、可交付、可维护的采集任务”：
- 普通用户描述需求并预览正确数据，不需要理解 CSS 或 Python；
- 开发者把已经完成的任务做成版本化模板，为多个用户重复交付；
- 企业按需采购采集配置、定期运行、质量监测、数据 API、代理或专属维护。

核心价值：**真实浏览器执行、AI 辅助生成与修复、许可与权限透明、验证可复现、可选托管执行**。不与所有爬虫平台在代理规模上硬碰硬。

## 3. 可售商品与上下游能力

| 商品/服务 | 客户购买的东西 | 收费优先级 | 必须交付的证据 |
| --- | --- | --- | --- |
| 官方/开发者采集模板 | 一个有范围、有版本、有测试说明的 Recipe 授权 | **首批验证** | 适用网站、样本、字段、权限、版本与维护状态 |
| 定制开发 | 将目标网站需求变成可重复运行的任务 | **首批验证** | 验收数据、交付配置/代码所有权、维护边界 |
| 长期维护 | 网站改版修复、规则重验、质量报告 | 首批验证 | 服务期限、响应级别、升级记录 |
| AI 规则生成/修复 | 按次数或额度的 AI 助手能力 | 基础能力成熟后 | 调用透明、草稿审阅、失败及费用记录 |
| 云端执行/调度 | 托管运行、定时任务、历史、导出 | P1 | 可追溯 runId、已验收结果、配额账单 |
| 代理资源/套餐 | 合作供应商代理或用户自带代理管理 | P2 | 合法供应/转售权、用量与区域、连接质量及成本 |
| 数据集/API/Webhook | 授权数据结果和系统集成 | P2 | 交付权、字段合同、访问令牌、结果质量 |
| 企业集成与咨询 | 对接 CRM/ERP/BI/RAG、专属部署 | 有真实订单后 | 合同、隔离方案、交付与维护约定 |

上游是云引擎、代理、AI 模型、服务器与支付供应商；中游是 OpenDesk 的任务制作/审核/版本/执行/计费；下游是消费者、模板开发者、定制服务商、企业数据系统。不同层不必由 OpenDesk 全部自营。

## 4. 推荐的最小商业闭环

初期不建设完整开放交易市场：
1. 官方先做少量优质合法目标站点模板，附真实样本与适用范围；
2. 用户在 ScrapyJS 内试采 1–3 页，确认满足需求后保存或购买模板；
3. 不满足时提交**经脱敏的**需求、字段和故障记录，请求开发者定制报价；
4. 开发者在受控环境交付固定版本，平台/用户验收结果；
5. 用户可选择本地重复运行（无隐藏云费）、托管执行或按月维护；
6. 根据真实成交率、维护量、退款和云成本，再决定开放开发者市场和代理服务。

模板商店、定制开发入口可放在扩展右上角简洁图标及独立网页，不与主采集数据界面混为一页。不要将云端服务、代理和模板购买自动打包收费。

## 5. 计费和分账设计原则

可组合计价：**模板授权费 + 已授权云执行费 + 可选 AI 请求费用 + 可选代理用量 + 存储/交付 + 定制与维护费**。本地已购模板可按许可在授权范围反复使用，不应因为运行按钮造成未经确认的云费用。

- 价格、执行预算、代理额度、退款规则和失败重试费用在购买/运行前明确显示；
- 计费事件与 runId、provider 账单、用量、验证结果关联，使用幂等 eventId 防重复扣费；
- 对失败、部分成功、超时、用户停止和重复请求分别定义结算；不默认向客户转嫁系统内部故障重试；
- 第三方代理采购成本、AI 成本、存储带宽及平台服务费独立核算，防止出现“收入增加、云成本更高”；
- 开发者分账、版权/许可、取消授权、删除商品、纠纷、退款、税务和支付渠道政策在开放上架前确定；
- 不在产品讨论文档中预设具体售价或利润率，必须由真实试点成本与成交数据决定。

## 6. 市场商品与用户信任

正式模板商品需包含：
- publisher、recipeId、version、hash、targetOrigins 与权限清单；
- 输出字段 Schema、验证样本（不泄露个人数据）、支持运行引擎、限制与预计费用；
- 最近测试结果、维护日期、变更说明、已知失败/阻断与适用范围；
- 使用许可、更新政策、退款方式、支持联系人/工单与安全审核记录。

上架必须做代码/配置扫描、Origin 与权限差异审核、凭据泄露扫描、资源用量约束、提供商审核。付费模板不能绕过原安装审阅或要求用户执行未经审阅的任意脚本。

## 7. 风险与反方观点

- **需求风险**：用户也许更愿意买一次性数据，不愿意长期购买采集工具。应同时测试“买模板”“买数据服务”“定制开发”，不要只用注册数判断需求。
- **网站变更风险**：稳定模板仍可能失效，需发布版本、维护状态、质量指标与回滚机制，避免承诺永久可用。
- **平台竞争风险**：Apify 已有运行和市场网络效应；OpenDesk 不应在初期投入复制完整云 Actor 商店。
- **成本风险**：代理、浏览器实例及 AI 模型可能吞噬利润；需预算、供应商账单和单次交付毛利核算。
- **合规与隐私风险**：公开采集不代表能任意再分发或销售。必须核实目标网站授权、条款、隐私、个人信息、内容版权、代理来源及跨境数据处理限制。
- **安全风险**：共享登录会话、Cookie、代理凭据或云任务输出应默认私有，不能因付费模板共享给开发者或其他购买者。

## 8. 评估顺序与 Go / No-Go

1. **产品闭环**：用户能不依赖开发人员从需求得到真实样本，保存并再次运行。未做到则不做公开市场。
2. **真实付费需求**：模板、定制、维护至少一个类别产生经过验收的订单；根据实际样本决定扩张，不虚构转化率。
3. **单位经济性**：云执行/代理/AI 成本可计量，最低预算与退款可追溯；亏损任务不能无限跑。
4. **质量与安全**：任务发布、权限、失败分类、跨用户隔离、数据权限经独立验收。
5. **平台开放**：上述门槛满足后才做开发者上传、复杂结算和多个代理/云引擎。

路线选择的设计适配度：推荐“现有 ScrapyJS + AI + 可选托管 Adapter”优于立刻自建完整平台；任何 95+/100 都只能是后续基于真实证据的专家复核目标，不是现有已完成评分。多个维度分别评分，综合成绩为算术平均值，禁止累加。
