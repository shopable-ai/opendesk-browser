## 1. 原始目标，不得漂移

将当前 ScrapyJS 从“保存采集配置、采集与导出”的浏览器工具，循序升级为：**AI 描述采集需求 → 生成可审阅的声明式任务 → 1–3 页真实样本测试 → 保存可重复使用的版本 → 用户确认后本地或云端长期运行 → 可选交付、付费模板、定制开发与维护**。

面向三类用户：
- 普通用户：不写代码，在当前已授权网站快速采集与导出；
- 专业用户/开发者：扩展字段、调试规则、复用任务或提供付费模板；
- 企业用户：定期获取经过质量验证的数据，按需购买运行、代理、集成和维护服务。

差异化定位：**本地真实浏览器采集 + AI 辅助配置与修复 + 版本化可复用任务 + 可选托管执行**。不以“AI 能绕过任何网站限制”为卖点。

## 3. 关键能力及优先级

| 优先级 | 能力 | 复用 / 新增边界 | 最小验收 |
| --- | --- | --- | --- |
| P0 | 收敛现有采集主链与正式候选 | 复用 React、App Model、Task、SDK；只修本轮真实阻断 | 保存、重开、采集、停止、导出逐一读回；标注具体候选 |
| P0 | AI 生成与审核任务配置 | 复用现有 AI 配置入口及受审 Provider；不允许隐式执行 | 输入需求→生成声明式草稿→差异/Schema/权限审阅→单独应用和运行 |
| P0 | 1–3 页样本试采与结果验证 | 现有固定 origin 内先实现；扩 Origin 需真实安装审阅 | 记录条数、字段完整性、重复率、失败原因、源网址；失败不伪 PASS |
| P0 | 采集失败诊断与恢复 | 优先规则层修复，保留原配置和草稿 | 结构变化/权限/超时/空结果有可区分提示；修复须再次预览确认 |
| P1 | 可选代理配置 | 复用 Host 的浏览器代理能力，但区分全局和任务隔离 | 显式启用、连接测试、作用范围、恢复和失败关闭有真实证据 |
| P1 | 执行环境选择 | 本地 ScrapyJS、第三方云 Adapter、后续自建 Worker | 统一任务/结果合同；切换环境不放大未获授权的能力 |
| P1 | 长时间任务、调度及结果历史 | 由云 Worker / 队列承担；不取消本地 Task 边界 | 单独确认后运行；Stop、预算、超时、任务身份、结果可读回 |
| P1 | 任务版本、云同步与 API 交付 | 新增后端服务；本地配置默认私有 | 跨设备恢复同版本；API/Webhook 导出有租户隔离 |
| P2 | 付费模板与开发者发布 | 复用现有扩展市场展示/安装，不假定已支持交易 | 发布审阅、权限差异、源码/规则版本、购买授权、售后可核 |
| P2 | 定制开发、长期维护、代理等增值服务 | 初期人工交付与供应商合作 | 有报价、验收标准、账单、范围与维护责任 |
| P1（可选验证） | 自有 Android 双网络任务节点 | 独立移动端 Node Agent；不改现有 MV3 Task 权限 | Wi-Fi 控制+蜂窝出口的 1–3 页真实样本与 fail-closed 读回，见[节点设计](COMMUNITY-NODES-MOBILE-EGRESS.zh-CN.md) |
| P2（延期） | 远程自愿领取任务与社区互助 | 先受限签名 Job，后独立审核共享代理与商业规则 | 设备同意/流量预算/Stop/权限/结算分别核验；**不开放通用代理** |
| P2 | 自建规模化采集平台 | 付费与负载得到验证后再建设 | 租户隔离、成本可控、计费与执行事件对账 |

不把“更多功能”视为直接成功：先提高普通用户完成一项真实采集任务的成功率，再扩平台。

## 4. 分阶段任务（后续实施顺序）

### R0 — 先查现有成果，不重做

只读梳理最新 main 的实际完成度、原任务合同与迁移状态；只补证据或真正未实现的阻断。React 正式界面、旧安装包、当前 Task 和 Mock 预览必须区分。当前本文件仅记录规划，**R0 本轮未执行**。

### R1 — AI 一键样本试采 MVP

在现有 ScrapyJS 右上角 AI 入口或采集操作旁提供一个明确入口：用户描述字段/目标 → AI 生成草稿 → 显示 Provider、拟发送数据、页面 Origin 和运行成本 → 用户确认 → 仅在已授权目标中采集 **1–3 页** → 校验并展示结果 → 用户认可后保存命名任务。

核心不是一次就创建通用 Agent；先拿到可靠、可重复的样本结果。第一阶段允许可选本机 HTTP Worker 试验 Scrapling + AI，但不强制普通用户安装 Node/Python；本地固定任务仍是默认选项。

### R2 — 本地/云端执行与代理

建立 Provider Adapter；验证一种云端或本机隔离 Worker。长时间运行必须单独点击和明确选择页数/超时/预算，不能将样本试采自动扩大为全站抓取。代理在本地与云端采用不同的隔离/授权方案，详见技术文档。

### R3 — 可长期复用的云任务

设计服务端用户私有任务库、版本、运行历史、调度、Webhook/API、结果存储和幂等 Stop/恢复。优先把可靠性、质量和成本监测跑通，再扩大并发。

### R4 — 小规模商业 MVP

由官方/受邀开发者提供少量受支持的采集模板；先验证一次性模板购买、定制开发和维护合同，再上线复杂分账、开放市场及代理转售。收益与成本、退款和授权边界要可追踪。

## 5. 必须保持的产品体验

- ScrapyJS 仍然是紧凑侧边栏工具：主入口“配置→试采→查看→保存/运行”，AI 与模板市场以图标入口为主；不另建平行 UI。
- 采集配置保留完整字段、分页、详情及高级 JSON，非专业用户优先表单和样本预览。
- 草稿不丢、Stop 作用于原实例、未知结果不重试副作用；安装一次授权与可信运行机制不绕过。
- 代理和云服务是可选项，默认本地运行；代理是否影响浏览器其他标签页必须清晰标明。
- 模板/云执行/代理/维护分别计价，不以隐含收费替代用户确认。

## 6. 验收与质量门槛

分别记录：功能正确性、数据质量、UX、权限/隐私、可靠性、成本、商业交易，每维目标 >=95/100；综合分只取各维算术平均，**不能累加**。评分是验收目标，非当前已获评分。每项需独立证据：NODE、CHROMIUM、REAL_RUNHOST、MAC_CHROME、REAL_SITE、CLOUD_RUN、BILLING 分层，不得以网页 Mock 代替。

最小指标：1–3 页预览结果的正确性与来源、必填字段完整率、重复率、运行成功/失败分类、预算消耗、原 runId 终止及产物读回。无证据的状态只能为 NOT_TESTED。

## 7. 明确不在本轮实施

不立即开发通用 AI Agent、自建代理池、代理转售、多租户大规模云集群、开放任意脚本执行、付费市场与分账，也不扩展现有固定 Task Origin 或放宽 90 秒限制。所有未来改动先查当前实际源代码，仅做差量，在 main 上实施，禁止平行产品与重复 Runtime。
