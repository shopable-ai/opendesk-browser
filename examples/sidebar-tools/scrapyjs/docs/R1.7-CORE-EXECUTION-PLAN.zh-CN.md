### 选择与职责

比较三种方式：强行保持两引擎全部语法一致，会把浏览器 detail/processing 等能力错误许诺给本机；整体另建 Scrapling 应用/Runner，会重复已有进度、身份、停止和导出。采用**原应用 + 引擎各自规则适配 + 原任务生命周期**，按需求实现能力，而不以调用旧业务代码为目标。

当前调用链保持 `CaptureWorkspace → createAiCapture → 公共 ai.generate → 本地规则校验 → local-runner-client → localTasks → 原 Python Worker`。Python 直接使用锁定的 Scrapling 0.5 Selector，没有调用 vendor ScrapyJS/Controller 执行器；继续使用原 HTTP 创建/查询和持久任务管理。

规则合同分开处理：

- **当前静态演示**：保留已验证的 HTTP JSON 数据形状，仅接受 `url,itemConfig,nextPageSelector,maxPages,dedupeKey,timeoutMs,waitForSelector`。这是一份工具与本机服务间的有界协议，不宣称它就是 Scrapling 原生 Python API，也不要求调用旧 JS 解析器。AI 提示词独立说明当前服务的字段读取、容器直接子项、静态分页与预算。
- **引擎差异**：Scrapling 0.5 自身具有 CSS/XPath 查询方法，但本服务合同只开放静态 CSS；其 `::attr(...)` 等原生投影不能直接冒充本服务 DSL。AI 优先输出 `{selector,read,attr?,cardinality?}` 描述符；由本机适配层执行。文本、相对链接、空值、数组、列表范围以本服务实测合同为准，不能从框架名称推定等价。
- **后续新能力**：先写出用户需要的字段/列表/分页行为，再在原 Python 编译边界设计规则版本和引擎适配；新规则不必采用旧字段名或旧执行逻辑。新版本必须显式识别并参与配置 hash，preview/full 绑定同一版本和快照；不得自动改写已存配置或旧任务。本轮没有发布新 DSL、XPath、动态浏览器或反爬能力。
- **旧配置**：能准确表达的旧规则可经显式适配复用；不能表达的保留原文并报告具体不支持项，允许继续走原浏览器路径。不得删字段制造兼容，也不为复用而强迫新功能沿用旧语法。

以上是工具内部设计，不增加公开 SDK 操作、Provider 配置、自由 Chat、Host、任务管理器或第二安装包。

| 维度 | 分值 | 必要证据 |
| --- | ---: | --- |
| 目标与交互 | 20 | 多余 UI 清理；原页面按钮、结果与失败反馈清楚 |
| 三页数据正确性 | 25 | 真实不同三页、全字段核对、去重、空值、来源与导出一致 |
| AI 与采集解耦 | 20 | 真实 AI 规则→真实采集；不调用 AI 的同链采集也成立 |
| 长任务可靠性 | 20 | 精确 preview/full、活跃重开同 run、Stop 退出、无重复创建 |
| 安全与可维护性 | 15 | 原权限/身份/撤权/unknown 保护；复用公开合同，无第二运行器 |

**硬门槛：** 无阻断缺陷、无高风险安全缺陷；豆瓣拒绝不能标三页成功；模拟链不能标真实 AI/安装态成功；旧候选证据不能覆盖新源码；Stop/下载未证实不得记 PASS。存在核心未测项时保持 `NOT_TESTED/NOT_SCORED`，不能保证或预填 95 分。

- [ ] 收集当前候选核心证据供 reviewer 复核，修复真实问题后只复验受影响部分。
- [ ] 原记录补充本轮最新阶段、候选身份、实际操作、失败/未测项与分项评分；不另建产品总 GOAL 或平行账本。
- [ ] 交付安装候选时遵守原唯一包的构建→相关门禁→同打包器晋升→同源核对；源码与正式包按适用合同安全提交 main，不混入他人修改。未经授权不推送。

上方阶段清单保留原实施顺序与历史内容，未逐项勾选不推翻顶部已核实证据。当前下一动作以“2026-10-31 新方案”T1–T3 和最新原生状态为准，不重新执行已通过的阶段 1–3/5，也不恢复旧全面验收清单。
