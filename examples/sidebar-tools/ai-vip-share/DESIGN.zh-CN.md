### 1.2 R4 产品定位

从“代理一键开关”转为 **「AI VIP Share 会员权益、兑换与使用中心」**。

会员权益/账号/剩余时长/兑换码/更多商品是首要信息；具体代理协议、PAC 和域名清单为低优先级能力详情。用户在目标 AI 网站使用服务时，工具主要承担会员管理，而非每天手动选代理节点。

**关键语义：**“AI VIP Share 会员”表示本产品合法交付、已在商品合同中列明的权益，**不天然代表** ChatGPT Plus、Claude Pro 等第三方账户的订阅状态或对第三方账号的共享授权。任何第三方会员商品必须有独立 SKU、权益内容、合法授权、交付状态与售后条款；不收集、分享或注入第三方账号密码、Cookie、会话令牌。

## 2. 核心场景与三种获得会员方式

| 入口 | 用户路径 | 终态 | 关键限制 |
| --- | --- | --- | --- |
| A 已有会员/账号 | 打开工具 → 登录/绑定产品账号 → 查看会员与到期时间 | 已有权益，展示剩余时间 | 会员有效 ≠ Chrome 代理已连接；未验证不得显示伪状态 |
| B 手动兑换码 | 打开工具 → 输入兑换码 → 预检内容/账号 → 显式确认兑换 → 服务器返回权益 | 展示对应时长和新的到期日期 | 后端幂等、防重放、兑换码只传受信任 HTTPS，不得伪造成功 |
| C 专属激活链接 | 受信任购买/兑换页点开特殊链接 → 检测宿主与工具安装状态 → 可选安装确认 → 展示码/权益摘要 → 用户确认兑换 | 与 B 的同一兑换结果 | 链接不自动给浏览器扩展安装权限，也不自动执行具有副作用的兑换 |

辅助路径：点击「更多商品」浏览合法上架的 1 天、1 个月、3 个月、1 年等 SKU；付款在经验证的商户页面完成。购买回跳只带订单/兑换意图，不以 URL 声称付款成功。

## 3. 界面结构：一张会员主卡 + 兑换卡 + 商品入口

建议以 **320–390px Chrome Side Panel** 为约束，默认只展示下列三层：

1. **主卡「AI 会员」**：脱敏产品账号或“登录/绑定”，商品名称/版本、会员状态。主卡最醒目的是剩余时长及到期日期；最近兑换和记录入口在卡片底栏。主卡在访客、未开通、权益过期、无法核验时使用清楚的空/错误状态，不填假时长。
2. **「会员时长兑换」**：一个兑换码输入框 + 一个“立即兑换”按钮。专属链接进入时新增紧凑的“已识别链接/待确认”提示；未安装工具时仅在这张卡里展开一步“确认添加工具并继续”，不新建高耸的独立安装页面。
3. **「更多商品」**：顶部次级快捷入口和正文“购买更多会员时长”入口打开同一个目录弹层；列示时长但不编造价格。实际购买链接仅在正式商品数据合法可用后开放。

底部仅保留可折叠的 **访问服务状态/适用站点**。网络未验证、受其他扩展控制、租约失效等是独立于会员的状态，必要时显示操作性提示，不抢占会员卡视觉权重。不展示任意代理服务器、PAC 编辑器、第三方 Cookie 或常驻日志。

主界面不同时展示多张冗余网络状态卡，避免挤高侧边栏；产品和时间等高价值信息在首屏。所有提示/按钮使用浏览器统一 Design System tokens、语义 CSS，不在生产界面创建第二套框架。

## 4. 商品、账号、兑换码、时长的领域模型

四个概念**必须分离**，不能仅用一个 `enabled` 布尔值表示：

| 模型 | 示例字段 | 真正可信的来源 |
| --- | --- | --- |
| `memberAccount` | `accountId`、`displayNameMasked`、`sessionState` | 已审核的产品账号服务 |
| `productSku` | `skuId`、`title`、`kind`、`duration:{unit,value}`、`entitlementType`、`priceCurrency`、`priceAmount`、`availability` | 审核后的商品目录/商户服务 |
| `entitlement` | `entitlementId`、`accountId`、`skuId`、`startsAt`、`expiresAt`、`status`、`version` | 授权服务（服务端时间为准） |
| `redemption` | `redemptionId`、`voucherPreviewMasked`、`source`、`redeemedAt`、`durationGranted`、`previousExpiresAt`、`newExpiresAt`、`idempotencyKey` | 兑换服务的原子账本与核验回执 |
| `installState` | `hostInstalled`、`toolInstalled`、`toolId`、`permissionState`、`epoch` | 浏览器宿主的可信安装管理器 |
| `accessState` | `authorized`、`proxyControl`、`runtimeStatus`、`lastVerifiedAt` | 公共 SDK + Chrome 原生状态回读 |

**会员账号 ≠ 设备码**：设备码只能用于设备授权或限制，不取代用户的商业会员账号；允许未登录访客先查看商品和输入兑换码，但兑换落账需要绑定用户权益归属。不得在工具页明文持久保存原始兑换码、登录口令或第三方 AI 会话。

### 4.1 时长规则（必须在商品中声明）

- 1 天 = 24 小时，或产品条款定义的自然日；必须选择并一致公开，不能混用。
- 1 个月/3 个月/1 年建议按服务端固定时区的 **日历月/年规则** 计算；需定义 1 月 31 日遇到 2 月、闰日、夏令时的行为。**不能一律把“一个月”写死 30 天**。
- 如果允许续时叠加，基础时间采用 `max(serverNow, currentExpiresAt)`；新 `expiresAt` 必须由后端事务确定、返回客户端。若不同权益类型不可叠加，按商品合同单独展示，不能混加。
- 兑换码验证与消费应为 **原子事务**，同一券码和 `idempotencyKey` 反复请求不重复加时；并发兑换、设备切换、断网重试需要返回可解释的唯一记录。
- 客户端可在内存中显示倒计时，但最终有效期以服务端核验为准，网络离线时只说明“上次核验时间/状态待确认”，不能无限延长。
- 兑换记录展示 SKU、来源、兑换时间、新增权益、到期变更及脱敏兑换码；不展示或上传完整敏感令牌到日志。

## 5. 专属激活链接的安全安装与兑换闭环

示意路径（**不是已部署 URL**）：`https://<approved-domain>/activate?ticket=<short-lived-one-time-ticket>`。

链接中应优先放**短效单次兑换意图 ticket**，避免把长期激活码、会员密码、代理配置或会话 Cookie 写进 URL；页面获得 ticket 后尽快兑换为受限意图，避免被 Referer、浏览器历史、统计、截图传播。用户可以在可信界面查看 **脱敏码**、SKU、赠送时间与归属账号，并主动确认是否兑换；若业务确需显示完整激活码，可增加明确的“显示/复制”操作及敏感值屏蔽，不在 DOM 日志持久保留。

安装状态机：

```text
官方授权的 HTTPS 激活页 / 深度链接（仅表达用户兑换意图）
           ↓
  检测 OpenDesk Browser 宿主是否已安装
     ├─ 否 → 引导用户至真实官方安装入口 → Chrome 明确安装确认
     │          → 返回恢复未消费的兑换意图
     └─ 是 → 检测 ai-vip-share 是否已安装且身份正确
                ├─ 否 → 「确认添加并继续」→ 可信安装授权/版本校验
                │          → 保留未消费的兑换意图
                └─ 是 → 直接打开「会员兑换」卡
                              ↓
           显示脱敏兑换码、商品类型、会员时长、绑定账号
                              ↓
              用户显式点击「确认兑换」→ HTTPS 后端核验/幂等消费
                              ↓
          展示回执、剩余时长和新到期日（不自动打开代理）
```

这里用户所说的“跳过一键安装”应理解为 **已安装时跳过冗余安装步骤**，而**不是未经过用户确认就自动安装浏览器扩展、跳过 Chrome 权限对话框或跨安装身份继承权限**。即使内部 Sidebar Tool 可由宿主安装管理器管理，首次新增/扩权仍需要真实用户授权和包/权限审查。

跨站联动如需 `externally_connectable`，只能为已批准的固定 HTTPS origin 开通最小权限消息入口，严格校验 `sender.origin`、请求签名/一次性 nonce、过期和工具安装身份。跨站消息只能**传递待处理意图**，不能作为直接调用 `chrome.proxy`、兑换扣码或跳过安装权限的权威；无法验证来源时应退化到用户手动粘贴码。`sidePanel.open()` 必须遵守 Chrome 的用户手势要求，不能假设异步跨域消息拥有永久有效的用户激活。

## 6. UI 状态与故障处理

- `guest`：登录/绑定账号、0 天/待领取或空状态；兑换与商品入口可发现。
- `member_active`：脱敏账号、SKU、剩余天数、到期时间、兑换记录；代理未连接仍可保持会员权益显示。
- `activation_link_pending`：显示脱敏兑换码、商品内容及待确认动作；待安装时禁用兑换按钮。
- `host_missing`：提示浏览器扩展安装，**不伪造安装状态**；意图保持未消费。
- `tool_missing`：确认安装独立工具并在安装核验成功后恢复兑换。
- `redeeming`：防重复点击，显示处理中；请求结果不明确则查询兑换记录/服务器状态，不盲目再次消费。
- `redeemed`：使用服务端 receipt 更新会员到期日和记录；不要仅改变本地 UI 并冒充成功。
- `voucher_used / voucher_expired / voucher_wrong_account / sku_mismatch`：明确区别错误，避免暴露账号隐私。
- `member_expired`：0 天、到期日、兑换/购买入口仍可使用。
- `provider_unavailable`：明确无法核验/无法兑换，**不能显示已激活**。
- `proxy_conflict / proxy_unknown`：归属“访问服务”折叠区，绝不把会员权益隐式切换成已连接。

## 7. 工程边界和落地顺序

**单工具业务边界**：会员 UI、SKU/渠道和兑换流程放 `examples/sidebar-tools/ai-vip-share/`；受信任的账号/订单/票据 Provider 适配应封装为工具自身的业务模块（需要对 HTTPS 起源权限进行单独审核）。`src/` 仅容纳可复用的 SDK、授权、浏览器安装管理、公共 Proxy Capability、通用可信用户操作与生命周期，不新增 AI VIP Share 专属业务 Host。

**平台分层**：`catalog`/安装器管工具安装，`SDK` 管独立能力，`Provider` 管账号/商品/兑换/租约，`Chrome proxy` 管代理实际状态；不把商业会员系统塞进 Chrome `proxy.settings`，也不允许下单/兑换自动改变全局代理设置。

建议分阶段：

1. **R4.0 设计定稿**：主界面、链接场景、异常与购买弹层；本次仅增加 Markdown、独立 HTML 原型和 README 导航，未替换运行时。
2. **R4.1 UI 接入**：审定设计后将主卡、兑换卡、详情迁入 `src/index.html|style.css|main.js`，复用统一 Design System；可信动作仍由公共宿主安全 UI/SDK 承载。
3. **R4.2 账号与商品 API**：审核正式 origin、身份、SKU、价格、权益模型，提供服务端失败与状态回执，保证未配置时 fail closed。
4. **R4.3 激活链接**：白名单 HTTPS、单次短票、安装检测、显式确认、幂等兑换、回跳继续；不走未授权自动安装。
5. **R4.4 公共 Proxy SDK / 原生 Chrome 验收**：迁出 `src/ai-smart-access/` 专用业务、验证 Chrome 代理控制/冲突/停用/重启/卸载；完整安装及真实联网证据分开记录。

## 8. 设计/工程 95+ 验收门槛

- [ ] 320 / 360 / 390px 不横向溢出，会员主卡、时长、兑换三处无冗余或截断；键盘可达、可读状态和错误提示。
- [ ] 已有会员、游客、待兑换、待添加工具、待装浏览器宿主、到期、服务未配置、冲突等状态都可复现。
- [ ] 每种兑换入口得到**同一服务端兑换结果**，不因链接/按钮差异而重复发放权益。
- [ ] 1 天/1月/3月/1年按商品时间语义及服务端到期回执显示，不做未经声明的 30 天假设。
- [ ] 已有宿主/已安装工具可跳过**不必要步骤**，但安装与兑换仍有明确用户确认；不自动获取 Chrome 权限。
- [ ] 购买入口只显示真实商品与合法商户；未配置价格/服务时不展示假价格或假支付完成。
- [ ] 特定账户、兑换码、ticket 不进入日志/URL 域外、屏幕常驻或仓库；隐私和重放测试通过。
- [ ] 所有会员、服务、代理状态分离；`PROVIDER_BLOCKED / NATIVE_NOT_TESTED` 不被 UI 模拟掩盖。
- [ ] 统一 CSS 语义规则、工具级隔离、主分支最小变更、构建与测试有可复核产物。
- [ ] 最终 95+ 是具备实际代码、系统与浏览器证据后的**工程验收门槛**；离线 HTML 原型的视觉评分不能代替交付评分。
