# Stay Focus · 完整扩展应用需求与运行架构（R4）

> 更新：2026-10-18。状态：**需求与架构决策已记录，R4 运行能力尚未实施、未验收**。
>
> 本文是 Stay Focus 后续迭代的**产品需求与分层边界**，不构成 Browser SDK 已提供这些接口、JSON 包可动态加载后台 JS 或 Chrome 原生验收通过的声明。现状与操作说明见 [README](README.zh-CN.md)，R2 源码提取事实见 [R2 工作记录](../../../docs/framework/workstreams/stay-focus-extraction-r2-20261018.md)。

## 1. 最高目标：一款普通用户可独立安装、使用、更新的应用

用户在不持有 OpenDesk Browser 源码的情况下，应能：通过「扩展」安装 Stay Focus、审阅必要权限、设置网站与额度、获得前台时间统计及超额限制；关闭侧栏后继续有受管后台行为；更新 Stay Focus 后保留已有配置并使新版本**受当前公共运行契约支持**的业务规则生效；停用或卸载只终止本应用的功能。

**独立的四层含义不可混淆：**

| 层次 | 通过标准 |
| --- | --- |
| 源码归属 | 网站分类、额度、时段、优先级、提醒产品决策及数据迁移只在应用工程维护，不回流到浏览器框架。 |
| 安装独立 | 用户可通过已支持的正式包、原安装器和授权流程安装，无须开发环境；安装后能检查缺失的宿主能力。 |
| 运行独立 | 侧栏关闭时，经明确授权的后台计时与规则仍由 Chrome 事件驱动执行、恢复和撤销，不依赖 iframe 定时器。 |
| 升级独立 | **宿主代码/构建产物与扩展 ID 保持不变**，只更新应用发行包，其已获公共 Runtime 支持的业务规则就能实际生效；超出合同的算法和权限必须明示不能独立升级。 |

不能以源码已移动、工具已显示在扩展中心、组件测试通过或 UI JSON 能更新，代替四层全部达标。

## 2. 当前真实基线与明确缺口

- 正式应用 ID 为 **stay-focus**，当前配置版本 **1.0.1**，能力声明为 **focus.control** 和 **currentPage.read**；入口在本工程 **tool.config.json**、**src/index.html**、**src/style.css**、**src/main.js**。
- R2 将唯一的产品侧业务源码归入本工程 **trusted/**，其中 **service.js** 同时包含产品额度/时段计算、Chrome 前台/idle 观察、Alarm、DNR 调整、安装校验等职责；**src/stay-focus/** 仍是测试/历史引用所需的兼容转发。
- 当前 JSON 工具包只发行 UI，不包含 **trusted/**；**src/sw.js** 静态安装 Stay Focus 专属服务，侧栏宿主及安装器也有专属接线。修改 trusted 业务代码仍需重新构建含它的 OpenDesk Browser。**R2 完成的是源码归属，不是后台业务独立升级。**
- 公共 SDK 当前存在 browser.scheduler、browser.storage、browser.network、browser.proxy.managed 等能力，但 **browser.scheduler 是已安装 Task 的调度接口**，不能冒充工具自有的长期后台事件处理器；尚无已确认完整支持本需求的通用活动计时 + 规则执行契约。
- 当前工具根没有按新约定晋升的唯一 **stay-focus.opendesk-tool.json** 正式文件。现有代码、历史 Mac 验收中的部分 PASS 不等于最新候选已完成真实额度耗尽、DNR 导航、撤权和新旧包独立升级的完整验收。

## 3. 同一应用可以有多个文件与执行角色

**源文件属于应用，不代表它可以在任意 JavaScript World 中执行。** 每一个入口必须明确是谁装载、在哪个世界执行、谁授权、如何停止。

| 角色 | Stay Focus 所需职责 | 现有/候选运行方式 |
| --- | --- | --- |
| UI | 推荐、网站编辑、额度/时段/白名单、状态展示 | 现有受隔离的 Sidebar Tool UI，通过 OpenDeskTool.request / 公开 SDK。React/HTML 是 UI 选择，不改变授权。 |
| Page | 在授权网页上展示提醒、有限 DOM UI | 现有固定 ISOLATED 适配器；未来可评估应用自有 Page USER_SCRIPT 及其安装/撤权合同，不直接拥有特权 API。 |
| Background policy | 共享预算、时间区间、规则优先级、跨日和应用自己的迁移规则 | 首选**应用拥有受限策略数据/纯模型，通用后台 Runtime 解释并执行其已支持的规则**；不是动态把任意 JS 导入特权 SW。 |
| Browser privileged host | 前台标签与 idle 观察、Alarm 唤醒、持久锁、DNR 写入和回读、权限及资源清理 | OpenDesk 现有 MV3 Service Worker / Browser Host / Authority；需要证明并补齐真正通用的能力。 |

建议的项目组织可包含 app/src/ui、app/src/page、app/src/background、app/src/shared 等多个文件，**仅是源码设计示例**；当前工具 JSON Schema 不会因为出现 background.js 或同名目录就自动拥有后台入口。不得先改名文件再把这种目录布局声称为已实现的运行时。

## 4. Background.js 的真实设计选择（按功能选，不一刀切）

| 实现模式 | 独立升级能做到什么 | 限制与决策 |
| --- | --- | --- |
| A. **声明式受管后台策略（R4 首选）** | 站点清单、用户批准的额度、时段、规则参数及已支持的规则组合可随应用包/配置独立升级；侧栏关闭后由统一 Worker 恢复执行 | 公共宿主需要有限规则解释器、事件与资源所有权；新算法语义超出 Schema 仍需升级宿主。 |
| B. 隔离事件驱动的应用业务 JS（未来选项） | 理论上可以在经过沙箱/权限设计与验证后更新应用特有的纯计算算法 | 当前未实现。必须验证隔离执行、持久事件投递、延迟/超时/重复、Stop、凭据/网络隔离、结果校验、Chrome/CWS 限制；绝不等同于在特权 SW 执行用户代码。 |
| C. 固定编译的第一方可信后台模块（现状） | 保留复杂 Chrome 特权业务功能 | 业务代码仍与浏览器构建绑定，**不能宣称独立升级全部后台功能**；可作为过渡和故障恢复基线。 |
| D. 独立 Chrome MV3 扩展（最后方案） | 自己拥有 Manifest、Worker 和必要 Chrome 权限，按 Chrome 扩展流程独立更新 | 不属于默认的 OpenDesk Sidebar Tool，增加安装/授权/扩展冲突成本；仅当通用能力无法安全满足核心业务时比较选择。 |

**架构决策：先以 Stay Focus 证明 A 的最小完整用户闭环；不要直接建设任意后台 JS 平台 B，不强迫所有应用用声明式配置表达所有算法，也不默认改做 D。** 若某项原业务只能由 B/C/D 完成，记录清楚并保留安全的现有实现，不删除功能、不虚报完成。

Chrome MV3 Service Worker 是事件驱动、可能休眠并丢失内存状态；使用 Alarm/事件与持久检查点恢复，不依赖永久运行的 setInterval。chrome.userScripts 用于网页脚本而非后台 SW。chrome.offscreen 有限定用途、仅 runtime 等受限能力，**不能直接作为通用任意后台脚本宿主**。参考 [SW 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)、[用户脚本](https://developer.chrome.com/docs/extensions/reference/api/userScripts)、[Offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen)。

## 5. 应用与框架的明确所有权

**Stay Focus 应用拥有：** 内置网站分类/推荐、默认 30 分钟娱乐额度、网站与分组、工作时间和专注体验、白名单/子域名优先级的产品选择、提醒文案、数据模型版本与迁移、用户在 UI 的修改流程。

**公共框架拥有：** 应用包/版本的真实身份验证、能力声明和按站点授权、活动观察事件及有界时间检查点、持久订阅与唤醒、受控网站规则资源、DNR 写入/读回、权限与安装代际、Stop/撤权/卸载事务、跨应用资源隔离及错误回执。

允许通用 Runtime 支持时间窗口和额度等**可复用的规则原语**，但不可硬编码 stay-focus、娱乐场站点清单、某款产品 UI 或独有的 30 分钟初始值。不要为此新建第二套 SDK、Host、安装器、Dispatcher、持久调度器或完全通用的后台脚本平台。

**候选 SDK 能力组（尚非正式 API 名称）：**

1. 授权后前台/空闲活动观察：按 Origin 和安装身份隔离，事件丢失/长睡眠不补算未知时间。
2. 有界、持久的时间预算与时段策略：能在侧栏关闭、SW 休眠与启动后对账；配置的更新/删除有安装代际栅栏。
3. 归属隔离的访问规则：只管理本工具明确获准的站点范围、DNR 规则和固定安全拦截页；效果和清理必须读回。
4. 仅本应用可读写的持久状态、审阅、停用、撤权和未知结果恢复。

SDK 新增项必须沿**现有 Browser SDK Registry → Schema → Host / Authority → Chrome Driver → 测试**完整接入后才允许在文档与 UI 中显示为已提供。应用不能直接从沙箱调用 chrome.idle、chrome.declarativeNetRequest、chrome.alarms 或全局 Chrome 特权对象。

限制页现在依赖固定扩展资源路径；若希望**无需重建宿主就更新限制页业务文案/UI**，需评估通用且安全的阻止页模板如何只读取经验证的应用安装数据并作为纯文本展示，不能从 URL 参数/未授权包执行任意 HTML/JS。未完成该能力前，将该类升级标记为宿主依赖。

## 6. 迁移、更新、权限与数据合同

- 继续使用原应用 ID；旧安装包、focus.control 权限、状态存储、Alarm 与既有 DNR 规则 ID 范围在迁移中需要**明确兼容映射**，不能隐式丢弃旧设置、额度或重装另一工具 ID。
- **旧版宿主缺少新公共能力时**明确提示版本不支持；先保证旧用户不会误判为「后台正在运行」，数据原样保留，不悄悄清理或伪造 DNR。
- **默认规则升级不得覆盖用户显式编辑**：例如新增推荐站点不能将新站点无提示加入拦截范围，更改默认 30 分钟不能重写旧用户自定义每日额度；新站点/扩大范围必须单独审阅。
- 修改安装包的 Hash/epoch 不自动继承旧后台运行授权。旧授权是否可沿用，取决于权限/站点范围/语义与已安装身份的精确校验；不兼容变更先停止并请求可信确认。
- 数据写入后需收到持久回执、执行层回读和 DNR 原生回读；结果不确定时保持安全状态、禁止盲目重复写入。Stop、撤权、卸载只清理应用拥有的计时策略、Alarms、DNR IDs 和业务数据，不能清空其他应用规则或全局 DNR 权限。
- 原生权限是 OpenDesk **Chrome 扩展级**能力，安装应用不等于自动获得该能力；工具级权限/网站授权仍由现有 Authority 判定。避免卸载 Stay Focus 时撤销其他工具仍依赖的原生共享许可。

## 7. R4 实施顺序与明确验收

1. **P0｜可行性与最小契约**：从现有 trusted/service.js 提取「事件/Chrome 操作」与「产品策略」调用链，明确现有 SDK 缺口、受限 Schema、谁在 SW 休眠后唤醒/重放、安装包能否真正存储更新规则，以及什么算法不能独立升级。只冻结最小可复用合同。
2. **P0｜实现公共后台能力**：复用唯一 Browser SDK/Host/Authority，先打通前台活动观察、持久策略和受控 DNR，并建立按 toolId + packageHash + installEpoch + Origin 的所有权与撤权。首个用例使用真实 Stay Focus，不用仅 Mock Demo。
3. **P0｜迁移现有 Stay Focus，不做功能缩水**：保持 UI/数据/权限行为；新的规则从应用安装/存储中读取并传到通用服务。保留老业务代码直至共享额度、工作时段、专注模式、白名单、提醒和所有权与旧行为同等验证。
4. **P0｜独立升级的反证测试**：**固定完全相同的 OpenDesk Browser 构建 SHA、Manifest 和扩展 ID**，先安装旧 Stay Focus，再**只升级应用包**，例如加入一个原先不存在的推荐站点并经用户确认应用该站点额度；从真实状态读回和 Chrome DNR/导航证明新规则生效。若只更新 UI 文本却仍执行宿主硬编码旧策略，则判 FAIL。
5. **P0｜真实 Mac Chrome**：从扩展中心安装、可信原生许可、正常前台用至测试额度耗尽、真实导航阻止、关闭侧栏、SW 休眠/重启、恢复、撤权、启停、同 ID 升级及卸载；核对 Time Review/AdBlock 规则和存储未受影响。**不由测试代码手动增加 usage 或直接注入 DNR 冒充应用效果**。
6. **P1｜清理旧固定路径**：只在所有真实消费者迁移、受影响安全/回归通过后删除 src/stay-focus 兼容转发、固定服务及专属宿主分派。Page 提醒与阻止页若仍需预编译，明确保留理由及独立升级限制，不伪称完全解耦。
7. **P1｜正式发布**：使用现有唯一打包器，生成候选→受影响测试→--promote-from→--check-project；在应用根仅保留一个 stay-focus.opendesk-tool.json。普通用户安装步骤与真实包 SHA/源码 SHA 一起交付。

**每阶段禁止伪证：**静态源码审计、Node 组件 PASS、生成包 PASS、Chrome 原生 PASS、真实独立升级 PASS、正式验收/发布分别记录。不能在 Mac 验证时标记 NOT_TESTED；真正功能阻塞时标记 SDK_GAP / BLOCKED 并给出原始原因。单次 R4 不顺带重构 Time Review、AdBlock、Reading TOC、Cookie Editor 或 React 五 Tab。

## 8. 六项最终产品问题（各自独立评估，目标 95+）

1. **安装独立性**：普通用户无需源码、无需重新编译，正确安装/授权并运行。
2. **后台能力完整性**：关闭侧栏、跨日、Chrome idle/重启及真实额度耗尽后策略行为正确。
3. **业务独立升级**：不改宿主 SHA，仅更新应用包，**运行中后台**真实采用新规则；超出 Schema 的变化明确不支持。
4. **SDK/架构边界**：框架没有 Stay Focus 特有业务、产品算法和硬编码名单；公共能力确实为其他工具可复用。
5. **安全与兼容**：站点许可、工具身份/epoch、规则所有权、旧数据迁移、撤权及卸载不影响其他工具。
6. **用户体验**：安装、功能启停、设置、权限提示、升级与失败恢复清晰，窄屏和键盘可使用。

各维单独给真实证据和评分；没有最新候选的原生结果时标记 NOT_TESTED，不能因为设计文档充分就宣称产品 95+。
