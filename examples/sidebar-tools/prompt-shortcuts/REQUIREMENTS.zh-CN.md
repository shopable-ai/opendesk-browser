> 状态：已确认的 R1.2–R1.3 产品需求基线，2026-10-15 汇总；补充 **R1.6 跨 AI 平台扩展需求**。**本文件是产品需求与交互验收合同，不是新 GOAL、测试报告或已完成功能声明。**
>
> 工具 ID：`prompt-shortcuts`；正式项目：`examples/sidebar-tools/prompt-shortcuts/`；**目前仅有 ChatGPT（`https://chatgpt.com`）适配源码**，P1 目标包含 Claude、Gemini、Perplexity、DeepSeek、Grok 等 AI 网站及 Cursor AI 编程工具（需单独验证 IDE 接入路径）；ComfyUI 等节点式 AI 工具属于 P2+ 研究范围；唯一交接/进展文档：`docs/framework/workstreams/prompt-shortcuts-r12-ui-handoff.zh-CN.md`。
>
> 重要：预览已确认，不要求重新设计 UI。正式产品必须以预览的产品区域为基准，并复用现有真实安装、SDK、权限、存储及可信网页适配器。**Node 通过、可移植包通过与真实 Chrome 验收是不同证据级别。**

## 0. 产品定位、目标平台与交付阶段（R1.6 补充）

**核心目标：** 让用户只需在 OpenDesk Browser 中维护**一套**常用提示词，就能在其主动授权且已完成真实适配的 AI 产品网页中，通过快捷按钮把完整文本插入目标草稿；用户继续编辑并决定何时提交。产品名称、工具 ID、存储模型、Side Panel 管理 UI 均**不绑定 ChatGPT**，站点 DOM 细节只能存在于各自经审计的网页适配层。

**边界：** “列入目标平台”≠“当前支持”≠“已通过真实浏览器验收”。本次只完善需求文档，**不声称下列新网站已实现**，也不因列出候选而新增权限。

| 平台/类别 | 典型使用场景 | 当前状态 / 演进阶段 |
| --- | --- | --- |
| **ChatGPT**（AI 对话） | 聊天输入框旁快捷插入、选中文字右键预填 | **P0 首期基线**：已有仅限 `https://chatgpt.com` 的可信适配源码；真实 Chrome、ChatGPT 编辑器及 Mac IME 仍按证据验收 |
| **Claude**（AI 对话） | 相同提示词库，适配 Claude 实际编辑器与页面布局 | **P1 明确的下一批候选**；未实现、未授权、未验收 |
| **Gemini**（AI 对话） | 相同提示词库，适配 Gemini 实际编辑器与 SPA 变化 | **P1 明确的下一批候选**；未实现、未授权、未验收 |
| **Perplexity**（AI 搜索/问答） | 在提问编辑区插入提示词；按实际输入与页面结构适配 | **P1 明确的下一批候选**；未实现、未授权、未验收 |
| **DeepSeek**（AI 对话） | 复用同一提示词库，按 DeepSeek 实际网页编辑器与页面布局适配 | **P1 明确的下一批候选**；未实现、未授权、未验收 |
| **Grok**（AI 对话） | 复用同一提示词库，按 Grok 实际网页编辑器与页面布局适配 | **P1 明确的下一批候选**；未实现、未授权、未验收 |
| **Cursor**（AI 编程工具/IDE） | 在用户明确选择的 AI 聊天输入区复用提示词；优先核实可被授权的网页入口或经批准的 IDE 集成方式 | **P1 明确的优先适配目标**；接入可行性和接口待核验，未实现、未授权、未验收；**浏览器扩展不能直接视为可操作桌面 IDE** |
| **其他 AI 对话/问答网站**（如 Copilot） | 用户需求验证后逐站接入，不复制独立提示词管理工具 | **P2 候选池**；并非兼容承诺 |
| **ComfyUI 等节点/工作流式 AI 工具** | 未来在用户明确选定的文本节点、参数编辑区复用提示词 | **P2+ 研究方向**；编辑器、画布、节点、工作流执行是不同能力，不能沿用“聊天输入框”假设 |

实施顺序：**先完成并证实 P0 ChatGPT 真实产品闭环 → P1 优先目标 Claude / Gemini / Perplexity / DeepSeek / Grok / Cursor 逐个验证、逐个接入 → 再根据需求进入 P2/P2+**。网站类目标每次只增加一个可验收的适配器；Cursor 先核实网页可用入口或必要的受控 IDE 集成通道，不把桌面软件等同于 Chrome 网页。排序可依据真实用户频率调整，调整前保留安全和质量准入。每个网站的精确 Origin、登录形态、实际 DOM、内容可编辑性和可选菜单能力须在实施前单独确认；上述平台名称**不是**通配域名授权清单。

共享行为：提示词数据**默认属于工具自身的全局库**，同一条目可在多个已支持网站复用，无须为 Claude/Gemini/Perplexity/DeepSeek/Grok 等已支持的网站各安装一次，也不为每个网站复制一套管理 UI。未来如需按网站显示/过滤，采用显式、可迁移的可选范围设置；不改变已有条目 ID、正文和用户数据，不把网站能力字段混入纯文本正文。

- 预览的 Chrome/ChatGPT 假页面、尺寸选择器、深色模式按钮、重置模拟数据、模拟授权/撤权、模拟保存失败和冲突、假右键菜单、`SIMULATED PREVIEW`、测试说明及演示快捷切换，是**预览实验台**，不得不加区分移植到正式工具页面。
- 正式 Side Panel 工具运行在现有 OpenDesk Tool 宿主外壳内，**不得复制一份假的顶栏、导航 Tab、ChatGPT 页面或新的安装器**。只移植预览中属于管理工具自己的版式、样式、控件、层级与交互。
- 正式 **ChatGPT** 网页按钮的外观和定位以 `preview/mock.html` 为准；Side Panel 跨平台复用 `preview/index.html` 的管理产品区域。未来其他网站尽量保持按钮尺寸、提示词查看和操作语义一致，但页面锚点必须依其实际布局安全适配，不能把 ChatGPT 的 DOM、12px 定位值或假页面原样套用。真实动作必须由经审计的可信页面适配器驱动，假右键不能代替 Chrome 原生菜单。
- 保留这两份 **原版 HTML/CSS/JS/交互** 作为可追溯设计资产，允许仅在用户确认新的视觉/交互基准后更新；不能用从正式 `src/` 重新导出的低保真页面替换预览。
- 默认浅色视觉与项目 UI Design Tokens / Shared Design System 一致。预览内的暗色/尺寸调试控件不构成正式产品的新增需求；不建立第二套 Design System。

## 2. 用户场景（S）

| 编号 | 用户期望 |
| --- | --- |
| S01 | 在正式 Side Panel 的「扩展」中安装并打开唯一的“提示词快捷按钮”工具，看到与 `preview/index.html` 的**管理产品区域**一致的界面。 |
| S02 | 只填“提示词内容”即可新建；短标签、名称、形状、启用状态均选填，默认值正确；关闭重新打开后仍存在。 |
| S03 | 在列表中快速浏览、编辑、启停、排序、复制和确认删除；修改中离开不会丢失未保存草稿。 |
| S04 | 已授权的 ChatGPT 主内容区域左边缘、整体垂直居中出现一列小按钮，不遮挡历史导航栏、不定位在底部输入框左侧。 |
| S05 | 悬停或键盘聚焦按钮时看到**完整名称和完整提示词**；点击向草稿末尾插入完整正文，保留已有草稿、换行、空行、中文与 Emoji，绝不发送。 |
| S06 | 用户在真实 ChatGPT 网页中选中文字，通过**Chrome 原生右键菜单**选择“添加为提示词快捷按钮”，原有新建表单自动预填正文，用户仍需自行保存。 |
| S07 | 用户独立开启/关闭网页按钮与右键快捷添加；关闭其中一个不影响另一个，更不删除已保存数据。 |
| S08 | 关闭 Side Panel、刷新网页、SPA 对话切换、BFCache 返回、多标签数据变动、停用/撤权/卸载后，按钮、授权和数据生命周期正确。 |
| S09 | 面对超额、并发写入冲突、存储错误、原生输入结果未知或中文输入法组合期间，宁可明确失败并保留数据，也不假装成功或自动重复副作用。 |
| S10（后续） | 用户在 Claude、Gemini、Perplexity、DeepSeek、Grok 等**已完成适配并单独授权**的网站复用同一提示词库；在 Cursor 等非网页 AI 工具中，仅在存在专用、经批准的集成通道时复用。点击后只填入目标草稿、由用户自行提交；不能误提示“所有 AI 工具均已支持”。 |
| S11（后续） | 用户对某个平台授权、停用或撤权，不意外扩展到其他 Origin；在尚未适配或页面结构未知的网站，按钮不误显示，提供清晰的不可用说明或手动复制退路。 |
| S12（探索） | 用户在 ComfyUI 一类节点式工具中，未来可以**明确选择目标文本节点/参数**并插入内容；绝不自动改变画布图结构、修改其他节点或执行生成工作流。 |

## 3. 可追踪功能需求（F）

### F01 — 管理首页与视觉架构

- 遵循 `preview/index.html` 管理产品内容区域的视觉层级：标题与说明、突出主按钮“＋ 新建”、提示词列表和数量、卡片的短标签形状/名称/正文摘要、卡片的操作入口、使用设置区、站点权限状态。
- 复用宿主既有页头、导航、滚动与 Design Tokens，不能出现预览套壳、重复标题、重复 Tab、过大的测试控件或明显低保真的替代布局。
- 真实默认态、空态、保存成功/错误态、停用态、授权态和窄 Side Panel 常用宽度须保持布局可用；不增加无需求的宽度×缩放专项矩阵。

### F02 — 内容优先的创建/编辑

- “提示词内容”放在编辑页最前、**唯一必填**，保留原始正文及 Unicode、多行、空行、Emoji，不默默裁切或规范化用户正文。
- 短标签、显示名称可留空；默认取正文开头的**前两个可见 Unicode 字素**，不是固定 2 个 UTF-16 code units；短标签手工值限制 1–2 个可见字素，两个字素在网页快捷按钮上纵向显示。
- 短标签和显示名称独立手工覆盖；自动字段应随正文变化更新，手工覆盖不得被意外改写。形状支持圆角方形、圆形；默认启用。
- 实时预览最终按钮与名称；“返回”“取消”及其他导航遇到未保存草稿时必须提供留在编辑/明确放弃操作。

### F03 — 管理列表和持久性

- 新增、编辑、列表展开/收起、顺序上移/下移（可用时）、启停、复制完整正文、删除确认均可实际操作，并反馈准确结果。删除/更新不得影响其他提示词。
- 单一隔离 `library` 数据项按完整 JSON 的 UTF-8 字节数实施 **8192 B** 上限；超限必须阻止写入、清晰说明且保留草稿。
- 既有 ETag/ifMatch 写入冲突保护、未知结果不自动重试、存储读取失败保守拒绝，不能因 UI 重做回退成直接写入、静默覆盖或假成功。
- 关闭重新进入管理页面、多标签变更时，显示已确认的正式存储数据，而不是预览的内存演示数据。

### F04 — 两个独立入口与网站权限

- 首页分别提供“网页左侧快捷按钮”和“选中文字快速添加”两个独立开关，状态可查、可操作、错误反馈不撒谎。
- 网站许可需通过现有工具详情/可信授权 UI 与 Chrome 可选权限完成；展示真实的授权/撤权及启停状态，不把预览“模拟已授权”文案变成真实结论。
- 原生右键功能不能因关闭网页按钮而失效；网页按钮不能因关闭原生右键而失效。

### F05 — 首期 ChatGPT 快捷按钮布局（其他网站按 F10 扩展）

- 参考 `preview/mock.html`：按钮栏位于 ChatGPT **主内容区域左边界附近，整体垂直居中**，不占历史导航栏，不依附底部 composer；随正常主内容布局/SPA 导航变化安全重算。
- 小按钮为圆角方形/圆形，默认仅显示 1–2 个竖排短标签，列表多项纵向排列；必要时按预览所示折叠/滚动，避免覆盖聊天主要操作。
- 鼠标悬停、键盘聚焦显示完整显示名称、完整多行提示词，长内容可阅读；焦点、键盘和 Esc/离开关闭行为合理，不能让 tooltip 遮挡无法操作。
- 不复制 Mock ChatGPT 的聊天导航、消息、输入框或假页面到真实网站。

### F06 — 首期可信草稿插入，永不自动发送（跨网站共用安全语义）

- 用户可信单击才执行；点击前复核正式安装身份、版本/包哈希、安装代际、工具启用、当前精确 `https://chatgpt.com` Origin、站点授权、条目仍存在且启用。
- 空草稿直接插入、已有草稿在尾部追加并**完整保留旧正文**；维持全部换行、空行、中文、英文、数字、Unicode/Emoji。
- 通过可信 `trusted/page.js` 与实际 ChatGPT 编辑器使用浏览器原生编辑语义（现实现 `insertText`）；校验插入后的完整文本，不通过写 `textContent`、造输入事件或无依据的成功提示掩盖失败。
- 真实验证 React/ProseMirror 更新、光标/焦点、继续编辑、Cmd+Z、Mac 中文 IME 组合状态、快速重复单击；同一次异步操作不并发双插入。结果不确定时只提示用户核对/手动复制，**绝不自动重试、自动发送、抓取或上传聊天历史**。

### F07 — 原生右键选区预填

- 使用既有 `OpenDeskSDK.browser.contextMenu`、`browser.launch.consume()` 和固定 Chrome Host；注册仅适用于已获授权的 ChatGPT 网站与用户选区。
- 右键菜单标题“添加为提示词快捷按钮”；选区文本作为新建表单正文，用户显式保存后才生成按钮。
- 选区票据单次消费、有时效并绑定真实网页文档；站点变化、禁用、撤权、卸载/重装之后拒绝旧票据。
- **预览中的 HTML 假菜单只是行为演示，不作为原生功能验收依据。**

### F08 — 生命周期与数据边界

- 关闭 Side Panel 后正式网页快捷按钮仍能在已授权的 ChatGPT 页面工作；页面刷新、SPA、BFCache 返回再次按身份/授权校验并正确恢复。
- 多标签状态变更同步；关闭网页按钮/工具停用/站点撤权立即清理网页控件；卸载只清理本工具数据及授权，不伤及其他工具；重装不沿用旧授权。
- 存储/权限读取失败时保守停止。不得新增不受审计的跨进程通道、泛域权限、第二个 SDK/Host/安装器/存储身份。

### F09 — 设计资源与正式安装包

- UI 原型资产仅保留在本扩展项目 `preview/`，正式产品文件仅修改该工具的 `src/` 及必要的现有可信固定模块；不把实验台控件打包进产品。
- 正式发布文件仍为 `examples/sidebar-tools/prompt-shortcuts/prompt-shortcuts.opendesk-tool.json`，同一 ID、官方 `scripts/build-sidebar-tool.mjs` 构建，不建立第二包或新构建器。
- 若变更固定 `trusted/` 模块，必须按既有安全审计更新**精确** Git blob 来源白名单与对应定向测试，绝不改为宽泛许可。

### F10 — 跨平台网站适配合同（新平台实施时必做，当前不等于已实现）

- **一个产品，一个数据模型：** 继续使用唯一工具 ID `prompt-shortcuts`、现有 Side Panel、`trusted/model.js` 和隔离 `library`，不因新增 ChatGPT/Claude/Gemini/Perplexity/DeepSeek/Grok/Cursor 适配而创建平行提示词库、第二套 SDK/Host/存储或独立浏览器扩展包。不得通过预览 Mock 的内存状态实现多站同步。
- **分层复用：** 列表、默认标签、正文、排序、启停、复制、失败保护、提示词浮层和用户动作语义保持平台中立；各网站仅提供经审计的适配部分：精确 URL/Origin 匹配、页面主内容区锚点、草稿编辑器识别、可靠文本插入与读回、SPA/导航/销毁清理。仅在第二个平台真实实施时，才从现有 `trusted/page.js` / `trusted/policy.js` 提取**最小**共用接口；不预先建立第二个注入引擎或庞大 Provider Registry。
- **明确能力边界：** 每站独立声明并验证可用能力，例如 `draftInsert`、`selectionToDraft`、`nativeSelectionMenu`、`undoVerified`；不支持的入口须隐藏或说明，而非假装可用。不同站点的文本框、富文本编辑器、Shadow DOM、SPA 与 IME 行为可能不同；不靠单个全站通配选择器猜测。
- **按钮位置：** 对标准 AI 对话网站，优先沿用 ChatGPT 批准的“主内容区域左缘、整体竖向居中”的体验目标，精确锚点由平台适配器确定。若存在遮挡、布局漂移、无法确认主区域或移动端空间不足，须可安全收起/隐藏并说明，不得随意漂移到输入框、遮住提交控件或强行固定在画布之上。
- **插入必须可核验：** 仅响应用户点击；先复核工具安装身份/包哈希、启停、精确 Origin、当前文档和站点授权；检查编辑器状态、IME 组合与并发；保留原草稿、多行、Unicode、光标和可撤销性，并读回确认。不确定即明确失败/提示检查与复制，禁止自动重试、发送、启动任务、模拟点击 AI 提交按钮、读取/上传历史消息。
- **逐站许可：** 每个平台新增独立的、明确展示给用户的精确 Origin allowlist 与必要浏览器可选权限；不得使用 `*://*/*`、全部网站/子域名通配、静默授权。改动现有单站 grant schema 时，必须设计兼容迁移、按 Origin 撤权、卸载/重装失效以及版本/安装代际/包哈希绑定；已有 ChatGPT 授权不得自动扩张到新站点。Chrome 原生右键菜单的 `documentUrlPatterns` 与票据文档身份也需逐站审计，不因网页按钮可用就假定右键可用。
- **失败回退：** 遇到网站改版、找不到编辑器、只读、权限撤回、DOM 身份不明或无法验证完整插入，必须 fail closed。提示词库的手动复制仍可工作；不得悄悄注入不可信任的编辑器或将草稿送至服务器。
- **候选进入正式支持的门槛：** 网页平台适配代码及精确来源白名单审计、隔离存储/权限测试、真实 Chrome 的空草稿与已有草稿、复杂 Unicode/多行、Undo、IME、SPA/多标签、停用/撤权/卸载、平台特有编辑器验证；原生右键仅在实际支持且测试后开放。所有证据标注站点与版本，不得用 ChatGPT PASS 冒充 Claude/Gemini/Perplexity/DeepSeek/Grok PASS。Cursor 另按下述 IDE 集成边界单独准入，不使用网页测试替代桌面验收。

### F10.1 — P1 Cursor（AI IDE）适配准入：与浏览器网页分开验收

- Cursor 与 Claude/Gemini/DeepSeek/Grok 的普通网页不同，主要使用场景是 AI 编程 IDE。**列入 P1** 表示优先开展真实适配，而不是声称当前 OpenDesk Chrome 扩展能读取或修改原生桌面 Cursor 编辑器。
- 先核验 Cursor 当前是否提供可供浏览器宿主访问的受支持 AI 草稿界面；如需要 IDE 内能力，必须另行证明现有、受支持的插件/扩展/本机集成接口可用，明确用户授权、进程隔离和数据传递边界。不得未经批准新增 Native 权限、扫描其他进程窗口、自动粘贴、调用不受审计的本机接口。
- 仍复用用户的一份提示词库；在不同运行环境下要明确同步/传递机制与用户授权，不能为了 Cursor 创建一个不兼容的平行数据模型。只有确认真实接入手段后才实施最小集成；不必预先扩建通用桌面自动化框架。
- Cursor 场景的用户动作是**显式选择 AI 输入区 → 插入完整提示词 → 用户检查与手动提交**；不可改写源码、自动执行命令、运行 Agent 工作流或发送消息。若只能稳定提供“复制提示词”，必须如实标注能力等级，不宣称已实现插入。
- 准入证据必须含真实 Cursor 版本/平台/集成路径、最小权限、完整插入与撤销、已有草稿保留、中文/Unicode/多行、停用/撤权/卸载、失败回退及未触发副作用。无真实 IDE 或受支持网页入口的证据一律 `NOT_TESTED`。

### F11 — ComfyUI 与非聊天式 AI 工具扩展边界（研究性，不在当前交付范围）

- ComfyUI 是**节点/工作流式交互候选**，不是可直接套用 ChatGPT composer 定位与插入逻辑的通用聊天网站。未来要先证明用户确有“输入文本节点/参数框复用提示词”的实际任务，再定义适配的具体编辑控件、显式目标选择、只改该字段的回滚和结果验证。
- 区分 `draftInsert`（聊天草稿）、未来的 `explicitFieldInsert`（明确选中的文本字段）与 `workflowExecute`（工作流执行）。本工具**不获得 workflowExecute 权限**，不可自动运行生成、改变连线/节点、覆盖其他参数或偷偷创建节点。
- 本机 ComfyUI 或用户自托管实例可能使用不同 Origin/端口：未来如适配，必须对用户明确指定的实例单独授权与核验；绝不为方便兼容而默认开放所有 localhost、局域网、端口或任意网站。
- 如后续确定范围，需要补专属交互样例、可靠的节点编辑与撤销测试；现有 `preview/index.html` 与 `preview/mock.html` **不作为 ComfyUI 原型**，本轮不得修改这两份已确认文件。

### 证据等级

- `SOURCE_WIRED`：源码已有接线，不能认定可用。
- `NODE_PASS` / `PACKAGE_PASS`：相同候选的定向测试/官方构建已通过，仍不等于浏览器产品通过。
- `INSTALLED_CHROME_PASS` / `REAL_CHATGPT_PASS` / `MAC_IME_PASS`：必须有同候选真实 Chrome、ChatGPT 或 Mac 操作证据。新增平台应单独标记如 `REAL_CLAUDE_PASS` / `REAL_GEMINI_PASS` / `REAL_PERPLEXITY_PASS` / `REAL_DEEPSEEK_PASS` / `REAL_GROK_PASS` / `REAL_CURSOR_PASS`（需真实 IDE/官方网页入口与集成证据），不可跨平台复用。
- `NOT_TESTED` / `BLOCKED`：缺实测条件必须如实标记；逐维评分缺证据保持 `NOT_SCORED`，不能主观声称 95+。

## 6. 变更和协作规则

- 严格以现有仓库最新 `main` 增量推进：先读 `AGENTS.md`、本文件、唯一主交接文档，再确认 `git status`；保护并行 Agent 与未提交文件，不开新分支、Worktree、PR，不强推。
- 如果已有本机 `npm run dev` watcher 写入 `dist/development`，不停止、不另启抢占输出的构建服务；不猜测 Chrome Extension ID 或 Native 配对。
- 先做**预览产品区域 ↔ 真实产品**差异清单和 UI 修复，再执行相应真实功能回归；禁止只提交截图/Mock/测试数据来认定生产 UI 完成。
- 需求变动须记录“用户确认、预览基准变更、正式源码映射、测试回归”；更新本文件，而进展、构建、CI、提交与阻塞继续写入唯一主交接文档。**本次跨平台需求补充不修改既有两份 ChatGPT 预览；也不代表候选站点已开发或取得新权限。**
- 尚未取得可复现的真实缺陷证据时不得为了视觉一致性重写框架或弱化可信授权、DOM 读取/写入、防重和撤权边界。
