# Cookie Editor R4.9 · UX 初审与证据状态

## 现有 R4.8 正式界面：问题 → 原因 → 本候选修复

- 列表中每条 Cookie 以带间距边框卡片承载，视线被重复边框分割 → 连续列表和分隔线，每行名称 + 域名/路径，H/S/P 技术标记简短。
- 原正式视图在授权状态区、网站切换、离线工作区、清理/观察入口及高级表单之间频繁切换注意力 → 网站状态占一行，高频「导入/导出/新建」与搜索常显，其他入口轻量折叠。
- 编辑表单含过多身份证明和安全文字 → Name/Value/保存/取消直达；属性按需展开；Store/Partition 只读，防止误当可编辑。
- 当前草稿的 dirty 与取消流程易形成打断 → 语义快照比较，恢复原值为 clean，未改动关闭无需确认，只有真正 dirty 才出现行内放弃选择。
- 导入场景步骤不够直观 → 文件或粘贴，自动识别 JSON/Header/Netscape，统一预览新增/覆盖/错误，明确确认后才在虚构内存写入。
- 导出操作分散且说明过长 → 仅「复制」「下载」两个并列主要按钮，默认 JSON 元数据，不含 Value。含值显式选择、模拟权限与独立最终确认。
- 首屏重复提示过多 → 状态只在异常、成功或用户请求时显示；复制/下载错误提供清楚的恢复路径。

## 安全与设计约束

- 本目录无网络请求、真实 Cookie API、OpenDeskSDK 或持久化；运行时只有本地打包 React + CSS。
- 不动正式 `src/`、授权、Host、SDK、Installer、工具配置、JSON 包、历史 R4.3 与 R4.8 预览。
- 用户确认后才允许迁移。正式版值读取、rename、冲突回读、PartitionKey 和未知写入状态应复用现有 Host 契约，不可照搬演示内存逻辑。
- React 可选：若工具 IIFE 220000 UTF-16 代码单元或完整工具 JSON 320000 字节超预算，正式版本应保留原生 JS，迁移交互设计而非扩大配额。

## 截至初始提交的真实验证

- **LOCAL_SCOPED：** React JSX 经 TypeScript JSX 转换，在预装 React 16 + 测试专用 hook 兼容层上执行 Chromium；首批 10 组交互 PASS，JS pageerror 0。仅为行为模拟烟测，**不是 React 19 构建或正式安装验收**。
- **REACT19_BUILD：** 等候 GitHub Actions 在新提交运行；必须以实际 Vite 产物与 Playwright Chromium 脚本结果为准。
- **NATIVE_CHROME_INSTALLED：NOT_TESTED**。原因：本轮禁止迁移正式扩展、不能接触用户 Mac 已安装 Chrome。
- **ACCESSIBILITY_AXE：NOT_TESTED**。已有语义/键盘设计待独立 WCAG 测试。
- **公共 R33 组件复用：NOT_TESTED**。最新 R33 文档明确不等于已有成熟库；并行改动须以后续仓库实际源码复核。
