## 团队账号核心流程（2026-11-06，合成开发）

**可复现的合成开发闭环已具备；已安装扩展尚未接入团队可信 adapter。** 普通预览和当前安装入口会明确显示团队连接未接入，不会借测试代理写入真实 Cookie。以下使用两个不同的合成会话，不读取个人浏览器数据、认证文件或上游额度。

在仓库根执行：

```sh
node examples/sidebar-tools/cookie-editor/preview/react/team-http.mjs
```

默认使用专用端口 43136，与已有 43135 服务分开。启动成功后打开终端输出的 URL（默认 `http://127.0.0.1:43136/dev.html?teamCore=1`）；端口已占用时停止新启动，不终止原服务，可显式设置 `COOKIE_TEAM_PREVIEW_PORT`。只构建本次管理 Web UI 到私有临时目录，不构建 Browser、工具正式包或覆盖已有 watcher。结束本进程会清除该实例的合成数据。

1. 展开顶部「合成团队开发控制」，点「发布并分配两个合成账号给 A」，收起控制区。在原「企业」Tab 点「读取获授权账号」，应看到合成运营与设计账号。此步不会写入 Cookie。
2. 对账号 1 点「请求设备配对」。真实部署中须由发送端通过独立可信渠道核对完整接收指纹；本例展开开发控制，明确点「核对指纹并交付账号 1」模拟发送者操作。现有 Relay 需要在线发送者，未实现无人值守离线账号池。
3. 收起开发控制，点「领取已交付会话」。应显示「已下载 · 尚未应用」，只是保存到该合成成员私有账号库，Cookie 写入数保持 0。
4. 点「核对应用」，审阅网站、版本、Store、精确分区。焦点落到确认标题，Tab 后可用 Enter 点「确认应用到当前目标」。只接受原可信服务的已核对 Cookie 效果回执；第三方网站是否登录、登录哪个身份仍为未验证。
5. 对账号 2 重复步骤 2–4。开发控制「读取合成应用观察」可核对 A 的标记从 `OPERATIONS` 变为 `DESIGN`，写入数为 2；B 始终为 `NONE`、写入数 0。卡片回执是历史动作结果，不表示多个账号同时登录。
6. 开发控制切到成员 B 后另点读取列表，应为空；切回 A 保留私有账号和回执。这里切换的是测试上下文，各自具有独立服务器凭据与设备键，ego TaskSpace 仍共享浏览器 Profile。
7. 先核对账号，再通过开发控制或原管理员团队对话框撤销该分配；旧确认必须失败，新列表不再提供账号。本地 Cookie 与私有账号保留，不回滚、不替第三方网站登出。发布新元数据版本同样使旧分配停止提供账号，须重新审阅分配与会话。

管理员原页面新增「团队账号管理」：沿用管理员会话；发布元数据后选择精确成员设备，登记原分享功能生成的单设备邀请。首次可不填发送端指纹，完成原发送端核对交付后补填同一邀请的发送端指纹，分配修订加一。这里不上传原始 Cookie、私钥或任意文件，保存引用也不证明已交付。成员标识由管理员签发配对码时指定，普通成员请求不能自选成员/租户。专用预览的 Node 驱动保留合成管理员会话，不将它返回 React。

**结果未知时停在原操作。** 服务端写入与本地可信动作分别留原操作 ID；超时、丢回执、重新打开及快速连点不产生替代写入。只读原服务回执可以解除已确认的服务操作围栏，但不会自动继续领取或应用。本地可信动作未知时保留记录待人工核对，不自动重放/回滚。管理页使用 Web Locks 串行保护同源多页日志，缺失锁能力时禁写。

## 当前服务引导（2026-11-06，核心开发）

本轮同源码开发界面已走通 **添加地址 → 保存并继续 → 配对 → 读取服务账号 → 按需关联 → 检查连接**。个人 Cookie 编辑不依赖企业服务。企业席位和预算示例收在「企业用途与示例」中，均为虚构数据。

可打开[同源码交互预览](http://127.0.0.1:43135/dev.html)；默认两条服务是预览专用虚构配置，不会注入真实工具存储。[隔离 HTTP 场景](http://127.0.0.1:43135/dev.html?isolatedHttp=1)使用真实业务 App、领域逻辑和普通服务协议，Cookie/账号及网络 SDK 边界为测试替身。本轮已完成的合成设备和关联均已撤销。预览服务运行期间入口有效；它不是已安装工具、Browser serve 连接或 production 证据。

1. 进入「企业」，点唯一的 **＋添加服务**。本机服务先启动配套账号额度后台；公司服务向管理员获取 HTTPS 地址。类型用于说明地址来源，不会自动部署服务。
2. 填可辨认名称和**精确服务来源地址**，例如 `http://usage-demo.localhost:61234` 或 `https://team.example.com`。只填协议、主机和实际端口，不带尾斜杠、路径、查询、片段或账号密码。后台管理页的完整链接、任意网站和 `chatgpt.com` 都不能代替服务来源地址。
3. 点 **保存并继续**，立即进入刚保存那条配置的配对页。此时只是地址已保存；取消配对仍保留配置，不创建设备。在目标后台「Cookie 同步设置 → 生成新应用连接码」取码，核对页面显示的服务名称和地址，再点 **确认连接**。码 5 分钟有效、只能用一次；管理员登录码不能代替应用连接码。
4. 服务回执确证后显示 **已配对**，并只读加载授权服务账号。没有账号表示后台尚未配置资源；网络失败则保留配对事实并显示错误。应用会话 15 分钟有效；重新配对需新码，不会自动续期。
5. 可跳过关联，直接查看账号和 **读取缓存用量**。需要关联时点 **关联本站账号（可跳过）**，选当前站点已保存账号和服务资源，先核对两端名称再确认。成功仍为 **UNVERIFIED／身份未核验**；手动关联不证明同一登录身份，不传输 Cookie。
6. 点 **检查连接**，分别看服务可访问、应用会话、账号资源读取和检查时间。它只使用现有授权的只读接口，不配对、不关联、不续期、不读取 Cookie、不查询上游额度。未配对或过期时不会猜测探测接口；**刷新服务列表只重读本地配置**。
7. 管理页、策略和断开放在「更多操作与同步策略」。解绑和断开都需明确确认，以服务端撤销回执为准；本地账号与 Cookie 保留。遇到 **结果未知**，先读原回执，不重复发送。新码无效、过期或已使用且原回执明确拒绝时，页面清空无效码并允许重新输入；不能把网络中断当成拒绝。

缓存结果独立判断：尚未读取、暂无缓存（尚无观测）、过期缓存、读取失败分别显示。读取失败保留已有缓存并标明本次错误；没有数据不显示为 0，也不表示连接失败。资源有读取来源与时间，用量有缓存来源与观测时间。已配对仅证明过去确证的配对，当前可用性看检查结果。

缺少 Chrome 网站访问权限时继续由原可信入口申请；普通服务 RPC 复用已批准的网络能力，不增加逐请求授权。本轮未在真实扩展执行该权限流程。
