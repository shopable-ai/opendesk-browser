## 你可以怎样试

1. 打开上面的测试站点，在 Chrome 侧栏进入 **扩展 → Cookie Editor → 企业**。
2. 初次配置时点 **添加服务**，填写名称（例如 `HTTP 测试`）和完整服务地址，再点 **保存配置**。本次地址是 `http://usage-491000299620e0c9a3a0bf84.localhost:61282`，不要改成 `127.0.0.1`，也不要加路径或尾斜杠。保存后显示「未连接」。
3. 在后台管理页点 **Cookie 同步设置 → 生成新应用连接码**。回到测试站点的侧栏，点 **连接服务 → 填入应用一次性配对码 → 确认连接**，应看到「已连接」。2.0.59 的普通 HTTP 请求不再逐次弹出 POST 审批；缺少 Chrome 网站访问权限时仍需授权。
4. 点 **读取资源**，应看到「简单测试资源（虚构）」。再点 **读取缓存用量**；本次实际显示「状态未知」「观测时间：暂无」「暂无用量窗口摘要」，这是空缓存，不是连接失败。
5. 点 **绑定账号**，本站点账号选 **HTTP**，远端资源选 **简单测试资源（虚构）**，依次点 **核对绑定 → 确认绑定**。应显示「已绑定／未核验」；它只表示手动关联，不证明两个账号是同一登录身份。
6. 点对应关联的 **打开资源管理页**，若出现打开网页许可，核对测试服务地址后点 **允许本次操作**；检查新页显示的是刚选的测试资源。
7. 回到测试站点侧栏点 **解绑 → 确认解绑**，应显示「已解绑」。再点 **断开 → 确认断开**，应显示「服务已确认断开」。本机账号保留。

每一步都等界面给出结果后再继续；切换标签页后也等侧栏恢复本站名称。若出现「结果未知」，先点「读取回执」，不要连续重发。

这次两版均已完成第 7 步，连接已经撤销。**同一配置断开后再次配对没有纳入本次测试**；若要再做一轮，可点「添加服务」另起一个测试名称，保留旧记录。应用连接码 5 分钟有效、只能用一次；已连接的应用会话为 15 分钟。

解绑或断开后，旧资源授权会失效。在仍打开的资源页可点 **关闭详情 → 返回本机管理入口**，回到已有管理员会话；不要把旧页面能显示历史内容理解为仍有设备授权。本次已实际通过这个入口恢复后台查看。
