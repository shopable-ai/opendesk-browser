# OpenDesk 应用市场 R2：设计评分、原型覆盖与验收边界

日期：2026-10-11（Asia/Shanghai）。范围：[R2 方案](app-market-r2.zh-CN.md)、[数据合同示例](app-market-r2.contracts-example.json)、[交互原型](../../prototypes/marketplace/app-market-r2.html)。

## 评分方法

评分是本轮 AI 分工后的产品设计静态评审，衡量需求闭合、交互说明、状态逻辑和对既有框架的复用；不是外部人类专家认证、真实用户调研或已上线软件的可靠性分。由不同任务视角交叉检查，发现缺口后修订，不根据目标分倒推实际得分。

R1 按用户本轮补充的完整市场目标为 74/100。R2 最终独立复评为：**产品设计规范 96/100；原型结构与流程覆盖 91/100**。规范已经达到本轮 95+ 的方案目标；原型覆盖度尚未达到同一分值，不能将两者混为一项成熟度分。原生浏览器、正式媒体、跨站安装和设备迁移不在本轮已验证范围内。

| 维度 | 权重 | R1 方案 | R2 设计规范 | R2 原型结构与覆盖 |
| --- | ---: | ---: | ---: | ---: |
| 发现与信息架构 | 20 | 16 | 19 | 19 |
| 状态与管理 | 15 | 11 | 15 | 14 |
| 独立详情、媒体与分享 | 15 | 8 | 14 | 13 |
| 安装与信任 | 20 | 17 | 19 | 18 |
| 套装与迁移 | 10 | 3 | 10 | 9 |
| 可评审性与工程复用 | 20 | 19 | 19 | 18 |
| 合计 | 100 | **74** | **96** | **91** |

未参与纯函数与原型编写的审阅方负责最终评分；纯函数作者自测、原型作者集成检查与根代理一致性检查分别记录。分数属于明确范围下的主观静态评审，不是对真实用户结果的保证。

### 设计规范剩余 4 分

1. 开发者/支持入口已有需求，但辅助页面路由尚未细化到消费者主链路的程度。
2. 正式媒体的类型、尺寸/大小控制已经提出，发行准入的具体数值预算尚未冻结。
3. 外部桥的职责与拒绝条件明确；版本协商、消息字段和错误响应形状仍需工程协议定稿。
4. 生产 schema 与不可变清单规范化字节规则尚未冻结为可执行合同。

这些项目是下一阶段需要明确的工程设计项，不是将后台未实现误判为产品需求缺失。

### 原型仍未完整演示的路径

- 版本对比已绑定目标/已有版本与数据兼容，但没有完整展示旧能力与新增能力差异。
- 应用详情尚未提供真实发行更新日志和完整作者支持区域。
- 套装内版本差异及非空偏好冲突有规范与模型依据，尚未全部连成可操作的页面流程。
- 开发者发布、目录加载与离线更多由文档说明；原型渲染与演示状态仍有耦合。

因此不将 96 分套到 HTML 原型整体。原型中的媒体是交互示意，正式截图/录屏、键盘与视觉表现另行验收。

## 已完成的合同修订

| 审查发现 | 修订后的要求 |
| --- | --- |
| 详情仅为弹窗 | 独立详情、固定版本链接、媒体、作者/权限/版本；确认仍用独立审阅面板 |
| 模拟网站控件 | 移除；适用网站筛选与真实来源上下文分别处理 |
| 外部链接与批准混淆 | GET只展示；用户继续后进入可信宿主确认，nonce不是安装批准 |
| 断线被当失败重试 | 在途或未知先查操作归属和安装回执，不盲目重放 |
| 本批成功导致计划失效 | 维护可追溯滚动基线，区分预期变化和计划外并发变化 |
| 短期意图过期丢操作 | 仅未批准意图过期，已提交 operation 持久保留 |
| unlisted 与撤回混淆 | 未列出仍可合法直链安装；停止发行和安全撤销分别处理 |
| 环境只能一个状态 | unknown/checking/assessed、多个安装/使用 blockers 与上下文身份 |
| 重复或冲突套装成员 | 一个 marketId 一个确定发行；同时检查本地 toolId 映射冲突 |
| 版本审阅漏数据兼容 | 目标能读现有数据或有受信恢复合同才允许改变版本 |
| 迁移等于备份所有数据 | 应用清单/非敏感偏好；正文、凭证、grants、本机证明分别处理 |
| 模拟安装被误作真实通过 | 示例身份与真实 hash 分开；原型只为演示；生产证据另列 |
| 草稿包有 hash 就被视为可装 | published/unlisted 正向准入，其余发行状态不进入安装 |
| 已有本地槽位被新市场身份占用 | 同时检查批内冲突和目标设备现有 toolId 的作者归属 |
| 版本和套装分享时信息漂移 | 固定版本贯穿详情/意图/确认；revision 冻结名称、说明与成员 |
| 迁移确认覆盖已有在途批次 | 同 transferKey 的 running/unknown 复用原操作；先查询结果 |

## 可评审的主要路径

1. 阅读目录完整详情 → 切换媒体/播放示意 → 普通分享与安装链接预览。
2. 扩展内安装审阅 → 安装过程 → 我的应用；重复安装同一发行不产生重复记录。
3. 公网安装落地 → 在 OpenDesk 继续 → 自有确认界面提案；无法连接与不支持时保留选择。
4. 阅读套装 → 逐项版本/权限预检 → 批量确认 → 各项结果；部分失败仅重试失败项。
5. 批量在途取消 → 后续取消、在途收敛、已成功保留。
6. 我的应用多选 → 创建固定套装演示 → 分享/导出纯数据清单。
7. 迁移清单解析 → 版本/来源预检 → 合并恢复；严格拒绝未知和敏感字段。

固定公开路径、媒体内容、应用状态和操作过程在原型中分别使用路由与内存示意。真实公网链接未部署，自建演示套装和安装状态刷新后不保留；正式版必须保存成功才提供持久链接。

## 本轮已完成的定向检查

- JSON结构、四款应用 ID/版本/权限与源码审计一致。
- HTML 片段与独立版同源，脚本语法有效，没有额外执行依赖、网络请求和持久存储。
- 路由明确处理固定版本、未知 ID、异常 revision 与无效参数。
- 纯逻辑检查关注来源/hash、未知结果、重复安装、批次取消/重试、迁移允许字段和导入导出一致。
- 只运行不依赖浏览器的静态或纯函数验证，不构造 DOM 点击、伪造 native 回执或调用真实安装器。

| 检查 | 结果 | 能证明的范围 |
| --- | --- | --- |
| 根代理最终交付检查 | 19 项 PASS | HTML 同源、脚本语法、固定 ID/版本/能力、同 revision 快照、示例迁移往返与声明一致性 |
| 交付 HTML 中提取的纯模型 | 17 组 PASS | 路由、身份、批次、失败重试、取消、未知结果与严格导入的模型规则 |
| 真实候选数据及原型所用辅助函数 | 20 条 PASS | 四款候选的明确演示流程与模型调用衔接；未执行 DOM |
| 原型结构检查 | 9 项 PASS | 单文件约束、同步、无网络/持久化、修饰键链接、移除假网站控件等 |
| 未参与实现方独立断言 | 44 条 PASS；最终补丁另 4 条 PASS | 独立负例与 queued/awaiting-confirmation 优先级；不计入作者自测数量 |

不同检查组有重叠，不将数量相加包装成互不重复的测试总数。检查过程中一个根代理字符串断言误用了局部变量名，修正的是检查脚本；最终交付均按最终文件复核。原型模型的显式人工回执只用于演示，不能算真实安装器成功证据。

最终原始结果见 [static-review.json](../framework/workstreams/evidence/app-market-planning-r2-20261011/static-review.json)。检查通过只证明所列范围，不能证明未运行的浏览器页面和真实安装链。
