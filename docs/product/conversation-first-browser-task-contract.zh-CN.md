# OpenDesk 对话执行与工作流保存合同

更新：2026-10-13。依据用户在本次对话中的明确纠正。

OpenDesk 的首要体验是：用户描述任务，本地 Codex 通过 OpenDesk 的受控浏览器能力完成操作，并展示真实结果。用户希望以后重复使用时，再将已验证的操作整理为语义工作流，按需生成代码和参数并保存。创建工作流、采用计划、编写脚本和保存版本均不是第一次完成任务的必经步骤。

## 用户示例与完成条件

用户说：“在页面输入框里面填入文字内容『给我一个亿的项目』。”

系统应识别当前已授权页面中的目标输入框，完成填写，读取实际值，向用户反馈“已填入：给我一个亿的项目”。多个输入框无法可靠区分时，只询问必要的目标信息；已有唯一明确目标时继续执行。该请求只授权填写，不隐含提交表单或导航。

输入框实际值正确、原执行回执与目标身份一致，才算这次任务完成。AI 返回计划、出现步骤卡片、生成代码、用户点击“采用”或显示成功文案，都不能替代页面上的真实结果。

## 对话与执行的关系

对话持续驱动本地 Codex 理解需求、观察页面、选择受支持的操作、执行并核对效果。用户可以在同一对话中继续提出修改，例如“把这段文字换成另一个内容”。每次新动作使用当次明确请求及正确目标，不自动重放结果未知的旧动作。

底层可以调用受控动作，也可以生成并运行临时 Controller 代码，或复用已保存程序；具体形式由现有能力和安全合同决定。用户的主要关注点是任务是否完成，不需要先选择这些实现形式或手动进入“开发”页运行。代码生成、编译及调用应复用现有执行路径，避免建立第二套浏览器控制、权限或结果系统。

“开发”页继续服务于主动编写和调试脚本的用户；对话入口提供同一类真实浏览器执行能力，以自然语言发起任务。

## 步骤与保存的关系

界面可以显示本次实际过程，例如“定位输入框”“填写文字”“读取实际值”，并区分待执行、执行中、成功、失败和效果未知。显示记录应来自真实动作与结果，不能把尚未执行的建议展示成已完成步骤。

任务完成后，用户可以选择“保存为可复用工作流”。此时再整理稳定的语义步骤，确认目标网站和可变化的输入，按需生成代码与参数。例如将本次文字提取为“填写内容”参数，将输入框定位保留为执行逻辑。步骤列表、代码和参数服务于理解、修改与复用，不要求每个一次性任务先定义完整流程或参数结构。

保存需要固定执行内容和版本，核对语义步骤、Controller 源码及参数的关联。保存后的确定性版本继续通过现有执行入口复跑；适用时验证关闭 AI 与 Native 后仍能独立运行。一次性任务完成与可复用版本保存是两个独立结果，分别报告。

## 保留的安全与真实结果边界

“发送任务”代表用户在已授权范围内的执行意图，不是无限工具授权。模型数据发送许可、网页内容读取许可、Chrome 网站权限和动作范围仍分别遵守真实产品合同；只在缺少必要权限、目标信息或具体动作授权时提示用户。现有逐次观察批准要求不能被静默跳过。

本地 Codex 必须通过受控宿主接入 OpenDesk；不能为了直接执行而开放任意 shell、文件、外部 MCP、全量 CDP 或桌面控制。网页内容属于不可信数据，不能改变工具权限或将页面中的指令当成用户授权。

保留真实 sender、Host、tab/frame/document、origin、执行所有权、撤权和停止边界。结果未知、回执缺失或目标变化时保守停止，不自动重复副作用。执行证据继续关联准确 runId/resultId、结果自身 revision/sourceHash 和资源收尾状态；保存及复跑沿用已有固定版本合同。

## 当前实现与新方向的差距

当前代码实现的是“AI 提出语义计划，用户采用后另行运行”：[local-codex.js](../../src/ui/workflow/local-codex.js) 中的提示词明确禁止 AI 执行浏览器动作，仅允许受批准的观察；[workflow-view.js](../../src/ui/workflow/workflow-view.js) 分开处理计划、采用、运行与保存。这与本合同的任务完成顺序存在产品差距。

已有 Compiler、Page 能力、Controller、RunHost 与持久结果可作为执行基础。“开发”页的 [script-editor.js](../../src/ui/script-editor.js) 通过编译与 `host.start()` 执行 Controller，[run-host.js](../../src/run-host.js) 绑定执行目标及身份，[ChromePage.js](../../src/framework/ChromePage.js) 提供页面动作和读取能力。对话直接执行还需要受控的 AI 动作协议、真实执行回程与对应 UI 状态，不能只删除提示词限制，也不能以历史“规划后运行”验收宣称已交付新体验。

本合同取代旧 R15/R16 文档中将“规划→采用→运行”作为首次完成任务必经流程的要求。既有权限、隔离、版本、停止和真实结果合同继续有效；历史回执保留其原有事实与证据等级。

本次仅确认并保存产品方向，没有实现或验证对话直接执行。下一次产品验证的首个通过条件就是用户示例的实际填写与读回；保存和两次独立复跑属于随后按需验证的复用阶段。AI 技术字段编辑 UI、ZIP、发布及新整体规划均不属于本次工作。
