# GrayDove 账号数据保存：连播助手首轮需求

> 用户在连播助手里保存片头、片尾时，可以选择存到 GrayDove 账号。下次用同一账号打开工具，能在原位置读回；换账号后，只显示并使用当前账号的规则。

**进度（2026-11-23）：** 原工具目前仍只存本机。已用本地测试后端验证 SQLite 落盘、独立读回及账号隔离。真实登录、原工具接入和非生产远端均未验收。

## 背景与目标

用户为一集视频调好片头、片尾后，[连播助手](../../projects/video-auto-skip/README.zh-CN.md)目前把规则存到浏览器本机。重新登录 GrayDove 不能从账号取回这套设置；本机规则也没有按产品账号隔离。

首轮让用户用原界面的「保存设置」把选定的规则存入账号，回来可继续用，交替登录时不串数据。用同一个隔离测试 Profile 就要能验收，无需换设备、迁移 Profile 或使用恢复页。

## 用户流程

1. **保存。** A 正常登录，把某集片头设置为 00:12–01:28。选择「保存到账号」、点击原有的「保存设置」后，在侧栏确认账号和范围。工具先存本机，服务器确认写入后才显示「已保存到账号」。
2. **读回。** A 关闭再打开工具，或退出后重新登录；工具向服务器独立读取，在原编辑位置显示 00:12–01:28。
3. **切换。** 同一 Profile 切到 B，A 的规则立即退出界面，也不再参与跳过。B 可以给同一集存另一个时间；切回 A，工具重新读回 A 的值。

## 功能树与具体需求

| 编号 | 功能 | 必须满足的行为 |
| --- | --- | --- |
| F1 | 选择与保存 | 保存前看清要存什么、存到哪里，再沿用原按钮提交。 |
| F2 | 打开与读回 | 打开或重登时读当前账号；区分已有规则、暂无规则和读取失败。 |
| F3 | 切换与隔离 | 先撤下离开的账号的数据，再启用新账号的数据。 |
| F4 | 失败与处理 | 保住本机有效设置，说明账号状态，用户可从原位置处理。 |

**F1 · 保存到哪里。** 每次默认「仅保存到本机」。选择账号保存时，侧栏在提交前确认当前账号、规则范围和实际改动；取消则保留草稿。只有相对编辑基线确实变化的字段才可上传。选择只对本次、当前目标有效；保存、换目标或换账号后复位。登录、打开工具、编辑草稿和只改连播开关均不上传。不能取得账号版本时，说明原因，仍可选本机保存。

**F2 · 读取时显示什么。** 等当前账号身份确定后，才加载规则。读取中显示「正在读取账号规则」；只有成功读空才显示「暂无账号规则」。读取失败时可重试，并标明临时使用当前账号确认写入过本机的值，即使那次保存后来也成功存入账号。仅从服务器读来的旧缓存不显示、不参与播放；没有确认过的本机值就按无规则处理。打开或重登都独立读取。读回本身不触发跳过，后续播放继续走原校验。

**F2 · 两处都有设置时。** 对同一范围、同一字段，当前账号尚未存入账号的本机改动优先使用，并标明「仅本机」或「待核对」；其他字段用服务端规则。原编辑位置和播放使用同一份合并结果。关闭跳过、屏蔽继承和删除例外都保留原含义，局部修改不覆盖另一字段。后续明确提交该字段且写入获确认后，采用已确认的账号值；没有明确提交的本机字段不会被顺带上传。

**F3 · 何时切断旧账号。** 宿主受理退出、登录失效或切号请求时，先关闭旧账号的数据与播放动作入口，撤下规则、草稿、作品列表及反馈。即使播放页还没收到失效通知，未执行的旧跳过或切集也不得再发起。确认已打开的播放页停用旧规则后，才启用新账号或访客分区。等待期间显示「正在切换账号规则」，不回退旧数据。回到同一账号可恢复它已确认保存的本机改动；旧回执不能进入新一轮 A。

**F4 · 反馈和下一步。** 在「保存设置」附近显示下表状态，便于用户处理。规则有效写到本机后，账号请求失败、重开工具或重新登录均不得清除该账号的本机改动。

| 结果 | 用户看到及可做的事 |
| --- | --- |
| 本机保存失败 | 提示「未能保存设置」，保留草稿供重试；不发账号写请求。 |
| 本机保存结果未知 | 只读回核对，始终不自动发账号请求。确认本机已保存时显示本机状态，可主动重提；确认未落盘时退出核对，提示「上次设置未保存」，原位置保留或恢复草稿供重试。无法读回则继续标明未核对。 |
| 本机保存成功，且用户只选本机 | 提示「已仅保存到本机」；不发账号写请求。 |
| 本机保存成功，服务端确认写入 | 提示「已保存到账号」。反馈只对应本次已确认的范围和改动。 |
| 服务端明确拒绝或发现版本冲突 | 显示「已保存到本机，未存到账号」及原因。原位置可「重新提交这次改动」，无需再改一次，只提交原范围内仍待处理的字段。如有冲突，先读回并展示账号最新值与本机值，由用户决定是否重新提交。 |
| 超时或中断，无法确定是否写入 | 显示「已保存到本机，账号保存待核对」。独立读回一致后，提示「已核对，账号当前设置与本机一致」，不补报原请求成功。该笔改动未被本机后续编辑替换时，解除对应的本机覆盖，让之后成功读取的新账号值生效；保留本机值供读取失败时使用。读不到或不一致就保留覆盖和待核对状态；不自动重发。 |

## 首轮数据范围

| 保存内容 | 规则 |
| --- | --- |
| 片头和片尾 | 仅本次明确改动的字段。包括固定起止时间、距离片尾的秒数、关闭跳过但保留时间。 |
| 匹配标识 | 仅作品、季或剧集所需的标识和范围，可能反映用户为哪部作品设置了规则，保存前须说明。iYF 仅当前集；当前可验证的作品或季范围仅在连播助手的本地测试环境使用。 |
| 清除或修改继承 | 必须显式保存。删除本集例外后按原规则决定是否继承；屏蔽继承则在本集不使用上一级规则。 |

**不发送：** 整份本机设置、未改动的值、连播开关、标题索引、原始网址、播放线路、播放记录或暂存回执。Cookie、凭据、网站登录态、浏览内容、临时任务和设备权限不属于账号配置。历史本机规则留在原分区，登录不会导入。

**不做：** 独立恢复页、安装清单、自动安装、Profile 迁移、历史备份、实时跨设备同步或会员体系。保留原编辑、播放校验、「网页功能帮助」和 Chrome 权限语义。

## 产品验收

在获授权的非生产环境，用同一个隔离测试 Profile、两个非个人账号及同一合成剧集。开始前独立确认 A/B 账号规则均为空，并准备一条只在访客分区的合成规则。下列用例均须通过；本机提示、测试替身或代码检查不能代替真实接口证据。

| 用例 | 通过条件 |
| --- | --- |
| F1 默认与明确选择 | 登录、编辑、仅本机、取消确认、只改连播均无账号写请求。A 确认账号保存 00:12–01:28 后，只提交该字段及匹配范围；服务端确认后才报成功。换目标或账号后旧确认无效；未确认的合法数据和重复提交旧确认均不得发请求。 |
| F2 重开与重登 | 先走 A 正常保存、重开、重登，独立读回原设置。另在工具关闭后、A 退出后分别用授权测试端写入本机未见过的账号值，确认它实际显示。确认过本机写入且成功上云的片头、仅从服务器读来的片尾同时存在时，阻断下次 GET：只显示并执行本机片头，提示读取失败。 |
| F2 局部改动与删除 | 对同一集只改片尾，不影响片头；能区分关闭跳过、屏蔽继承和删除例外。仅存本机的字段继续在本机生效，且未被带入其他字段的账号保存。 |
| F3 同一 Profile 切换 | 分别暂停 A 已算出但未执行的跳过、切集；每条路径都在宿主受理切号后扣住失效通知，再放行旧动作。两条都不得触发播放动作，新分区尚未启用。之后验 A→B→A：B 初读为空，可为同集写不同值；界面、作品列表、SDK、播放与独立 GET 各只用当前账号。迟到的旧读取或回执不得更新 B 或新一轮 A。侧栏关闭时也验证退出与会话失效。 |
| F4 拒绝、冲突或本机失败 | 拒绝或冲突均保留本机且不报账号成功。本机明确失败保留草稿且无账号写请求。冲突时让服务端先更新目标字段及另一个字段；用户看过差异后不重新编辑，主动重提并确认。独立 GET 证实只更新原目标中仍待处理的字段，其他新值不变。 |
| F4 本机结果未知 | 本机确认前中断，重开后分别验证三种记录：已提交则显示已存本机；仅有准备记录则提示未保存、恢复草稿；查无记录则只显示上次确认值，无草稿可恢复。三种均无自动账号请求。 |
| F4 账号结果未知 | 请求后中断，分别验证服务端已提交和未提交，仅读回核对。已一致只报核对结果；再改变该服务端值，下一次成功读回应显示新值，读失败仍可用本机值。读失败或不一致保留本机覆盖。旧回执不得清除更新的本机改动。 |

证据按环境和用例记录：工具操作与可见反馈、服务端写入结论、另一次读取及读回值。用 A/B 标签、请求关联号和修订号核对记录，不保存凭据或个人数据。只有真实产品入口与非生产服务在同一操作链通过，才能宣布首轮用户功能验收完成。

## 附录：接口、依赖和验证证据

### 已查明的归属和缺口

- **原工具保存。** [侧栏编辑器](../../projects/video-auto-skip/src/main.js)调用[网页伴随模块](../../projects/video-auto-skip/src/page/main.js)的 `video.save`。伴随模块校验当前视频、规则范围和 ETag，通过[原可信宿主](../../src/scripting/user-scripts/app-page-contract.js)写入本机命名空间 `opendesk.sidebar-tools.data.v1:video-auto-skip` 中的 `rules.v1`。侧栏随后核对本机读回；该回执不代表服务端写入。
- **产品身份。** 「扩展 → 更多 → 扩展数据与恢复」的[账号适配器](../../src/sidebar-tools/recovery/account.js)返回空。[旧统一账号设计](../architecture/unified-account-cloud-sync-r1.zh-CN.md)里的会话接口和 `/v1/sync/…` 未查到对应路由、客户端接线或联调部署。本仓库的[云控鉴权](../../scripts/cloud-control/provider.mjs)用于执行器配对；匿名统计、Cookie 分享 Relay，以及相邻 OpenDesk 仓库 `cmd/opendesk/app_scheduler.go` 校验 App Token 的本机桥接均不提供产品账号会话。Chrome Profile、站点 Cookie、设备 ID 或显示名不能替代产品账号。
- **待确认。** 两个仓库均未找到可用的产品账号入口、服务端会话校验、配置接口部署或授权联调环境；仓库外是否已有服务未知。仍需确认身份与数据服务维护方、非生产登录与回调、会话校验、可信宿主的传输入口和两个非个人测试账号。

### 最小接入方案

连播助手持有[字段筛选与校验](../../projects/video-auto-skip/src/account-rule-change.js)和[服务端处理器](../../projects/video-auto-skip/server/account-rules.js)。试点接口为 `/v1/products/video-auto-skip/timing-rules`：GET 返回当前账号规则和修订号，无需发送正在看的剧集；PATCH 只提交用户明确保存的范围、改动和预期修订号。服务端从已验证会话取得 `issuer + subject`，与固定产品 ID 组成隔离键，不接受请求自报账号。持久库原子校验修订号并提交后才返回 `{saved:true, revision}`；冲突返回 409。GET 和 PATCH 响应不缓存。

接入复用现有可信宿主。凭据只留在可信宿主与服务之间，不交给沙箱或网页模块，也不开放任意网络或账号选择权。账号校验叠加在原有安装身份、站点权限、撤权和并发校验上。以下是接线必须满足的约束，尚未在原工具实现。

1. **编辑基线与修订。** 开始编辑时固定用户看到的规则、原始范围、账号快照修订和本机存储版本。只为用户主动编辑且最终偏离该基线的字段生成设置、屏蔽继承或删除操作。显示的继承值不得被当成该范围的新规则；保存整份草稿也不能扩大账号改动。保存前复核账号、视频绑定和范围。修订已过期时不静默换成新修订；先读最新账号值，让用户核对后再提交原目标中仍有效的改动。旧记录不能替换或重提已被更新的字段。
2. **可信确认。** 复用现有可信侧栏确认，确认面板由宿主渲染，显示宿主验证的账号、视频范围和实际变更。宿主将可信点击绑定到一次操作、安装身份、账号会话代际、验证过的视频绑定、精确字段操作和基线版本；发请求前逐项复核并原子消耗一次。改变确认内容、离开目标、切换账号或重复使用均拒绝。工具提交合法字段或声称「已确认」不能代替用户确认；显式重提也要重新确认。该授权只存在当前会话内，不随重开恢复。
3. **本机提交与恢复。** 先在当前账号分区持久化准备记录（操作号、目标、字段操作和基线版本），确认后才尝试规则写入。以同一次带版本校验的提交记录规则和「本机已提交」。本机回执未知时先等原写入结算，或在原写入的待决窗口关闭后由同一写入边界读回：有已提交记录才能认定已保存；仅有准备记录则终止核对、提示未保存，并从记录恢复草稿供重试。若准备记录也未能落盘，不尝试写规则；重开无记录时只显示最后确认的本机值。失败及恢复不自动发起账号请求。
4. **账号请求与降级。** PATCH 发出前先落盘「可能已发出」，关停后只读回核对。核对按目标的实际字段操作比较，包括删除与屏蔽；一致只证明服务端当前状态，不能补报原请求成功。服务错误未证明发生在提交前时按结果未知。处理回执或核对结果时，按操作号和本机版本校验，不能清除后来改动。分别保存本机确认值、未同步字段覆盖及服务端快照：收到确认或独立核对一致后，仅解除这次操作仍匹配的字段覆盖，保留已写本机的值。GET 成功以最新服务端快照和未同步覆盖合并；GET 失败只用当前账号已确认的本机值，纯服务端缓存不得成为本机确认值。
5. **统一切换护栏。** 可信宿主维护会话代际，约束侧栏、作品列表、[Browser SDK 存储入口](../../src/ui/sidebar-tools/storage-state.js)和网页伴随模块的读写。切号受理与实际 seek、切集的发起必须经过同一个可信执行闸门，并以该闸门的先后为准。动作在同一临界区核验当前代际、有效会话和原播放条件，然后立即发起；不得把授权票据传回网页，等稍后执行。切号受理在闸门内先关闭旧代际，撤下界面数据，再通知已登记的播放文档；通知在途期间，已算好但未进入临界区的旧动作也会被拒绝。已在闸门关闭前发起的动作不回滚。须确认各旧文档已清空规则和排队动作、或已卸载，才启用新分区；无法确认则保持切换中。不能在现有可信执行路径实现同一闸门时停止接入，不能用客户端缓存的代际或通知代替。

### 非生产接入和停点

| 责任方 | 交付与进入下一步的条件 |
| --- | --- |
| GrayDove 身份维护方（具体负责人待定位） | 提供获授权的非生产登录入口、回调、A/B 测试账号、服务端会话验证和宿主可消费的登录、退出、过期信号。记录真实会话对应的签发方、稳定账号标识及产品授权规则，不记录凭据。缺任何一项，停在身份确认。 |
| 数据服务维护方（部署归属待定位） | 提供非生产持久库与事务、部署本处理器，接上同一会话验证。先用真实 A/B 会话做隔离探针：各自读空，A 写一个合成值后独立读回，B 仍为空，失效会话不能读写。缺真实校验或持久库，停在本地试点，不接原工具。 |
| Browser 可信宿主与连播助手维护方 | 在现有权限内证明两条链路：宿主验证会话和可信确认后才请求固定产品路由；播放动作实际发起与账号切换能在同一闸门内排序。两者均成立后才接原保存按钮和账号分区。找不到合法传输或不能锁住通知在途的旧动作，停在宿主接线，不扩大权限、不启用账号保存。 |

**下一条可验证动作：** 先定位身份维护方，拿到非生产登录、回调和已授权 A/B。在确认同一会话能被服务端验证后，执行上述隔离探针。若没有现成账号服务，由 GrayDove 产品决定并负责统一身份接入；现有空适配器不替代产品会话。
