# 高商业价值用户群 × 内容创作者数据工作流：X 维度研究 R2

> 日期：2026-10-12。状态：**RESEARCH / HYPOTHESIS；暂未获得客户访谈、真实付款、用户账号数据或可正式上线的跨平台 API 授权。**
>
> 决策：**接受“跨行业高商业价值用户群”作为新的机会发现 X 轴；不接受“高流量/粉丝量自动意味着高收入、愿意付费”作为商业事实。** 创作者、MCN、直播机构、品牌营销团队是待验证样本，不是已选定的首款产品。X 轴横切电商产业域，而不是第六个电商行业；不另建机会总账、Browser SDK、任务运行器或新的产品工厂。原 84 个 OPP、8 个 EXP、R8 188 项能力、E01–E40 均保留。

## 一、假设核验与反证

| 假设 | 证据/反证 | 研究状态 |
| --- | --- | --- |
| 创作者经营存在丰富数据 | YouTube Studio 可比较、筛选和导出分析数据；TikTok Shop Creator Center 的指定地区文档有订单/佣金/结算；Shopify Collabs 有创作者与商家指标 | **平台能力事实成立**，不是 OpenDesk 的用户需求证明 |
| 高流量意味着愿付费 | 无可靠因果证据；单个账号流量和净收入、预算权、重复工作不是同一变量 | **拒绝该推断** |
| 单纯导出后台数据可收费 | YouTube 官方导出、TikTok Affiliate Orders 导出、Shopify Collabs 商家报表导出和 Metricool 多客户报表构成强免费/成熟付费替代 | **不能作为独立产品差异化** |
| 佣金对账/商单交付可能有价值 | 平台存在预估与最终佣金、订单创建与结算、退款调整等不同口径；代理商需按合同交付报告 | **合理但未验证的需求假设** |
| 可以自动读取所有后台及粉丝明细 | TikTok Display API 的公开资料/公开视频不等于 Shop 私有佣金 API；地区、OAuth、审核、角色、数据许可均不同 | **不成立；逐入口审核** |

## 二、X 轴：不要按名气排序，要按可解决的商业问题排序

每条候选同时登记：**职业角色、付款人、可合法取得的数据、真实任务触发、数据量、损失或人工成本、现用免费/付费替代、权限和政策、技术复用、验证证据**。

候选评价轴：① 收入/预算是否有可核验证据；② 决策发生频率；③ 错误或人工成本；④ 谁控制账号和数据；⑤ 是否可用官方导出/OAuth；⑥ 免费替代强度；⑦ 付费采购能力；⑧ 获客渠道；⑨ 多账号复杂度；⑩ 站点适配与 API 维护；⑪ 敏感信息/法律风险；⑫ 可否量化投入产出；⑬ 证据可信度。**逐维解释，不用平均数掩盖 BLOCKED。**

| 用户群/角色 | 可付费的潜在结果 | 首轮需研究的真实场景 | 第一判断 |
| --- | --- | --- | --- |
| 专业带货创作者 | 对佣金结算和退款调整准确核账 | 导出本人 Affiliate Orders，和 Earnings 按账期核对 | **P1：重点验证** |
| MCN / 直播工作室 | 多账号结算与佣金分配 | 合法授权的直播/带货报告与合作分账 | **P1**，账号/委托授权硬门 |
| 品牌投放/广告采购 | 商单交付证据和投产核对 | 合同交付要求、内容指标、付款记录对照 | **P1** |
| 社交媒体营销代理 | 每客户月报与可追溯证据 | 自有/客户授权的多个后台下载报告 | **P1**，需超越 Metricool |
| 高成交额电商卖家 | SKU/货款/推广费用对账 | 已授权订单与结算 CSV 差异核对 | 原电商 P1，继续保留原优先级 |
| 独立站品牌 | 创作者带货归因及合同成本 | Shopify Collabs 商家报告与品牌支出 | **P1/P2** |
| 广告预算负责人 | 预算异常和素材归因 | 官方导出与账单核对 | P2，权限/归因定义较复杂 |
| 会员/知识付费经营者 | 订阅退款及续费对账 | 用户拥有的支付与销售导出 | P2，客户隐私硬门 |
| 高流量网站/Newsletter | 赞助广告库存与交付证据 | 授权访问量与赞助合同 | P2 |
| B2B 供应商和企业采购 | 报价/交付成本差异 | 用户拥有的 RFQ/发票/合同报表 | P2 |
| SaaS/专业服务机构 | 授权工时、客户续费及对账 | 自有 CRM 与服务合同导出 | P2 |
| 金融/医疗/法律行业 | 合规账务/专业作业 | 需要特殊许可及高敏数据处理 | **LATER**，不能按“高收入”自动优先 |

## 三、创作者后台：应当核对什么指标？

下表是**跨平台候选指标字典**，不代表每个平台提供全部字段。必须保存平台、地区、账号权限、时间范围、时区、币种、单位、分子分母、来源、导出时间与口径版本。

| 数据分组 | 可见/可研究的指标 | 可回答的经营问题 |
| --- | --- | --- |
| 流量曝光 | views、impressions、reach、流量来源、自然/投放 | 哪个渠道、内容实际带来触达？ |
| 内容表现 | 发布时间、观看时长、平均观看时长、完播/留存、分享与收藏 | 哪个内容系列值得继续制作？ |
| 受众 | 粉丝增减、活跃时段、聚合画像、回访 | 是否匹配目标品牌和发布时间？ |
| 商品漏斗 | 商品曝光、商品点击、CTR、订单和销售件数（平台可用时） | 哪个视频/直播带来交易？ |
| 收入和佣金 | 预估佣金、佣金基数、费率、最终结算佣金 | 为什么预计收入与已结算不同？ |
| 退款和归因 | 退款/取消、无资格订单、归因窗口、订单创建与结算日期 | 哪些差异合理？哪些无法解释？ |
| 品牌商单 | 合同交付、内容链接、曝光承诺、投放结果、应收款 | 有没有按合同交付、完成结案？ |
| 经营成本 | 制作费、样品、广告、团队分成、工具费 | 哪些项目有真实利润？ |

**严禁混淆**：播放量≠独立观众；曝光≠触达；GMV≠净收入；估算佣金≠已到账；订单创建日期≠结算日期；互动率不同分母不能直接横比；跨平台销售归因存在重复计算风险。没有完整收入和成本时不能声称 ROI 或净利润。

## 四、36 个有具体输入/输出的微工作流（不是 36 款插件）

**内容表现（6）**：①导入自己的多日内容报表找表现变化；②前 24 小时和第 7 天复盘；③统一时区对比发布窗口；④对照合作与非合作内容留存；⑤流量异常附证据；⑥授权指标媒介包。

**受众与引流（6）**：⑦按同窗口汇总粉丝净增；⑧按内容对比有效外链点击；⑨聚合受众地区做品牌适配；⑩不同内容形式表现口径提示；⑪曝光→点击的漏斗核验；⑫内容与品牌简报数据追溯。

**商品和佣金（6）**：⑬导入本人 Affiliate Orders；⑭预估/结算佣金按账期对齐；⑮退款及无资格订单原因归类；⑯核对费率、佣金计算基数；⑰对齐订单创建/结算日期；⑱导出差异清单，不含买家个人信息。

**商单与机构报告（6）**：⑲导入官方视频报告和商单合同字段；⑳检查内容交付要求；㉑生成带来源及截止日期的证据包；㉒多合作项目按品牌归集；㉓区分创作者收入、代理服务费与待收款；㉔生成待确认的客户月报，不自动发送。

**直播与商品（6）**：㉕按场次比较有效已结算佣金；㉖商品曝光→点击→成交漏斗；㉗高流量低转化商品标注；㉘货盘/商品与直播时段人工对应；㉙直播结束经营核对清单；㉚广告成本与净收入在数据齐全时核算。

**授权数据治理（6）**：㉛Shopify Collabs 商家合法报表导入；㉜多币种汇率和账期说明；㉝指标定义及分母冲突警告；㉞授权账号/导出来源清单；㉟合同、费用和付款凭证人工核对；㊱保留脱敏来源哈希与手动撤销/删除记录。

36 项只表示可观察任务分类，**不据此新增独立机会编号或 Chrome 扩展**。先映射 OPP-015～021、OPP-031、OPP-060、OPP-078、OPP-080、OPP-081、OPP-083；出现确证的全新用户任务时，才按唯一登记机制增量新增 OPP。商业测试可先给 EXP-005/007 加研究旁支，不把它们改写为已成交。

## 五、研究排序：要与现有电商首选公平比较

| 顺序 | 假设产品/任务 | 潜在购买者 | 竞争风险 | 最适宜起步 |
| ---: | --- | --- | --- | --- |

| 2 | 商单交付与成效证据包 | MCN/代理商 | **高**：YouTube 导出、Metricool | A：本地报告工具 |
| 3 | 品牌/创作者合作成本与合同对账 | 品牌方 | 高：Shopify Collabs | A：授权文件导入 |
| 4 | 多账号客户月报差异复核 | 社媒代理商 | 很高：Metricool | A → D |

## 六、三个最小 MVP 的操作闭环（均为设计，未实现）

### A. Creator Commission Reconciliation：优先验证

1. 用户：已经获得带货佣金、自己有合法下载权限的 TikTok Shop 创作者或经明确授权的 MCN 财务。
2. 打开官方 Creator Center → Earnings → Affiliate Orders；**用户主动导出**允许的佣金记录。
3. 在 OpenDesk Side Panel「工具」→「佣金对账」上传 CSV；显式核对来源国家、币种、账期、订单日期类型。
4. 本地计算预估、已结算、退款调整、未解释差异。输出分组 CSV 和口径说明，无法解释的标 UNKNOWN。
5. 与 Creator Center 自带报表和手工 Excel 比较准确率、任务完成时间、差异解释率；观察两个自然结算周期、真实报价或付款。
6. 最少权限：只读用户上传文件；不需要读取账号 Cookie 或网站全部请求。首版不抓后台、不自动提现、不宣称平台欠款。
7. GO：用户自然重复、明确节省时间或避免实际账务错误，并出现有证据的采购/付费信号；PIVOT：更需要合同/商单工作流；STOP：官方报表完全覆盖或数据出口不可用。

### B. Sponsored Content Proof Pack：商单证据

1. 用户进入 YouTube Studio Advanced Mode → Export current view，上传自己或客户明确许可共享的报表。
2. OpenDesk「商单交付证明」输入合同交付条件，映射发布 URL、内容、时间窗、播放或点击等合同相关字段。
3. 生成带来源、截点、字段定义、未满足事项的客户审核报告，用户确认后导出；不自动发邮件或提交合同。
4. 比较官方导出+人工模板/Metricool 的工时、漏项、客户追问数量；没有明显差异或真实付费则 STOP。

### C. Brand Creator Cost Audit：品牌合作对账

1. 品牌授权人员打开 Shopify Collabs 商家 Sales report，主动导出；另外上传自己的合作合同/费用汇总。
2. OpenDesk 将创作者、渠道、合同费用、已知销售归因及退款状态做可审计核对。
3. 只有数据定义对齐才计算 ROI，缺失成本或归因冲突显示 NOT_COMPARABLE；不读取第三方私人账号。
4. 若仅复制 Collabs 内建报表或买方无预算，归并回原卖家对账方向，不独立发行。

## 七、技术交付及商业硬门

- **A 通用 OpenDesk 工具**：本地 CSV/Excel 导入、字段规范、对账、报告导出。最适合首版，不强依赖新 SDK。
- **C 站点 UserScript**：仅用于经过授权的特定后台局部提示；DOM 和权限变更风险高，不得绕过 API 或反自动化限制。
- **B 独立 Chrome 扩展**：只有独立用户群、单一用途、真实复用/付费、最少权限及商店政策均通过才考虑。
- **D 官方 API + SaaS**：多账号 OAuth/后台历史/多人协作有真实需求后考虑；不等于已有接线 API 全部正式可用。
- **BLOCKED**：无授权账号/订单、静默采集、第三方 Cookie/凭证、跨账号越权、对外自动发布消息、自动操作支付或退款，以及为佣金收入私自修改联盟标识。
- **数据可信度**：平台/角色/地区/账号、导出时间/时区/币种、定义、关联键、可删除性、脱敏和安全留存不可缺失。
- **合规审查**：Chrome Web Store Single Purpose、Minimum Permissions、User Privacy、Affiliate Ads、MV3 Remote Hosted Code、站点协议都为独立门槛。
- **代码复用**：先核查 src/ui/sidebar-tools/package.js、src/platform/host/broker.js、src/framework/sdk/browser-contract.js 和现有 R8 工作流；不新建第二套执行器、权限账本、产品工厂。

## 八、研究计划和可推翻条件

**0–2 周**：按买方角色而不是粉丝数量招募访谈，建议每个首选方向总计争取 10–15 位用户；调查最近一次真实对账/商单结案任务、时间、替代成本、数据许可与付款审批。取得脱敏且经授权的样本时才能做真实字段映射。

**第 3–4 周**：先使用脱敏报表制作 A/B 两种本地任务原型，与平台原生导出+Excel/Metricool 进行同任务对照；不急于开发独立扩展。

**第 5–6 周**：争取 5–10 位实际试用者、至少两个自然业务周期，记录实际任务时长、错误/差异、自然复用与真实报价/付款。没有真实试用时保持 NOT_TESTED。

**3 个月**：仅对获得真实用户价值和数据合法性证据的一个流程进入产品实现。**6 个月**：付费复用成立才评估独立发行、后台 OAuth 和团队协作。**12 个月**：跨行业复制已验证的报表/对账核心，而不是复制同质插件。

**立即停止条件**：平台原生工具已足够、无法合法获得数据、客户不愿采购、DOM/API 维护成本超过价值、统计口径不可解释、隐私合规无法满足。高流量、高净收入、高预算均不能替代客户访谈。
