# OpenDesk Browser Global First R5 · TOP 20 小山头与 84 OPP 实际产品组合

> **2026-10-13，AI-first 竞争投资视图，非世界排行。** 原正式机会主账本 [84 项 OPP](opportunity-register.json)，原商业实验证据 [8 项 EXP](commercial-experiments.json)，原 [14 项 GF 声明](first-claims-ledger.json)，[45 个竞争对象](competitor-timeline.json)。本文是上述唯一账本的**人类可读视图**，不新增重复 OPP/GF/EXP、假客户或已发行 APP。已证明世界/区域/任务第一 **0**，TOP 20 和 TOP 5 都只是当前战略验证顺序，未有独立分数。

## 一屏决策：从“争第一”变成“值得用、能获客的产品”

**最重要的选择**：OpenDesk 应当争夺“AI 协助制作 + 用户审阅源码/网站权限 + 固定版本真实安装 + 模型断开后的确定性多次 Run + 可检查的结果与撤权”的**完整使用体验**，而非再次投入“让用户手写 React/Vue 更方便”。

但[Google Chrome Skills](https://blog.google/products-and-platforms/products/chrome/skills-in-chrome/) 早在 2026-04-14 已保存/复用 AI 提示词，[Claude in Chrome 2026-07-24 发布说明](https://support.claude.com/en/articles/12138966-release-notes) 已提供录制可重复工作流；[UiPath Delegate](https://docs.uipath.com/delegate/standalone/latest/release-notes/august-2026)、Axiom、Power Automate 与 Apify 已覆盖很多相同用户价值。**OpenDesk 不能只靠“AI+可复用”声称历史第一**，必须以合法使用条件下的完整成本、可审阅性、部署摩擦和真实成功率说服用户。

本轮主决策：
- **横向 P0**：GF-007 + GF-004 同一产品闭环，一次 AI 创建→安装→关闭 AI→两次独立运行。GF-004 是信任基础不是第二套运行器。
- **纵向 P0**：OPP-059/057 有限授权的企业表单操作（EXP-001），OPP-015 卖家商品 Listing 检查（EXP-005）；先证明用户愿第二次使用，再扩大业务模块。
- **低争议可验算入口**：OPP-022/025 研究资料来源核对（EXP-003），OPP-071/072 SEO 自有页面质量检查（EXP-006）。与原生工具和第三方最佳体验比较。
- **短期明确退出**：泛化世界第一、零许可登录、无证明 7×24 长期跑、重建通用网页采集、复活已归档 EXP-002 Page QA Inspector。第三方成熟录制器和内建工具更好的场景不争。
- **上市营销级别**：现在仅 M0 准确产品目标和有源码的限定功能说明；M1 真同版完成后只说功能证据；M2 指定完整实验范围的比较名次；M3 独立审核通过才说世界第一。

## 三条可以真正形成竞争壁垒的产品路线

### 路线 A：AI 只参与创造，用户以后拥有可独立运行的“已验证工具”

目标：普通用户在当前自己可访问的网页描述需求，不要求懂 JSX；可在 Side Panel 审核“来源 / 影响网站 / 将做什么 / 需要什么参数 / 是否外发”，通过同一 Candidate→Verified→Available→Installed 后在“我的”一键复用并可升级、停用/撤权。技术上已有 `src/ui/workflow/workflow-view.js`、`src/ui/local-project-install.js`、原 Task/Authority/RunHost、独立 Browser SDK；不能另建模型运行层。

**成功第一关**：真实 macOS Chrome 的同一冻结包，外部真实 AI/本机 Codex 产生至少一个不同源码版本；用户完成审批与真实 native 操作回执，安装后关闭全部模型/Provider，同一固定版本不同 RunId/ResultId 重复两次；出错可诊断，不得自动重复提交。

**公平取胜指标**：完整初次总分钟数、第一次成功率、审批误操作数、第2–20次模型调用与总成本、改变网页/撤权后的安全失败、版本升级/停止。先比较 Chrome Skills/Claude Recorded/Axiom/UiPath/AI coding + 管理器，而不只找没有 AI 的传统油猴版本。

### 路线 B：具体卖家/企业任务，以人工重复工作和数据准确性换钱

优先 EXP-001 企业业务按钮（有限网站和客户授权）与 EXP-005 卖家 Listing QA；Shopify Payout Auditor 的独立研究仍是**研究方向**，不能混成 EXP-005 已实施。做一个能明确展示“减少一次人工错误/复核返工”的产品，而不是又做一套 SaaS。需要真实合法后台数据或用户授权的模拟测试站；金额和敏感数据默认不发远端 AI。

**成功第一关**：一个确定性字段规则、完整错误标注、真实用户复现和下一周期自然重复；标记使用人、付款人、数据许可/保留、当前 ERP 或官方 Export 的最强反证。如果平台本来就免费解决，退出而不是编织独家。

### 路线 C：固定版工具资产的审阅、升级、撤权与企业交付

技术差异在于用户能看到来源、依赖/权限差异和每次实际产生的回执；R7 依赖缓存、统一 Browser SDK、Task/Authority 都应沿用当前所有权，不能为了“最安全第一”加平行 Host。需求侧先证明已有人维护 5+ 自制工具并有版本审阅痛点，B2B 用户愿按维护/内部合规付费。

**成功第一关**：同一客户合法站点的两次不同源码版本，安装、回滚/撤销旧代、失败安全和真实运行审计的原生录像；独立对照 ScriptCat Beta、RPA 企业审批。安全审计未经过不说“全球最安全”。
