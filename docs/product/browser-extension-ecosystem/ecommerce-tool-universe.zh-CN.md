# 电商工具宇宙 R1：产品功能树、技术复用、商业优先级

> 日期：2026-10-12。本文为 **RESEARCH / HYPOTHESIS**，不是已完成产品或付费验证。“工具宇宙”是检索与产品设计用的分类树，**不是要批量开发或上架 100 个扩展**。既有 [84 条 OPP 唯一机会记录](opportunity-register.json)、[R8 188 能力账本](../browser-automation-feature-catalog-r8.zh-CN.md)、[E01–E40](../browser-automation-r8-implementation-plan.zh-CN.md) 不复制、不重编号。

## 一、五个产业域，二十个功能领域

```text
电商工具宇宙
├─ A 消费者：搜商品 → 比价 → 优惠 → 下单决策 → 收货/售后
├─ B 卖家与店铺：选品 → 上架 → 商品资料 → 定价 → 库存 → 履约 → 客服
├─ C 品牌与增长：广告投放 → SEO/内容 → 客户会员 → 多店运营 → 报表
├─ D 供应链与合规：采购/B2B → 仓储与跨境 → 风险/税费/条款
└─ E 生态参与者：联盟/内容作者 → 运营服务商 → 开发者/官方平台 API
   每个场景交叉：用户角色 × 网站平台 × 地区法规 × 数据来源 × 付费者
                 × 现有 Core/SDK 能力 × 产品分发方式 × 维护风险
```

## 二、目标市场与平台研究矩阵

- 购买者：B2C、跨境购物、家庭/专业采购。卖家：独立站 DTC、平台卖家、中小/大型团队、代运营、批发商。品牌/服务商：广告代理、内容/联盟、物流与企业 SaaS。
- 备选研究平台：Shopify、WooCommerce、Amazon Seller Central、eBay、Etsy、Walmart Marketplace、TikTok Shop、AliExpress、Temu、Rakuten、Mercado Libre、Shopee、Lazada、淘宝/天猫、京东、拼多多等。**列为候选并不表示有 API 授权、已经支持或允许抓取。**
- 地区分别看中国、日本、北美、欧洲、东南亚、拉美，不把某国购物税、产品合规或卖家规则复制到全球。
- 数据源优先级：商家自有/官方经授权 API → 获得许可的第三方数据 → 用户明确操作可访问网页的有限字段 → 来源不明 **BLOCKED**。
- 初核官方 API 入口（2026-10-12）：[Shopify Admin GraphQL](https://shopify.dev/docs/api/admin-graphql/latest)、[Amazon SP-API](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview)、[eBay Sell Inventory](https://developer.ebay.com/api-docs/sell/inventory/overview.html)。需逐平台核查 OAuth/角色/速率/用户许可及产品业务条款。

## 三、映射现有 OpenDesk 产品机会

- 既有消费端 OPP-008 至 OPP-014：历史价格、跨店比价、到手价、优惠码、降价提醒、清单、商家透明度。
- 既有卖家端 OPP-015 至 OPP-021：Listing 完整性、SKU 导出、竞品提醒、毛利试算、客服模板、商品信息一致性、运营台。
- 可复用交叉机会包括 OPP-078（用户授权表格整理与导出）、OPP-080（报表时点快照）、OPP-081（口径核对），以及现有 Page、Storage、Browser SDK 和工具市场等**待核验实际实现能力**。
- 既有实验 EXP-005 卖家 Listing 与 EXP-007 到手价应优先进行**商业研究**。后续正式立项/新增 OPP 时查重，不要把行业分类或一个站点改名生成重复产品记录。
- 既有 QA 工程测试样品不等于付费产品，见 [最新商业决策](commercial-decision-ecommerce-20261012.zh-CN.md)。

## 四、四种产品形态的选择

| 类别 | 适合的任务 | 例子 | 上线前硬门 |
| --- | --- | --- | --- |
| A：OpenDesk Tool | 多网站通用、用户点击即完成 | 到手价试算、合法 CSV 导出、毛利计算器 | 独立沙箱权限、数据留存 |
| C：UserScript | 指定网站的局部流程增强 | 卖家后台 Listing 清单、字段提示、手动价格核验 | 网站版本、同意、更新回滚 |
| B：独立扩展 | 明确独立用途、品牌、持续用户工作流 | 某类卖家运营套件、专业购物决策产品 | 独立市场需求、最小 Manifest、CWS |
| SaaS/API | 多用户、稳定历史数据、后台同步/计算 | 可靠价格历史、库存订阅、跨店对账 | 数据许可、服务器成本、OAuth、隐私 |

不要为了提升“插件数量”发布仅改名和配色的多个同质扩展；每款产品必须能清楚解释单一用户价值与差异。参考 [CWS 重复内容政策](https://developer.chrome.com/docs/webstore/program-policies/spam-faq/)。

## 五、建议优先验证的具体任务（均为假设）

| MVP 切片 | 付费方 | 可实测的单一任务 | 主要风险 |
| --- | --- | --- | --- |
| Seller Listing + SKU QA | 卖家、运营主管 | 开店后台只读检查→高亮问题→导出表格 | 店铺条款、DOM 变化 |
| Seller 毛利与费用核对 | 店主/财务 | 用户输入/授权读取费用→计算利润→导出假设 | 费用实时性与错误成本 |
| 商家客服模板与辅助填表 | 客服团队 | 用户选择模板→预览→确认填表 | 隐私与误发 |
| 授权表格数据工作流 | 运营/采购分析 | 用户选择合法表格→字段转换→导出 | 数据权限与可维护性 |
| 购物到手价与规格比较 | 消费者 | 当前商品→透明费用/规格→清单 | 价源、税费、同款识别 |
| 优惠券真实利益验证 | 消费者/联盟 | 用户点击后验证有效优惠，透明披露 | 联盟政策、虚假优惠、信任 |

优先研究有明确采购预算、重复工作流的 B2B 卖家产品，同时研究 B2C 购物工具的流量、合法数据源与获客成本。现有没有真实访谈、订单、留存；不宣称“谁最赚钱”。

## 六、长期研究和审查要求

1. 从“岗位→常做什么→哪里费时/易出错→当前替代品→谁支付→数据在哪里”挖掘任务，不以插件功能名称代替用户问题。
2. 每类比较竞品官网、商店、收费、免费替代、用户反馈与维护记录，注明网页 URL、核查日期、证据等级和地区；不能编造安装量、收入、转化或用户评论。
3. 定义小范围 MVP：1 个核心动作、1–2 个合法授权网站、5–10 个实际用户测试目标、至少两个自然任务周期的重复使用观察，并区分口头意愿、签单与实际收款。
4. 每条机会独立评估痛点、频率、付费方、竞争替代、复用、数据许可、安全、CWS、网站维护和单位经济；不足处保留 UNKNOWN，不为凑评分升至 95。
5. [商业实验](commercial-experiments.json) 唯一记录买方/付款证据；[机会表](opportunity-register.json) 唯一记录机会，不另建竞争主账本。
6. 按 GO/PIVOT/STOP 筛选 3 个 MVP 后才考虑独立打包；商业可行性与技术测试分别验收。

## 七、合规硬门

- CWS [单一用途/质量](https://developer.chrome.com/docs/webstore/program-policies/quality-guidelines-faq/) 和 [禁止重复上架](https://developer.chrome.com/docs/webstore/program-policies/spam-faq/)。
- [联盟营销](https://developer.chrome.com/docs/webstore/program-policies/affiliate-ads)：链接、优惠码、Cookie 的推广用途必须明确披露、用户相关主动操作与真实直接利益；**禁止静默替换或没有优惠仍加联盟标识**。
- 不绕过登录、CAPTCHA、付费墙、反爬/配额；不得未经授权获取第三方订单、客户 PII 或店铺数据。
- 任何发布、改价、群发、退款等有影响写操作必须另获授权、逐项预览/确认/可审计；公开文档不含账号密钥和原始客户数据。
- 实时价、利润、税率、库存必须有数据来源与时间戳；没有就只标“示例/估算”，不可冒充真实。
- 未实际运行、未访谈、未成交、未获商店批准始终分别写 NOT_TESTED / NOT_MEASURED / NOT_APPROVED。

## 九、X 维度：跨行业高商业价值用户 × 数据工作流（2026-10-12 增量）

**研究接受、商业优先级未验证。** 创作者、带货机构、品牌投放团队与多客户代理商属于可研究的高价值用户群；但**粉丝/流量不等于净收入、预算与愿意付费**。跨行业机会应按用户可合法访问的后台数据、重复决策、财务/工时损失、现有免费工具替代、付费决策人和维护成本判断，不自动升级为 MVP 或独立 Chrome 扩展。

已核查 YouTube Studio 高级报告导出、TikTok Shop 菲律宾 Creator Center 佣金导出与结算口径、Shopify Collabs 佣金/销售及商家报表导出；这些也构成强大的**官方免费替代反证**。优先研究跨结算周期差异、商单交付证明、机构的多客户对账等任务，不把普通播放量看板、粉丝导出或静默采集作为商业候选。

详见 [X 维度研究与反证](high-value-audience-creator-analytics-x-dimension-r2-20261012.zh-CN.md)；独立下一轮研究任务见 [X 维度 R3 GOAL](../../framework/prompts/goal-high-value-user-workflow-research-r3-20261012.zh-CN.md)。复用 OPP-015～021、OPP-078/080/081/083 等已有机会，不新建平行总账；所有人群高频及付费结论仍是 HYPOTHESIS。
