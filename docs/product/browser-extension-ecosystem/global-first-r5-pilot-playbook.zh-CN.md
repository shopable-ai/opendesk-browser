## 为什么不要把 20 个候选一起开发

浏览器插件和 AI Agent 的功能很容易做得越来越多，却难以确定哪个用户会真正安装。OpenDesk 的优势必须表现为有人**自愿在自己的合法网页重复使用**，而不是“我们能写更多代码”。

同一阶段建议仅在**实际有权限与产品资源**的前提下竞争五条短任务：一个企业、一个卖家、一个研究、一个网站 QA、一个客服。它们属于不同客群，不能将五组小样本加起来宣布“中国第一、全球第一”。客户愿为减少错误和返工而付费，与用户愿意安装免费脚本也不是同一个问题。

## 五个验证包（不是五个新插件）

### 1. 企业表单授权重复操作 · OPP-059 EXP-001

**谁会使用/决策**：内部运营/流程负责人。**必须合法使用的网站**：企业明确批准的模拟/内网测试页。

**演示一定从用户的真实问题开始**：在个人获授权的后台执行非支付/不可逆的表单检查；后续可重复同一个固定 Task

**最强对照**：Microsoft Power Automate Desktop + 企业 IT 原生自动化。不能为了突出 OpenDesk 而禁止用户用现成软件、模板或内置工具。

**真实访谈需要确认**：每次检查多少分钟、发生过哪些误输入、是否真有每周重复。

**隐私与技术硬边界**：高：员工权限/PII/审计; 真实页面不得自动提交关键业务。

**首个可以反驳的实物**：同包原 Task Installed、模型断开 Run×2 和人工许可/撤权回执。

**现状**：还未访谈、没有付费订单、没有真实 Mac 同包安装验收。状态 `RESEARCH_ONLY`；这是预登记探索而不是已经开始的试点。

## 客户流程：招募 → 首次成功 → 二次自然复用 → 真实竞争对比

1. **招聘真实性**：优先针对一个可合法公开的任务找至少 5 名愿意参加探索的用户，每位都说明自己近两次如何手工完成。**5 人是探索样本建议，不具统计代表性，也不构成“95分”“全球第一”的证明**。记录自身产品类型、任务频率、实际替代工具/价格，不收集不必要的账号、密码、Cookie。
2. **合法权益/数据范围**：用户在自己或被明确授权的真实/模拟网页操作。涉及卖家后台、客户/招聘数据、财务金额时以合成样本先验；商业账号真实数据需单独授权和可撤回原则，测试记录去敏，不远传敏感明细。对方的私人网站不可因技术上能访问就视为合法。
3. **第一次使用全成本**：从安装扩展/配对所需 Native/Node 开始计时，不为“快”去掉前置步骤。展示具体源码、网站权限和用户动作；验证/安装未完成就是 INCOMPLETE，不能把“AI 生成草稿”登记成功。
4. **真实结果正确性**：以用户预先确认的标准判对错；保存实际错误、回执、页面影响/模型费用、首次耗时。对于高风险按钮/付款/对外发送，默认只生成待确认草稿，真实提交仍由人控制。
5. **第二次自然重复**：同一用户下一周期**自己再次遇到需求并主动点击同一固定版本**，才算自然复用。创始人/AI 反复演示不算“7日留存”；记录第一次和第二次间隔、主动触发、是否调用 AI、Site 权限是否变化。建议 14 日观察窗仅是招募计划，不是实测事实。
6. **最强替代方案**：在同样环境、允许用户选择自己熟悉的 Axiom、ScriptCat、Text Blaze、ERP、Readwise、DevTools、UiPath 等；量实际用时、正确性及人力维护成本。对手不适用记 NOT_EQUIVALENT，无法测记 NOT_TESTED，不记录虚假的竞品失败。
7. **决定投资或退出**：能测出重复工作频率、被采用、实际错误/成本改善、足够真实客户支持后再立项相应 OPP；若只提供“第一次感觉有趣”，维持 RESEARCH；平台原生按钮比插件更好则记录 STOP；高风险数据许可未知则 BLOCKED。

## 五个用户可接受的产品方案，分别如何胜出

| 方案 | 用户能直接看到 | 胜出的真实条件 | 最强失败反例 | 适合渠道 |
| --- | --- | --- | --- | --- |
| AI 创作 → 固定安装 → 无模型复用 | 一句需求后审核来源、权限、结果，以后直接点「我的任务」 | 相同任务下更低的 20 次真实总成本 / 更可解释的审批 | Chrome Skills/Claude/Axiom 已有保存/录制/导入 | 官方 Chrome/开发者内容/AI 社群（验证后） |
| 受控企业操作按钮 | 某个合法内部页面中少量按钮、可见动作与失败结果 | 管理者批准且 IT 维护成本低于现有 RPA | Power Automate/UIPath 就能完成 | 受邀企业私有交付、实施伙伴 |
| 卖家 Listing QA | 页面字段检查清单与待人工复核项 | 比 ERP/平台原生更少遗漏或返工，且合规 | Shopify/Amazon 内建质量检查足够 | 卖家社区、合规商家试点 |
| 来源证据/合规 | 一键保留可回溯来源、变更审阅与误差说明 | 与 Readwise/Glasp/浏览器书签相比自然找回更成功 | 现有知识工具已经可靠且免费 | 研究和创作者社群 |
| 网站发布前 SEO/质量检查 | 自有网站 meta/schema/链接问题原位提示 | 在真实上线 QA 中缩短诊断且减少误报 | DevTools、Rich Results、Requestly 已更快 | 搜索/站长/SEO 开发内容 |

这些是**可检验竞争条件，不是已经测到胜出**；目标用户和行业差异说明了为什么不能把一条固定流程推广为所有网页通用最快或第一。

## 实际销售和安装漏斗的区别

- **发现（Find）**：Google/Bing/视频/社区来源和用户真实问题; SEO/GEO 页未部署仍不能算 Search 引荐。
- **尝试（Try）**：进入合法演示、明确权限、当前能够下载/运行的固定产品包；GitHub 研究文档不可当成 Chrome Web Store 下载。
- **第一次成功（Activate）**：不靠工程师按键/解释，真实用户完成结果，并知道失败如何处理。
- **第二次自愿使用（Retain）**：该用户因为真实任务重复回到 OpenDesk；此前的创造者 demo 循环不得混入。
- **愿付（Pay）**：谁实际支付、维护包条件、金额与支付/合同证据；问卷“愿意付”不代表收款。
- **复购/维护（Renew）**：网站版本变化后仍可验收固定版本和重新审批；人工维护成本须计入服务经济性。

## 先开发哪个？实际决策树

**产品目前没有真实 AI→Installed→关闭模型两次运行** → 先让原 AI/Task 负责人关闭这一共享基础门，行业交付只准备合规测试数据，防止同时开发5套互不兼容安装器。

**已有可信安装但用户首次不会使用** → 先优化一个最短合法用户体验：明确状态、权限、失败恢复和“我的”复用按钮；不用大规模重做 Side Panel。页面窄屏和实际 Chrome 原生检查仍要遵守统一设计规范。

**已有首次成功、自然第二次复用差** → 找具体导致用户不用的原因（浏览器权限复杂、网站改版、结果不准、已有软件更好、模型费用），按单项证据修复或 STOP，不开发第84个功能。

**自然复用成立但没有订单** → 面向真正有预算的人测试企业私有维护/卖家专业工具的采购逻辑，不从工程师的喜好臆造高额定价或 SaaS 用户规模。

**用户和收入成立** → 再争具体范围第一：同版竞争测试、国家/语言渠道、可合法推广的产品包、外部独立审核与证据账本全部闭环后，才可修改 GF 的公开声明状态。

## 最值得保留的结束条件

只要没有同时满足真实技术闭环、用户自然复用、最强竞品的公平对照和公开产品渠道，就**不为了宣传“第一”继续堆叠伪差异**。当前阶段的目标是找到**可能有真实用户和转化的可检验优势**，而不是制造大量候选口号。

当前真实结果：5 个 pilot 方案已形成**预注册研究合同**，实际开始用户访谈 / 用户付款 / 用户 Mac 同包原生运行、地区第一宣称均 **NOT_TESTED / NOT_MEASURED / NOT_APPROVED**。
