## 一、核心战略：从安装目录到开发者商业生态

OpenDesk 的方向是让开发者**开发、审核发布、分发、销售**可安装工具，并按真实商业贡献持续获得收益。平台通过分发、会员、授权管理和企业服务获得可持续收入；不将开发者一次性发码收费视为唯一商业模式。

| 产品能力 | 谁使用 | 承担的价值和商业模式 |
| --- | --- | --- |
| **OpenDesk Market** | 用户与开发者 | 发现、真实审阅安装、更新、展示作者与商品；免费和独立付费并存，按实际提供的交易/分发服务收费 |
| **OpenDesk Pass** | 终端会员 | 一次订阅，使用**自愿加入计划**的各个工具所声明的会员权益；开发者参与可核验的会员收益池 |
| **OpenDesk Creator** | 扩展/教程/工作流创作者 | 合法引流首次付费奖励、有效持续贡献分成、用户自愿支持；需归因与防作弊 |
| **OpenDesk License** | 独立销售的开发者 | 激活码、期限/次数/席位、续期/恢复、退款关联、授权审计及合法站外订单接入；可另收 SaaS 服务费 |

这四者是**同一平台的产品能力，而非四套 SDK、四个 Host 或四个后台权益权威**。OpenDesk 内 Sidebar Tool、Page Program、Task 的安装合同不同；内置工具市场不天然等于 Chrome Web Store 独立扩展商店。普通开发者可先免费投稿，后续仅为明确的增值服务或成交费用付费；不因尚未购买高级授权服务而禁止发布合规免费工具。

## 二、共存的盈利路径

| 模式 | 用户或企业购买什么 | 开发者收益 | 平台收入与启动次序 |
| --- | --- | --- | --- |
| 免费应用与开源支持 | 免费功能、可选赞助 | 自愿支持、可能的后续转化 | 优先建立安全且有价值的供给；安装量不是收入 |
| **独立付费扩展** | 单工具 Pro、期限或指定版本许可 | 由实际销售主体依合同取得销售收入 | 平台仅为自身提供的交易/分发服务按明示规则收费；**先试点** |
| **站外销售+授权** | 在开发者官网、电商、经销渠道购买工具 | 开发者自行收款、履约 | 可选 License 服务费；站外成交**不默认抽成**；**先试点** |
| **Pass 收益池** | 一组经声明的会员功能 | 参与作者分得可核验收益 | 平台按公开的净额分配规则留取份额；**稍后小规模试点** |
| **首次付费奖励** | 用户经扩展、教程等真实入口首次付费 | 有资格的作者获一次性转化奖励 | 由明确的获客预算/平台份额承担；随真实付费验证 |
| 团队/企业套餐 | 组织席位、集中配置、部署与支持 | 开发者按企业合同/工具销售结算 | 平台管理、集成和维护收入；有买方再做 |
| 工作流/模板/组合包 | 审核后可实际使用的自动化方案 | 按固定作者归属或先约定的组合分成 | 发布/交易服务费；不把模型脚本当自动特权 |
| AI/Cloud 资源包 | 有单位与上限的云任务/AI 用量 | 提供合法服务的供应商/开发者收入 | 资源成本与计量可控后再启动 |

其余已有商业方向（企业定制、工具链、站点适配、可选赞助等）继续由 [R2 研究](browser-extension-ecosystem/monetization-unit-economics.zh-CN.md)维护，不在此复制第二张机会账本。**禁止**销售私人浏览数据、静默插入广告/联盟 Cookie、刷点击分成或以付费绕开用户权限。

## 三、五种商品权益必须清楚区分

1. **Free**：工具免费功能，不需要市场付费账号即可浏览，既有实际安装授权规则不变。
2. **Pass**：仅对**主动参与计划**的工具开通约定的功能；会员不自动获得所有独立 Pro、第三方付费会员或无限 AI/云资源。
3. **工具独立 Pro**：某开发者、某 SKU、某账号或组织的明确期限/版本/功能许可；商品指定且仅有一个**权益权威写入源**。
4. **资源额度**：有真实上游成本的调用次数/计算量/云服务，需明确消耗、失败返还与有效期。
5. **Business**：团队席位、企业集中管理、审计、SLA 或按合同的部署支持。

开发者可把一部分功能加入 Pass，同时保留独立 Pro 和按量资源包；**参与与退出规则须事先披露并保护已售权益**。商品应明确销售方、币种、计价单位、时效起算、设备/席位、续期、退款、离线和售后。时间类商品不能把自然月强行等于 30 天。

**OpenDesk Pass ≠ AI VIP Share 自有会员 ≠ 第三方 AI 订阅。** `ai-vip-share` 的合法 SKU、会员、激活码、兑换记录及代理管理属于工具业务；除非未来经正式商品合同及用户确认加入 Pass，否则不能互相继承权益，也不能兑换后自动安装应用、读取 Cookie、启用代理或获得浏览器权限。

## 四、Creator 分配规则：先分清获客、留存、收益

### 4.1 一次性首次转化奖励

用户通过某个工具付费入口、教程/作者推荐链接首次成为符合条件的付费会员时，可对可核验来源给予一次奖励。需明确**归因窗口、首次资格、重叠归因、反自推/刷单、观察期、退款追回和申诉**。教程创作者与工具作者可以按已披露规则分配一次获客预算。**首次开通的作者不能永久占有该用户后续的全部订阅收入。**

仅点击链接、打开激活页面、网页跳转成功均不能证明支付成功。禁止擅自改写其他推广链接、浏览器 Cookie 或秘密添加归因参数。

### 4.2 持续有效使用贡献

对于自愿加入 Pass 的工具，按**可解释且难以刷量的有效贡献**参与会员池，而非简单后台运行时长、按钮点击数、页面浏览次数。可研究实际任务成果、在已告知的范围内去重的有效使用、留存及用户主动支持。不能收集私人会话、网页正文、浏览历史、Cookie 或第三方账号内容来计算收益；未经核验的客户端自报不能成为唯一权威。

### 4.3 会员主动支持

会员可自愿指定部分支持对象，允许免费或开源工具的作者参与贡献，赞助与商品购买/订阅的付款性质必须清楚区分。

### 4.4 分成基数与提案数值

先确定该交易的销售主体、已收款金额、适用税费、退款/拒付、支付费用、必要可变资源成本和约定准备金，再确认该合同的**可分配净额**。订单总额、开发者应付款、平台真正收入、未结算资金不能合为一项 MRR。

| 数值 | 仅为研究假设（不得上线硬编码） |
| --- | --- |
| 开发者收益池 40% / 平台 60% | 假如某账期扣除约定项目后可分配净额为 8 美元，则分别为 3.20 / 4.80 美元；实际比例待验证 |
| 首次付费奖励 10% | 假定该 8 美元的 10% 为 0.80 美元，由平台**获客预算/平台份额**承担，不再无说明地扣开发者收益池 |
| 独立市场交易开发者获得 85%—90% | 仅为可测试的谈判范围，须先确认平台服务、销售主体、实际支付费用、退单成本与合同 |
| License 基础订阅+管理规模 | 按受管理权益/席位等可复核单位计费，不按随机字符串数量无限收费；定价未决 |

这些数值标记为 **`PRICING_HYPOTHESIS / NOT_APPROVED`**，不是承诺价格或已实施结算规则。反刷量、账单审计、退款冲回、争议准备金、开发者申诉和不可重复结算必须在真正自动分账之前落实。

## 五、全球销售与激活：统一权益交付，不强制平台统一收款

允许三条授权路径复用同一业务语义，而非三套 SDK：

- **A 托管激活码（首期）**：开发者定义 SKU → 自己合规销售 → 用户输入码或打开短效单次激活 ticket → 服务端预检商品、接收账号、有效期 → 用户明确确认 → 服务端原子幂等兑换和真实回执。未知结果先查记录，不盲目重复消费。
- **B 付款自动开通（下一步）**：销售方的服务器验证真实支付回执或主动核查订单后，为指定账号/组织开通权益；浏览器购买成功回跳不具备付款权威。
- **C 开发者自有 License Provider（后续）**：受审核的开发者授权后台提供状态；**每一项权益只有一个权威写入方**，标准化是接口/状态语义，不是复制另一份可相互覆盖的授权账本。

站外销售解决不同地区的**交易渠道选择**，不免除销售方及其合作方对商品履约、销售资格、税务、退款与争议的责任。平台向开发者销售 License 服务与平台为终端用户销售商品属于**不同交易**。支付服务的跨境收款能力不自动代表可以替所有开发者代收、入驻、全球分账；真正做 Marketplace 需额外审批交易主体、KYC、结算国家与支付合同。软件授权码不天然等于储值礼品卡，应按实质商品、服务与地区规则审查。

License 可测试“月度/年度基础费+包括的有效授权对象/席位+可复核超额”或“明确期限的授权管理服务包”。开发者停止续费后必须依已公布条款履行**已售/未兑换权益、保障期限、数据导出、迁移与退款售后**；不能突然让终端用户丢失合法购买，也不能无限期承诺无成本托管。

## 六、身份、订单、安装与权限的唯一权威

| 事实 | 权威及隔离规则 |
| --- | --- |
| Publisher / 市场发行 | 唯一作者、市场 `marketId`、固定包版本/Hash 和审核状态；仍使用现有可信 Catalog 和发行/安装合同 |
| SKU / Offer | 商品、销售方、许可范围、币种、参与 Pass 意愿及购买外链；由经审核的商业 Provider 提供 |
| Order / Payment | 可核验的销售服务/支付回执、退款及拒付；客户端 `paid=true` 永远不能作权威 |
| Account / Organization | 用户或企业商业身份、成员和席位；不以 Chrome Extension ID 或设备指纹代替 |
| Entitlement | 商品 × 所属账号/组织 × 时效/额度/版本；由该商品唯一指定的业务 Provider 权威处理 |
| Redemption | 脱敏码、幂等键、消费状态、实际回执；断线未知不伪报成功 |
| Attribution / Settlement | 可归因获客事件、有效账期贡献、分成/冲回/结算记录；不应与安装或会员真假混用 |
| Installation / Permission | 真实的宿主安装身份、用户授权、Chrome API 状态和撤权；**收费不赋予权限** |

以上是领域概念，**不是本轮新增 Schema、数据库、API 名或 SDK 契约**。开发者身份/发行与商业权益不能重复创造当前已经存在的安装事实数据库。研究实验继续使用现有 `commercial-experiments.json`/机会唯一账本；未来真实交易/结算数据属于必要的业务账本，不能误写入实验台账冒充交易。

工程边界：`src/` 只保留平台通用 SDK、可信 Host/Authority/Dispatcher/安装权限生命周期；各工具会员/商品 UI 与合法 Provider 适配属于 `examples/sidebar-tools/<id>/`，业务后端按合法交易合同提供真实订单与权益。市场目录只提供可信发行与安装入口，不建第二套 Installer、Runner、Host 或授权系统。AI VIP Share 保留已确认的外部商品链接与自身兑换流程，不因为平台商业讨论新增其内部购物车、支付弹窗、代理自动启用或 Cookie 额外权限。

## 七、风险、透明度与全球合规

- **支付/身份**：明确用户实际向谁付款、谁开票/收据、谁负责退款、支持哪个国家的买家和开发者；服务商费率必须注明核查日期和适用场景，不将零售 MoR 误当多商户分账资格。
- **隐私**：收益指标使用必要的低侵入数据；不为商业目的上传浏览内容或私人会话；安装用户无需为了浏览免费目录被强制注册。
- **可信软件**：作者验证不等于代码安全审计；远程授权仅返回受约束的业务数据，不能远程执行 JS；付费、兑换、续期不能跳过 Chrome 的权限审阅、真实用户操作或撤权。
- **运营**：审计、异常归因、作弊、退款冲回、开发者欠费/退出、平台停运迁移及争议处理必须可说明；首期没有这些能力时不得展示“已分成”“已结算”假状态。
- **平台政策**：在真实发售前逐一核验 Chrome Web Store 的收费、有限使用、MV3 远程代码与联盟营销政策，以及商品类别/第三方转售许可。不得用积分、卡密等名称规避其实际金融或商品性质。

## 八、分阶段落地及停止条件

| 阶段 | 唯一最小成果 | 验证门槛与未覆盖状态 |
| --- | --- | --- |
| **S0：商业设计落库（本轮）** | 本文和现有文档交叉引用，明确边界、价格待定项 | **DOCS_ONLY**：支付、会员池、分账、生产 Provider、Chrome 支付闭环 `NOT_TESTED` |
| **S1：一个官方真实付费商品** | 外部合规交易 → 确认订单 → 账号/时效授权或激活 → 到期/退款/离线与重复请求结果对账 | 假订单与本地 UI 不能计 `PAID_VALIDATED`；必须保留真实交易与权限证据 |
| **S2：3—5 个真实开发者试点** | 合规审核发行、自有渠道销售、透明 License 计费、入驻与实际支持 | 验证接入时间、用户付费意愿、售后和成本；不是仅演示发布按钮 |
| **S3：自愿加入 Pass 的小范围试点** | 正式列出所含权益、收益池的预算上限、归因和反作弊、开发者可查账单 | 核实留存、净收益、隐私与可解释贡献，再决定自动结算 |
| **S4：企业及高级市场服务** | 需求确认后加入席位、工作流组合、资源包、必要的真实多商户结算 | 收款/入驻/国家资格和争议机制具备后才能扩大规模 |

单位经济沿用 [现有 R2 指标](browser-extension-ecosystem/monetization-unit-economics.zh-CN.md)：真实已付费留存、获客成本、贡献毛利、退款/争议、作者参与与结算差异。延续既有 [商业实验与机会唯一账本](browser-extension-ecosystem/README.zh-CN.md)，新实验先去重，不设第二套平行 EXP/OPP。未获得真实客户或交易证据时标记 `NOT_MEASURED` / `NOT_TESTED`，不拿专家评分替代市场验证。

## 九、必须独立确认的决策

1. 哪个法人/销售主体出售平台服务，是否以及何时允许平台代售第三方商品；实际商户准入、支付和税务范围。
2. Pass 的价格、参与工具、资源额度、开发者自愿退出和售后保障。
3. 获客归因窗口、奖励预算、会员贡献权重、退款冲回与反作弊口径。
4. 独立交易佣金、License 的价格和用量计费规则、开发者迁移保障期限。
5. 公共市场在线作者身份/上传/发布托管/商品后台/支付/结算的真正权威及 API 合同。

**本轮不是商业功能实施授权：仅落库规划，不修改正式运行时、扩展业务代码、支付基础设施或真实 Provider，也不对外宣称正式价格和分成方案已生效。**
