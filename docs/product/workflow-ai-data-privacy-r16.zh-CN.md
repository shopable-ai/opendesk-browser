# OpenDesk Browser 工作流 · 自带 AI 模型直接使用原则

> 2026-10-13 更新：本文件取代 R16/R16.1 的「首次同意、180 天授权、撤回按钮、确认卡」设计。**项目未上线，这套额外模型授权交互已取消**。需要新的服务或法定义务时再按真实场景设计，不提前实现。

## 当前用户流程

用户在「工作流」输入需求，选用自己已连接的 Codex 或自行配置的 HTTPS 模型，**点击发送箭头直接生成工作流建议**。不出现默认勾选、首次同意、二次确认、授权有效期、撤销许可按钮或常驻数据发送说明。更改模型或输入后同样直接使用，不创建独立 consent store。

- 本机 Codex 通过已连接的 OpenDesk Native Agent 调用用户自己的 Codex，推理可能使用网络。
- 自定义 HTTPS 通过用户填写的地址和 API Key 直接请求选定模型，不通过当前尚未开放的 OpenDesk 官方 AI 服务。
- 手动编辑与已保存任务重复运行不依赖模型调用。
- 实际的 Chrome `permissions.request`、Native Messaging 准入及真实网页/文档身份复验**不可绕过**。若 Codex 要把当前网页结构/文字摘要发送给模型，仍按已存在的单独读取授权执行；该能力与普通文本生成不同。
- 发送模型的规划输入仍进行最小化：移除原填写文字、参数默认值和导航 URL 查询参数；AI 建议保留人类审阅并采用步骤，绝不自动执行、安装或放大权限。

## 为什么不建立额外授权层

当前没有上线的 OpenDesk 官方 AI 中转服务或额外合作模型数据处理链。用户主动选择模型、输入需求并点击生成即可表达使用意图；再加入独立的「同意并生成」二次流程会增加噪声，却不替代真实 Chrome 权限或服务商条款。

**这不是 OpenDesk 的免责结论。** 开发者仍需确保实际数据流、安全边界和适用的平台/法律要求；若将来启用官方托管 API、增加自动上传网页内容、统计收集或跨境业务，应核查并补充相应的告知/授权机制。不要根据地区 IP 提前为开发期用户增加许可弹窗。
