# 普通用户指南：开发与更新 OpenDesk 扩展应用

这是一份**普通用户使用说明**。你要开发或更新的是 OpenDesk 里面的「扩展」应用，不是重新编译 Chrome 的 OpenDesk Browser 插件本体。

## 你只需做什么

**新建扩展应用**：在对话中描述要实现的功能 → 查看 AI 提供的真实同源交互预览 → 反馈修改 → 确认准备安装 → 打开 OpenDesk「扩展」，审阅并确认安装 → 打开应用验证。

**修改已有扩展应用**：例如说「把阅读目录顶部四个切换按钮改好，并更新我已有的阅读目录」→ AI 在原项目修复、定向测试、准备新的同 ID 版本 → 用户在「扩展」里审阅并确认更新 → 重新打开应用、验证功能与原来的数据。**不需要先卸载，不用重新安装 Chrome 插件。**

在「开发」中修改 Controller/Page 草稿时，先试运行/预览；要永久安装为「网页增强」时走其原有发布与网站许可流程，**不是导入 Sidebar App 的 JSON**。

## 想自己改代码并马上看界面

在已连接的本地项目中，AI 先启动或确认应用编译与预览监听，帮你用 VS Code 打开关键 UI 文件。你修改一处标签文字并保存，OpenDesk 原侧栏收到成功快照后更新；不需要每次安装/升级，也没有第二次“批准隔离存储调试”。有未保存的应用内容时，界面会等待你保存或结束编辑。

这适合你与 AI 一起改自己的应用。具体可从 [Quick Notes React 的手动步骤](../../examples/sidebar-tools/quick-notes-react/README.md#现在手动试改一个字符就看到界面变化)开始；[更新原理与工具链现状](../api/sidebar-tool-development.zh-CN.md#保存以后为什么会更新)解释了编译、预览和 SDK 的分工。

**普通用户无需 Browser 源码来安装/运行应用，但目前仅安装 OpenDesk 还不足以获得完整的本地 React 连续开发工具。** 当前示例的编译/预览/打包命令仍有仓库依赖。将它们作为可独立使用的官方开发工具交付，是接下来需要完善的部分；不能把维护者现有的仓库环境当成普通用户已经具备的能力。修改 Browser 内置共享组件则另属维护者工作。

## 如何知道是否真的更新成功

1. AI 交付时说明：应用名称和 ID、旧版本、新版本、权限是否变化、正式安装文件、尚未验证的步骤。
2. 在 OpenDesk「扩展」中选择 **导入本地工具包**，检查应用 ID 和新版本，审阅能力变化并点击 **确认安装/更新**。官方候选已在当前 Browser 内时，也可使用已有官方更新入口。
3. 再次打开应用，确认功能、安装版本与原有数据。对于网页注入功能，还应刷新对应网页，确认真实行为。
4. **生成 JSON、CI 通过、看到新版候选 ≠ 安装成功**。未实测时状态写 `INSTALLED_CHROME_NOT_TESTED`；安装失败或结果未知保留旧数据并经原恢复入口核对，不能盲目重装。

## 谁来操作命令

正常用户只需描述需求与确认安装。AI/Codex 在本地项目内部可以执行：

```bash
npm run app:update -- reading-toc --check   # 只查当前应用包状态
npm run app:update -- reading-toc           # 检查、必要时提升 PATCH、测试、准备唯一正式包
```

第二条命令**不直接控制或自动授权 Chrome**，不会卸载用户应用；它会输出待导入的真实文件位置、版本与摘要，安装依然由 OpenDesk 原有可信界面确认。复杂 React/Vue UI 的编译先使用该应用已经有的构建入口，不能用旧 `dist/build-ready.json` 冒充新源码。

## 为什么有时还需要管理员

如「阅读目录」的侧栏 UI 属于可独立更新的应用包，但网页上的悬浮目录控制器（`trusted/`）会静态编译进 OpenDesk Browser。**仅改/安装应用 JSON 无法替换这些可信脚本**。遇到这种情况，AI 应告知「本次还涉及 Browser 内置代码，由维护者处理」，用户不必自行执行 WXT、Service Worker、扩展 ID 配对等技术命令。需要管理员实际更新时，参见 [浏览器插件持续开发与部署](../framework/extension-development-r131.zh-CN.md)。

产品边界：普通用户的「扩展」包括「应用（Sidebar Tool）」与「网页增强（Page Program）」，两者共用列表入口但采用不同安装协议；后台服务、扩展框架与原生权限仍由可信宿主管理。
