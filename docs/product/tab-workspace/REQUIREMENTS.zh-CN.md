## 0. 执行结论

### 0.1 产品结论

建议把产品定义为：

**一个以主题为中心、保存网页地址集合、支持持续追加和按需恢复的轻量级临时工作集管理器。**

它管理的是用户主动保存的网页链接及其主题关系，不管理完整浏览器运行会话。

核心对象只有两类：

- **Topic：** 用户创建并持续维护的主题。
- **Tab Entry：** 主题中的一个网页地址记录。

一个主题是一份可持续修改的网页集合。追加页面不会自动产生新快照；删除页面不会影响其他主题中的同一 URL。

### 0.2 产品归属决策

**推荐：在 OpenDesk Browser 中建立独立 Sidebar Tool。**

- 不扩展 Bookmark Manager 的既有业务职责。
- 不新建第二套 Chrome/Edge 扩展宿主。
- 复用 OpenDesk 的 Sidebar、工具安装更新、共享 UI、设计 Token、国际化和可信 Host 体系。
- 保持独立的工具 ID、数据命名空间、需求文档和能力授权。
- 后续正式项目 owner 候选为 projects/tab-workspace/；本轮只保存研究文档，不提前创建正式工具包或源码目录。

### 0.3 立项判断

**内部 OpenDesk 工具：Conditional GO。**

成立条件：产品目标是给 OpenDesk 用户提供统一的主题工作集入口，而不是声称发明了新的标签页管理品类。

**独立商业产品：暂不批准。**

Chrome Saved Tab Groups、Edge Workspaces、OneTab、Session Buddy、Toby、Workona 已覆盖大量核心需求。当前没有证据证明仅凭“主题保存、追加、批量恢复、保存后关闭”就能形成足够的市场差异化。

### 0.4 MVP 收敛结论

MVP 只考虑：

1. 创建、重命名和删除主题。
2. 收集当前标签页、原生多选标签页或当前窗口全部标签页。
3. 保存到新主题或追加到已有主题。
4. 查看主题内页面，移除页面。
5. 打开单页、选中页面或整个主题。
6. 明确确认后执行安全的“保存并关闭”。
7. 本地持久化、重复识别、失败结果展示。
8. 不读取网页正文，不上传 AI 对话内容，不恢复完整运行状态。

多级目录、快照历史、AI 自动分类、跨设备同步、主题分享、完整浏览器会话恢复均不进入 MVP。

### 1.1 当前已验证事实

- 当前仓库分支为 main；本轮审计基于文首记录的 HEAD。
- Bookmark Manager 是正式独立 Sidebar Tool，当前配置版本为 0.3.14。
- 当前 Bookmark Manager 处理 Chrome 原生书签树，不具备本产品所需的通用标签页工作集业务能力。
- 根 Manifest 已包含 storage、tabs、unlimitedStorage 等权限；incognito 为 not_allowed。
- OpenDesk 普通 Sidebar Tool 的现有 storage.local 合同为每工具最多 32 个键、总计 32 KB、单项 8 KB。
- 当前公开 browser.tabs SDK 主要提供工具自身创建标签页的受限操作，不能让普通工具任意枚举或关闭用户已有标签页。
- Chrome 原生多选标签页可通过 tabs API 的 highlighted 状态读取。
- Chrome 本地存储、同步存储、MV3 Service Worker 生命周期均有官方文档约束。
- Toby 官方文档已明确支持保存当前窗口到已有 Collection，并选择 Save & Close Tabs 或 Save & Keep Tabs Open；固定标签页不会被关闭。

### 1.2 合理推断

- 以 Topic + Tab Entry 作为唯一核心对象，足以覆盖原始目标；没有证据要求完整 Session 或 Snapshot。
- 新产品最适合成为 OpenDesk 独立 Sidebar Tool，而非 Bookmark Manager 的子栏目或完全独立扩展。
- 现有通用 SDK 不足以安全完成任意标签页收集和关闭，需要新增受可信宿主控制的窄能力。
- 现有 32 KB 工具存储合同不足以作为长期工作集数据库。
- 通用标签页收集功能本身已是成熟品类，OpenDesk 内部集成价值高于当前可证明的市场差异化价值。

### 1.3 尚未验证

- 用户真实工作中，每个主题平均包含多少标签页、主题数量和追加频率。
- 是否需要跨窗口一次性收集。
- 是否必须跨设备或跨 Chrome/Edge Profile 同步。
- 用户是否愿意把 Chrome 原生 Tab Groups 作为主题，还是明确需要独立主题目录。
- Edge 原生 Workspaces 与 OpenDesk 工具在真实 Edge 稳定版中的交互兼容性。
- 新增可信 Host 能力与独立持久化服务的完整实现成本。

## 2. 原始问题、根因与产品目标

### 2.1 原始问题

浏览器同时打开大量临时页面，这些页面围绕不同主题、项目或任务形成短期工作上下文。

它们有继续使用的价值，但不适合长期占据标签栏，也不一定值得作为长期收藏夹内容保存。

用户需要：

1. 工作时同时打开多个相关页面。
2. 把这些页面归入一个有名称的主题。
3. 随时追加新页面。
4. 不再需要时安全清理原标签页。
5. 未来按主题重新打开全部或部分页面。
6. 关闭浏览器、重启浏览器或清理标签栏后，仍保留主题和页面关系。

### 2.2 根因

浏览器标签栏承担了三个不同职责：

- 当前正在使用的页面。
- 临时任务上下文。
- 长期保存的网页入口。

这三类对象的生命周期不同。仅依赖标签栏或长期书签，都会让临时工作上下文缺少独立的持久化组织方式。

### 2.3 产品目标

把“临时打开的一组网页”变成“用户主动维护的主题工作集”。

产品成功不以功能数量衡量，而以以下结果衡量：

- 用户能够快速收集一批页面。
- 页面与主题的关系不会因关闭标签页而丢失。
- 追加和恢复不需要重新整理全部页面。
- 保存并关闭不会导致未保存页面丢失。
- 用户能清楚知道哪些页面已保存、哪些未保存、哪些已打开。
- 不需要读取网页正文或获取不必要的站点权限。

### 2.4 非目标

- 不保存完整浏览器会话。
- 不恢复网页表单、滚动位置、页面内存、DOM 或 JavaScript 状态。
- 不管理浏览器 Cookie、账号登录或密码。
- 不替代 Chrome 原生书签。
- 不替代浏览器原生 Tab Groups 或 Edge Workspaces。
- 不在 MVP 中实现 AI 自动理解网页内容。
- 不默认同步、分享或上传用户 URL。

## 3. 产品本质与边界

### 3.1 候选产品类型比较

| 类型 | 与目标的关系 | 决策 |
|---|---|---|
| 标签页收藏管理器 | 只强调保存链接，容易退化为另一个书签工具 | 不采用 |
| 浏览器会话管理器 | 需要保存窗口、标签页和更多运行上下文，范围过大 | 不采用 |
| 标签页工作集管理器 | 以用户主动维护的页面集合为中心 | 采用 |
| 主题目录管理器 | 以主题作为入口，但不必引入多级文件树 | 采用扁平主题列表 |
| 临时工作空间管理器 | 容易让用户误以为能恢复完整页面状态或切换隐藏窗口 | 不采用完整 Workspace 语义 |

### 3.2 核心对象区别

| 对象 | 保存内容 | 是否进入 MVP |
|---|---|---|
| URL | 可重新打开的网页地址 | 是 |
| 标题 | 保存时的标题快照，用于识别 | 是 |
| 网站图标 | 纯展示元数据，可缺省或重新获取 | 非必需 |
| 页面顺序 | 主题内的稳定顺序 | 是 |
| 原浏览器窗口 ID | 仅当前会话有效，不作为长期身份 | 否 |
| 原标签页 ID | 仅用于本次保存/关闭操作 | 不持久化 |
| 原标签页分组 ID | 浏览器会话内标识，不作为主题 ID | 否 |
| 页面运行状态 | 表单、滚动、DOM、内存等 | 否 |
| 浏览器完整会话 | 多窗口及其完整恢复信息 | 否 |
| 时间点快照 | 某次主题状态的历史版本 | 否 |

### 3.3 Topic 与 Snapshot 的关系

采用单一可变主题集合：

- 新建主题后，主题拥有一组 Tab Entry。
- 再次保存时，默认追加到该主题。
- 用户可以删除主题内的某个页面。
- 页面顺序可在后续版本中调整。
- 每次追加不自动生成历史快照。
- 主题的 createdAt、updatedAt 只记录生命周期时间，不代表版本历史。

**否决：主题 + 多快照作为 MVP 数据模型。**

原因：快照会引入版本选择、重复页面、合并、回滚、删除和存储增长问题，而原始目标没有要求恢复主题在某个历史时点的精确状态。

### 4.1 正式项目现状

正式目录：projects/bookmark-manager/

- 配置版本：0.3.14

- 说明：README.zh-CN.md
- 测试配置：app.ci.json
- 证据：evidence/

### 4.2 真实职责

Bookmark Manager 管理 Chrome 原生书签树：

- 读取完整书签树。
- 文件夹层级浏览。
- 书签和文件夹创建、编辑、移动、删除。
- 搜索书签。
- 观察原生书签变化。
- 处理权限撤销、并发变化、草稿、写入失败和结果未知。
- 卸载工具不删除 Chrome 原生书签。

其数据对象是 Chrome Bookmarks API 中的节点和文件夹，不是当前打开的标签页。

### 4.3 不应合并的原因

| 维度 | Bookmark Manager | Tab Topics |
|---|---|---|
| 数据来源 | Chrome 原生书签 | 当前打开的标签页 |
| 生命周期 | 长期收藏 | 临时工作上下文 |
| 核心操作 | 创建、编辑、移动、删除书签 | 收集、追加、恢复、保存并关闭 |
| 组织结构 | 原生书签文件夹树 | 扁平主题集合 |
| 权限 | Full Bookmarks | 受控标签页读取/打开/关闭 |
| 删除语义 | 删除书签节点 | 从主题移除链接或删除主题 |
| 恢复语义 | 打开书签 | 按主题批量重建标签页 |

合并会让同一个 UI 同时承担两套不同的对象模型、权限和危险操作，增加用户理解成本与回归范围。

## 5. 产品归属方案比较

评分仅用于本轮结构决策，按职责清晰、用户理解、入口、数据模型、权限、UI、维护成本和扩展性综合判断，不代表市场调查数据。

| 方案 | 综合参考分 | 决策 |
|---|---:|---|
| A. 在 Bookmark Manager 增加工作集栏目 | 46/100 | 否决 |
| B. 新建完全独立的 Chrome/Edge 扩展 | 64/100 | 不推荐 |
| C. 新建 OpenDesk 独立 Sidebar Tool | 90/100 | 推荐 |

### 5.1 A：扩展 Bookmark Manager

优点：入口统一、可能复用部分书签展示组件。

缺点：

- 书签节点和工作集条目不是同一数据模型。
- 一个面向长期收藏，一个面向临时工作上下文。
- 权限、危险操作和生命周期不同。
- UI 会逐渐变成书签、标签页、会话等多个产品的混合面板。

结论：否决。

### 5.2 B：完全独立扩展

优点：权限、发布、品牌和数据可以独立。

缺点：

- 重复建设宿主、安装更新、UI、国际化和 SDK。
- 与 OpenDesk 的其他工具入口割裂。
- 需要独立维护权限、数据迁移、版本和兼容。
- 对当前只管理 URL 集合的需求来说过重。

结论：不推荐。

### 5.3 C：OpenDesk 独立 Sidebar Tool

优点：

- 产品职责独立。
- 复用 OpenDesk 现有安装、更新、Side Panel 和 UI。
- 可以建立窄而明确的标签页 Host 能力。
- 数据命名空间与 Bookmark Manager 完全分离。
- 后续可以独立演进，但不重复建设第二套浏览器扩展宿主。

结论：推荐。后续正式 owner 候选为 projects/tab-workspace/。

## 6. 竞品与浏览器原生替代方案

### 6.1 能力比较

| 产品 | 主题/集合 | 批量保存 | 保存并关闭 | 追加已有集合 | 选择性恢复 | 其他能力 |
|---|---|---|---|---|---|---|
| Chrome Saved Tab Groups | 原生分组 | 支持 | 关闭分组可保存 | 支持 | 通过分组打开 | 命名、颜色、跨设备同步 |
| Edge Workspaces | 原生工作空间 | 支持 | 保存工作空间 | 支持移动标签页 | 打开工作空间 | 需要 Edge 144+ 与登录 |
| OneTab | 分组、文件夹 | 支持 | 核心工作流 | 可整理和合并 | 支持 | 搜索、分享、加密同步 |
| Session Buddy | Collections | 支持 | 支持清理标签页 | 支持 | 支持 | 重复检测、时间线、备份 |
| Toby | Spaces、Collections | 支持 | 明确支持 | 明确支持 | 支持打开集合 | 固定标签页不关闭、AI 分组 |
| Workona | Spaces | 自动保存 | 关闭 Space 时自动保存并关闭 | 支持 | 支持 | 多窗口、同步、协作和资源管理 |

### 6.2 关键竞品发现

**Chrome Saved Tab Groups**

已支持命名、颜色、添加标签页、关闭分组后保留分组，并可重新打开；启用账号同步后可以跨设备使用。对只在 Chrome 内管理一个主题标签页集合的用户，原生能力已经很强。

**Microsoft Edge Workspaces**

新版官方说明支持以当前窗口标签页创建 Workspace、创建空白 Workspace、编辑、删除和同步。新版不支持旧版共享协作；要求桌面 Edge 144+ 和 Microsoft / Entra 登录。

**OneTab**

官方帮助说明支持保存当前窗口、单独或全部恢复、文件夹、拖动排序、多选、搜索，以及从浏览器原生多选标签页中仅发送选中项。其云同步和备份采用端到端加密。

**Session Buddy**

官方产品说明已支持按主题建立 Collections、保存完整会话或挑选标签页、按原窗口或当前窗口恢复、重复检测、搜索、导入导出、自动备份和本地存储。无需登录。

**Toby**

官方帮助文档明确支持：
- 保存整个窗口。
- 选择目标 Space。
- 保存到新 Collection 或已有 Collection。
- Save & Close Tabs / Save & Keep Tabs Open。
- 固定标签页保存但不关闭。
- 打开 Collection 中全部保存页面。

这与本产品最初描述的核心链路高度重合。

**Workona**

官方说明 Spaces 可以作为命名的项目浏览器窗口；关闭 Space 会自动保存并关闭标签页，重新打开会恢复；还支持在 Space 间切换、单独窗口打开、多选、重复标签页处理和跨设备/浏览器同步。

### 6.3 差异化结论

本产品不能把以下内容作为市场独特卖点：

- 按主题管理标签页。
- 当前窗口批量保存。
- 追加到已有主题。
- 保存后关闭。
- 选择性恢复。
- 本地保存 URL。

这些能力已经被成熟竞品覆盖。

本产品唯一已确认的定位优势是：

**作为 OpenDesk Browser 内部工具，提供统一 Sidebar 入口、独立数据模型和受控的本地工作集能力。**

这属于生态集成价值，不等于已经具备独立商业产品差异化。

## 7. 用户角色与场景

### 7.1 主要角色

**个人知识工作者 / AI 工具重度用户**

典型工作内容：

- 同时使用 ChatGPT、Gemini、Claude 等平台的多个独立对话。
- 开展软件研发、技术研究、产品设计。
- 同时打开资料、搜索结果和参考网页。
- 工作主题经常变化，但部分主题需要持续数天或数周。

MVP 不需要管理员、团队协作者或共享主题角色。

### 7.2 场景清单

| 场景 ID | 场景 | 结果 |
|---|---|---|
| SC-01 | 保存当前活动标签页 | 页面进入一个主题 |
| SC-02 | 保存原生多选的标签页 | 仅收集被选中的页面 |
| SC-03 | 保存当前窗口全部可用标签页 | 一次收集当前窗口工作页面 |
| SC-04 | 创建新主题 | 形成新的工作集 |
| SC-05 | 追加到已有主题 | 保留原页面并追加新页面 |
| SC-06 | 查看、移除主题内页面 | 整理工作集 |
| SC-07 | 打开单个或部分页面 | 继续部分工作 |
| SC-08 | 打开整个主题 | 恢复主题页面集合 |
| SC-09 | 保存并关闭原标签页 | 清理标签栏但保留工作集 |
| SC-10 | 保存期间发生失败或中断 | 不丢失未确认保存的页面 |
| SC-11 | 浏览器重启或扩展更新 | 主题和页面关系仍存在 |
| SC-12 | URL 失效或登录过期 | 保留原记录并显示恢复结果 |

### 7.3 不进入 MVP 的场景

- 一次收集所有浏览器窗口。
- 多人共同编辑同一个主题。
- 主题自动识别与自动分类。
- 浏览器运行状态跨设备恢复。
- 无人值守的自动清理标签页。

## 8. 核心业务链路

### 8.1 批量收集

用户入口：

1. 当前活动标签页。
2. Chrome / Edge 原生多选标签页。
3. 当前窗口全部标签页。

不重新制造一套复杂的标签页选择 UI。优先利用浏览器原生选中状态。

如果只有活动标签页被选中，则按单页处理；如果存在多个 highlighted 标签页，则收集这些标签页。

收集时展示候选页面列表，允许在持久化前排除某些页面。

### 8.2 创建主题或追加主题

用户可以：

- 新建主题并保存。
- 选择已有主题并追加。
- 取消，不修改任何主题。

追加时检查目标主题内部的精确 URL 重复项。默认不重复插入，展示已跳过数量。相同 URL 可以存在于不同主题。

### 8.3 保存并关闭

这是最高风险链路，必须遵循：

**读取候选 → 用户确认 → 写入持久存储 → 读回验证 → 再次核对原标签页 → 关闭符合条件的原标签页 → 返回逐项结果。**

规则：

1. 存储写入失败或结果未知时，关闭数量必须为 0。
2. 只有已确认持久化的页面可以进入关闭候选。
3. 关闭前重新检查原 tabId 仍存在、URL 未改变、仍属于原窗口。
4. 固定标签页默认不关闭。
5. 不支持恢复的浏览器内部页面不进入关闭候选。
6. 如果用户选择了窗口内全部可关闭标签页，必须先建立一个替代空白标签页并确认成功，之后才允许关闭原标签页，避免误关闭整个窗口。
7. 替代标签页创建失败时，原标签页全部保留。
8. 部分保存成功时，只能关闭成功保存且通过再次核对的页面。
9. 部分关闭失败时，保留失败页面并逐项展示。
10. 不因 Service Worker 重启而自动重试关闭操作。

### 8.4 页面恢复

MVP 默认恢复到当前窗口：

- 打开单个页面。
- 打开用户选中的多个页面。
- 打开整个主题。
- 按主题内保存顺序依次创建标签页。
- 检查当前目标窗口内是否已有完全相同 URL；默认跳过并显示重复数量，允许用户明确选择仍然打开。
- 某个 URL 打开失败，不影响其他页面继续恢复。
- 失败页面仍保留在主题中。

P1 再考虑恢复到新窗口。

### 8.5 生命周期

创建 → 追加 → 整理 → 使用 → 再次追加 → 归档（P1）→ 删除。

删除主题只删除本工具中的主题和页面引用，不删除浏览器书签，不关闭当前打开的标签页。

## 9. 数据对象与业务规则

### 9.1 Topic

建议字段：

| 字段 | 含义 | MVP |
|---|---|---|
| id | 稳定主题 ID | 必需 |
| name | 主题名称 | 必需 |
| createdAt | 创建时间 | 必需 |
| updatedAt | 最近修改时间 | 必需 |
| entries | 有序页面记录集合 | 必需 |
| archivedAt | 归档时间 | P1 |

不设置 parentId，不建立多级目录。

### 9.2 Tab Entry

建议字段：

| 字段 | 含义 | MVP |
|---|---|---|
| id | 稳定记录 ID | 必需 |
| url | 原始完整 URL | 必需 |
| titleSnapshot | 保存时标题 | 必需 |
| order | 主题内顺序 | 必需 |
| addedAt | 添加时间 | 必需 |
| faviconSnapshot | 图标展示元数据 | 可选 |

tabId、windowId、groupId 只允许作为当前浏览器操作的临时参数，不得成为持久记录的身份字段。

### 9.3 URL 与重复规则

- 只接受可恢复的 HTTP / HTTPS 网页地址。
- 拒绝 javascript:、data:、chrome:、edge:、devtools:、扩展内部地址和空白页。
- MVP 不支持 file: URL。
- 保存时保留原始 URL，包括 query 和 fragment，不得擅自删除参数或改写地址。
- 同一主题内完全相同 URL 默认只保留一条。
- 不同主题可以保存相同 URL。
- 不做未经验证的 URL 规范化，不擅自去掉跟踪参数或 query。
- 标题是保存时快照，打开网页后实际标题可能变化。

### 9.4 顺序规则

- 收集当前窗口全部页面时，按原标签栏顺序保存。
- 收集多选页面时，保留这些页面在原窗口中的相对顺序。
- 恢复时按主题内顺序创建。
- 不依赖 Promise 并发完成顺序来决定最终标签页顺序。

### 9.5 固定标签页

- 固定标签页可以进入主题。
- Save & Close 默认不关闭固定标签页。
- 结果中必须明确显示“已保存但仍保持打开”。
- 用户不得误以为固定标签页已经关闭。

## 11. 隐私、安全和异常边界

### 11.1 本地优先

- 工作集默认只保存在当前浏览器 Profile。
- 不默认调用网络服务。
- 不上传页面正文、AI 对话正文、Cookie 或表单内容。
- 不默认同步 URL。
- 不因浏览器登录账号而自动把工作集发送到云端。

### 11.2 URL 敏感信息

URL 可能含有：

- 访问令牌。
- 临时签名。
- 邮箱或用户标识。
- 查询参数中的私有信息。
- 可直接访问特定资源的凭据。

规则：

1. 为保证网页能够正确重新打开，持久化时保留原始 URL。
2. 列表默认显示标题、域名和必要路径，不默认展示完整 query / fragment。
3. 用户查看或复制完整 URL 时应有明确入口。
4. 未来导出、同步、分享前必须明确提醒 URL 可能包含敏感信息。
5. 不允许把 URL 当作普通、无敏感性的分析数据。

### 11.3 权限

- 标签页收集需要读取用户当前窗口标签页的能力。
- 读取标题和 URL 需要对应 Chrome tabs 权限或满足的 Host 权限。
- 当前 OpenDesk 根 Manifest 已声明 tabs；但普通工具仍不能绕过 SDK 和 Host。
- MVP 不要求 tabGroups。
- MVP 不要求 sessions。
- MVP 不要求所有网站的内容读取权限。
- 当前 OpenDesk Manifest 不允许 incognito，MVP 不支持无痕窗口。

### 11.4 保存失败

- 存储失败：不关闭任何原标签页。
- 读回失败：视为未确认保存，不关闭。
- 单个页面 URL 无效：该页面标记失败，不进入关闭候选。
- 部分写入：必须有逐项结果，不能只展示一个“成功”。
- 结果未知：锁住重复提交，先重新读取并核对持久数据，再允许用户继续。

### 11.5 恢复失败

- URL 失效：保留记录，展示失败原因。
- 需要登录：打开网页，但不能承诺恢复登录状态。
- 站点迁移：不自动猜测新 URL。
- 重复页面：默认跳过并显示数量，允许用户明确覆盖。
- 单页失败：继续恢复其他页面。

### 11.6 Service Worker 中断

- 不能依赖全局变量保存操作进度。
- 保存数据必须先持久化。
- 保存确认与关闭操作分开。
- 如果 Worker 在写入后、关闭前终止，工作集保留，原页面可能仍然打开。
- 如果 Worker 在关闭过程中终止，不自动重新执行关闭；恢复后展示可能存在的剩余原页面。
- 用户可以手动再次整理，不允许系统猜测并重复执行危险操作。

## 12. 技术可行性核查

本节仅验证技术边界，不定义完整代码架构。

### 12.1 Chrome / Edge API

| API | 可行性 | R1 决策 |
|---|---|---|
| chrome.tabs.query | 可查询当前窗口标签页及 highlighted 状态 | P0 |
| chrome.tabs.create | 可重新打开网页 | P0 |
| chrome.tabs.remove | 可关闭指定标签页 | P0，但必须受 Host 控制 |
| chrome.tabs.update | 可用于有限页面更新或焦点处理 | 按设计需要 |
| chrome.tabGroups | 管理原生标签页分组，需要相应权限 | P1 |
| chrome.sessions | 最近关闭标签页和窗口恢复 | 不用作工作集数据库 |
| chrome.storage.local | 本地持久化，容量高于 sync | 可行候选 |
| chrome.storage.sync | 约 100 KB 总容量、单项约 8 KB | 不用于主题库 |
| chrome.sidePanel | 提供统一侧栏入口 | 复用 |
| chrome.contextMenus | 可提供快捷入口 | P1 |
| chrome.commands | 可提供快捷键 | P1 |

### 12.2 原生多选标签页

Chrome 官方标签管理说明支持 Ctrl/Command 点击选择多个标签页、Shift 选择范围，并可执行批量操作。

tabs.Tab 的 highlighted 状态可作为读取原生选择结果的依据。

结论：不应在 MVP 中重新设计一套复杂的“从全部标签页列表中勾选”的收集 UI。

### 12.3 Chrome Tab Groups

- 原生 Tab Groups 已能承担一部分主题组织职责。
- 组 ID 不能作为本产品持久主题 ID。
- 当前 OpenDesk Manifest 没有声明 tabGroups 权限。
- MVP 不需要读取颜色、折叠状态或分组元数据。
- 未来若用户需要导入原生分组，再独立评估权限。

### 12.4 Chrome Sessions

sessions API 面向最近关闭的窗口和标签页恢复，最近关闭结果有数量上限，不适合保存用户长期维护的主题列表。

本产品必须维护自己的 Topic / Entry 数据。

### 12.5 持久化

官方 Chrome 文档给出的关键边界：

- storage.local 默认 10 MB；声明 unlimitedStorage 后可以扩大。
- storage.local 数据属于本机，扩展卸载后会清除。
- storage.sync 约 100 KB，单项约 8 KB。
- IndexedDB 支持结构化数据事务。
- MV3 Service Worker 通常在约 30 秒空闲后可能终止，不能依赖内存变量。

仓库额外约束：

- 普通 Sidebar Tool storage.local 合同：每工具 32 个键、总计 32 KB、单项 8 KB。
- 根 Manifest 虽然有 unlimitedStorage，但不能因此让普通工具绕过宿主权限。
- 现有 Browser SDK 的普通 browser.tabs 能力只允许有限的工具自有标签页操作。

结论：

**工作集产品需要新的宿主持久化合同和受控标签页能力。**

后续技术设计应比较：

A. Host 管理的 chrome.storage.local 独立命名空间。  
B. Host 管理的独立 IndexedDB 数据库。

必须考虑事务、数据迁移、扩展更新、卸载、读回核验和备份。不得直接把整个主题库塞进现有 32 KB 工具存储，也不得擅自扩大普通工具通用权限。

### 12.6 MV3 可信边界

- 不允许普通 Sidebar Tool 直接访问 chrome.tabs。
- 新能力必须在 Browser SDK / Host 注册表中明确声明。
- Host 必须核对当前工具身份、能力授权、窗口与标签页身份。
- 关闭标签页必须是明确用户操作触发的受控 Host 操作。
- 标签页在保存和关闭之间发生导航、移窗或固定状态变化时，必须重新核验；不匹配就不关闭。
- 不增加第二套 SDK、Host、安装器或权限系统。

### 12.7 Chrome / Edge 兼容

- 当前 OpenDesk 根 Manifest 的 minimum_chrome_version 为 138。
- Edge Workspaces 新版官方要求 Edge 144+，且需要登录。
- OpenDesk 产品不应依赖 Edge Workspaces 私有对象。
- MVP 仅依赖 Chromium 标准 tabs / storage / Side Panel API。
- Chrome 和 Edge 的真实安装、选中标签页、窗口关闭与恢复行为仍需分别原生验收。

## 13. MVP 范围与验收矩阵

### 13.1 MVP 必须交付的用户链路

**链路 A：保存到新主题**

当前页面 / 原生多选 / 当前窗口全部  
→ 选择候选页面  
→ 创建主题  
→ 写入并读回  
→ 显示成功结果  
→ 用户决定是否关闭原标签页。

**链路 B：追加到已有主题**

选择页面  
→ 选择已有主题  
→ 检查重复 URL  
→ 追加成功项  
→ 保留原主题数据  
→ 展示追加与跳过数量。

**链路 C：恢复主题**

打开主题  
→ 查看全部页面  
→ 选择单个、部分或全部  
→ 检查目标窗口重复 URL  
→ 按原顺序打开  
→ 展示成功与失败数量。

**链路 D：保存并关闭**

选择页面  
→ 用户明确选择 Save & Close  
→ 写入持久数据  
→ 读回验证  
→ 再次核对 tabId / URL / windowId / pinned 状态  
→ 关闭符合条件的页面  
→ 展示保留、关闭和失败数量。

### 13.2 验收矩阵

|---|---|---|

| U-07 | 用户是否需要市场化独立产品 | 当前按 OpenDesk 内部工具处理 |

### 15.2 已作出的产品决策

1. 核心对象是 Topic + Tab Entry。
2. 一个主题是持续维护的可变集合，不是会话快照。
3. 主题列表采用扁平结构，不引入多级目录。
4. 保存入口优先复用浏览器原生多选。
5. 默认只处理当前正常窗口。
6. 主题数据本地优先。
7. 保存成功并读回验证后才允许关闭。
8. 固定标签页默认不关闭。
9. 浏览器内部页面不进入关闭候选。
10. 不恢复完整网页运行状态。
11. 不读取 AI 对话正文。
12. 新产品独立于 Bookmark Manager，但共享 OpenDesk 宿主。

### 15.3 需要坚持的否决边界

- 不为了“看起来完整”而增加快照。
- 不为了“像文件管理器”而增加多级目录。
- 不为了“AI Native”而默认抓取网页内容。
- 不为了复用 SDK 而绕过可信 Host。
- 不为了减少一次点击而默认关闭原始标签页。
- 不因为竞品存在某功能就全部复制。

## 17. 下一阶段建议

### 17.1 是否可以进入下一阶段

**可以进入 R2：产品交互与技术设计。**

前提：保持“OpenDesk 内部独立 Sidebar Tool”定位，不扩大为完整浏览器会话管理器。

### 17.2 R2 必须交付

1. Side Panel 主要界面结构和主题/页面交互。

3. 新主题与追加已有主题的交互。
4. Save Only 与 Save & Close 的明确操作设计。
5. 部分保存、写入未知、Worker 中断和关闭失败的状态机。
6. 单页、部分、全部恢复及重复 URL 处理设计。
7. Topic / Entry 数据结构和迁移策略。
8. 可信 Host 能力合同与授权边界。
9. 32 KB 普通工具存储限制下的新持久化方案。
10. Chrome / Edge 兼容性矩阵。

### 17.3 R2 完成标准

- 所有危险操作都有确认和失败反馈。

- 原生多选优先，不重复制造复杂选择器。
- 没有把主题误设计为完整浏览器会话。
- 不扩大权限到读取网页正文。
- 可信 Host 和数据存储没有第二套架构。
- 至少完成一次反方审查和需求追溯复核。
