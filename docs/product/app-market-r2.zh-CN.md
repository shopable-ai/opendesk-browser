## 1. 本轮结论与评价范围

### 1.1 六个产品决策

1. **详情是独立页面。** 用途、媒体、权限、版本、作者及安装说明拥有固定地址；弹窗只用于确认、分享或危险操作。
2. **三种链接各有职责。** 详情链接供了解与分享；安装链接预选应用；套装链接分享固定的多应用组合。
3. **安装结果可恢复。** 安装事务、当前安装、运行能力和网站授权分开表达；断线或超时先查结果，不盲目再次安装。
4. **批量确认不合并权限身份。** 同一确认页可批准多个应用，每项仍有自己的权限、版本、安装回执和结果。
5. **分享与迁移分开。** 分享应用清单；迁移额外支持明确允许的非敏感偏好。内容备份、授权和本机证明分别处理。
6. **市场不模拟当前网站。** 目录中的“适用网站”是筛选条件；来源网页由真实宿主在实际使用时识别。

## 2. 产品结构与功能树

Side Panel 保留“我的任务 / 发现 / 开发 / 工作流 / 工具”。“发现”仍查找本机已安装任务。由“工具”打开独立应用市场，不新增第六个常驻 Tab。

市场内部采用“推荐应用 / 应用套装 / 我的应用”。搜索、用途分类和适用网站为目录筛选；开发者入口位于辅助导航。分享与迁移从“我的应用”进入，必要时有自己的完整页面。

- 应用发现
  - 浏览四个已有工具候选；生产首页只展示实际可发行项目。
  - 按用途和适用网站查找；清除筛选；空结果、加载失败、离线目录。
  - 查看适用环境及受限页面说明，不展示伪造的当前 Tab。
- 应用详情
  - 固定详情链接、返回列表、浏览器前进与后退。
  - 截图、短演示、文字替代；功能、权限、版本、来源、更新说明。
  - 安装、已安装操作、更新差异、安装不可用原因。
  - 分享详情链接、安装链接、复制开发者使用的安装按钮链接。
- 单应用安装
  - 扩展内直接审阅；公网链接交接；无扩展、旧版本和连接失败恢复。
  - 预检、确认、排队、安装、成功、取消、失败和结果未知。
  - 重开对账、幂等请求、冲突保护、容量不足。
- 应用套装
  - 从我的应用选择；给组合命名；保存固定版本清单。
  - 分享固定 revision；成员详情、兼容性、权限和版本差异预检。
  - 一次确认，逐项执行；成功、跳过、失败、阻塞与取消分别显示。
  - 只重试失败项；继续未开始项；不重复安装已成功项目。
- 设备迁移
  - 导出应用清单；可选导出有正式合同的非敏感偏好。
  - 导入预检、选择恢复、保留目标设备现有应用和设置。
  - 网站重新授权、Native 重新连接、路径重新选择、本机重新验证。
  - 笔记和其他业务数据按应用自己的导出/导入能力单独迁移。
- 作者与发行
  - 草稿、媒体、版本说明、来源绑定、审核、发布和取消列出。
  - 详情页、安装链接与嵌入式安装按钮共用同一稳定身份。
  - 版本安全撤销、来源冲突、不可用旧链接和联系方式。

## 3. 详情页：从卡片变成可分享的产品页面

### 3.1 页面内容与操作

桌面详情的主体是媒体与使用说明，右侧是紧凑的安装摘要；窄屏上下排列。顶部有返回入口、应用名称、小图标、作者和来源标识，不堆虚构安装量或星级。版本、兼容性和安装状态必须来自对应事实。

| 区域 | 必需内容 | 用户要判断什么 |
| --- | --- | --- |
| 标题与身份 | 名称、一句话用途、稳定作者身份、当前发行版本 | 是否找到了正确应用 |
| 媒体 | 主图、至少两种不同任务场景；可选短演示、清晰标题 | 装好以后会是什么样、怎么用 |
| 安装摘要 | 当前设备可执行操作、实际大小或预算提示、环境要求 | 现在能否安装、下一步是什么 |
| 功能与边界 | 三至五项实际功能、使用位置、不支持的内容 | 是否适合自己的任务 |
| 权限 | 按真实应用能力逐项说明，站点能力与安装分开 | 应用能读、改、导出什么 |
| 版本与来源 | 更新日志、兼容范围、包身份、发行渠道 | 是否可信、是否会改变权限 |
| 分享与支持 | 详情链接、安装链接、作者支持入口 | 如何分享、遇到问题找谁 |

详情页不需要登录即可浏览。只有创建或更新公开作者身份、保存云端套装、编辑本人发布内容时才要求相应身份；基础安装不强制注册市场账号。

应用未发布时明确显示“待发布”，不得用“安装”按钮承诺不存在的发行包。作者身份认证与软件安全审核使用不同标识；“作者已验证”不能暗示程序获得全面安全保证。

### 3.2 截图与动态图规范

正式发行的媒体与具体应用版本绑定，保留来源、拍摄日期和环境。建议首批每个应用提供：一张完整效果图、一张关键交互图、一段约 8–20 秒的手动播放演示。这些数量与时长是本项目的设计预算，不是平台规则。

- 首张图直接显示应用价值，例如 TOC 的目录和章节定位，不使用纯宣传封面替代功能画面。
- 以图片和带 poster 的短视频为默认；GIF 作为兼容回退，不作为唯一说明方式。视频手动播放、可暂停、不默认有声、不无限循环，遵循减少动态效果的系统偏好。
- 每张图有可读说明和替代文字。窄屏可选缩略项，不要求横向精细拖动；键盘能切换、播放和停止。
- 媒体缺失或加载失败时保留文字功能说明和安装操作，不能让详情页空白或不能安装。
- 正式投稿限制媒体类型、尺寸、文件大小，清理不必要的 EXIF；拒绝执行性内容及任意 HTML 嵌入。安装摘要和权限文案由宿主可信数据呈现，不从作者图片或描述中推导。
- 媒体经批准的来源交付，不让作者通过第三方 tracking pixel 获取用户浏览信息。图中隐藏账号、会话内容、token 和本地敏感路径。

**本轮原型用可交互的 HTML/CSS 示意展示 TOC 等工具的操作，明确标为“交互示意”。它不是当前产品真实录屏，也不能替代正式截图和实际验收。**

### 3.3 真实网站上下文

移除“演示当前网站”下拉框。公共市场和独立扩展市场通常没有目标网页上下文，不猜测“最后活动 Tab”，不读取不相关网站。

从目标网页 Side Panel 进入且宿主已有可信 sourceTab/document 绑定时，可以显示只读来源提示，例如“适用于你正在阅读的网页”。如果上下文失效，则撤销此提示并要求回到目标网页使用。这个来源绑定与页面权限均由宿主验证，不能从 URL 参数直接相信。

TOC 与正文剪藏的首次网站授权在目标网页的 Side Panel 发起。TOC 授权允许该精确 Origin 持续显示目录；正文剪藏单独授权。市场详情中的“适用于 ChatGPT”只是匹配信息，不是任何授权证据。

## 4. 稳定链接与路由合同

### 4.1 三种链接

以下使用保留示例域名 market.opendesk.example，**仅表示拟议地址结构，尚未部署**。正式域名确认后统一替换，不在工具包中写死可变环境地址。

| 类型 | 拟议公网路径 | 打开后发生什么 |
| --- | --- | --- |
| 普通详情 | /apps/opendesk/reading-toc | 展示完整详情，不自动发起安装 |
| 固定版本详情 | /apps/opendesk/reading-toc/versions/1.0.1 | 展示该版本及其当前可用性 |
| 安装意图 | /install/opendesk/reading-toc?version=1.0.1 | 预选应用与版本，显示简洁安装落地页 |
| 套装详情 | /collections/reading-kit/revisions/1 | 显示固定成员清单，不随作者后续编辑变化 |
| 套装安装意图 | /install/collections/reading-kit/revisions/1 | 预选这份固定清单，进入批量预检与确认 |
| 本机管理 | 扩展自有市场内的 /my-apps、/transfer | 查看或迁移本机安装，不能当成公网分享地址 |

不固定版本的单应用安装链接可以解析“当前受支持发行版本”，但在确认时必须冻结到确定版本和包字节身份；若确认前发生变化，重新展示差异。固定版本链接不静默替换为最新版本。缺失、下架或被安全撤销时明确说明，并让用户主动选择其他可用版本。

### 4.2 URL 不是权限

长期链接只含稳定市场 ID、可选版本或套装 revision，不携带代码、任意包下载地址、本地路径、授权 token、Cookie 或已批准字段。拒绝 packageUrl、script、autoApprove、returnUrl 等未定义的执行/跳转参数。展示和复制按钮也不为作者生成执行代码书签。

市场 ID 可以包含 publisher/app-name；现有 Sidebar v1 toolId 仍遵循现有简单 ID 规则。由可信来源映射二者，并记录作者绑定；不同作者不能凭相同本地 ID 覆盖已有工具。应用或作者显示名可改，稳定身份不复用，历史公开链接不交给另一作者。

域名未知、路由无效、版本不存在、已取消列出、已停止发行、安全撤销、私有资源未授权分别显示对应页。只有 published 或 unlisted 的发行能继续安装预检；draft、in-review 与未识别发行状态不因具有 hash 就获得安装资格。unlisted（未列出）只退出搜索和推荐，持有固定链接且发行仍受信、兼容的用户可以安装；withdrawn（停止发行）禁止新安装，已安装版本是否可继续使用按发行声明处理；revoked（安全撤销）阻止新安装，并由待实现的宿主撤销合同阻止受影响运行。取消列出不自动删除已安装应用。私有资源不可用时避免泄露其他用户的应用或套装信息。

公开详情提供 canonical、标题、描述和 Open Graph 预览图；预览爬虫读取页面永远不会安装。清单链接和安装链接保留可见作者/应用身份，短链接不能遮住最终目的地。分享组件显示完整域名和可复制文本，复制失败时允许手动选择，不虚报复制成功。

### 4.3 生产和原型路由的区别

正式公网采用可直接加载的 HTTPS 路径，服务端要正确处理详情页、版本页、404/410 与固定 revision，不能只有浏览器内跳转可用。扩展内部可以采用 hash 路由；原型采用相同信息结构的 hash 路由，无需服务器。

原型的固定示例路由可刷新恢复到相同页面；内存中的演示安装、自建套装和编辑状态刷新后清空。自建套装分享面板必须说明这一限制。正式版只有保存成功并取得 revision 后才提供“已生成链接”，不能先展示尚未持久化的地址。

## 5. 安装链接：减少查找步骤，保留一次可信决策

### 5.1 扩展内部

详情页或套装页点击安装 → 宿主预检 → 扩展自己的确认界面 → 安装事务 → 结果。既有应用按钮无需绕到公网再回来。

确认界面展示确定应用、作者、版本、来源、已有安装变化和能力。安装不创建运行 iframe、不执行网页业务动作；成功后由用户选择打开。没有新增能力且身份一致时复用已有授权，不重复制造没有意义的同意框。

### 5.2 从外部分享进入

外部安装链接 → 已选好应用的落地页 → 用户点“在 OpenDesk 继续” → 扩展自有确认页 → 安装。详情仍可展开，取消后回到对应详情，不丢掉选中的版本或套装。

本期选择这个稳定流程。仅打开链接不自动唤起多个扩展窗口，不自动批准权限；未来若已验证环境允许，可以优化一次交接操作，但不能让安装决策消失。公网内绘制得像 OpenDesk 的弹窗不构成可信宿主确认。

Chrome 官方提供了通过 externally_connectable 允许指定网站与扩展通信的机制；实际接收端仍须验证来源和消息内容。[官方外部连接配置](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable)、[消息传递与安全](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)。

确认页优先由扩展打开自有完整 Tab。Chrome 的 tabs API 可创建扩展页面；sidePanel.open 要求用户操作，不能假定公网异步消息链总能满足其手势要求。[tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)、[sidePanel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)。这些事实支持本方案的交接选择，不代表本项目已实现或完成原生验证。

### 5.3 缺少或无法连接 OpenDesk

| 观察结果 | 展示与操作 | 禁止的推断 |
| --- | --- | --- |
| 尚未尝试交接 | 在 OpenDesk 继续、查看详情 | 不探测用户安装的全部扩展 |
| 没有响应或 API 不可用 | 无法连接 OpenDesk；提供安装 OpenDesk、已安装后重试 | 无响应不能准确区分“未安装”和“被禁用” |
| 已连接但版本过旧 | 更新 OpenDesk；保留本次应用/套装选择 | 不静默拉取远程代码兜底 |
| 浏览器或设备不支持 | 说明已验证环境；复制链接到支持设备 | 不宣称手机、任意 Chromium 浏览器均可用 |
| 用户安装了 OpenDesk | 返回原落地页，点击重试继续 | 不承诺商店安装后自动携带任意 returnUrl |
| 交接已发出但无安装结果 | 查看安装状态、重新连接 | 不把超时写成失败后直接重装 |

正式商店链接与固定生产扩展 ID 应由可信发行配置提供；开发版随机扩展 ID 不能成为对外永久链接。没有已发布商店入口时显示真实未发布状态，不放假的“已可下载”地址。

### 5.4 安装桥的最小合同（新增需求）

外部入口只提供有限操作：协议兼容检查、提交应用/套装安装意图、查询本次意图。不能提供任意包导入、执行脚本、读取网页、修改授权或枚举所有已安装应用的通用接口。

1. 来源仅允许正式市场的精确 HTTPS Origin。读取浏览器提供的 sender 信息，拒绝不支持的来源、子框架与失效文档；不能相信网页自己传的 origin、trusted 或 userGesture。
2. 输入采用严格 schema，限制长度、条目数和类型；套装通过受信 catalog 获得固定 revision，不接受公开 URL 直接嵌入整份可执行清单。
3. 宿主生成短期意图身份，绑定来源、可用的 tab/document 身份、选定清单摘要和有效期；这是临时交接凭证，不是长期分享链接或安装批准。缺少必需的 sender 证据就拒绝公网交接，提供扩展内手工打开应用 ID 的回退。
4. 宿主重新解析来源、版本和包字节，对照本机安装与环境预检，生成待确认计划。前端传来的包名、权限和安全标记只可作显示建议，不能作为权威。
5. 安装批准只能来自扩展自有确认页的真实用户操作。检查确认页身份、意图未过期、包摘要未变化；双击只提交一次。
6. 对相同来源和文档限制待确认意图数量，复用或聚焦既有确认页；限频，避免网页造成确认页洪泛。尚未批准的意图可以取消或过期，重新尝试须重新预检。批准并提交后转为持久安装 operation，意图 TTL、来源页关闭或连接断开不能删除在途操作或回执；提交后的取消按批量在途收敛规则处理。
7. 网页最多查询自己创建的操作的最小结果，不获得其他应用清单、站点授权、业务内容和本机内部证明。导航/关闭之后若不能维持合法查询身份，结果在扩展“安装记录”中恢复。

已有源码没有这个公网安装桥。上述接口角色是待实现合同，不是现成 API 名称；上线前必须补 origin/frame/document、重复意图、伪造批准、超时和重启验收。

## 6. 状态模型：事实分开保存，界面给出一个主要下一步

### 6.1 状态轴

| 状态轴 | 代表值 | 事实所有者 |
| --- | --- | --- |
| 发行 release | draft、in-review、published、unlisted、withdrawn、revoked | 可信目录/发行记录 |
| 已安装 installation | absent、present；带 toolId、版本、hash、来源 | 既有安装服务 |
| 安装事务 operation | checking、awaiting-confirmation、queued、installing、reconciling、succeeded、failed、cancelled、unknown | 新增窄事务编排与回执索引 |
| 运行 lifecycle | ready、paused、running、stopping、error | 各既有宿主/运行服务；通用暂停须新增合同 |
| 权限 permission | not-required、missing、granted、revoked | 既有逐应用/逐网站授权服务 |
| 环境 environment | assessment: unknown/checking/assessed；按动作分开的 installBlockers[]、useBlockers[]；附检查时间与来源上下文 | 本机能力探测与各运行时准入 |
| 连接 connection | not-requested、connecting、connected、unavailable、lost | 安装桥当前连接；不是安装成功证据 |

权限作用于具体能力与目标 Origin；安装状态带版本与来源；页面适用性带有效上下文。多个环境条件可同时缺失，例如既需升级宿主又缺 Native，因此环境不是互斥单值。未探测为 unknown；没有目标网页为 context:none，不等于 restricted-page 或 supported。不要把七类事实压成单个 enabled 或 status，也不要让公网目录回写本机已安装状态。

UI 根据当前意图派生主操作：安全撤销/完整性冲突阻塞新的安装与受影响运行，同时保留在途操作或结果未知的核对入口；不能用“目录已不可用”覆盖已提交操作的未知结果。已有操作优先展示进度或查询；然后处理新动作相关的版本/环境；最后才是安装、使用或恢复。使用条件不冒充安装条件：当前网页受限或未授权不阻止安装一个兼容的 Sidebar 工具，只影响使用入口。已安装应用遇到市场离线不整体变成不可用。

### 6.2 用户可见状态与下一步

| 场景 | 主文案/操作 | 应保留的行为 |
| --- | --- | --- |
| 可安装 | 安装 | 确定版本、来源后审阅 |
| 正在预检 | 正在检查 | 可取消；不显示虚假精确百分比 |
| 等待确认 | 确认安装 | 一次只批准所见固定计划 |
| 等待其他安装 | 排队中 | 可取消尚未开始项 |
| 正在安装 | 正在安装第 N 项 | 防重复；取消请求有独立状态 |
| 成功 | 已安装；打开/查看我的应用 | 必须已有真实持久安装记录与回执 |
| 已有同版本同 hash 同来源 | 已安装；打开 | 幂等跳过，保留数据和授权 |
| 已有其他版本 | 查看版本差异 | 不静默升级或降级；先显示影响 |
| 同版本不同 hash 或作者冲突 | 无法安装；查看原因 | 完整性/来源冲突不能普通重试绕过 |
| 包校验失败 | 安装失败；查看详情 | 不注册半包、不影响旧版本 |
| 当前扩展没有所需包 | 更新 OpenDesk | 不把 JSON 后缀当远程代码许可 |
| 容量不足 | 管理已安装应用 | 不替用户卸载腾位，预检计算净新增数 |
| 用户拒绝 | 已取消；返回详情 | 无新增安装与权限副作用 |
| 取消请求已到达 | 正在停止后续安装 | 在途提交先得到定论，不能假称全部撤销 |
| 连接断开/超时 | 结果待确认；检查安装状态 | 保留操作 ID，先对账，不盲目重放 |
| 已成功但页面没收到回复 | 已恢复安装结果 | 由回执确认，不再安装一次 |
| 缺网站权限 | 使用时授权网站 | 安装仍为已完成，不把市场域名当目标 |
| 当前页受限/不适用 | 返回支持的网页使用 | 不把全局应用标成坏了 |
| 缺 Native 或工作区 | 连接本地助手/选择工作区 | 不声称市场安装等于本机组件就绪 |
| Page/Task 缺本机证明 | 导入并验证 | 不能用签名、合集或他人回执替代 |
| 已暂停 | 恢复应用 | 保留数据与原授权；恢复仍检查实际条件 |
| 更新要求新增能力 | 审阅变化后更新 | 未批准时保留旧版；旧版已安全撤销另行阻塞 |
| 套装部分成功 | 已完成 X 项，Y 项待处理 | 分项结果，不写整体“安装成功” |
| 目录离线 | 本地目录；稍后重试 | 当前扩展内受信包与已安装应用可继续使用 |
| 详情或媒体失败 | 重新加载/文字说明 | 安装状态不由媒体请求决定 |
| 应用未发布或停止发行 | 待发布/已不可用 | 保留可解释详情，不展示可用安装按钮；unlisted 仍可经合法固定链接安装 |

### 6.3 持久事务、幂等与恢复

事务日志只记录安装编排和审计；已安装事实仍从已有安装服务读取，不建立第二份 UI 安装数据库。日志至少记录 hostOperationId、冻结计划摘要、原安装身份、每项 attempt、阶段、回执引用和最后可确认结果。

每个目标应用串行修改；单装、批装、更新和卸载共用同一资源互斥，避免互相覆盖。确认之后若权限、版本、包 hash、来源绑定、容量或当前安装身份出现计划外变化，受影响计划失效并重新预检。批量安装维护滚动的预期基线：本批已成功项目引起的容量与身份变化有操作归属，按预计净新增数扣减，不导致后续项无意义地全部失效；其他无归属并发变化才触发重新检查。套装中尚未开始的其他项目可在安全时继续，但不能静默替换已确认版本。

操作先登记，后调用既有安装器；提交完成后绑定其实际安装身份。事务完成标记与安装服务之间若暂时不一致，进入 reconciling/unknown，通过 operationId 和安装身份查询。只有同版本/hash 不能证明某个超时操作已经成功，必须结合操作记录与调用绑定；若无法证明归属，就显示当前已安装状态与本次结果未知，不伪造归属回执。

Worker 或整浏览器重启后按日志恢复检查。没有完成安装器侧操作绑定、互斥与恢复合同前，不能发布“可恢复批量安装”能力。对未知状态不自动重试执行；明确失败且未提交才可重试新 attempt。导出/运行网页任务等业务效果不属于安装重试范围。

已有 Sidebar 安装通道包括 validateSidebarToolPackage、reviewCandidate()、install()。通用持久暂停、事务操作 ID、原子更新恢复等仍是待实现的宿主合同；不要把它们当现有包字段写入严格 v1 JSON。

## 7. 应用套装：一次分享，选择安装多个应用

### 7.1 定义与创建

对外名称采用“应用套装”。它是一份可编辑后发布为新 revision 的推荐组合，不是新的运行包、授权容器或自动化工作流。

在“我的应用”勾选多个应用 → 创建套装 → 输入名称与说明 → 确认公开成员信息 → 保存 revision → 获得详情/安装链接。每次修改成员或固定版本都生成新 revision；旧链接内容不漂移。套装总览可指向最新 revision，但复制给他人的安装链接默认固定 revision。

不默认公开整个安装列表。用户必须选择成员；确认页显示作者、应用名和版本，避免因分享清单泄露私人项目工具。私人/企业来源不能自动转成公网可安装条目；缺访问权只说明不可用，收件人重新取得来源访问权。

### 7.2 清单身份

正式 revision 包含不可变 revisionId、作者稳定 ID、创建时间、清单摘要；每个成员包含 marketId、发行版本、受信包 artifactSha256/发行身份、可选性与排序。不包含可执行源码、任意下载 URL、设备 ID、安装权限、业务内容或本机验证回执。

清单摘要由服务端或可信打包流程针对确定的规范化字节计算；哈希提供完整性，不单独提供作者真实性。签名/来源校验沿用发行信任方案，安装前仍验证实际原始包字节。示例 JSON 中未取得的真实发行 hash 使用 null 并明确不可安装，不能编造 64 位数冒充已验证包。

当前上限 12 个 Sidebar 工具，套装最多 12 个成员作为首版预算。预检按目标设备现有工具计算“净新增数”；重复项先去重/跳过，不能仅按清单总数拒绝。一个套装可以包含少量已有应用，不为凑数重复安装。

成员按 marketId 唯一：同应用同版本/同字节的重复项可以合并；同一 marketId 指向不同版本或不同字节时阻塞并要求选择一个，不能在同一批次顺序覆盖。预检既检查所有新成员之间的本地 toolId 映射，也查询目标设备已有安装的槽位归属，禁止不同市场身份互相争用或接管一个本地安装槽位。

### 7.3 批量预检和一次确认

| 每项检查结果 | 默认选择/动作 |
| --- | --- |
| 未安装、来源/版本/环境合格 | 可选中安装 |
| 已装同来源、版本和 hash | 标记已安装，跳过，不重复请求权限 |
| 已装其他版本 | 默认保留现有；用户查看差异后选择更新/降级 |
| 同版本 hash 变化或作者冲突 | 阻塞，不能勾选覆盖 |
| 当前宿主没有包、版本不兼容 | 标阻塞与修复动作，可先安装其他兼容成员 |
| Page/Task 未在本机验证 | 进入待验证队列，本次普通安装不计成功 |
| 缺少成员依赖 | 展示依赖及解决方式；首版套装选独立应用，不自动运行依赖任务 |
| 容量不足 | 展示还可安装数量、管理入口；用户减少选择或自己卸载 |

确认页显示“新增 N、跳过 M、待处理 K”，能逐项展开权限。相同权限可以汇总为便于阅读的说明，但每个应用仍保留独立授权身份。确认只批准选中的冻结成员及其安装能力；首次使用时仍按各应用的真实需要授权网站。

初版套装成员彼此独立，没有隐式“装完后执行某个脚本”。将来存在依赖时必须显式依赖图、版本约束和安装顺序；失败依赖的下游标 blocked，不自动认为整套可用。

### 7.4 执行、部分成功和取消

一个 batchId 对应多个独立 itemOperationId，顺序执行以简化宿主资源与容量管理。总进度以已处理项/总项及当前动作显示，不能把模拟计时映射成真实字节下载进度。

- 每项分别显示 queued、checking、installing、succeeded、skipped、blocked、failed、cancelled、unknown。
- 普通成员失败后可以继续其他独立成员；遇到清单完整性或发行信任错误应阻塞相关项目，必要时停止整批。
- “取消后续安装”阻止未开始项目。正在提交的项目完成或对账之后再确定结果；已成功安装保留，不自动卸载回滚。
- “只重试失败项”不会重做成功/已安装/未知项；未知项先查询。重试前重新校验受影响的计划，必要时再次审阅版本或能力变化。
- 重开进度页或重启浏览器后从真实记录恢复；不以网页内存记录宣称生产可恢复。
- 未实现跨包事务原子性，不能承诺“全部成功或全部恢复原样”。若用户要撤销本次新增，展示精确新增名单及各项数据删除影响，单独确认；绝不删除原来已安装的项目。

套装完成只表示所选应用的安装处理结束。TOC 的网站授权、Page 验证、Native 连接等可能仍待完成，结果页明确下一步。

## 8. 迁移：清单、偏好、内容和授权分别处理

### 8.1 两种入口和准确命名

“分享应用套装”只分享应用组合；“迁移到新设备”导出可恢复清单，并允许选择有合同的非敏感设置。首版按钮应叫“导出迁移清单”，不能在没有业务数据备份能力时宣传“完整备份所有应用”。

迁移文件是纯数据描述，不是新的执行包。导入器严格限制大小、成员数、字段、版本格式；未知字段拒绝或明确报告，不能直接合并到宿主 storage。本轮原型采用 schemaVersion 1 的最小结构，仅接受 schemaVersion、kind、apps 三个根字段，最多 30 项、UTF-8 编码 65536 字节；每项仅有 owner、appId、version 与空的 preferences。该限制与合同示例、自导出文件一致。

正式迁移合同还需明确 sourceHostVersion、导出时间、受信发行引用、允许的非敏感偏好字段与完整性校验。增加这些字段时发布显式新 schema，并提供版本识别与兼容迁移；不能把未登记字段塞入当前严格示例格式，或将未知偏好直接写入宿主存储。

| 数据 | 默认是否迁移 | 目标设备处理 |
| --- | --- | --- |
| 稳定应用 ID、期望版本、受信发行引用 | 是 | 重新从可信来源解析并预检 |
| 工具排序、固定项、明确公开的显示偏好 | 用户选择后可迁移 | 通过白名单与设置 schema 校验；与目标当前值比较 |
| 期望暂停状态 | 仅宿主正式支持后可选 | 当作用户偏好，不能绕过目标权限或假称已有暂停能力 |
| 笔记正文、收藏、草稿、附件 | 不混入通用清单 | 使用各应用自己的明确导出/导入入口；没有合同就标不支持 |
| 网站 grants、OAuth token、Cookie、密钥 | 不迁移 | 用户在新设备按实际使用重新授权 |
| Native 配对、绝对路径、目录句柄 | 不迁移 | 新设备重新连接、选择位置 |
| installationId、session、nonce、operationId | 不迁移 | 目标宿主生成自己的身份 |
| Page/Task Verified、Available、本机效果证明 | 不迁移 | 重新走目标设备的真实验证流程 |

### 8.2 导入流程

用户选择文件 → 解析与版本校验 → 展示来源和差异 → 选择恢复应用及允许偏好 → 一次安装确认 → 批量进度 → 逐项补齐授权/本机条件。

默认合并，不删除目标已装但清单里没有的应用。已有同包跳过，已有不同版本保留并让用户选择，已有同版本不同字节或来源冲突阻塞。没有合法包时显示“找不到此发行/请更新宿主/请求来源访问”，不信任文件附带的 URL 或脚本。

配置冲突采用逐应用“保留本机 / 使用迁移偏好”，默认保留本机；只对已经安全安装且设置 schema 兼容的应用应用偏好。失败不写一半配置，旧值可恢复。首版 Sidebar 迁移安装本身不会自动读取网页或执行业务脚本。后续 Page 程序在目标机完成真实验证、网站授权并被用户明确启用后，依照其既有匹配规则运行；迁移清单不能替用户完成这些条件。

文件只在本机显式导入处理，首版不自动上传到市场服务器。导出和导入都给出包含/不包含的准确摘要；分享链接不能冒充私密备份通道。普通清单没有敏感数据仍需尊重用户选择，因为应用名称也可能暴露工作习惯。

### 8.3 内容迁移的后续条件

若用户希望连笔记一起迁移，应为该应用提供版本化 exportData/importData 合同、容量检查、冲突策略、预览与恢复方案。当前 quick-notes 的命名空间删除语义、32 KB 总预算不能被通用迁移按钮绕过；Markdown 工作台尚未导出的内容也不会因市场存在而自动保存。

本期不把整个浏览器 storage、profile 或所有插件目录打包。后续业务备份可考虑本地加密档案，但需要独立确定加密、密钥恢复和数据兼容合同，不凭“应用清单迁移”宣称已经支持。

## 9. 我的应用与更新、暂停、卸载

我的应用聚合既有安装服务。勾选只选择要分享或迁移的应用，不同时执行启停。排序、筛选、进入详情、分享套装和导出迁移清单使用统一数据来源。

通用应用级暂停仍是新增宿主合同：暂停保留数据和原授权，阻止后续桥调用并清理受管界面；恢复时重新检查包和当前权限，不重复未变化的授权，不自动执行业务动作。未完成这一合同前，实际产品只能显示已有关闭工具、撤销网站授权或卸载操作。原型的暂停仅展示拟议状态。

当前 Sidebar 卸载会删除该工具的数据命名空间和授权。确认前说明准确影响，网页笔记提示保存需要的内容；已导出文件不受影响。批量失败不能自动调用卸载做“回滚”。Page 程序现有清理只保证受管资源，不能声称撤销已经提交的网页表单。

更新使用同一安装器，显示版本、包来源和新增能力差异。旧安装正在使用、笔记保存尚未完成、工作台有未导出草稿时，先协调会话和保存动作；禁止用单个按钮悄悄关闭会丢内容的 iframe。旧版本不能继续使用时说明真实原因。

版本变更还必须检查应用持久数据的 schema 兼容。旧版不能读取当前数据、又没有受信且可恢复的数据迁移合同，就不能提供降级；用户同意也不能让不兼容数据自动变得可读。升级需要数据转换时，须先形成受信迁移、恢复旧数据和提交边界；未满足时保留当前安装并说明具体阻塞。套装和迁移中的版本差异复用这一检查。

## 10. 作者发布与分享：先建立身份，再扩大分发范围

### 10.1 作者的最短工作流

开发已有工具 → 本地校验与预览 → 填写名称、用途、权限说明、媒体和更新日志 → 绑定稳定作者身份 → 提交发行 → 获取详情页及对应状态 → 正式可安装后复制安装链接。

作者可以分享未列出的详情页供试用反馈，但链接必须真实反映可安装性。草稿、审核中或当前宿主没有代码的条目不可伪装为已发布。安装按钮可嵌在作者网站或 README 中，但只能指向市场受控 HTTPS 安装意图地址，不是一段拥有本机权限的嵌入脚本。

详情身份与不可变发行版本分开保存；单次版本发布包含包身份、能力、兼容性、媒体版本和变更记录。作者改名称或介绍不应改安装身份；改变执行内容必须是新发行或显式同版本冲突，不能后台替换旧包字节。

### 10.2 按现有运行合同分阶段开放

| 渠道 | 当前可复用基础 | 市场交付方式与剩余门槛 |
| --- | --- | --- |
| 官方 Sidebar 应用 | 四个现有工具、既有 v1 校验/审核/安装 | 首期执行代码随扩展打包，目录指向已包含包；网页笔记和工作台仍需接入正式内置清单 |
| 本地自定义工具 | 现有 JSON 导入与 sandbox host | 保留明确导入；公共在线发行还需完成来源验证、执行分发审查和宿主导出边界 |
| 社区页面脚本 | 既有 Page Program / userScripts | 按其真实 API、用户开关、站点权限和本机验证准入，不套用 Sidebar 的无验证安装 |
| 自动化 Task | 既有 Task package 与真实验证 | 详情/套装可引用，但目标设备必须 Verified → Available 后才能安装运行 |

Chrome 的 MV3 政策允许外部数据/配置，同时要求遵守执行代码来源规则；把任意程序放进 JSON 不会自动变成可自由远程分发的数据。userScripts 等路线有各自用途与限制，不能外推成所有自定义工具的通用例外。[MV3 政策](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)、[userScripts API](https://developer.chrome.com/docs/extensions/reference/api/userScripts)。

因此市场首发必须同时做到“分享页面完整”和“安装能力诚实”。作者详情可以先建立，真正的快速安装只对已满足该执行渠道准入的发行开放。需要扩大实时第三方分发时，先完成一条可实测的渠道，不额外新建第三种运行器。

## 11. 数据与实现边界

### 11.1 新增什么，复用什么

| 模块 | 职责 | 实施限制 |
| --- | --- | --- |
| 目录与详情路由 | 应用/发行/媒体、固定详情和套装页面 | 包外元数据；不修改 v1 允许字段 |
| 公网安装意图接收 | 来源验证、短期意图、打开自有确认页 | 新合同；不能通用 RPC 化 |
| 安装计划与事务编排 | 固定版本预检、逐项审核、互斥、进度和恢复 | 复用现有安装器；新增日志不是第二份安装事实 |
| 套装与迁移数据 | 不可变清单、数据白名单、差异预检 | 不携带执行代码、授权和本机证明 |
| 现有工具宿主 | 打开、桥权限、数据、网站授权、卸载 | 继续拥有实际运行和授权事实 |
| 现有 Page/Task 服务 | 本机验证、安装、运行/停止、结果 | 市场不能绕过 Available 或替造回执 |

本轮不指定 React 或更换 UI 框架。沿用已有静态 UI/CSS 的可审阅原型，生产技术选型与共享组件改造在其专属方案中决定。市场业务状态与路由合同不依赖某个前端框架。

### 11.2 容量与性能

当前 Sidebar 单包上限 320000 字节、最多 12 工具，仍以实际源码为准。媒体属于市场展示资源，不打进每个严格工具包，不因每个工具详情都含视频而扩大运行包。目录和工具按需加载，不能把所有应用脚本导入 SW。

内置目录和已交付工具能离线使用。未知远程发行、必须检查的安全撤销状态失效或完整性无法确认时，显示具体阻塞；不能以“离线体验”为由绕过发行信任。普通展示媒体失败不阻止本机已知安全包的安装。

### 11.3 最小产品指标（待埋点与验证）

观察详情到安装意图、意图到确认、确认到真实成功、缺宿主后续接成功、套装分项成功与恢复、媒体播放和失败原因。分母和事件阶段应明示，不能把点击数当安装量；不采集笔记正文、完整浏览历史或站点授权清单作为增长指标。指标尚无实际样本，本方案不提供虚构转化率。

## 12. 推进顺序与 95 分以上的验收门槛

### A. 设计闭合（本轮）

完整详情、媒体示意、三类链接、正常/异常安装、套装和迁移原型；需求、路由与状态合同一致；移除模拟网站控件；独立静态评分有依据。真实媒体、浏览器视觉和生产安装证据另列。

### B. 扩展内 MVP

四个工具进入可信内置目录；完整路由详情；复用审核安装；安装/更新日志及幂等对账；真实我的应用；套装预检与顺序批装；清单导入导出。先用固定内置套装验证真实断线/重启/取消语义，再开放用户保存组合。

### C. 公网分享与安装交接

正式域名与固定生产扩展 ID；详情和媒体公开访问、服务端直达路由；外部安装意图桥；无扩展续接、失效链接、版本冲突和真实安装回执。完成这一阶段后才对外宣称“打开分享链接即可快速安装”。

### D. 作者与内容迁移

作者身份、不可变发行、未列出分享、审核/撤销；先开放已完成准入的一种第三方执行渠道。按应用补内容迁移，随后才考虑云同步、私有源、收费和评价。

### 必须检查的关键场景

| 门槛 | 可验收结果 | 证据等级要求 |
| --- | --- | --- |
| 独立详情 | 直接链接、刷新、返回/前进均正确，媒体失败不丢主要操作 | 原型结构；正式浏览器路由/视觉证据另取 |
| 无假网站状态 | 主流程没有模拟当前网站控件；目标来源由宿主验证 | 静态及实际来源切换 |
| URL 与确认 | 普通和意图 GET 均不安装；实际批准来自扩展自有页面 | 原生消息与用户操作证据 |
| 安装幂等 | 连续点击、跨页面重复、已装同包均不重复写入 | 同候选实际回执与身份 |
| 未知结果 | 成功后断回复、Worker重启、浏览器重启不重放执行 | 原生故障注入与持久回执 |
| 套装部分成功 | 已有一项、成功一项、失败一项各自真实；只重试失败 | 分项真实结果，不用模拟进度替代 |
| 取消 | 不启动后续项，在途明确收敛，不自动删除已装应用 | 原生安装日志 |
| 来源/版本 | hash 变化、作者冲突、旧版本、缺包均有正确阻塞 | 来源与安装器定向证据 |
| 权限与运行 | 安装不运行；TOC/clip各自网站授权；迁移不复制 grants | 真实网页、应用和目标绑定 |
| 迁移 | 默认合并、保留目标数据、拒绝执行字段和凭证 | schema检查与真实导入回执 |
| 可访问性 | 键盘、焦点、320px、200%缩放、减少动态效果可用 | 实际视觉/交互，不凭CSS断点宣称通过 |
| 作者分发 | 已发布链接始终指向确定来源、版本及真实安装方式 | 发行记录、媒体来源与渠道验收 |

95 分以上在本轮只可能指“已审阅的产品设计质量”。产品的真实可靠性必须由 B/C/D 对应实现与验收逐项支撑；源码存在、HTML 动效或静态评分都不能提升为生产安装 PASS。
