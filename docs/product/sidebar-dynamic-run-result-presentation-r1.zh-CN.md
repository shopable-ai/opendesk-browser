# OpenDesk Browser Sidebar R1：动态运行结果原值展示与分层诊断

> 状态：产品设计决议 / 反方审计 / 待工程实施与真实 Chrome 验收。
>
> 适用：`我的任务` / `开发` / 本地 Controller 项目 / Page USER_SCRIPT 试运行等结果入口。
>
> 核心：**先显示脚本实际返回的值，再按需显示运行历史，最后才显示框架技术信息。** 结果字段永远是动态的，不能预设 title、url、value 等业务 Schema。

## 1. 决议和非目标

- 运行结果的权威来源是现有 Controller/RunHost/Result 或 Page 预览的合法回执，不改变运行、权限、结果存储、任务归属、停止、恢复、下载原有合同。
- **展示对象是经既有 Value Codec 成功解码的 `outcome.valueWire`，而不是整个 `snapshot`/`run`/`controller-result` 信封。**
- 不对用户返回的 `title`、`url`、`value`、`status` 等键赋予额外 UI 意义；不生成固定表格、不改名、不重排为业务字段。
- 结果默认是可读的**通用文本表示**（对象/数组缩进、字符串原文、标量原文）；结构化树查看器只能作为后续可选增强，不能替代默认文本。
- 单次运行支持空结果、标量、嵌套对象、数组、多个合法结果以及授权拒绝/交付不明；这些状态不可相互假冒。
- “开发”是产品功能，不是管理员权限；“显示技术诊断”是可选界面偏好，不是新身份、授权或提权机制。
- 保留 Sidebar 三页签 `我的任务 / 发现 / 开发`；不增第四页签、不造第二套运行引擎，也不将结果显示逻辑加入业务脚本。
- 本文档记录方案与验收门槛，**不代表代码已经修改、测试通过或 Mac Chrome 验收完成**。

## 2. 用户示例：预期展示内容

当前草稿：
```js
async function main() {
  return {title: await page.title(), url: await page.url(), value: params.value};
}
```

如果解码的返回值为 `{title:"脚本猿",url:"http://192.168.30.8:8000/",value:0}`：

**结果（默认）**
```json
{
  "title": "脚本猿",
  "url": "http://192.168.30.8:8000/",
  "value": 0
}
```

**不应该默认展示：** `runId`、`resultId`、`sourceHash`、`revision`、`tag`、`sourceKind`、`resultDeliveryDenied`，也不应把返回字段加工成“网页标题/网页地址/返回值”的固定表格。

另外三个动态示例：

- `return "完成 2 条记录";` → 默认正文为 `完成 2 条记录`（字符串原文，保留换行/空白），复制也应默认为原文，不要加 JSON 引号；可以标注小型“文本”类型。
- `return [1, {ok:false}, null];` → 展示 `[1, {"ok":false}, null]` 的缩进结构，不添加推断的列标题。
- `return 0;`、`return false;`、`return null;`、`return undefined;` 与返回对象中嵌套 `undefined` → 类型与内容必须可区分；空结果不得被当作加载中或无权查看。

## 4. 唯一显示层合同

建议抽取无副作用的展示模块，例如 `src/ui/run-result-presentation.js`。输入为经过权威归属/权限检查、成功解码的 **值**（以及单独的状态元数据），输出类似：
```ts
type ResultPresentation = {
  valueKind: 'string' | 'number' | 'boolean' | 'null' | 'undefined' | 'array' | 'object';
  displayText: string;     // 通用预览文本；不是业务字段映射
  copyText: string;        // 与用户选择的“复制展示内容”语义一致
  truncated: boolean;      // 如果截断，必须显式说明并保留完整取回路径
  format: 'text' | 'json' | 'js-like';
};
```

原则：

1. **字符串默认原文展示。** 对象/数组在可表达为标准 JSON 时按 2 空格缩进；普通数字/布尔值/null 显示对应字面量。
2. **不得以 `JSON.stringify` 作为唯一保真打印器。** 它会丢失对象属性中的 `undefined`，把数组 `undefined` 变成 `null`，把 `-0` 变成 `0`。对于 Codec 已支持但标准 JSON 不能表示的值，采用明确标注的 JS-like 安全文本视图，如 `{ "a": undefined, "n": -0 }`，不能错误标称严格 JSON。
3. **保留原值语义，但不承诺引用相等。** 跨上下文传输只能保证 Codec 所定义的有限数据值，不能保留原 JS 对象的引用、原型、函数或 DOM 句柄。`NaN`、`Infinity`、`BigInt`、`Date`、`Map`、`Set`、循环引用、函数、Symbol 等目前不可作为普通支持类型悄悄“字符串化成功”；序列化失败必须显示真实错误。
4. 默认文本渲染使用 `textContent`，不使用 `innerHTML` 或 Markdown/HTML 执行；支持多行、长字符串和窄侧栏横向折行。
5. 结果长度受 UI 性能约束可折叠/局部预览，但必须明确显示“预览已截断”，并保留授权范围内的完整值查看、复制或现有 typed-JSON 持久导出；不应默默返回不完整内容。
6. `undefined` 属于一次成功运行的合法结果，不等于“无结果”“未交付”“仍在运行”。`resultDeliveryDenied` 与 `paused_unknown` 必须单独以状态渲染，不能偷换成 `null` 或 `undefined`。
7. 切换脚本、任务、窗口或运行记录时，展示投影严格绑定 `runId` 和当前获准的 Result。晚到回包不能把上次执行的值显示成当前执行结果；保留现有 Stop 归属和重试安全边界。
8. 复制分两种明确语义：“复制结果”复制当前用户可见数据表示（字符串为原文）；“导出类型保真结果”沿用现有 typed-JSON 下载。对于不完全 JSON 兼容的值，不得把 JS-like 文本标称 JSON 导出。
9. **隐私透明。** 当前已安装任务存在敏感字段/URL 自动遮盖。若延续默认遮盖，必须显著标识“已遮盖预览”，并提供经过既有权限确认的显式查看/复制原始返回值流程；原始持久值不变。禁止默认自动复制凭据，禁止把遮盖后的文本叫作原值。无需为此新增远端账户或管理员身份。
10. 错误时优先展示“失败 + 安全、可执行的处理建议”。`E_*`、堆栈、documentId/sourceHash 等归于诊断详情；未知副作用的任务不建议盲目重新运行。

## 5. 推荐结构与交互

### 5.1 “开发”页

- 编辑器和真实运行按钮原样保留。
- **运行结果**：一行“成功/失败/运行中/待确认”状态；下方独立滚动、可复制的等宽文本结果。最近一次自己启动的草稿完成后自动展开这个区域。
- “复制结果”是高频动作；在结果区域右侧优先放“复制”，**不放 Switch**。历史记录使用 `<details>` 或简洁的“历史记录”入口，默认折叠。
- “技术信息”可经结果右侧 `⋯` → “查看运行诊断”或现有折叠详情访问。可在全局设置中增加“显示开发者诊断”，默认关闭；这不是角色权限，不影响 Result 可见性和网站授权。
- 历史显示用户可读的执行时间、状态、脚本名（来源可靠时），而不是以 UUID 作为主标题。无可信时间时不要伪造时间。
- 当前结果与历史查询不能互相覆盖：点击历史记录明确改变选中记录，关闭或返回恢复当前结果。

### 5.2 “我的任务”页

- 与开发页使用**相同格式化函数和同样的值语义**，但保留现有任务级历史关联与权限门槛。
- 结果可按模板需求展示，但默认永远是动态原值文本；若未来任务清单确实定义了可选业务展示 Schema，则属于**作者显式提供的视图**，需与“原始结果”一键切换，不得推断字段名。
- 无历史时不占用空间；有历史才出现“运行记录”。

### 5.3 设置入口

- 可以考虑一个紧凑设置入口管理：显示开发者诊断、历史记录管理、隐私显示偏好。设置内容优先在独立扩展页或 popover；300px 窄栏测试通过后再定。
- 不强制增加“管理员”新角色，也不因显示诊断而改变网站访问、SDK 授权、Native/MCP 接入或脚本执行准入。
- 内部 `Advanced / Diagnostics`、SDK 授权、健康检查与单纯数据显示是不同能力，不能一键把原本受保护的操作放开。

## 6. 反方审计（必须检查）

| 可能犯的错误 | 反方结论 | 必须证明 |
| --- | --- | --- |
| 根据 `title/url/value` 设计固定结果表格 | 否决，脚本不保证固定字段 | 任意字段的动态对象、数组、字符串都正确展示 |
| 把完整 `snapshot.results` 当成返回值显示 | 否决，泄露框架细节且混淆运行身份 | 成功结果区只取获准运行的 `outcome.valueWire` |
| 只用 `JSON.stringify` | 否决，undefined/-0 不保真 | 深度嵌套中 undefined/-0 等值完整显示 |
| 把敏感字段遮盖当成原始返回值 | 否决，信息不真实 | 遮盖清晰告知；显式原值操作守住权限边界 |
| 开启开发者 Switch 就能看所有历史 | 否决，存在越权风险 | 只影响界面，不绕过结果可见性和授权 |
| 结果格式化时使用 HTML 或脚本解释 | 否决，XSS 风险 | 文本作为纯文本渲染 |
| 将运行成功等同于操作生效 | 否决，存在未知副作用 | 中断/状态不明须保留“不确定”提示，避免自动重试 |
| 为统一视图重建 RunHost/Result | 否决，结构性过度设计 | 仅修改视图投影和纯展示逻辑 |
| 为了“简洁”隐藏完整复制/下载 | 否决，不满足开发平台需求 | 可准确导出或复制有权查看的真实值 |
| 只测 Demo 不测真实 Chrome | 否决，不能验收 | Node + 测试包 + Mac Chrome 横向与真实运行回归 |

## 7. P0 工程验收清单

1. 单独的格式化器单元测试：空字符串、含换行/HTML 标签的字符串、`0`、`false`、`null`、`undefined`、`-0`、对象带 undefined、数组带 undefined、嵌套数组对象、`__proto__` 键、非 ASCII/Emoji；不支持类型必须清楚失败。
2. 编写三条运行集成用例：运行 A/B 切换时晚到结果不串位；历史选中与最新运行互不覆盖；用户无权获得结果时不能从开发者开关/复制按钮绕过 `resultDeliveryDenied`。
3. 运行中、成功、失败、停止、未交付、未知效果与恢复后历史分别验证。成功值 `undefined` 不得误显示为“没有运行”。
4. 显示与下载复核：显示文本不同于 typed-JSON 的时候明确标识；长值截断有提示、复制/授权导出完整。
5. 开发页、我的任务页、Page 试运行三个入口的数据值与编码一致（在各自既有回执能力范围内）；原 RunHost/任务归属/权限/SDK/Native Agent 不回归。
6. 300/360/420/520px Sidebar 与 Chrome 125%/200% 缩放：无横向溢出、能键盘复制、长数组对象折行、结果不会挤走 Stop 操作。
7. 检查 `npm test`、`npm run check`、`npm run build`、`npm run build:dev`、`npm run verify`；真实 Mac Chrome 工作流需另有证据，禁止用纯 Node 通过冒充浏览器验收。

## 9. 实施顺序

1. 先新增并测试纯格式化器及脱敏状态合同。
2. 然后修改 `script-editor.js`：`showSnapshot` 默认结果只投影 `valueWire` 解码值；技术快照移入折叠区；避免交叉覆盖。
3. 再收敛 `task-workbench.js` 和 `task-run-diagnostics.js`，统一我的任务与开发页结果。
4. 处理本地 Page/USER_SCRIPT 预览的回执特殊性，技术哈希不拼在用户结果文本后。
5. 最后再考虑设置按钮和高级诊断显隐，确保不会成为此 P0 闭环的前置条件。
6. Mac Codex 在实际仓库跑完整测试、修改、真实 Chrome 验收；安全合并 main，保护当前工作区和协作者变动。
