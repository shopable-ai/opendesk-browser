# R5.0 工具无 JavaScript 弹窗交互（2026-10-11）

目标：阅读目录、网页剪藏、知识收件箱及后续 Sidebar 工具的应用级站点开关，只用用户明确点击完成，不叠加 `confirm()`。

- 授权/撤权、显示隐藏均不弹网页 JavaScript 模态框；仍保留逐 Origin、能力和当前文档的可信校验。
- 卸载并删除本地数据：点击卸载后，列表或详情下方出现行内确认区，只有独立点击“确认卸载并删除数据”才执行，随时可取消，不会出现弹窗。
- 未保存内容：扩展内切换工具仍提示先保存并阻止意外销毁，但不再注册 `beforeunload`。浏览器直接关闭标签页时不会有弹窗，无法保证尚未保存的编辑保留；Native Workspace 的知识草稿界面会明确提醒先创建文件或复制内容。
- 跨发行者更新：在无法安全核对来源时拒绝更新，不以取消确认框作为默认同意；普通版本变更的明确确认安装按钮即为最终选择，权限差异仍须提前展示。
- Chrome 原生系统权限请求（`chrome.permissions.request` 等）不属于 JS `confirm`，不可静默越权或绕过。

实施分支 agent/no-js-modal-tools-r50-20261011。正式状态须以精确提交的测试和 Chrome 验收为准，不将修改等同于运行通过。

## R5.1 无原生确认弹窗回归

- 工具宿主和 Native Workspace 不再注册 `beforeunload` 弹窗处理。
- 卸载先显示行内确认区；取消不改变数据；独立确认再次核对已安装包身份，继续使用既有锁和存储清理。
- 浏览器标签页关闭时可能丢失未保存内容，不能在取消系统弹窗的同时承诺自动恢复。Chrome 原生权限提示仍由浏览器控制。

## R5.2 官方 Markdown 工具遗漏修复

全局审计发现官方 `examples/sidebar-tools/markdown-workbench/src/main.js` 仍使用两处 `confirm()` 和一个 `beforeunload`。已改为编辑区域内可取消的导入覆盖／清空确认，不会在确认前丢弃草稿；异步文件读入若被后续编辑打断也不会覆盖新内容。官方示例版本提升至 `1.0.1`，保证已装 `1.0.0` 可以正常识别更新。Chrome 原生文件选择与权限窗口不属于 JavaScript 确认框，不能替用户静默同意。

## R5.2 补齐未保存编辑的非模态出口

在 Side Panel 的工具详情中，如果关闭／切换时检测到未保存编辑，工具仍保持原来的受限 iframe，顶部显示行内“继续编辑／放弃修改并返回”操作。用户可以继续保存，也可明确放弃后返回列表，不会出现浏览器 `confirm`。保存或删除正在进行期间仍禁止放弃；保存完成后自动关闭确认区。预览模式仍按只读隔离规则处理。

浏览器或扩展标签页直接关闭不弹 `beforeunload`，未保存内容可能丢失；关键内容应先在工具内保存、复制或导出。

## R5.4 面向后续版本的自动化守卫

`tests/environment/no-modal-ui-r50.test.mjs` 将可信 Side Panel、应用市场、Native Workspace、官方工具示例中的浏览器 `alert()/confirm()/prompt()` 及 `beforeunload` 弹窗作为回归错误，并要求工具卸载、未保存编辑、工作流新建和 Markdown 清空仍有页面内明确取消／放弃入口。此检查已纳入 Sidebar PR 定向工作流；外部浏览器扩展自身的权限窗口不可由本项目静默取消。

工具沙箱的 MV3 CSP 使用 `sandbox allow-scripts`，不包含 `allow-modals`。这只限制非受信任工具 iframe 的浏览器模态能力，不意味着可以取消 Chrome 自己的权限确认。
