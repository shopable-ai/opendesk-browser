# OpenDesk Browser Side Panel · Extension Center R4 现行产品规格（2026-10-14）

> **唯一现行一级导航与产品术语说明**：以 `src/ui/tool.html`、`src/ui/extension-center.js`、`src/ui/extension-center-model.js` 和任务工作台为准。下方 R21/R5/R6 为历史存档。R27/R28/R30 负责视觉和子视图方法。本文本不构成实际 Chrome 验收证据。

> 跨「开发 → 安装 → 扩展管理 → 发布」的所有权、Sidebar/Page/Task 真实包格式及公开上架状态，以[安装与发布所有权合同](../architecture/browser-framework/extension-installation-and-publishing-ownership.zh-CN.md)为准；本规范不将在线发布标为已实现。

## 正式五个一级 Tab

| 一级 Tab | 当前职责 | 旧入口关系 |
| --- | --- | --- |
| **我的** | 单一已安装 Controller 任务列表、按需搜索与筛选、运行结果、定时计划和任务管理 | 旧「发现」没有独立区块或重复列表；默认显示全部已安装任务 |
| **扩展** | 在统一列表查找、筛选、打开、安装、更新、管理应用及已安装网页增强，查看详情和授权 | 原「工具」改为「扩展」；`tab-tools` / `workbench-tools` DOM ID 为兼容而保留 |
| **工作流** | AI 对话、步骤预览/确认、审批、结果与设置 | 延续原 Workflow |
| **开发** | JavaScript、Controller、Page、React/Vue 的草稿运行与本地项目创作 | 正式安装的 Page 由「扩展 → 网页增强」管理 |
| **云控** | 连接、RunHost、队列状态和托管 | 开发版隐藏的「调试」不是正式第六个 Tab |

## 我的：单列表任务与定时计划（2026-10-14 更新）

- 首屏只有「自动化任务」标题、已安装数量、搜索图标、定时计划图标与「＋添加」，直接展示同一个真实已安装任务列表。默认「全部」，不因当前网页受限而隐藏其他任务。
- 点击搜索图标，**在该任务区内部**展开输入框及「全部／当前网页／已停用」筛选，结果直接过滤 `#task-installed-cards`；不产生第二套任务卡片、独立「查找本机任务」标题、重复导入按钮或常驻统计解释。收起搜索恢复全部列表。
- 「当前网页」按现有精确 CurrentPageTarget origin 和已启用状态匹配；受限网页只在用户主动筛选时出现简明提示。搜索与筛选只影响呈现，不改变任务安装、运行所有权、授权或未保存的参数。
- 「＋添加」复用现有完整可信任务目录；定时计划仍复用原 Schedule Workbench，Index → Detail / Create / Edit / Manager 与返回、草稿保护不变。打开定时计划时隐藏完整 Tasks surface，**包括搜索**，避免检索区出现在计划标题与表单上方。
- 验证需覆盖 0/1/20+ 任务、搜索空状态、当前网页不可用、停用、跨页面焦点和草稿、300–520px 与 200% 缩放。源码/Node/静态 Chrome 不是 Mac 已安装扩展的原生验收，未经实测保持 `NOT_TESTED`。

## 扩展统一列表与运行环境

- **统一列表**：`#extension-center` 组合 Sidebar Tool 已安装条目、官方候选和 Installed Page Program。「应用 / 网页增强」是**单行类型标签**而非 Tab；支持搜索、更多菜单类型/范围筛选、官方市场与本地包导入。条目按类型和状态进入应用、设置、管理或审阅前信息，具体见 R4.7。默认展示已安装项及尚未安装的可信预装候选；其他官方可选应用通过搜索或范围筛选发现。旧 Profile 不因进入「扩展」或升级而自动补装，安装仍通过原可信审阅并明确点击。
- **应用（Sidebar Tool）**：原 `examples/sidebar-tools/<id>/` 与 `opendesk.sidebar-tool.v1/v2` 技术合同不变；动态 HTML/CSS/JS 在 opaque-origin iframe 中通过 `OpenDeskTool.request` 请求经过宿主审核的能力。预编译第一方后台/Content 服务可为特定应用提供能力，但动态导入包绝不直接获得 SW、Native 或 `chrome.*` 特权。
- **网页增强（Page Program）**：Page `USER_SCRIPT`/受管网页 UI 只在完成专用 Installed/Authority、网站授权后作为「网页增强」展示；保留其启停/撤权体系，不打包成 Sidebar Tool JSON。
- **Controller Task**：在「开发」创作，按 Task Authority 安装，在「我的」运行和定时调度；不因此变成应用或网页增强。
- **可信功能与 Skill**：OpenDesk Browser 本身是一款 Chrome Extension；产品「扩展」是统一管理入口；第一方静态审计代码、动态应用、Page、Controller、Agent Skill 都必须独立区分。

### 已安装网页增强详情：真实设置与安装维护（2026-11-14）

网页增强详情页头只保留返回、当前对象标题及适量对象动作（如卸载）；不显示 Logo 或「应用 · 网页增强」类型说明。列表的类型标签不受影响。

已安装网页增强的条目进入既有的网站与状态管理视图。首屏显示扩展名称、用途、适用网站和当前状态，只提供真实可用的操作。阻断使用的原因、权限缺口及恢复入口放在受影响功能旁，用户无需展开技术信息就能找到。真实设置继续使用原设置入口，管理视图不重复设置内容。

只有存在实际可配置功能时才显示对应设置内容；没有配置项时，不生成「设置」「设置与管理」等空卡片，也不以版本、说明文字或导入图标填充占位。AI 对话滚动导航等扩展的真实设置继续由原业务 owner 提供。

**关于此扩展**是次要信息。已安装应用放在「工具设置」底部；有独立设置页的网页增强放在该设置页底部（例如 AI 对话滚动导航的右上角「导航设置」）。没有设置入口的扩展在详情底部提供同名分区。各入口统一使用侧栏标准折叠样式，默认展开，首行可直接查看「已安装版本」，其余已记录的作者、支持链接等信息依次显示。用户可手动收起；首页、网站管理和编辑子页不重复展示。内部修订号仍在原技术信息里供排查使用。

已安装网页增强的列表菜单使用短动作名：「停用」（按状态变为「启用」或「恢复」）、「更新」和「开发」；置顶与卸载沿用列表共用动作。进入网站与状态管理使用条目主体，不在菜单重复提供「查看」。「更多 → 更新」进入原有的官方更新审阅或本地导入入口，打开时不会直接安装、升级或授权。适用网站、真实错误与权限缺口继续可见，修订、来源与安装身份放在原「权限、版本与技术信息」中。

哈希、内部修订与安装或原生标识在确有排查价值时，放在既有设置或可折叠的技术信息中；无设置页时复用详情中既有的次级技术入口。纯开发记录留在「调试」。网页增强的网站权限审阅、访问恢复与网页功能帮助仍走原入口，不因技术信息收起而隐藏。

停用设置已保存、Chrome 原生注销仍待核对时，共享通知提示一次，原因与核对入口继续留在关联控件旁。普通列表和详情不展示旧网页清理记录。网页仍显示旧功能或使用异常时，可在「扩展 → 更多 → 网页功能」查看恢复步骤。开发构建的「调试 → 网页清理诊断」集中显示已安装及已卸载扩展的记录；重新核对只读取原 Authority 状态。安装、卸载或授权结果未确认时，仍在对应流程保留原因与恢复入口。见[扩展详情的停用回执与生命周期状态](../architecture/browser-framework/confirmation-and-feedback.zh-CN.md#扩展详情的停用回执与生命周期状态)。

### 已安装应用的单行当前页标题（2026-10-26）

安装后的工具共享页头只保留 **返回图标 + 一条当前页短标题 + 必要操作图标**。根页显示「书签管理」或「提示词快捷按钮」；可信设置只显示「设置」；书签编辑 Sheet 只显示「编辑」，提示词详情只显示「详情」，新建页只显示「新建」。不再展示「书签管理 / 设置」「提示词快捷按钮 / 提示词详情」这样的冗余可见路径，也不让父名 `flex:1` 撑出大片空白。完整应用名称、原业务页名及版本留在悬浮 `title`，完整路径写入 `aria-label`；长未知标题保持原文，确有空间不足才 CSS 省略号。固定 Back 和动作按钮热区不被标题挤压；极窄布局仍可让操作自然换行。返回、草稿/未知写入保护由真正业务 owner 处理，详情抽屉、Dialog、菜单不构造伪路由；未经官方安装包与活动实例验真的沙箱不能控制可信 Header。现行实现和测试见[Sidebar Tool 导航合同 R2.2](../architecture/sidebar-tool-navigation-contract-r1.zh-CN.md)。

R2.2 补充：设置返回恢复的必须是仍然有效的业务实例；撤销后的旧实例不得继续更新标题或发出导航动作，旧异步恢复失败也不得清空新页面。书签新建/编辑区域的无障碍名称与当前页相同。与本次标题修改直接相关的源码级回归入口为 `tests/environment/sidebar-tool-header-title-r2.test.mjs`、`sidebar-tool-hierarchical-back-r12.test.mjs` 和 `sidebar-tools-view.test.mjs`；没有已提交的同版本 Mac Chrome 证据时标记 `NATIVE_NOT_TESTED`，不得声明八维均达到 95 或正式发布验收完成。

## 状态、交互与验收

扩展中心从统一列表按 R4.7 进入对应视图，返回时恢复列表上下文。安装、更新、网站授权、撤权和运行都由现有可信 Host 与独立 Authority 明确执行。进入设置、管理或审阅前信息不隐式执行源码或扩大权限。UI 遵循 R27/R28/R30、`design-system.css`、`design-tokens.css`、ARIA/键盘、响应式与草稿保护。下方自动恢复段落仅描述实际进入详情后的行为与既有验收记录。

自动恢复适用于原生侧栏里仍有详情的已安装条目，例如从列表进入的「网站与权限」和专用产品管理。普通应用从列表直接打开，从菜单进入设置；两条操作都不需要通用详情页。同一窗口正常关闭再重开时，如果上次停在「扩展」标签，有效记录会打开详情首页，无记录则显示列表。每个浏览器配置仅在现有本地存储保留一个 `app:<id>` 或 `page:<id>` 标识，新记录覆盖旧记录；普通完整标签页不读写该偏好。正常关侧栏保留记录；主动返回或退出已安装详情、确认卸载对应扩展后清除记录。安装数据尚未到达或读取失败时保留记录；确认标识无效或扩展已不在安装列表时，清除该条记录、保留列表，并提示一次。恢复只导航，不启动扩展，也不恢复设置子页、草稿或弹窗；明确的打开请求和用户后续导航优先。

实际可达的已安装详情默认参加记忆，无需作者声明。框架在详情原有管理/关于区域提供「重新打开侧栏时恢复此详情」开关；AI 对话滚动导航复用原设置页的关于区域。偏好由本机可信存储持有，以 `opendesk.sidebar.extension-detail-memory.v1:app:<id>` / `…:page:<id>` 隔离类型，不写入工具安装包。关闭时当前详情不跳转，只清除该条目的已记页面；进入已关闭记忆的详情也会替换更早记录为无记录，重开留在列表。重新开启不立即记忆，下次进入有效详情才记录。操作其他扩展的偏好不得清除较新的记录；确认卸载后清除对应偏好。跨侧栏文档写入使用同源 Web Lock 排序，恢复获得锁后再次核对安装数据及用户导航。读取失败保留未知状态，保存结果未确认显示错误和只读重新核对入口，不自动重放，也不报告成功。

**保存时机（2026-11-24 最新纠偏）：** 用户通过真实列表入口进入已安装详情 A 时，在这次导航处理中立即保存带类型的 A 标识到现有 `opendesk.sidebar.last-extension-detail.v1`，默认参加。必须区分已经完成的可信存储写入与侧栏内存中等待身份验证、Web Lock 或偏好读取的意图；仅调用尚未完成的异步保存不能视为可靠持久化。点击浏览器右上角图标关闭侧栏不触发保存，也不清除记录；`pagehide`、`unload`、`dispose` 均不是保存入口。“关闭后 A 仍保留”只检查进入时已经写入的记录。身份验证、偏好读取及文档销毁的时序不得丢失已经进入详情的记录。若真实取证证实侧栏销毁打断事务，最小复用现有可信后台接收并完成记录事务，不另建存储系统；未取证前不把该假设当成根因。

独立的自动恢复验收先执行下列首要用例，再检查其余设置。全程使用同一个日常 ego（AGo）窗口、同一实际应用的当前开发构建；**关闭和打开必须点击浏览器右上角的同一个图标**，不得使用侧栏内部返回/关闭按钮、程序化 `sidePanel.close/open`、其他窗口或预览替代。

1. **A（原样本）· 网页笔记：** 现行「扩展」列表点击 `app:quick-notes` 直接打开应用，「⋮」进入设置，已移除通用详情入口。在此入口下原 A 不适用；运行界面、设置子页都不代作详情。此调整不改变其他可信入口实际可达的已安装 App 详情的恢复规则。
2. **A′ · 首要失败路径：** 从真实「扩展」列表进入「AI 回复思维导图」已安装网页增强 `page:opendesk.ai-reply-mindmap` 的「网站与权限」，记忆默认开启。看到详情后按正常速度立即点击浏览器右上角图标关闭侧栏，再点击同一个图标打开，直接恢复该详情首页。不要等待诊断字段、保存 Promise 或测试信号，不增加测试专用等待。必须取得进入时已写入 A 的独立证据；关闭后的保留检查不能代替它。
3. **B · 第二个管理页：** 从真实列表进入另一项有效已安装网页增强的「网站与权限」，写明实际条目及类型键；进入 B 时即覆盖为 B，再重复 A′ 的同图标关开。重开后只显示 B 的管理首页。
4. **C · 返回列表清除：** 在详情主动按「返回扩展列表」，核对列表上下文、焦点及反馈，并核对记录已清除；再用右上角同一图标关开，重开后仍显示列表。
5. **D · 单项关闭与重新开启：** 在真实详情的原管理/关于区域关闭当前条目的开关，状态可见、当前页面不跳转；直接同图标关开后在列表。先记另一项，再进入已关闭记忆的详情，直接关开仍在列表，旧项不得复活。重新开启后立即同图标关开仍在列表；下一次重新进入有效详情才产生新记录，再同图标关开恢复首页。修改另一项偏好不抹掉较新的记录。

## 1. 定位与信息架构

普通使用方式：找到已安装任务 → 选择 → 填写必要参数 → 在当前网页运行 → 查看状态/结果。开发方式：编写 JavaScript → 直接运行未保存草稿 → 按需保存/制作候选。OpenDesk Browser 独立于 Codex / Native Messaging / MCP 运行。

三个一级页签：

| 入口 | 长期可见 | 按需出现 |
| --- | --- | --- |
| 我的任务 | 紧凑已安装任务列表、选中卡片的网页匹配和必要参数、拥有者 Run/Stop | 最近结果（确实有运行时）、运行历史（存在时默认折叠）、网站权限/版本、管理 |

“发现”不是联网市场，不列未安装候选，不申请新权限，不因选中而自动执行。点击结果仅选中同一个工作台的已安装任务，返回“我的任务”。“导入”打开已有独立完整目录；不能在发现页隐式安装。

## 3. 我的任务：选择与运行

- 列表一项约 58px（随着字号、文本伸缩，不强制裁掉关键标题），选中卡片内部紧跟网页匹配、参数、操作结果和折叠历史。没有结果/历史时相关区块不占高度。
- 同一个真实 DOM 表单、`task-installed-list`、`task-params-form`、`task-result`、`task-history`、RunHost 不随切页重建；移动的是同一组节点。任务切换保留每一任务未保存的参数缓存。
- 展示网页适用/不适用状态。真正启动前保持原来的捕获→可信点击权限申请→精确 document 二次校验→resolve Installed→Run 的顺序。停用/未验证/不匹配状态不可启动。
- 网站范围、版本、来源、声明权限放在“网站与权限”；刷新、复制草稿、停用、卸载和导入/管理在“更多操作”，不作为主按钮。
- 运行历史只关联当前已安装脚本版本（`scriptId`），最多 8 条、晚到的异步结果不得覆盖新选中的任务；runId、技术版本放在每条历史的次级技术信息。
- 当一个任务正在运行，切换发现/开发只显示该运行实际拥有者的 Stop，不重复启动、不把按钮切到另一个 Runner。失败、停止、目标不匹配须保留可理解反馈。

## 4. 发现：本地已安装检索

- 紧随导航显示搜索栏与紧凑筛选，筛选值为“当前网页 / 全部 / 停用”。搜索名称、用途、ID、站点声明；不搜索网页内容或云市场。
- “当前网页”严格使用 CurrentPageTarget 的可用 HTTP(S) `origin`，同时要求已安装、已启用、站点来源准确匹配。不可猜测子域，不回退旧文档。
- 条目显示名称和一行用途；停用、其他网站才提示相应状态。在“当前网页”已匹配列表中不重复每行“网站匹配”。站点集合藏在可访问名称/进入任务后的详情。
- 无安装任务、网页不可用、没有匹配项分别显示一条简明指引；`local-discover-status` 仅用于错误，不常驻“这不是市场”等说明。
- 发现仅在没有拥有者运行时隐藏整个固定底栏；其余页签启动的任务仍由现有 `syncRunDock` 决定停止入口。

## 5. 开发：代码优先

- 页面可运行状态摘要后直接是语义标注的 JavaScript 编辑器，初始高度至少 260px，保留可调整大小。
- 普通脚本为 `async function main()`，代码直接从未保存的 textarea 冻结进入现有 Controller / RunHost；“运行草稿”和“保存版本”始终独立。
- 参数 JSON 默认折叠；结果与历史、运行目标、版本和页面 USER_SCRIPT 试运行均按需展开。页面用户脚本模式不能冒充 Controller `page` API 模式。
- 页面依赖区自动读取 `@require`，可选来源、审核并锁定；明确选择经典顶层或页面 `async-main`，无需先保存。旧 jQuery checkbox 仅留作折叠迁移备用，待新链取得原生迁移证据后删除。
- 代码、参数与运行归属不应因页签切换丢失。权限、停止和持久结果身份不因视图精简而修改。

## 10. R6 定向收敛（候选代码，不等于真实 Side Panel 验收）

R6 继续保持 R5 的个人工具产品定位和唯一正式规格。仅优化以下源代码缺口：

- **验证合同**：定向组件测试覆盖运行前切换任务、迟到回程、跨任务 Stop 门槛、卡片焦点与 Tab 导航；现有 Sidebar PR CI 需执行 Node、check、build、build:dev 和 verify。静态 CI 不能等同原生 Chrome。

## 12. R6.1 跨页签运行底栏精简（源码候选）

- 源码审计确认：R6 的 `syncRunDock` 会在切到「发现」或另一个任务时继续展示 Run/Save 等非拥有者操作；即使按钮被禁用，也长期占用窄栏底部空间。

- Stop 的可访问名称在任务运行时使用启动任务名称，不因当前选择改变。无需新增运行器、结果存储、权限委派或 DOM ID。
- 新增定向 Node/源码回归，检查任务 A / 任务 B / 发现 / 开发的拥有者呈现、草稿跨页签、终态底栏与 CSS；不将模拟测试视为真实扩展。

> 设计说明与反方审计：[Sidebar 动态运行结果原值展示与分层诊断 R1](sidebar-dynamic-run-result-presentation-r1.zh-CN.md)。该设计待实施/验收，不改变既有 R5/R6 RunHost、权限或三页签合同。
