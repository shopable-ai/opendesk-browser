# OpenDesk Browser Sidebar UI SPEC · R5（现行）

> 2026-10-08。适用：个人使用的 Chrome Side Panel。继承 R4 工作流、R3 浅色视觉和现有真实任务服务。
> 历史设计：`examples/ui/sidebar-r3-light-preview.html`、`examples/ui/sidebar-r4-installed-discovery-preview.html` 均保留，不覆盖。
> 唯一 R5 自包含可点击原型：`examples/ui/sidebar-r5-compact-preview.html`。该原型**仅为 UI 模拟**，不含真实 Chrome 权限或运行证据。

## 1. 定位与信息架构

普通使用方式：找到已安装任务 → 选择 → 填写必要参数 → 在当前网页运行 → 查看状态/结果。开发方式：编写 JavaScript → 直接运行未保存草稿 → 按需保存/制作候选。OpenDesk Browser 独立于 Codex / Native Messaging / MCP 运行。

三个一级页签：

| 入口 | 长期可见 | 按需出现 |
| --- | --- | --- |
| 我的任务 | 紧凑已安装任务列表、选中卡片的网页匹配和必要参数、拥有者 Run/Stop | 最近结果（确实有运行时）、运行历史（存在时默认折叠）、网站权限/版本、管理 |
| 发现 | 搜索已安装任务、当前网页/全部/停用筛选、匹配列表、行内「导入」 | 无匹配提示、真正错误状态、已存在运行的**归属 Stop** |
| 开发 | 当前网页状态、JavaScript 编辑器、草稿运行/保存 | 可选参数、结果与历史、运行目标与版本、页面 USER_SCRIPT 依赖与试运行、保存版本/制作候选、SDK 诊断 |

“发现”不是联网市场，不列未安装候选，不申请新权限，不因选中而自动执行。点击结果仅选中同一个工作台的已安装任务，返回“我的任务”。“导入”打开已有独立完整目录；不能在发现页隐式安装。

## 2. R4 冗余审计与决定

| 问题 | R5 决定 | 依据 |
| --- | --- | --- |
| 三页签后重复标题和功能说明 | 删除普通页签中的重复大标题、教学段落 | 导航已经提供上下文，真实操作应占首屏 |
| 顶部恒显任务目录 | 从顶栏移除，改为发现页搜索旁的「导入」及任务管理的二级入口 | 完整目录用于导入 JSON/JS、候选验证与安装，不是频繁的日常操作 |
| 发现计数与状态重复 | 计数仅 `aria-live` 供辅助技术读取，不再常驻占行 | 列表自身已经表达结果 |
| 发现底栏重复任务/目录按钮 | 空闲时完全隐藏底栏；运行时保留真实拥有者 Stop | 不增大搜索路径，也不破坏取消能力 |
| 已安装卡重复启用徽标、用途/版本 | 默认只显示名称/用途，停用作为例外状态；网站与权限折叠 | 正常状态无需反复声明 |
| 无结果时常驻结果/历史 | 未运行隐藏结果和历史；有历史时展示最近结果并提供折叠记录 | 避免解释性占位造成大块空白 |
| 草稿编辑器被大块状态表单挤压 | 当前网页摘要 + 大编辑器；运行身份/结果/历史按需展开 | 日常高频操作是写脚本和直接运行 |
| R2/R3/R4 多组重复 CSS 选择器 | 收敛为一套 R5 样式，完整目录样式单独保留 | 直接修结构，而不是在末尾无限补丁 |

## 3. 我的任务：选择与运行

- 列表一项约 58px（随着字号、文本伸缩，不强制裁掉关键标题），选中卡片内部紧跟网页匹配、参数、操作结果和折叠历史。没有结果/历史时相关区块不占高度。
- 同一个真实 DOM 表单、`task-installed-list`、`task-params-form`、`task-result`、`task-history`、RunHost 不随切页重建；移动的是同一组节点。任务切换保留每一任务未保存的参数缓存。
- 展示网页适用/不适用状态。真正启动前保持原来的捕获→可信点击权限申请→精确 document 二次校验→resolve Installed→Run 的顺序。停用/未验证/不匹配状态不可启动。
- 网站范围、版本、来源、声明权限放在“网站与权限”；刷新、复制草稿、停用、卸载和导入/管理在“更多操作”，不作为主按钮。
- 运行历史只关联当前已安装脚本版本（`scriptId`），最多 8 条、晚到的异步结果不得覆盖新选中的任务；runId、技术版本放在每条历史的次级技术信息。
- 当一个任务正在运行，切换发现/开发只显示该运行实际拥有者的 Stop，不重复启动、不把按钮切到另一个 Runner。失败、停止、目标不匹配须保留可理解反馈。

## 4. 发现：本地已安装检索

- 紧随导航显示搜索栏与紧凑筛选，筛选值为“当前网页 / 全部 / 停用”。搜索名称、用途、ID、站点声明；不搜索网页内容或云市场。
- “当前网页”严格使用 CurrentPageTarget 的可用 HTTP(S) `origin`，同时要求已安装、已启用、站点来源准确匹配。不可猜测子域，不回退旧文档。
- 条目显示名称和一行用途；停用、其他网站才提示相应状态。在“当前网页”已匹配列表中不重复每行“网站匹配”。站点集合藏在可访问名称/进入任务后的详情。
- 无安装任务、网页不可用、没有匹配项分别显示一条简明指引；`local-discover-status` 仅用于错误，不常驻“这不是市场”等说明。
- 发现仅在没有拥有者运行时隐藏整个固定底栏；其余页签启动的任务仍由现有 `syncRunDock` 决定停止入口。

## 5. 开发：代码优先

- 页面可运行状态摘要后直接是语义标注的 JavaScript 编辑器，初始高度至少 260px，保留可调整大小。
- 普通脚本为 `async function main()`，代码直接从未保存的 textarea 冻结进入现有 Controller / RunHost；“运行草稿”和“保存版本”始终独立。
- 参数 JSON 默认折叠；结果与历史、运行目标、版本和页面 USER_SCRIPT 试运行均按需展开。页面用户脚本模式不能冒充 Controller `page` API 模式。
- 页面依赖区自动读取 `@require`，可选来源、审核并锁定；明确选择经典顶层或页面 `async-main`，无需先保存。旧 jQuery checkbox 仅留作折叠迁移备用，待新链取得原生迁移证据后删除。
- 代码、参数与运行归属不应因页签切换丢失。权限、停止和持久结果身份不因视图精简而修改。

## 6. 完整任务目录：独立页面

采用现有受信任 `ui/tool.html` 完整扩展页。保留真实 JSON/JS 导入、任务包阅读与版本/权限说明、候选证据验证、明确安装、停用和卸载。只有已成为 `Available` 的真实版本可安装；不可把点击预览看作权限批准。成功后仅通过 `BroadcastChannel` 提醒 Sidebar 重读权威 Task Catalog，绝不以通知消息作为可信任务数据。

## 7. 视觉系统与布局基准

- 浅背景 `#f5f7fb`，白色交互表面 `#ffffff`，主文字 `#1b2c49`，次文字 `#53647e`，主按钮 `#365eda`。重要状态有文字，不依赖颜色。
- 品牌栏约 47px、导航约 40px；内容区 10–11px 外边距；主体任务条目约 58–62px。以 4 / 8 / 12 / 16px 为主要间距节奏。
- 使用内容区单独纵向滚动；仅在实际提供 Run/Stop 时显示固定底栏。不得横向溢出，长网址和错误消息换行，列表标题可换行。
- 300、360、420、520px 及约 700px 高度分别检查，360×700 发现页以搜索、筛选和 ≥4 条普通任务不滚动可见为目标。125%/200% 缩放、键盘焦点、Tab/Enter/Space、WCAG 2.2 AA 对比度均需单独验证。
- `:focus-visible` 显著，输入控件有可访问标签，`aria-live` 说明结果计数/错误；不要通过缩小到 10px 字体解决所有空间问题。

## 8. 实施边界、验证与证据等级

正式文件：`src/ui/tool.html`、`src/ui/tool-shell.css`、`src/ui/task-workbench.js`，必要时仅小改现有 UI wiring。不得改 Controller/Worker/RunHost/Manifest 授权、CurrentPageTarget 安全边界或重建任务状态模型。

定向验证：`node --test tests/environment/task-workbench.test.mjs tests/environment/sidebar-product-contract.test.mjs tests/environment/script-editor.test.mjs`；`npm run check`；必要的 `build:dev`、`pack:dev`、`verify`。保留 DOM IDs 和监听器回归、跨页 Stop 所有权、导入/安装入口、参数草稿、无结果占位的测试。

验收层级严格区分：**原型交互（UI_SIMULATION）≠ Node/静态（COMPONENT_TESTED）≠ 真实受控 Chrome（NATIVE_TESTED）**。真实 Chrome 侧栏、用户触发权限、扩展重开、跨页授权与 Stop 未验证时必须标注 `NATIVE_NOT_TESTED`；不虚构截图或 95 分以上得分。

六维独立审计：视觉排版、信息密度、交互效率、开发体验、普通使用体验、无障碍与状态正确性。任一项未通过真实验证，不以“95/100”自动认定交付。R5 通过检查与安全集成后方可取代 R4 作为产品现行视觉验收基线。
