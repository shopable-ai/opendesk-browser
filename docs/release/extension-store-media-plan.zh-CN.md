# Chrome 网上应用店：浏览器插件与五款独立扩展拍摄方案

2026-11-25 · 浏览器插件中英文素材与独立扩展素材 · [原图档案与审阅状态](extension-store-media/README.md)

## 浏览器插件本体：每种语言都先「扩展」，再「开发」

浏览器插件本体（GrayDove）有自己的商品图，不与独立 AI 扩展的截图混排。英文和简体中文各拍两张；切换实际界面语言，分别实拍，不翻译或覆盖截图文字。每种语言独立上传，并在商店预览核对首图与顺序。两组用相同主题的真实 ChatGPT 对话、相同窗口比例和侧栏宽度。左侧要提供可读的功能结果，右侧显示真实入口；普通占位页不进入候选。

| 顺序 | 英文文件 / 画面 | 简体中文文件 / 画面 | 取景与通过条件 |
| --- | --- | --- | --- |
| **01 首图** | `01-extensions.png` · 侧栏英文「扩展」列表 | `01-extensions.png` · 侧栏「扩展」列表 | 右侧使用实际扩展列表，保持产品排序；左侧用真实 ChatGPT 显示简短回复、快捷按钮和实际填入的草稿，草稿保持未发送。 |
| **02 次图** | `02-develop.png` · 侧栏英文「开发」工作台 | `02-develop.png` · 侧栏「开发」工作台 | 左侧保留同一真实回复，右侧开发工作台显示短脚本及其实际返回值。用只读脚本提取回复中的清单，截图中左右结果可相互核对。 |

两组分别归入同一商品的 `en` 与 `zh-CN` 子目录，单组顺序均为 `01-extensions.png` → `02-develop.png`。原生侧栏和网页同屏，交稿 1280×800 RGB PNG；先确认轮廓在 640×400 仍能读，再决定是否加第三张任务结果。仓库中的界面样机只用于取景参考。正式候选无法完整切换两处界面语言时，记录缺失，保留现有版本证据，不用另一语言截图替代。

## 独立扩展素材

本轮优先用真实 ChatGPT 拍一组最少镜头：**展开英文导图、同一对话里的提示词快捷按钮与待发送队列、一次有落点的对话翻页**。同框以商品实际包含两项能力、画面可读为前提；五款独立商品分别裁定素材归属。Gemini 先修输入区排版，通过实站验证后再补一张跨站图。队列优先用连续视频证明「上一轮完成后自动续发」。选题依据是场景价值和画面可证实性，目前没有功能使用统计。

## 商店规格与商品范围

| 素材 | Google 规则 | 本轮采用 |
| --- | --- | --- |
| 商品截图 | 每个商品 1–5 张；1280×800 或 640×400，直角、满幅 | 1280×800 RGB PNG，另以 640×400 检查可读性；每张一个结果 |
| 演示视频 | 可选，填写一个 YouTube 链接；可为支持的语言分别设置。展示顺序：本地化视频、本地化截图、全局视频、全局截图 | 英文字幕，建议 1080p；在退出登录时确认视频可播放，并在商店预览中核对实际位置 |
| 图标和宣传图 | 商店图标 128×128 必须提供；440×280 小宣传图和 1400×560 大横幅可选，另算 | 保留已确认的正式图标；先做截图和视频，宣传图随后 |

依据：[图片规范](https://developer.chrome.com/docs/webstore/images#screenshots)、[商品详情与素材顺序](https://developer.chrome.com/docs/webstore/cws-dashboard-listing#graphic-assets)、[商品页最佳实践](https://developer.chrome.com/docs/webstore/best-listing)。Google 建议尽量用满 5 张；本轮先交少量能看懂且各有新信息的图。视频上传到 YouTube 后填链接，商店后台无需上传 MP4。若选 [YouTube「不公开列出」](https://support.google.com/youtube/answer/157177)，有链接者仍可观看，且要验证实际嵌入。1080p 和下文时长是制作建议。

- **独立商品**：先核对商品 ID、正式名称和发行包。每款先准备 1–2 张：一张证明核心结果，另一张只在能补充操作入口或另一个重要结果时采用。队列与快捷按钮可以共用演示对话，独立商品从各自功能取景，避免暗示另一款能力随包提供。播放器留给对应商品或项目介绍。
- **一个 AI 总商品**：按实际发行能力挑三张：①英文导图；②快捷按钮、已填草稿与真实等待中的队列；③翻页控件、轮次和目标提问。第二张挤压可读性时，从同一对话拆成两张。导图未获准则由快捷按钮与队列领衔。若更新 [GrayDove Standard](greydove/STORE-LISTING.md)，以其真实发行范围和现有商品说明为准。若同时发布总商品和独立商品，先核对各自用途及 [Chrome 网上应用店的重复内容政策](https://developer.chrome.com/docs/webstore/program-policies/policies#building-quality-products)。

截图和视频可按包中实际支持的语言单独配置，商店语言入口与包中支持的语言对应。英语字幕本身不会新增商店的语言入口。封面按展示顺序单独审核，小宣传图用于搜索、分类等位置，和商品首图是两份素材。

## 取景表：图片尺寸、窗口尺寸和保留区域

**Gemini 同屏补拍（AI Scroll Navigation + AI Send Queue）：** 在同一真实演示会话里固定导航控件和队列的位置。推荐镜头是一次真实跳转后的目标提问、轮次计数与一条真实队列状态同屏；队列区过空时优先展示两条短条目，画面只有一条时按实标明。保持轮次和队列不重叠；选不出能同时读清的构图时才拆成两个镜头。现有两张诊断图仅用于对照构图。同步确认 Gemini 及画面展示的两项功能均属于对应发行版本；联动图可用于联合介绍，独立商品不得用它暗示包含另一款扩展。

**交稿图统一 1280×800 像素，比例 16:10。** 窗口总尺寸、网页可视区域的 CSS 像素数、实际保存的图片像素数是三个值。先把浏览器网页缩放设为 100%，调到下面的内容区尺寸，再检查保存结果；Retina 可能导出双倍像素。同构图大图可按等比例缩到 1280×800。截图接近 16:10 时只裁非关键边缘，否则重设窗口重拍。最后另缩一份 640×400 看可读性；单纯缩小输出文件不会触发网页响应式切换。图片文件大小以实际输出为准，不牺牲文字清晰度去压到人为设定的 KB 数。

| 取景预设 | 从这个尺寸试拍（CSS px） | 保留区域 | 收起／裁掉区域 |
| --- | --- | --- | --- |
| **A · 展开导图／导出** | 内容区优先 1280×800；需要构图余量时试 1440×900，缩图后复查 | 真实画布占宽约 75–85%，根节点、4 条一级分支、叶节点和实际打开／返回入口在相关各图中可读；留一处对话上下文说明来源 | ChatGPT 左侧历史、输入框（与镜头无关时可滚出）、无关交互提示、过长的回复段落；不剪支线、不遮真实工具栏 |
| **B · 网页操作镜头** | 内容区 1280×800，关闭 OpenDesk 原生侧栏，收起 ChatGPT 历史栏 | 导航保留目标提问首行和整组浮动控件；队列保留回复末段的生成状态、两条队列项与皇冠附近；快捷保留按钮和输入框里填好的关键句，同框显示仍未发送 | 浏览器地址栏、书签栏、历史记录、其他产品悬浮控件、正文的大段无关文字；按钮和结果不得各自落在截图边缘 |
| **C · 网页并排原生侧栏** | 网页＋侧栏内容合计先试 1280×800，右侧栏约 360–400，左侧余约 880–920；如窗口控件占空间，以实际内容边界测量 | 连播留下正片、播放器时间、侧栏当前集、时间轴与保存状态（按镜头选择）；提示词管理保留工具名、三条条目或编辑区，网页只给少量上下文 | 浏览器边框、个人名称、无关网站推荐、调试条、空白列表；不把单独侧栏截图粘到网页上 |

每个预设先截一张打样，记录实测外窗与采集内容区宽高、侧栏宽、页面缩放、系统像素比例、滚动点和主题。用实测外窗参数复现同一构图。主体与重要文字尽量留约 24 像素画内余量，不加外框；视频封面关键字或节点避开中央播放按钮。换尺寸、开关侧栏或重新定位以后，确认正文和扩展控件没有被重新排版到不同位置再截。

AI 商品首图必须在同一帧看见站点名称或字标、原生对话线索和扩展结果。导图保留 ChatGPT 字标、用户问题和原生输入框；用同一回复的原文图交代入口，展开图交代结果。截图先在 640×400 判断站点和用途，再放回 1280×800 检查分支、按钮和裁边。只显示扩展卡片或全屏画布、需要靠图注才能知道运行在哪个网站的样片，不作为首图。

**响应式排版检查顺序**：先用真实界面收起无关导航和菜单 → 核对按钮、输入框、轮次和时间轴是否换行、重叠或被裁切 → 首选扩大可视区或侧栏，其次缩短示例内容、调整导图自身缩放 → 以同一构图导出正式尺寸。侧栏在 360 和 400 两个宽度各看一次；出现标题栏换行、横向滚动、时间端点或保存回执落出画面就换宽度重拍。如果宽窗口会让导图在缩图中太小，回到 1280×800 或精简叶节点。选尺寸看实际排版，不假定同样的 16:10 比例会触发同一布局。

## 可直接使用的英文演示素材

用虚构的「社区工具借用库」串起四款 ChatGPT 扩展。它有清楚的对象、数字和行动，英文图节点也能保持短。公开视频和截图只使用专用演示对话。

**导图 · 发送以下提示词**

    Reproduce the outline below as rendered Markdown headings and bullet points. Do not use a code block. Keep the heading and bullet text exactly as written. Do not add an intro or conclusion.

    # Tool Library

    ## Stock
    - Start with 60 tools
    - Label every shelf

    ## Members
    - Invite 25 neighbors
    - Set a 7-day loan

    ## Checkouts
    - Scan each tool
    - Log every return

    ## Launch
    - Run a repair demo
    - Open for two hours

主图目标为 **Tool Library → Stock / Members / Checkouts / Launch → 8 条执行项**。主标题是 12 个字符，符合当前提取器的根节点裁切长度。用实际生成的回复和展开后的布局验收；若 640×400 下读不清就缩短节点，别继续缩小。导图工具栏个别控件可能仍含中文，首图重点放在英文主题和真实画布，避免无关悬停提示。

**滚动导航 · 在专用会话依次发送四轮**

1. What should a 60-item neighborhood tool library stock on day one? Group the inventory into four useful categories.
2. How should 25 founding members sign up? Write a three-step onboarding flow and a short welcome message.
3. What happens when a borrowed tool comes back late or damaged? Write a 650-word operating guide with short headings, three examples, and a closing checklist.
4. Give me a two-hour launch agenda with a 10-minute check-in buffer and four volunteer roles.

第三轮形成足够长的正文。主图先到第四条用户提问起点，再实点「上一轮」落到第三条。若起点在第四轮回复中，第一次点击可能先返回第四条提问。轮次数字拍实际识别结果，不补画总数。

**发送队列 · 一条长回复期间加入两个后续任务**

- 首条用原生发送：Write a 500-word operating plan for a neighborhood tool library with 60 tools and 25 founding members. Cover checkouts, repairs, and a two-hour launch.
- 队列 A：Turn the plan into a four-row volunteer checklist.
- 队列 B：Draft a 70-word invitation for the first 25 members.

在已建立的会话录制。A、B 按顺序从网页皇冠入队。回复若结束太快，可在支持的版本另拍 Shift + 点击直接暂停；自动续发镜头单独录制，避免把暂停画面剪成自动状态。状态未知的消息不自动重发。

**提示词快捷按钮 · 三个英文示例**

| 短按钮／显示名称 | 保存正文 |
| --- | --- |
| Plan / Action Plan | Turn the notes above into a three-step launch plan. For each step, give an owner, a deadline, and a clear definition of done. Flag one assumption to verify. |
| Brief / One-Page Brief | Write a one-page brief with the goal, audience, proposed approach, and two decisions we need to make. Keep each section under 60 words. |
| Review / Decision Review | Review the plan for missing dependencies and unclear ownership. Give the three highest-impact fixes in priority order. |

追加演示先输入 **Audience: neighborhood volunteers.**，再点 Plan，让原草稿和模板同框。若快捷按钮标签被截断，改用实测能完整显示的短标签，显示名称和正文不变。

**连播助手 · 内部构图样片《Field Notes: The Tool Library》**

## 拍摄、后期和验收

1. **开拍前核对商品和候选。** 记录商品 ID、安装构建版本／修订、站点、决定性操作和真实回执。按 [ego-browser 技能](/Users/shopme/.agents/skills/ego-browser/SKILL.md) 先运行 ego-browser skill。一个拍摄目的复用一个 TaskSpace，使用专用演示对话。网页截图若不包含原生侧栏，改用已验证的定向窗口采集；必须使用 Chrome 或固定候选的原生专项保持原合同。
2. **先构图再取景。** 使用真实满幅界面；避开个人聊天列表、账号信息、调试提示和无关标签。每张一个可见结果，不拉伸、不贴设备框、不拼出无法实际运行的状态。若加标题或单个标注，以约 5–9 个英文词为目标，避开控件。先调窗口、真实缩放或演示内容长度，再导出，以 640×400 实看首屏。
