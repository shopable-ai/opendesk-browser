# GrayDove（灰鸽）未来商业化规划

> 商业化是独立工作流，不是免费首发上架的前置条件。本文件只记录可能的商业模式、依赖和合规事项；不表示仓库已经实现支付、会员、广告或分成。

## 1. 首发策略

建议首发先提供免费版本，优先验证：
- 用户是否能理解产品定位。
- 用户是否能顺利安装并完成核心脚本/自动化流程。
- 哪些功能被持续使用。
- 哪些场景产生稳定、明确且愿意付费的价值。

不要为了未来收费，在首发前匆忙加入账户、会员、广告或支付代码。

## 2. 可能的收入模式

### 2.1 免费版 + Pro 会员

可能的权益方向：
- 更高级的自动化能力（必须先完成并验证）。
- 可量化的执行额度或项目管理能力。
- 团队/企业管理。
- 跨设备同步（若未来真正实现）。
- 高级支持。

要求：免费与付费边界明确，不要把基本功能的限制设计成误导性收费门槛。

### 2.2 AI 或云端用量收费

可能按请求量、任务量、计算资源或第三方 AI 成本计费。

必须先具备：
- 服务端身份和权益校验。
- 用量计量、限额和异常检测。
- 成本核算和预算保护。
- 失败、超时、重试和退款/补偿规则。
- 用户数据保护和第三方 AI 服务披露。

### 2.3 应用市场和开发者分成

未来若允许第三方开发者销售工具，需要额外建立：
- 开发者身份和收款资料。
- 工具审核、来源、许可证和安全审查。
- 商品定价、订单、退款和争议处理。
- 平台佣金和开发者结算。
- 税务、发票和地区合规。
- 下架、撤销和恶意更新处理。

当前仓库有应用发现、发行目录和安装审阅能力，不代表已经具备支付市场或开发者结算系统。

### 2.4 广告、赞助和联盟推广

广告不是首发必需功能。若未来研究：
- 优先考虑明确标注的自有推广、赞助或推荐内容。
- 不得干扰用户浏览和第三方网站原生广告。
- 不得伪装浏览器系统通知。
- 不得强迫用户点击广告或提交个人资料。
- 不得用受限浏览活动数据做个性化广告。
- 联盟链接必须披露，并在每次加入前要求相关用户操作和提供直接透明的用户利益。
- Google AdSense 当前不得用于在扩展产品内投放广告。

## 3. 收款主体与支付架构

必须区分：

- Chrome Web Store 发布者：负责扩展商品、更新和商店合规。
- 商家/卖方：与用户形成购买关系、承担销售条款和退款义务的主体。
- 支付服务商（PSP）：处理支付交易和资金结算。
- Merchant of Record（MoR）：在合同约定范围内作为交易卖方并承担部分税务/交易责任的服务商。

这些角色不能混为一谈。使用 MoR 也不代表开发者免除全部税务、公司、消费者保护或隐私责任。

评估支付服务商前先确认：
- 实际经营/居住国家或地区。
- 个人或公司经营主体。
- 可接受的业务类型。
- 可用币种和结算国家。
- 订阅、退款、拒付和税务支持。
- KYC / KYB 和公开商家资料要求。
- 是否支持数字软件和浏览器扩展业务。

不要借用他人的公司、身份或支付账号。

## 4. 推荐的付费架构（未来实施时）

```text
GrayDove 扩展
  └─ 登录 / 查看权益 / 发起升级
       └─ GrayDove 官方网站结账页
            └─ 第三方支付服务商或 MoR
                 └─ 服务端验证 webhook 和交易状态
                      └─ GrayDove 账户/权益服务
                           └─ 扩展读取服务端确认的权益
```

安全原则：
- 不在扩展包中放支付密钥。
- 不信任客户端自行修改的 VIP 标记。
- 服务端验证订单、订阅状态、退款、撤销和 webhook 签名。
- 处理重复 webhook、乱序事件、重试和未知结果。
- 用户取消、退款或拒付后及时更新权益。
- 不收集或存储不必要的银行卡敏感信息。
- 明确价格、自动续费、取消、退款、试用和税费。

## 5. Chrome Web Store 付款披露

官方政策要求开发者清楚说明销售内容、销售主体和销售条款；如基本功能需要付费，必须在用户决定安装时明确披露。开发者必须明确自己是卖方，而不是 Google。

官方政策：[Accepting Payment From Users](https://developer.chrome.com/docs/webstore/program-policies/accepting-payment)

## 6. 广告与用户数据限制

广告属于扩展产品体验的一部分，仍需遵守商店政策。Google AdSense 当前不得用于扩展产品内广告。广告不得伪装系统提示、强迫点击或干扰第三方网站广告。

Chrome Web Store Limited Use 对浏览活动和用户数据用途有严格限制，不能把用户浏览数据出售给广告平台，也不能将受限数据用于个性化广告。

联盟推广需要在商品页、界面和安装前披露，并在每次加入链接/代码/Cookie 前取得相关用户操作，且必须为用户提供直接、透明的利益。

官方政策：
- [Ads](https://developer.chrome.com/docs/webstore/program-policies/ads)
- [Affiliate Ads](https://developer.chrome.com/docs/webstore/program-policies/affiliate-ads)
- [Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use)

## 7. 商业化实施的启动条件

只有满足以下条件，才启动单独的商业化工程：
- 已验证真实用户需求和付费意愿。
- 已明确个人/公司收款主体和经营地区。
- 已选定合规支付方案。
- 已确定免费/付费权益边界。
- 已完成服务端身份、权益和用量设计。
- 已完成隐私、税务、退款和消费者保护评估。
- 已由项目负责人明确批准商业化实施范围。

在此之前，本仓库只维护本规划，不添加支付 SDK、广告 SDK、会员标记或空壳购买入口。
