## 已核对的原需求和事实

- 旧对话「优化脚本运行位置配置」（01a1fc48-5e35-78e3-b2d6-aa3468f42bb6）的首条用户消息原话是“里面只有两个值，如果需要保留，把它作为滑块也远比下拉框要合适的多”，并提出应尽量由代码决定、不要另设框架选项。关于已有参数“似乎……控制是否需要打开新的选项卡”是当时的推测。后面两条用户消息明确指出「更改执行标签页」及多出的段落、按钮令布局变差。[原需求稿](./baidu-manual-run-ui-20261121.zh-CN.md) 中「总是新开标签页」及两项开关是候选。本稿建议将其改为一次性动作。
- 用现有包校验器核对了 1.1.5、1.1.6 的 Manifest 和源码哈希，两者均与各自发行 pin 匹配。当前工作区[固定包 1.1.6](../../task-packs/baidu.search/releases/baidu.search.top3.v1.opendesk-task.json) 的 sourceUtf8 与[百度脚本](../../task-packs/baidu.search/src/baidu-search-top3.js)逐字节一致；当前 main 的 HEAD 同一路径还是 1.1.5。工作区的 1.1.6 及相应发行登记是已有改动，浏览器安装和运行版本未核验。
- 两版固定参数只有 query、limit（固定 3）和 showExecutionTab；拒绝额外字段。1.1.6 在首页填词并提交一次；完全匹配关键词的结果页不再提交、只读提取；其他获准同站页面可经原受控导航进入结果页。1.1.5 的可用路径较窄，保留原入口。脚本在已绑定的页上调用 page.bringToFront()；显式 false 只跳过这个调用，不跳过搜索或读结果。

## 方案比较

下表从参数面板已打开、填完同一关键词计数。试用控制台制造环境变化的点击不计入产品路径。

| 情景 | A · 完全自动 | B · 默认自动 + 本次新开 | 判断错了会怎样 |
| --- | --- | --- | --- |
| 在可用百度首页或不同关键词结果页上搜索 | 看到「使用当前百度标签页」和可识别的页名；**运行 1 次** | 同样 **运行 1 次**，旁边可点「本次新开」 | 误判应复用可能改变用户当前页的搜索内容。预告明确提示这页可能改变；执行时重验目标。 |
| 当前为其他站点，或确认没有合适页 | 看到「新开标签页 · 打开百度首页」；**运行 1 次** | 相同；常用区不显示冗余的新开动作，**运行 1 次** | 如果把正在检查误当作无目标，就会多开一页。必须等待确认；权限不满足不以新开作为绕行。 |
| 当前页是同一个词的结果，想读前三条 | 预告复用并提示直接读取；**运行 1 次** | 相同，**运行 1 次** | 用新页会重复搜索，丢失“从眼前这页取结果”的效果。 |
| 当前百度页要保留：旧结果正做比较、草稿未提交、当前页需要继续阅读；用户想新搜另一个词 | 表单内无解。需切到非百度页，让目的地重新检查或重开参数，然后运行；至少 **1 次外部切页 + 1 次检查，以及 1 次运行**。 | 点「本次新开」，马上看到将开新页，再点运行；**2 次**。可用同一个按钮恢复自动。 | 误点自动并运行会改原页；误点新开只选定本次行为，点运行前可撤销。运行后的新页仍按原任务清理合同处理，不承诺保留。 |
| 填完后原百度页变化（包括同站切页、刷新或改址） | 看到「原百度页已变化，暂不能运行」；**重查 1 次 + 运行 1 次** | 同样重查；若不想借用另一页，可 **本次新开 1 次 + 运行 1 次** | 旧去向后静默改投，会导航另一页或意外开页。若点运行时才发现变化，该次不派发，保留输入并说明原因。 |
| 要让搜索继续，但不打断正在看的页面 | 两版都在「更多参数」点「执行时切到前台」使其关闭；初次 **展开 1 次 + 关闭 1 次 + 运行 1 次**，保存过则日常仍只点运行。预告旁补「不主动切到前台」。 | 同 A，且可独立配合「本次新开」 | 关闭不会把原已在前台的借用页转入后台；它仍可能在原页搜索。要同时保留原页，应选新开并关闭前台。 |

A 够轻，但把保留现场的成本转移到浏览器切页。B 在有可复用页时增加一个低强调的动作，换来原页保护；自动会开新页时隐藏它。无需让每个人理解一个长期生效的「总是新开」开关。这里的「本次」指未派发的这份草稿：关闭面板重开仍恢复；本次有可信终态后，下一次回到自动。提交回执未知时停留在原请求的恢复状态，不重置成一个可再发的新表单。

## 两个独立决定

**在哪里执行。** 合适页是侧栏所属窗口当前选中的、已实读并可校验的顶层文档，具有可确认的 window/tab/frame/document 身份和完整网址，Origin 精确为该安装已批准的 https://www.baidu.com，无凭据并满足访问授权。用用户能认出的标题和必要的网址来解释，真实界面不展示内部 ID。现有只读目标发现能区分 resolving 和 unavailable；当前百度选页却会把没有现成可借用快照直接当成新开。建议尚未加载或正在采样时显示「正在检查当前页」，暂不承诺复用或新开；明确没有合适页且仍有对百度的合法授权，才自动在后台创建一页，从 https://www.baidu.com/ 开始。可见的百度安全验证不是一个可以靠另开页规避的“不适用”状态。

第一次已明确显示的目标在这份表单内保持稳定。首次检查还没有发布去向，可以随选中页的变化重取一次；发布后，借用页换标签（含同源）、窗口、重载或完整 URL 改变时停止，保留关键词；「重新检查当前页」只读并更新预告，让用户另点一次运行。如果原来已预告新开，也不能因用户后来切到百度页而静默改成复用；可以继续原先预告的新开，或主动重查。重开表单重新取目标；显式新开不绑定旧页，回到自动仍校验原快照。用户点击以后冻结已预告的选择；权限等待期和实际派发前核对，原 Host/Authority 检查目标身份及访问权。派发后导航只走该 Controller 授权的正常转换；目标竞争、撤权、失败、安全验证或未知提交均不自动换页或重放。

**起始网址。** 首页已覆盖绝大多数搜索；1.1.6 从其他站内页仍可能跳转，因此起始网址不是“限定搜索范围”。只有用户明确要从批准的站内入口（例如已经带上同词的结果地址，意图先打开该地址再读取）启动新页时才值得展示。在 B 的「更多参数 → 指定百度起始网址」一次进入显式新开并展开输入；普通自动回退以及仅点「本次新开」时不必看到完整网址输入。填值后在运行上方展示具体去向。解析后必须是无凭据的完整 HTTPS URL，Origin 精确匹配 https://www.baidu.com；拒绝 HTTP、子域、站外、其他端口、相对地址和格式错误。非法值持久就近提示、不可运行、不回退到首页；点击时与 Host 再校验。留空才是首页；恢复自动后暂存的地址不能参与运行或出现在有效 JSON。

**执行时切到前台。** 名称用「执行时切到前台」，保留 showExecutionTab 的默认 true。关闭只意味着任务不主动切标签或聚焦窗口；实际搜索或提取不受影响。它适合在「更多参数」，不会让每次搜索多一个选项。关闭时主页面保留短提示，帮助用户理解为什么没看到切页。不能把它与开新页共用字段。原 Script 和 Host 的置前失败、未知和权限围栏继续有效。

**草稿和 JSON。** 在原窗口及准确安装身份下恢复关键词、固定数量和明确保存的 showExecutionTab:false；旧 JSON 省略该项按 true。没有 openInNewTab 的旧草稿/JSON 意味着自动。原位置下拉框的临时选择不推断为新偏好。B 候选将 openInNewTab / startUrl 当作手动表单的宿主参数；仅显式新开有有效网址，JSON 矛盾、未知字段、非法类型和非法网址就近报错并保留原文。提交前由同一参数来源投影宿主选择与脚本参数，后者仍严格只有原三项。选择值可回读，真实标签、文档、权限和未知回执不能由草稿或 JSON 恢复。预览的「应用到表单」用于对照 JSON 与界面的同一份值；正式实现复用现有 JSON 模式，不为普通搜索增加保存步骤。

## 定稿前需要决定的取舍

- **是否确实要表单内保护原页。** 历史明确要去掉独立选择区，没证明有人日常使用显式新开。B 把它放在会改变结果的地方；如果用户试用后确认可接受去浏览器切页，A 会少一个控件，也可不提供百度专属的起始网址参数。两方案都需要原目标变化的恢复动作。
- **新开是这一次，还是以后也记住。** 草稿要恢复不等于跨次偏好。预览推荐“提交前恢复、确认完成后重置”，避免费心回忆上次为什么一直新开。若要持久偏好，应改为含义明确的「总是新开」，并把偏好保持、窗口范围及何时恢复自动作为另外的产品决定。
- **起始网址是否还需要表单入口。** 旧框架允许合法自定义网址，尚未看到它是百度任务的常用路径。B 把它留在高级入口；若只留 JSON，同站高级用例仍可达但更难发现；如果移除，用户只能使用首页回退或自行打开合适百度页。没有定稿前不删除工作区已提供的路径。
- **多窗口中的新页归哪一个窗口。** 合适的借用页可以绑定侧栏窗口；现有宿主为新页调用后台创建时未显式传入窗口 ID，合同也未承诺同窗口。预览只说「新开标签页」。若要保证新页出现在侧栏所属窗口，需单独确认该行为，再验证权限等待期间切换窗口的结果；不能在文案里先作保证。

## 定稿后的最小实现和验证边界

继续沿用「我的 → 参数与运行」可信点击、现有 TaskWorkbench、RunHost/Authority、业务回执和草稿处理。Controller 公开 page API 操作已绑定目标，不能打开或选择另一页；任务 owns 的新页由原宿主创建（先后台），借用的原页不会被当任务临时页关闭。保持选择固定、安装身份/代际、同窗口顶层文档检查、撤权、用户手势、点击前无派发、重复点击和请求未知保护。用同一原请求查询未知状态；运行中的、上次和本次结果分别显示；脚本返回停止、验证、DOM 不可用或未知不能显示成功。

只在准确匹配的已审阅百度 1.1.6 手动入口使用新展示。若任务专属的宿主适配足够，保持 1.1.6 固定字节、双哈希和安装合同，用旧 Worker 参数执行。若决定由包声明新增手动参数或改脚本/Manifest，须用下一未占用的不可变版本（例如 1.1.7，届时核实），重算 Manifest/源码摘要，先证明宿主识别并走原候选验证、安装审阅。仅显式迁移获准的有效业务草稿；不自动复制授权、安装身份、目标、执行记录或未知请求。Google 通用任务、同名自定义任务、Web Flow 的分步确认、网页交接、计划任务不随改。
