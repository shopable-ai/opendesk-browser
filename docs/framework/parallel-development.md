# OpenDesk Browser 多 Agent 并行开发协议 v2

> 2026-10-12：按用户本次要求修订，与 [AGENTS.md](../../AGENTS.md) 一致。替代 v1 的自动分支/worktree 和整个工作目录单写入规则；旧记录、原始验收证据与 `public-owner.json` 保留。本协议不新增创建分支/worktree/PR、提交、推送或发布的授权。

## 默认决策

**同一 `main` 工作目录中，不同文件、兼容契约、独立资源可以并行。** 冲突按实际重叠范围处理，不按整个仓库处理。未提交改动和其他 Agent 的存在只是核查线索，不是停工理由。

| 实际情况 | 动作 |
| --- | --- |
| 不同文件，接口兼容，不争用输出/测试资源 | 记录本任务范围后直接继续，无需询问用户 |
| 工作区有其他文件的未提交改动 | 保留这些改动，继续自己的范围 |
| 本任务文件已有改动，当前未发现其他活跃写入者 | 读取现有 diff，在授权范围内增量修改并保留既有工作；不能只因 dirty 停工 |
| 同一文件已有活跃写入者，即使修改不同行 | 该文件只由一个负责人落盘；其他 Agent 提供补丁/建议，或等待明确交接 |
| 不同文件，但改变同一消息协议、schema、公开 API 或执行入口 | 指定一个契约负责人；先约定兼容接口，再并行实现；不兼容切换按依赖排序 |
| 输出到同一 dist/ZIP、使用同一 profile/端口/数据库 | 只串行占用该资源，或采用已授权的独立资源；其他编辑继续 |
| 修改同一工作目录的 Git 索引/HEAD | Git 写入串行；稳定的其他文件可继续编辑 |
| 相关验证输入正在变化 | 先稳定这些输入/使用已授权稳定快照；不能把漂移期间的结果标为当前候选 PASS |
| 无关文件或 HEAD 改变 | 检查影响；无相关输入变化时继续，不全量重跑 |
| 归属无法确定且继续可能覆盖他人工作 | 暂停该文件/资源，说明实际冲突；继续无争议部分 |

不同文件是默认并行条件，但不是行为兼容的充分条件。例如生产端修改消息字段、消费端仍按旧字段读取，需要协调契约；分别修改互不依赖的工具文档则可直接继续。

## 开始、编辑与交接

1. **核对现状。** 读取 `git branch --show-current`、`git status --short` 和本任务相关 diff，确认当前为 `main`。查相关工作流的当前范围、状态和资源；历史记录不是永久锁。当前若在未获授权的其他分支，只读核查，不自行切换或写入。
2. **声明最小范围。** 在自己的 `docs/framework/workstreams/<任务唯一标识>.md`（已有 JSON 工作流可沿用）记录负责人/对话、起始 HEAD、预期写入路径、公共契约、依赖、测试输入和输出资源。默认声明具体文件，避免用 `src/**` 等过宽目录占用。新增文件也要声明；扩展范围前重新核对。
3. **独立范围直接执行。** 不同文件且契约/资源兼容时继续，无需中央 owner 批准。原生子 Agent 分配互不重叠的文件；父 Agent 负责整合和最终核对。跨对话协作只使用已有用户授权的通道，不因本协议额外获得发送消息权限。
4. **写入前复核。** 重新读取将修改的文件和相关 diff，与上次读取的内容/哈希比较；采用小范围补丁，避免回写旧整文件、批量替换/格式化无关文件。目标漂移时停止旧补丁、重新读取并判断归属；发现未协调的写入只暂停该范围，不用旧副本覆盖恢复。
5. **编辑后核对。** 检查本次 diff、实际文件列表和意外漂移。需要修改其他负责人文件时，提供补丁/建议，由对方落盘或先完成交接。误触时只修复自己明确产生的改动，不整文件恢复、不撤销他人修改。
6. **释放与交接。** 自己的记录写明 `ACTIVE`、`WAITING`、`RELEASED` 或 `COMPLETE`，并分别列出仍占用与已释放的文件/资源。交接说明当前内容/哈希、未提交改动、后台进程和验证状态；接手者核对后接受。任务完成不代表 watcher/profile 等仍运行的资源已经释放。

记录是协作约定，**不是原子锁或技术隔离**。同时声明同一范围时不能靠“先写了记录”抢占；由当前负责人通过已有授权通道拆分、串行落盘或交接。时间戳、沉默或超时既不能单独证明活跃，也不能证明释放。无法安全协调时才询问用户，不伪造他人状态、不改旧 `public-owner.json`。需要可强制隔离的工作区时，仍须用户对具体分支/worktree 例外明确授权。

## 文件与公共契约的边界

- 默认同一文件只有一个落盘者。不同代码行仍可能被编辑器保存、生成器或格式化器整文件覆盖，不能据此自行并发写同一文件。
- 消息协议、存储 schema、公开 API、RunHost/Controller admission 和 `async function main()` entryFormat 属于跨文件契约。一个负责人定义接口和兼容策略，消费端按已约定接口并行；删除/重命名字段、不兼容 schema 迁移等切换须先后协调。
- `package.json`、依赖锁、构建配置、设计 token、公共测试 fixture、全局账本和 AGENTS.md 都按具体文件协调；它们的改动可能影响更多验证输入，但不自动锁定整个仓库。
- 同一任务可将源码、独立测试和文档拆给不同 Agent；测试消费者等待必要实现稳定后验证。不得复制第二套执行器、存储或权限体系来回避依赖。
- 生成/格式化命令也有写入范围；会写别人文件或共享产物的命令必须先缩小范围或协调。

## Git 操作与集成

共享工作目录的索引和 HEAD 是共同状态。源码编辑可并行，以下事务串行：`git add` 到 commit 及提交后核对、stash、merge/rebase、checkout/switch、pull 等修改共享状态的操作。Git 自带的索引锁不能替代整个暂存/提交事务的负责人协调。

- 本协议不额外授权 commit/push、分支/worktree/PR 或发布；只有已有具体任务授权的负责人执行对应操作。
- 暂存前核对当前 HEAD 和完整 staged diff；已有他人暂存时保留，并协调原负责人处理，不能自己 unstage/reset 或将其顺带提交。只指定本任务文件路径；同一文件含多方改动时，先确认最终补丁范围。
- 禁止 `git add .`、`git add -A`、`git commit -a` 等批量收走工作区改动。commit 前检查完整 staged 内容和依赖，commit 后核对实际提交文件/补丁及剩余 diff，不能只看命令返回成功。
- 暂存到核对期间，提交文件不再被其他 Agent 修改；其他独立文件仍可编辑。提交事务完成后释放 Git 写入占用。共享状态操作会改写的工作区文件也要取得对应文件范围，不能只登记 Git 占用。
- 远端 main 集成/推送由获授权负责人串行执行，核对最新主干、目标、提交内容、依赖和必要验证。已有另行授权的 PR/worktree 按同样原则审查，不把草稿或局部 PASS 当正式交付。
- 不使用 `reset --hard`、`git clean`、强推或旧整文件复制处理冲突。回退只针对明确属于本任务的变更，不能抹掉并行工作的记录。
- 服务端分支保护按实际发布流程另行配置；本文不代表 GitHub 已启用保护，也不授权为了匹配文档自动修改仓库设置。

Git 的 [git-add 文档](https://git-scm.com/docs/git-add)说明暂存记录的是指定路径在执行时的内容；[git-commit 文档](https://git-scm.com/docs/git-commit)说明提交从索引取内容。因此独立文件可并行编辑，但共享暂存/提交仍需要事务协调。

## 构建、浏览器与验证

独占按具体资源身份划分，包含 Chrome/CFT profile、真实扩展 ID/加载路径、端口、数据库路径、dist/ZIP 输出路径、冻结候选和发布槽。不同目录/端口且没有共享副作用的任务可并行；不得通过擅自改扩展 ID、Native 配对或日常加载目录取得隔离。

- `dist/development` 由既有 `npm run dev` watcher 持续更新；记录其进程和输出，保留既有服务，不重复启动 watcher/build 覆盖相同输出。独立源码编辑可触发它正常更新，但此目录变化期间不能当成冻结验收包。
- 源码编辑与资源占用分开登记。占用一个浏览器 profile 不阻止其他任务编辑独立源码；测试进程、构建进程、fixture 服务等也要列出其实际写入文件和资源。
- 执行前读 [testing-guide.md](testing-guide.md) 和对应工作流，先复用输入/合同/环境一致的原始证据。定向测试使用自己的输出和日志目录；公共 fixture、生成目录、缓存或数据库有写入副作用时也需协调。
- 测试前后核对相关源码及传递依赖、测试/fixture/观察器、配置和构建产物哈希；需要稳定性时，由相关负责人在验证窗口暂停这些输入的修改，或使用已授权的稳定快照/候选。**前后哈希相等不能单独排除中途变化又恢复**，没有稳定窗口或快照时不宣称冻结候选正式 PASS。
- 相关输入发生变化：保留原日志/receipt，记录 `AFFECTED_INPUTS` 或 `NEEDS_REVIEW`，稳定后只补受影响验证。无关文件、聊天变化或无关 HEAD 更新不使已有证据自动失效。
- 正式候选冻结、全链路/F3/ZIP 验收仅稳定该候选的实际输入和资源；仍允许无关工作继续。维持 AGENTS.md 的全部验收合同和身份绑定，不提升组件/旧候选证据等级。
- 释放资源前确认进程停止或完成明确转交，保存失败/`NOT_TESTED` 和原始证据。不得把任务状态 COMPLETE、端口暂时未响应或过期登记当成真实释放回执。

## 工作流最小记录

每个任务只更新自己的记录，不争抢中央状态文件。已有格式直接沿用，至少包含：

- 负责人/对话标识、日期、状态、分支及起始 HEAD；
- 预期与实际写入文件、公共契约、依赖以及冲突处理；
- 当前占用/已释放的文件、Git 事务和具体资源身份；没有占用也明确说明；
- 验证输入、原始输出路径、复用决定、真实结果与未执行项；
- 剩余任务、交接对象与已取得的特殊授权（没有则无）。

旧 sourceFingerprint、product/verification inputs、receipt、dist 和 ZIP 保持可追溯；元数据更新不重写旧证据，不登记虚假释放。

## 历史 Sidebar R1 依赖示例

保留 v1 的实际依赖约束作为示例，不以本节另行启动功能任务：

- **P0 草稿直接运行**：核对 `async function main()`；新草稿、A→B→C freeze、可信手势权限、精确 document、RunHost/Worker/Result、取消/重连须沿正式路径验证。
- **P1 三页签**：独立 UI/信息架构可先做，但 `script-editor.js`、`tool.html` 的公共接线由当前负责人协调，在所依赖的 P0 行为稳定后接入；界面改造不替代运行修复。
- **P2 任务包/安装**：manifest/schema 和威胁模型可独立准备；正式 Available/Installed/run 接入依赖真实可验证任务候选，未经验证不可显示 Available。
- 独立测试设计、文档、API 契约审计、第三方库映射和只读 Legacy 核查可并行。旧来源工程只读，不另造执行器、持久存储或权限体系。

普通用户运行交付任务不依赖 Codex/MCP/Native Messaging；真实运行仍遵守受控目标、授权、停止、deadline、unknown-effect 与持久化栅栏。各任务完成不代表整体 F3/ZIP 验收。
