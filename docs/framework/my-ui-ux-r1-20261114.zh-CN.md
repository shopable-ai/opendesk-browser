# “我的”页 UI/UX 优化目标 R1

**2026-11-15 最新实施范围**：用户已要求对齐现有“我的”主页面，重点为自动化任务列表下方，暂不完成子页面。当前原 React 已接入状态、结果、失败/未知提示、运行记录及网站权限展示；本说明覆盖下文此前“仅离线设计、不改正式源码”的阶段限制。具体决定与证据归 [DESIGN 最新主页面条目](../../DESIGN.md#我的主页面原型对齐2026-11-15核心实施)。下方原型、计划与管理页的设计/评分保留原候选身份，不据此扩展本轮实施；实际侧栏视觉与 production 尚未验证。

日期：2026-11-14。状态：**设计与交互原型阶段**。本轮交付目标规格、关键测试条件与已有 HTML 候选的明确定位；本次包含离线候选的独立专家评分与复评，不包含正式产品源码实施、构建安装、提交发布或完整测试矩阵。

**最新用户纠偏（同日）**：原“我的”业务布局基本可用，优先沿用，不重新设计整页。去掉顶部“设计更好的日常工作流”示例网页卡片，脚本列表收紧；点击行内运行按钮后尽量复用现有“参数与运行”，操作使用“取消 / 运行任务”，不另造“暂不运行 / 模拟运行”。当前只迭代独立 HTML 和本页规范，未实施正式产品。

**任务管理入口与交互补充（2026-11-15）**：按最新要求，管理入口移至右上角、时钟左侧；顺序为搜索、任务管理、定时计划、添加任务，删除集合底部重复入口。管理图标是进入独立子视图的导航，具名且提供悬停/键盘提示，不使用暗示即时启停的 pressed 状态。主列表的简化搜索保持原状。本次仍只更新本离线 HTML 与规范，不实施正式 React、构建或安装。

- 管理页搜索名称、ID 或网站，保留全部/已启用/已停用筛选及真实内存数量；无匹配可重置，空安装态可返回原添加入口。普通行先显示任务名、固定示例版本/网站，再显示图标＋状态与开关；关联计划展开按钮、新建计划、更多操作同排，后果说明归关联展开内容，避免每行重复。
- 关联计划可进入详情；返回恢复管理页关键词、筛选、展开、滚动与原触发焦点。嵌套从详情再管理任务保留父级来源；删除关联计划也返回原管理页，原链接消失则聚焦同任务的关联或更多按钮。更多菜单只保留复制到开发、固定版本/网站范围、卸载，避免重复新建计划入口。
- 停用/结果未知的任务不能新建计划；停用关联任务会暂停相关计划，重新启用不会自动恢复计划。运行中禁止停用/卸载；结算后即时刷新管理行，已打开菜单关闭时仍恢复同任务按钮。未知结果可查看本页原记录，不因查看结算，不新建计划或卸载；真实产品的查询/结算继续归原 owner，本原型不新增恢复协议。
- 从计划编辑进入管理时隐藏新建计划，关联计划不跳转，返回保留原草稿、错误、滚动及入口焦点。管理页 Escape 在有关键词时先清空，否则返回实际来源，IME 输入不触发返回。

**搜索简化（2026-11-15）**：当前任务较少，右上角搜索只展开关键词输入，移除「全部 / 当前网页 / 已停用」分类行及主列表筛选条件。搜索覆盖全部已安装任务的名称/摘要；清空或收起恢复全部。停用/网站状态仍归任务本身，独立任务管理筛选不变。本次仍仅迭代原独立 HTML 与规范。

**参数抽屉补充（2026-11-15）**：用户要求“我的”及 WebFlow 的运行抽屉点击阴影直接关闭。本次最小产品改动限于原共享 React `TaskRunSheet` 的遮罩关闭与焦点恢复，并同步独立 HTML 及生成的 React 预览；关闭保留草稿，内部点击/跨边界拖拽不误关，关闭不执行任务或取消原准备。整页重设计与正式原生验收仍不在本次范围。

**添加任务 / 计划的后续修订（同日）**：添加任务沿原页内展开，提供选择/拖放文件、任务目录、新建脚本三入口；目录与文件预览有逐级返回，不再用说明弹窗引向另一份预览。计划列表去重复状态/演示说明、保留文字“新建”，表单统一字段；检查确认展示任务、目标、时间与暂停状态，保存后回到该计划详情；编辑取消/放弃回原详情，创建取消回列表。切“开发”也保护计划脏稿。

设计入口：[DESIGN.md](../../DESIGN.md#my-ui-ux-20261114)。交互候选：[我的原型](../../prototypes/sidebar/my/index.html)及其[说明](../../prototypes/sidebar/my/README.md)。行为门槛：[关键测试条件](my-ui-ux-r1-test-spec-20261114.zh-CN.md)。视觉依据沿用 [R20](../architecture/sidebar-design-system-r20.zh-CN.md)、[R27](../architecture/ui-layout-conventions-r27.zh-CN.md)、[R28](../architecture/sidebar-multi-section-tab-contract-r28.zh-CN.md)、[R33](../architecture/react-ui-shared-components-r33.zh-CN.md)和[确认与反馈合同](../architecture/browser-framework/confirmation-and-feedback.zh-CN.md)，不建立另一套设计系统。

**本轮设计阶段结果（2026-11-15）**：列表、新建/编辑和独立任务管理已完成离线重设计；当前候选79条操作记录通过，两位未参与实施的原生专家逐项评分均≥95，复评发现的3处组合缺陷已关闭。精确候选、逐页分数、报告原文及限制统一见[测试规格第5节](my-ui-ux-r1-test-spec-20261114.zh-CN.md#5-当前离线候选独立评审与证据边界)。此结果不代表用户视觉终审或正式产品实施。

**2026-11-15 最新重设计（当前有效）**：用户否定旧列表和新建表单。行高及旧测试通过不构成设计完成；本次重新组织列表、创建/编辑和任务管理，并以每个关键页面的独立评分 ≥95/100 且无未解决阻断为门槛，不用平均分抵消低分。原业务任务集合和“参数与运行”继续沿用。

- 列表：左侧语义图标＋“已启用 / 已暂停 / 待处理”，中间计划名、下次时间或恢复后的规则、明确的执行任务；主体有详情箭头。右侧独立暂停/恢复调度图标，恢复不用容易被误认为立即执行的播放三角；有名称、提示与34px命中区，状态不只靠颜色。没有固定82px指标。
- 新建/编辑：名称 → 执行任务与目标 → 执行安排 → 保存后状态。任务选择器全宽，具名“新建脚本 / 管理任务”在同组；编辑明确绑定原固定任务，更换需新建计划。重复规则、星期/日期、时间及北京时间摘要分别归位；每天/每周保留同一时间，单次日期时间独立保留。保存后状态用原生radio正向选择“按规则执行 / 暂停”，就近解释未来调度及不会停止当前任务。固定操作栏为“取消 / 检查计划”，检查后“返回修改 / 保存计划”。字段错误就近并关联，修改无关字段不清除未修复错误。
- 任务管理：独立子视图，有名称/ID/网站搜索和带数量的全部/已启用/已停用筛选，显示版本、网站、关联计划；启停用明确任务开关，关联计划的暂停后果就近可见。独立管理提供每任务“新建计划”，复制到开发、固定版本/网站和卸载在更多操作；表单绕行管理隐藏新建计划以免覆盖原草稿。返回保留草稿、错误、滚动和焦点。任务目录是添加入口，不能代替任务管理。
- 边界：所有变更仍为独立离线 HTML；复制入口展示交接与风险说明，不创建真实开发草稿；启停/卸载/计划仅更新内存示例，不证明真实安装、身份或调度成功。输入边界沿canonical `--od-input-border`，装饰分隔线保留轻边框；不修改公共CSS或Token文件。

## 1. 最终体验与当前完成边界

**让用户在“我的”页快速找到已安装任务，辨认当前网页是否适用，按需填写参数，明确运行，随后看懂结果并随时停止原任务。** 查找、添加、管理、AI 和定时计划保持可发现；低频信息不挤占任务主流程。

主要使用场景是正常缩放、实际默认宽度的 Side Panel。本轮原型的历史观察尺寸为 360×820 CSS px，仅为提案画布，不据此规定实际侧栏宽度。

## 3. 信息架构与风格决定

```text
我的
 ├─ 任务集合：标题/数量 + 查找/添加/AI/计划入口
 │   ├─ 选中任务：状态 → 最近结果（存在时）→ 记录 / 网站与权限
 │   ├─ 准备运行：参数 Sheet → 明确 Run → 状态/结果
 │   └─ 对象管理：原管理动作 / 原审阅链 → 返回原列表
 ├─ 任务管理：搜索/启停筛选 → 版本/网站/关联计划 → 启停/复制/卸载/建计划
 ├─ 添加任务：页内文件入口 / 目录 → 详情 / 文件只读预览 → 原入口
 └─ 定时计划：列表 → 详情 → 创建/编辑 → 检查确认 → 保存后详情
     └─ 任务管理绕行 → 返回原表单/详情/列表；正式独立运行页能力继续保留
```

- 任务是主对象，保留原业务布局；不展示顶部示例网页卡片，不新增仪表盘、统计卡或永久教程。当前网页适用性留在原任务状态/权限和参数目标信息，不增加第二个来源或重复授权。
- 任务集合复用 `od-collection` 与原 `tasks.tsx` 布局：当前原型按现有普通行最小 60px、上下 8px、左右 12px；标题和摘要各一行，完整名称仍可访问，不靠缩字压高。选中底色、Hover 和焦点独立；行内动作不占独立右列，键盘及触屏可发现。
- 选中任务只展开信息；行内运行按钮打开现有 `TaskRunSheet` 的“参数与运行”。保留原标题/任务名、表单/JSON、左侧标签字段组、底部“取消 / 运行任务”，不另造“暂不运行 / 模拟运行”。唯一明确 Run 放在抽屉操作栏；空闲状态不加重复固定运行栏，运行期间沿原 Dock 保留真实 owner 的 Stop。
- 参数默认紧凑表单，JSON 为同一草稿的编辑方式。保持原 Schema 的类型、默认值和空值语义，不把原型示例的关键词必填、数值上下限或不允许额外字段推广成所有任务的新规则。
- 普通状态一句表达原因/下一步；没有结果就不摆空结果大卡片。技术身份、版本和诊断按需展开；权限缺口、未知效果与阻塞原因不能被隐藏在其中。
- 完整结果查看保留原有按需披露：只有默认内容被截断或敏感字段被隐藏才显示轻量“展开图标＋查看完整结果”，展开后“收起完整结果”；不采用难以辨认的纯图标。原因及敏感内容提示就近可见，最近结果和历史可独立查看，离开/切换任务恢复隐藏。查看不改变持久结果，不新增保存操作。原型用离线样本演示；正式产品继续由原 Codec/结果 owner 处理真实返回值。
- 页首、控件、折叠和卡片复用原组件；页面单 gutter，父容器负责兄弟间距，字段组负责 label/control/help，折叠正文负责 inset。具体数值以原 Token/CSS 为准，不从 HTML 复制一套共享样式。
- 采用原亮色字阶与语义色；重要状态/权限/错误不降到 11px 技术字号。新入口有名称、可见焦点；正文/控件按现行 AA 对比度要求，不用缩小图标或删除功能增加密度。
- 短成功回执使用原共享通知；错误、未知及字段校验留在业务位置。取消不报成功，成功不清无关错误，模态不吞消息。

## 4. 现有功能处置与原型差异

| 能力 / 当前入口 | HTML 覆盖 | 后续产品处置与约束 |
| --- | --- | --- |
| 单列表、关键词搜索 | 有，固定示例数据；按最新反馈移除主列表分类行 | 后续沿原集合和搜索 owner 实施同样简化；搜索覆盖全部任务，清空/收起恢复全部，不改安装、选择/草稿和运行归属；任务管理筛选独立保留 |
| 行内准备运行、表单/JSON、关闭草稿 | 有，仅内存参数及示例校验 | 复用真实 Schema、安装身份、参数缓存和原 session 持久化；本提案不改原持久化期限 |
| 运行、停止、结果及运行记录 | 计时器模拟，记录只在内存 | 原 Host/RunHost 控制执行与结算；不能用关闭浮层、隐藏状态或 UI 文案证明停止成功 |
