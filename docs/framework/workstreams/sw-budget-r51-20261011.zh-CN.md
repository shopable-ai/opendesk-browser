# OpenDesk Browser：SW 构建预算 R5.1（2026-10-11）

## 1. 背景与结论

用户反馈本地 SW 构建反复受到 300 多 KiB 上限阻断，希望找回此前 500 多 KiB 的决议，并允许在合理范围内进一步扩大。

历史 [e5908c5](https://github.com/shopable-ai/opendesk-browser/commit/e5908c55f4a1cae4fb5d4542da7e596765af7027) 已将生产 SW 上限提高到 **512 KiB**、开发 SW **768 KiB**，并把其他固定 JS 上限提高到 **512 KiB**。本轮从 `main` 直接核实发现，生产 SW 的 `serviceWorkerProductionBytes` 连同验证器及测试被改回 **320 KiB**。320 KiB 是项目工程上限，**不是 Chrome MV3 官方规定的 SW 单文件上限**。

本轮对用户所担心的未来增长预留更多空间，并以独立软预警继续保障架构审查。以下为本轮的新生效策略；R5 历史文档及其 CI 证据仅代表对应历史候选，不再作为当前硬上限的依据。

| 资源 | 非阻断人工审查阈值 | 单文件硬上限 |
| --- | ---: | ---: |
| 生产 `sw.js` | **512 KiB（524,288 B）** | **1 MiB（1,048,576 B）** |
| 开发 `sw.js` | 独立体积审计 | **1.5 MiB（1,572,864 B）** |
| 其他 WXT 固定 JS（生产/开发） | **320 KiB（327,680 B）** | **512 KiB（524,288 B）** |
| vendor JS、Page framework、manifest、license | 现有严格合同 | 不变 |

## 2. 唯一运行规则与防回退约束

- `scripts/build-contract.mjs` 内的 `BUILD_POLICY` 与 `entryByteBudget(target, mode)` 是唯一产物预算来源；`wxt.config.mjs` 的 WXT 生成门禁、`scripts/verify-package.mjs` 最终包检查和 `scripts/audit-fixed-entries.mjs` 的真实 SHA-256、字节与 Rollup 模块审计均复用该函数。不新增第二套预算注册表或用户手工开关。
- 生产 SW 达到 **512 KiB** 发出 `BUILD_SIZE_REVIEW` / `reviewRequired`，**并不停止构建**；超过 **1 MiB** 必须失败。80% / 90% 容量风险告警继续保留。其他 JS 维持原 320 KiB 提醒与 512 KiB 硬上限。
- `scripts/check-source.mjs` 和 `verify-package.mjs` 的精确结构断言同步变更；`tests/environment/sw-budget-policy.test.mjs`、`fixed-entries-audit.test.mjs`、`native-agent-package.test.mjs`、`package.test.mjs` 覆盖生产/开发模式、旧 320 KiB 非阻断、512 KiB 软线、硬线值恰好通过及 **硬线 +1 字节拒绝**。未来不得仅改配置数字而遗漏验收合同。
- **不改变 Chrome 权限/CSP、固定输出白名单、classic SW 单个 IIFE、受控静态 `importScripts`、远程 JS 禁止规则、vendor hash/许可或最终包验证；不把 React/Vue 自动打进特权 SW。** 更大上限不等于更快的启动、更小的运行时占用或已通过真实 Chrome 验收。

## 3. 本地/CI 验证顺序

先核实 `main` 与写入者、`dist/`、Chrome Profile 没有并发占用，保护未提交修改；不要对已被其他 Agent 占用的工作目录运行共享构建或清理。

```bash
git status --short --branch
npm ci --ignore-scripts --no-audit --no-fund
node --test tests/environment/sw-budget-policy.test.mjs tests/environment/fixed-entries-audit.test.mjs tests/environment/native-agent-package.test.mjs
npm run check
npm run build
npm run build:dev
npm run verify
npm run build:size
npm run build:size -- --development
node --test tests/environment/package.test.mjs
```

验收时分别记录当前 SHA、`dist/production/sw.js` 和 `dist/development/sw.js` 物理字节、`build-*.json` 收据、真实包 SHA-256、警示信息，以及必要的 macOS Chrome MV3 Worker 注册、停止/唤醒/恢复结果。若接近 512 KiB 软线应评估 Rollup 模块归因、实际启动耗时、堆占用与架构边界，不能无限扩大硬线。没有当前候选实际构建及 Chrome 原始证据时，明确标注 `NOT_TESTED`，不可拿过去 e5908c5 的 CI 和旧 ZIP 冒充通过。

## 4. 本轮环境证据边界

本轮从连接的 GitHub 仓库接口读取、修改并提交 `main` 文件；此执行环境无法访问用户 Mac 的本地工作目录，也无法经网络克隆仓库安装依赖。提交结果和源码中的合同可核实，**完整 npm/WXT 构建、生产包校验与真实 Chrome 只能在本地或 CI 补验**，不预先宣称它们已通过。
