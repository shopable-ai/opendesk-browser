# Side Panel 网站开关无二次弹窗（2026-10-11）

## 目标和真实入口

OpenDesk Browser 的「阅读目录」「网页剪藏」「知识收件箱」都有当前网站权限按钮。新版本官方工具管理使用精简「我的工具」列表，权限位于各工具详情右上角「设置」，阅读目录的网页悬浮层另有眼睛按钮。**不要恢复旧版列表中的授权图标**，也不要将独立的外观「显示/隐藏」误认为授权本身。

## 本轮修复

- 在已有明确「授权当前网站」按钮之后，删除再次调用 `window.confirm()` 的三处重复问询，用户一次点击即执行。启用并不自动抓取完整网页或保存回答，实际数据读取仍须既有工具能力及用户操作。撤权不删除历史知识条目。
- 授权仍只按**已安装工具能力与精确 HTTP(S) Origin** 生效；知识保存按钮仅允许项目既有的 ChatGPT 域名白名单。保留工具版本身份、活动页面 document/URL 验证、同一存储锁、写后读回校验、撤销、跨窗口冲突拒绝。
- 展示权限说明而非弹窗；按钮 `aria-pressed` 显示真实授权状态，状态栏非阻塞提示。增加单个工具的操作中守卫，双击不能反转同一次操作，设置页的关闭和相关按钮在等待期间暂时不可重复点击。
- 「眼睛」只改变当前站点/页面的目录显示偏好，不静默授予读页权限；无授权时保持禁用并提示在设置中明确授权。
- **保留风险保护**：卸载和清除本地数据、放弃未保存编辑、高风险来源/版本变更仍需明确确认；Chrome 自身必需的原生权限对话框不能绕开。

## 影响文件与受影响验证

- `src/ui/sidebar-tools.js`：仅修改站点设置、显示开关并发守卫及三处 `confirm()`，保留现有 R4.7/R26 UI 与存储语义。
- `tests/environment/sidebar-tools-host.test.mjs`：三个工具逐一测真实设置入口、单击/连续点击/撤权、精确 Origin、过期页面拒绝及无 `confirm()`；阅读目录额外验证显示偏好不改授权。
- `tests/framework/reading-toc-native-r41.test.mjs`：真实安装 Side Panel 和网页浮层两次授权的 JavaScript dialog 数量为零。
- CI 复用现有 `.github/workflows/reading-toc-r41.yml`，其 main push 流程包含 Node、完整环境回归、构建/校验和受控 Chrome。对每次实际候选记录 Git SHA、通过/失败和 NOT_TESTED，不能借历史 CI 当新提交真实验收。

## 手工验证入口

启动 `python3 -m http.server 43111 --bind 127.0.0.1 --directory examples/tasks`，在 `http://127.0.0.1:43111/demo-form.html` 打开工具详情设置 → 点击「授权当前网站」→ 目录可见 → 点击眼睛隐藏/恢复 → 点击「撤销当前网站授权」。整个过程不应出现 JavaScript confirm。网页剪藏与知识收件箱按各自已支持的站点检查相同的开关流程。正式 Chrome 仍应遵循仓库隔离 Profile 和资源占用规则。
