## 实际日常路径与剩余缺口

1. 首次在**可信本地终端**运行 `node scripts/lock-program-remote.mjs examples/programs/remote-esm-page`，核对域名/URL、获取 reviewToken；再以 `--approve <reviewToken>` 发起明确批准。下载中新发现的 URL 必须逐项在终端交互确认。保留 `opendesk.remote-lock.json` 和 `.opendesk/remote-cache/<sha256>.mjs` 固定字节。第三方内容经哈希验证不代表已完成安全审计。
2. 用户用已有 Native/MCP 连接**有权读取**的合规项目，选择目标网站并**另行**明确运行。解析器仅用固定的本地闭包构建，不再访问 CDN；源码改动必须再次明确运行，不自动重放页面操作。
3. 需要发布冻结时才运行 `npm run build:program -- <项目路径>`；构建完成属于 `BUILT_UNVERIFIED`，不代表通过 Chrome 或已安装。
4. **未完成**：Sidebar/Workspace“一键审阅并锁定”原生 UI/写授权协议。Provider 当前 `projects.list/project.resolve` 只有只读取源职责。本地 CLI 用本机 OS 用户权限访问用户指定目录，不冒用 Go Native 临时 lease；如要 UI 接入需先实现 Go/Node/Browser 新的明确 RPC、目录和绑定身份、读写授权、来源/连接代次、源码/URL 审批指纹、撤权和并发验证，并完成真实 Chrome 测试。不把现有 RW 文件编辑授权错误扩展成网络依赖写锁权限。
5. Browser 运行世界仍以 MV3 User Scripts/RunHost 固有边界约束；Go `.mjs` 具名导出 `main` 与 Browser 默认函数出口不同。无法安全确认的 Node API/动态 import/裸名远端模块按现有合同拒绝。
