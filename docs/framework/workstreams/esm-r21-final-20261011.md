## HTTPS 参数泄密额外修复

审计发现公开 HTTPS 模块 URL 可以含 `?token=` 或 `?api_key=` 等键；原实现将 URL 原文放进 reviewToken 可见审阅、下载错误和版本控制锁。此轮新增 `E_REMOTE_URL_SECRET` 离线拒绝含疑似凭据的查询参数，错误不回显 URL 原文；允许 `?target=es2022` 一类非敏感配置查询。负向测试证明审阅失败不启动 Mock 网络也不提交锁文件。该保护不能自动撤销历史提交里已经泄露的密钥，历史误入库需要另行吊销轮换。

## 真实 Chrome 首轮失败与只读 ping 修复

候选 `3b84a7d5cdb37724b69a7cfeed649959a7001b5c` 上运行既有隔离 macOS CFT/MCP 工作流：[失败原始 run #38111642158](https://github.com/shopable-ai/opendesk-browser/actions/runs/38111642158)。Native 安装与真实握手 PASS、Controller 多文件 `sourceHash`、`runId/resultId/documentId` 已建立；但第一个 `page.title()` 的只读 readiness ping 报 `E_CHROME: The message port closed before a response was received.`，持久结果为 FAIL 且资源释放。未伪造成功。

原 `pageReady()` 只识别 `Receiving end does not exist` / `Could not establish connection`，遗漏 Chrome 155 上其它 onMessage listener 收到无响应 ping 时返回的 port-close 形式。只对**只读 readiness ping** 扩展此种反馈的固定 Page Session 注入；注入前后沿用 `verifyTarget`、真实 `documentId` 与固定脚本路径。不重放 `execute`、页面提交或用户脚本。组件回归模拟该 Chrome 错误并检查一次注入及唯一实际操作；新候选须由下一次真实 macOS workflow 复核，不能以旧通过掩盖本次失败。
