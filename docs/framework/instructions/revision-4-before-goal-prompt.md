# OpenDesk Browser：交付可使用的脚本工作台

继续完成 `/Users/shopme/Documents/workspace/opendesk-browser`。用户最终必须能亲自完成：

**选择网页并授权 → 编写脚本和参数 → 保存版本 → 选择版本运行 → 随时停止 → 查看结果或错误 → 下载文件。**

完整流程必须在真实工作台和真实浏览器中通过。下述三步用于说明当前在交付什么；原始任务的范围、限制和全部必选验收仍由 [goal-constraints.md](./goal-constraints.md) 及其冻结附件约束。

## 第 1 步：用户写的脚本能操作网页

先执行用户输入的 async 函数体，而不是只运行工具内置示例。用参数指定网页，实际打开它并返回标题和地址：

```js
await page.goto(params.url);
return { title: await page.title(), url: await page.url() };
```

接着验证输入文字、点击按钮、等待页面变化和读取内容。还要验证脚本报错、操作失败、超时、停止，以及越权和伪造请求被拒绝。死循环是否真正停止、停止后是否释放资源，必须有独立浏览器证据。

本步交付：实际操作及返回值、失败原因、停止和隔离的验证记录，经独立复核判断是否通过。测试运行器能执行脚本，不代表用户已经能从工作台使用它。

沿用已批准的执行方式和 classic Blob 的已有局部证据；保留其他加载方式的失败结果。不要求四种加载方式全部成功。测试程序自身出错与必需执行能力失败分别记录，不把尚未测试当作缺少前提。

## 第 2 步：用户能从界面编写、保存和运行

第 1 步的必需验证通过且独立复核有效后，接入真实工作台：

- 选择明确的网页范围并授权。
- 编辑脚本和参数，保存后看到版本。
- 选择一个已保存版本，点击运行或停止。
- 查看运行状态、返回结果和错误原因。

本步交付：用户能亲自在界面完成这些操作，并有从界面开始的浏览器验证记录。使用现有公共底座，不建立第二套权限或运行记录。

## 第 3 步：保存的版本、结果和下载可靠

从同一个真实工作台验证：

- 运行版本 A 时保存版本 B，A 的执行内容不变；删除脚本也不破坏正在运行的版本。
- 停止、超时、撤权或连接丢失后，不重复执行结果未知的写操作。
- 关闭工作台后旧任务被隔离；重新打开能查到已保存的状态。显式重跑才开始新任务，不恢复旧程序栈。
- 返回结果和错误真正保存下来；下载真正完成，实际文件内容与记录的 hash 一致。
- 全程不依赖采集模板、采集权限凭证、行数据或封存流程。

本步交付：完整用户流程、原始全部必选用例及独立代码和功能复核的实际证据，绑定同一个最终包。全部通过后才宣布完成，随后停止，不进入采集迁移、优化或发布。

## 执行时怎样报告

每次更新先写清楚“当前是第几步，正在交付哪一个用户操作”，再只报告：

1. **已经能做什么**：明确是在测试运行器还是在真实工作台中能做。
2. **实际验证了什么**：写用户进行了什么操作、得到了什么结果。
3. **还差什么**：将失败、尚未测试和不支持分开；指出当前阻挡进入下一步的具体问题。
4. **下一步交付什么**：写一个具体结果及通过标准，不只说继续研究或补测。

同步维护 [progress.md](./progress.md)。工程实现、浏览器诊断、审查编号、hash 和完整日志放证据附件；不能用这些内容代替用户进度。需要比较时，只使用“用户要求｜实际操作｜实际结果｜证据｜是否通过”表。

## 继续与停止

当前原生 Goal 处于运行状态时，继续已经授权、可逆且在原范围内的实施和验证，不停在说明或计划上。必需能力真实失败、必要前提确实缺失或独立审批不能通过时，按原始停止规则保存证据并暂停；不造替代后端、不扩大研究。

以原生 Goal 的实际状态为准。用户暂停后不自行恢复；恢复当前开发工作时不恢复或消息启动旧审计 Goal、旧实施任务或旧②B。完整执行边界、权限和验收见 [goal-constraints.md](./goal-constraints.md)，这些要求不因本提示词改写而缩减。
