# 定时计划：从已验证任务到真正自动运行

OpenDesk Browser R1，2026-10-12。本说明描述产品入口和必须满足的前提；Mac Chrome 整体 E2E 以工作流验收记录为准。

## 如何创建第一个定时计划

1. 在 Chrome 中打开要操作的 HTTP(S) 网页，例如本地的 `examples/tasks/demo-form.html`。确保扩展已被明确授予该网站权限。
2. 在 Side Panel 的「我的」安装一个**已验证**的 Controller Task。如果还没有，使用已有「开发」流程：写脚本 → 在目标网页真实运行 → 保存版本 → 以真实完成且资源释放的 RunId 验证 Task 候选 → 转为 Available → 明确安装和授权。仅复制未验证的源码无法排程。
3. 点击「我的」中「自动化任务」右侧的时钟图标，选择「新建计划」。在「执行任务」下拉框选择任务。**右侧两个图标**分别是新建脚本与管理任务；它们不属于下拉选项。
4. 填写计划名称、精确目标 URL、JSON 参数，选择执行一次、每天、每周或间隔；填 IANA 时区（例如 `Asia/Tokyo`），查看「预计下次」；根据需要在高级选项设置错过规则、等待时长及是否允许主动新建目标标签页。
5. 保存计划后返回列表，检查下次执行时间。点击「打开运行页」打开可见的独立 OpenDesk 运行页。它和 Side Panel 使用同一个 RunHost/Authority；关闭 Side Panel 时，**只要运行页仍保留**，就能继续承接后续计划发生。关闭两者会显示等待宿主，而不会暗中运行脚本。
6. 到期后查看本次发生状态、RunId 和 ResultId，并验证目标网页确有实际效果。只有真实原生运行、结果落盘且资源释放才可当作任务完成。

### 目标网页与运行条件

- 如不勾选「允许新开标签页」，到期时需要已经打开**精确相同 URL**、非隐身、完成加载的目标主文档；否则会等待目标，过期后按策略跳过。
- 如勾选，则在没有符合条件的现有文档时允许由受控 Controller 创建新标签页；每次启动仍先经过当前网站权限、安装身份和 Authority 的校验。
- 浏览器关闭不会凭空执行到期任务。重新打开浏览器且存在合法宿主后根据计划的错过规则处理。选择「跳过」就不会补跑错过的执行；「只补最近 1 小时内的一次」只考虑最近一次，且不会对已经派发或结果未知的任务重新执行。
- Chrome Alarms 是**可能被延迟的唤醒提示**，不能承诺毫秒级或严格整秒触发。运行页不是后台守护进程，受 Chrome 浏览器生命周期制约。

### 管理任务和计划

在执行任务选择器右侧点击「管理任务」图标，可搜索和筛选已安装任务，查看版本与授权网站、关联定时计划，停用/启用、卸载、复制到开发、为指定任务设置定时。卸载或更新不会自动授予原计划新权限。旧 FireId/RunId/ResultId 不会因删除计划而变成新执行。

计划列表中的「编辑、暂停/恢复、删除」直接更改持久记录，不触发原生弹窗。更改计划会增加授权代次，避免已有到期通知用旧规则执行。

### 未知效果与故障处理

- `READY / WAITING_HOST / WAITING_TARGET / WAITING_SLOT` 表示尚未开始新的原生执行，可在截止窗口内检查条件。
- `ADMITTED` 已经绑定真实 RunId/ResultId；一个 FireId 永远不创建第二个 Run。
- `UNKNOWN / NEEDS_ATTENTION / MISSED` 不执行盲目重试，请检查权限、任务版本、目标网页及原始运行记录。
- 不要把 Alarm 到期通知、静态截图或前端 Mock 测试当作脚本执行成功的证据。
