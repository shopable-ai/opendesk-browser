# 网页增强性能：本轮目标与关键测试条件

日期：2026-11-14。阶段：核心开发与最小验证。用户要求在尚未完成优化时设置目标与关键测试条件；本合同对应本对话新建原生目标，不恢复、迁移或改写历史目标。

## 当前结论

**整体优化尚未完成。** 既有改动已明显改善用户体验，但上一轮没有新增源码修复，也没有证明三项增强满足统一的可用性等待目标。

- 用户反馈队列约 10 秒改善至约 2 秒；这是体验反馈，不是 P95。
- 上轮一次导航起算观察：队列约 2.10 秒、导航 Dock 约 3.58 秒可见且可命中，目录约 3.48 秒可见；目录收起/恢复和导航回顶/到底部实点成功。这些值不是相应网页前置条件就绪后的等待。
- 上轮队列仍有世界锁约 104ms、第二次 fresh FULL 约 66ms、原生三次隔离证明约 287ms；导航实际 ready→lease 等待约 2.04 秒。均为单次区间，不能相加或直接推导可节省时长。
- 上轮旧编辑器定位器失配，目录为 closed ShadowRoot，且所测会话没有标题：尚缺有效的 ready→可用区间、目录章节跳转及持续运行开销证据。

已有成果和拒绝路线按 [复用经验](page-startup-lessons.zh-CN.md) 保留；完整历史事实仍归 [原性能记录](page-startup-performance-20261113.zh-CN.md)。上轮独立证据为本机 `artifacts/page-startup-incremental-20261114-53/result.json`，不是本轮新候选证据。

## 目标与完成条件

**阅读目录、AI Send Queue、适用的 AI 对话滚动导航，在各自网页前置条件满足后，1 秒内真正可操作，并在随后至少 5 秒的短观察中保持可用。** 提示词快捷按钮作为同页体验参照；保留动态 Page 的原执行世界、安装链与权限边界。

1 秒是本轮设置的开发目标，不是用户历史测得值、旧 P95 承诺或正式验收结论。导航起算总时间同时记录，以免只优化局部却没有改善用户体验。

完成必须同时满足：

1. 三项适用行为各有同一最终候选下的 3 次连续有效观察，每次 ready→真正可用的保守上界均 ≤1000ms；不向下取整。队列与导航可共享一次页面访问，目录使用确有标题的已批准网页。首次已超限就记录失败并停止该候选的余下计时，不补快样本。
2. 队列按钮可见、启用、可命中且可键盘聚焦；目录展开/收起及章节跳转有效；导航实际滚动至预期目标，且适用的回复内导航没有同目标重复或遮挡。三项的真实操作与计时证明分开记录。
3. 本轮相关行为、身份、安全与生命周期检查通过，原有任务、草稿、来源、撤权、unknown 与不重放保护保持有效；没有新错误或观测到的失用。运行中的身份与实际交付候选一致。
4. 新增性能改动有同口径真实可用等待的改善证据。仅有微测、Node PASS 或单次快值不算提速；没有收益的实验撤回。如果初始核对已经满足以上全部条件，可直接复用既有成果，不为制造工作修改源码。

任何一项未满足，目标仍未完成；“本轮无足够证据继续某条路线”只能报告未完成和剩余假设，不能标记目标成功。

## 关键测试条件

| 条件 | 必须证明的行为与判定 |
| --- | --- |
| 真实入口与身份 | 仅在已批准且安全空闲的页面操作；按 `targetId→tabId→documentId` 精确绑定，核对已安装版本、源码/清单/授权代际与 applied 候选。相同 URL 或 active 不能代替精确绑定。运行身份或并行构建变化时，相关观察作废并保留原因。 |
| 队列起点 | 当前站点适配器真实识别的编辑器及所属表单已连接、可见，插入位置存在。先验证当前定位器，不再依赖失配的 `#prompt-textarea`。起点不能移到框架授权完成、lease 获取或程序回执之后以隐藏等待。 |
| 导航起点 | 唯一滚动容器和真实会话目标已可识别、可见，存在可滚动距离。回复内按钮另要求同一条长回复及其合法工具栏已就绪；Dock 与回复内按钮分别判断适用性。无长回复不能充当回复内导航通过。 |
| 目录起点 | 已批准站点的正文和实际标题候选已连接、可见且可滚动；原目录功能有效。没有标题只能记不适用，不能用空目录证明章节索引/跳转。closed ShadowRoot 的真实操作由 AX 控件完成。 |
| 终点与持续性 | 分别记录首次可见和首次真正可用。真正可用要求目标控件可见、未禁用、真实命中/焦点可达；加载壳和占位不算。终点后至少观察 5 秒，并做对应无害操作；出现消失、遮挡、重复或点击无效则失败。 |
| 计时质量 | 同时保存导航、网页前置就绪、首次可见、真正可用、观察结束的时间；记录扫描间隙，使用保守区间上界。页面隐藏、绑定变化、定位失败或观测缺口不足以判定阈值时，记无效/未知，不算通过或产品故障。 |
| 公平比较 | 同一次改动的前后比较保持页面入口、视口、适用内容、安装集合、功能配置和运行模式一致。只补旧证据失效或改动直接需要的比较；最多 3 个有效观察/候选/适用行为，保留全部失败与无效原因。不是 P95 或稳定性统计。 |
| 行为检查 | 队列在真实网页仅检查显示、命中与焦点，不入队或发送消息；队列调度/恢复用已有相关定向测试。导航实点回顶/到底部及适用的回复目标；目录实点章节并核对滚动落点。恢复本轮改动的显示/滚动状态。 |
| 安全与生命周期 | 只针对改动涉及的保护运行现有定向检查：身份/来源/精确 document、安装/撤权、同 owner 保序、手动 Run、unknown、不重放、一次性准备句柄、原 2/4/8/6 容量，以及取消/导航/清理。结束后精确回执结算、相关 slot 释放；不以全部 completed 代替 UI 可用。 |

## 执行顺序与边界

1. 保留已完成的存储、准备、准入、授权及世界分配优化。仅复核下一条操作依赖的当前源码、安装身份和运行候选；不从头重做调查。
2. 先修正本次观测所需的编辑器定位与精确目标绑定，沿用轻量观测，独立命名新产物；旧原始材料只读。修观测不算产品提速。
3. 优先确认世界锁、第二份 fresh FULL、原生证明及实际父 lease 占用中哪一项确实阻塞当前目标；一次只选一个有证据的最小改动。不同时改框架和三个工具，不默认修改目录索引、650ms 轮询或导航广域观察。
4. 先运行直接相关的行为/安全检查，再复用唯一 dev writer 更新所需候选，最后进行上述有限核心验证。没有新源码、身份变化或新失败，不重复已有效的测试/构建/采样。
5. 候选没有改善就保留失败并撤回无收益改动；连续两项同路线实验无收益且无新因果证据时停止该路线，报告剩余假设，不扩成长时间刷新或取样循环。

仓库只在现有 `main` 工作；不建分支、worktree、PR，不提交或推送。保留 `dist/development`、原扩展 ID、Profile、Native 配对和所有并行服务。浏览器遵守 ego-browser TaskSpace 所有权；旧 Space53 已释放，不接管用户 Space50。不得发送 ChatGPT 消息、创建 Subagent 任务或为测试升级业务包。
