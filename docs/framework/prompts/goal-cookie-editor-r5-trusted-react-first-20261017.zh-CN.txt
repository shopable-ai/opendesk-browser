## 三、P0 实施顺序（不再反复重讨论架构）

### P0-1：源码及预览同源

核对用户已认可的 R4.9.2 样式与随后 R4.10.x/R4.11 的最新交互改动；不要凭旧 README 恢复过时的导入预览或多次确认。实际运行现有 preview/react 的构建一致性检查；仅在必要时用原构建器刷新可双击打开的离线 HTML，不直接手改内联 bundle。

从已批准 App.jsx 中渐进提取可复用的 CookieEditorView/专用组件；同一个 JSX View 同时作为可信 UI 和离线 Preview 的呈现来源。模拟数据、场景开关、模拟授权和等待时钟只留 Preview Adapter，绝不进入正式 Host 业务。

### P0-2：真实共用组件，不创建第二套 UI

复用 src/ui/react/components/ui/button.tsx 已有的 Button/IconButton，引用官方 Tokens 和现有 CSS primitives；只有真实需要且两端消费者确实复用时，再最小增补 Field/Message/Menu 等。

保留原有 380px 紧凑布局、顶部导入/导出/新建、行内编辑、Value 显隐按钮位置、语义 dirty、授权后隐藏引导、焦点和浅深色；未提出修改的区域不重新设计。输出实际复用组件/调用次数、已消除的重复定义、硬编码 Token 改动，不能把 UI 共用比例 0%（原基线）伪报为已完成 50%/80%。

### P0-3：优先完成无敏感数据的 Trusted React 最小试点

使用已经静态审核/编译的 Cookie UI JSX，以虚构 Cookie 元数据，在现有 src/ui/react/main.tsx 的**唯一宿主 React Root/Portal**中展示并正确卸载；不创建第二 React Root、第二入口、第二 Installer、第二 SDK/Host。先核对 R33 当前文件 owner 与并行任务，不直接重写六 Tab。

先调查 src/ui/trusted-cookie-workbench.js 的**实际引用和功能重叠**，以及 Time Review 已实现的可信 UI 固定准入。不能为 UI 名称创建第三套 Cookie 工作台。

证明：静态编译的受审 UI 可直渲而不使用 iframe；普通安装、同 ID 冒充、来源/哈希/版本失配、启停和 epoch 撤销后的动态 JS 始终留沙箱或安全拒绝。禁止从 JSON、用户文件、远端/CDN、AI 生成字符串加载 JS 到可信页；不通过任何 trusted:true/admin 标记提权。

此阶段只使用虚构数据。必要的非敏感 Demo 对照、DOM owner、卸载、旧 instance 失效和构建证据必须实际执行；未知项保持 NOT_TESTED。

### P0-4：通过 P0-3 后接入正式 Cookie 核心操作

正式能力只能复用现有可信 Host、Browser SDK/原权限与数据合同。React 负责视图与组件状态，Controller/Adapter 负责真实网站、授权、Cookie 列表、精确保存/删除、导入导出、错误回执及生命周期。不能让旧 DOM renderer 与 React 同时更新同一节点。

保留当前网站和合法自定义目标、Store/PartitionKey 完整身份、Value 授权、写入回读、重命名、过期与无效记录、setMany/单条 set 回退、未知结果不自动重试、输入保留、离线工作区、观察和清理；已经实现的功能不能因 Preview 没画出而丢失。

操作体验：导入文件或粘贴内容后自动解析，**一次明确点击执行**，不新增独立预览页、重复导入确认；复制/下载正常情况一次操作，不额外发明确认弹窗。仍保留真实 Chrome/Host 必需的网站及敏感 Cookie 值读取授权和危险操作安全限制。写入结果未知不能误报成功或自动重放。

### P0-5：真实编译、预算、安全与回退

同时对照两种路线：
A：React Sandbox 预编译后的主 JS <= 220000 原始 bytes、完整 JSON <= 320000 bytes；不得用 gzip、CDN 或放宽 CSP 伪通过。
B：现有 WXT 固定入口的真实增量、React 是否运行时去重、现有 extension 安装/权限/内存/升级代价；只有审计来源和准入均实测通过才可以逐步启用。

React 19/JSX 开发允许编译，但保存代码应通过原有 Vite/WXT/dev 自动构建，不要求用户每次手动打包。独立 file:// 预览仍直接可打开。不要新增 packages/opendesk-ui-react、动态渲染 DSL、第二 React Root 或全量重做构建器。

如果 B 无法在已有安全或包体积合同内成立，保持 A 和正式 2.0.23 原样，不强迫改成危险的可信 UI；若确有可证明且安全的最小修复，则只修改必要模块。正式发布前必须明确“更新浏览器扩展”与“仅更新 Cookie JSON”的不同机制，不能声称只换 JSON 可部署内置可信代码。
