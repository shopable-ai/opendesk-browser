## 二、默认先验证真实本地接口

从仓库根目录，先确认 examples/tasks/request-sample.json 存在且 JSON 可解析，再运行：

python3 -m http.server 43111 --bind 127.0.0.1 --directory examples/tasks

实际浏览器唯一 URL：http://127.0.0.1:43111/demo-form.html

GET http://127.0.0.1:43111/request-sample.json => 真 HTTP 200 JSON，source 应为 opendesk-browser-local-fixture。
GET /__opendesk_expected_404__.json => 真 HTTP 404。
GET /demo-form.html => 真 HTTP 200 text/html，界面仅显示文本，不执行响应 HTML。

若默认请求 404，先检查 checkout 是否包含 JSON 文件、根目录和服务器端口；不得制造假 PASS 或改用 mock 对付失败。

需要服务端真实延迟、状态码和 POST 才将 Python 服务优雅退出、改用：

node examples/tasks/http-test-server.mjs 43111

真实测试接口：
GET /__test__/status?code=429 => 429
GET /__test__/status?code=500 => 500
GET /__test__/text => text/plain
GET /__test__/delay?ms=2000 => 延迟后 200
POST /__test__/echo，JSON {"hello":"OpenDesk"} => 返回包含 received 的 JSON 200

必须先检查端口占用，不能无条件杀死其他程序。

## 三、网页 MAIN OpenDesk SDK axiosx：最高优先级

构建扩展并用隔离 profile 的真实 Chrome / Chrome for Testing 加载 dist/development；不要关闭 Web Security、伪造用户事件、合成 native ack 或模拟通过。

目标网页必须是真实 HTTP 标签页。通过扩展现有「独立网页 SDK」选择当前 tab/frame/documentId、勾选 network、可信用户点击批准并安装；按需批准额外目标 Origin。验证 ISOLATED relay + MAIN SDK 安装在相同精确 document，且 window.OpenDeskSDK.ready() 返回正确 allowed methods。

页面第 06 组的 #api-send 只验证网页 fetch。MAIN SDK 使用下述独立调用入口，验证真实调用经 SDK -> Relay -> Broker/Authority -> 扩展后台 HTTP Driver，返回 data/status/headers；不能用该按钮的 DOM 结果替代 SDK 回执。检查 HTTP status=200、真实 JSON source 和实际 SDK operation/目标证据。

在 DevTools 的目标网页 MAIN 中可独立验证：
const sdk=window.OpenDeskSDK;
await sdk.ready();
const response=await sdk.axiosx.get('http://127.0.0.1:43111/request-sample.json',{timeout:5000});
console.log(response.status,response.data,response.headers);

未安装 SDK、没有 network 能力、拒绝站点权限，应明确报 E_SDK_UNAVAILABLE/E_CAPABILITY 或 Broker 实际错误；绝不可自动转为 Fetch 成功。

再验证真实 HTTP 404、429、500；SDK 非 2xx 按当前 E_HTTP 契约检查 status/response，网络失败与超时不可误报 HTTP 200。

## 四、跨 Origin CORS 对照：验证扩展的核心价值

保持 43111 的 Node 服务，在另一个终端运行：

node examples/tasks/http-test-server.mjs 43112

从 43111 网页发起 GET http://127.0.0.1:43112/request-sample.json：

A. 在页面第 06 组填入该 URL 并点击“发送 GET”：浏览器按标准 CORS 应阻止网页读取；43112 服务器应确实收到请求并返回 200，但不提供 Access-Control-Allow-Origin。检查真实 DevTools Network/Console 而非 Node fetch。
B. 使用上述 MAIN SDK 的 sdk.axiosx.get 调用，尚未批准 43112 额外目标 Origin：Authority 应拒绝，不能发到未授权目标。
C. 通过真实用户权限对 43112 Host Permission 和精确目标 Origin 明确批准后，使用网页 SDK axiosx 发同一地址，应可以从扩展后台获取 JSON 200（以真实结果为准）。
D. 撤销权限、页面导航、扩展 Worker 重启后，旧授权不得继续通行；确实需要重新授权时遵循现有机制。任何不确定副作用不能盲目重试。

不允许无条件授予所有目标 Origin 来图方便。原生权限和 SDK 应用级目标授权必须同时满足。

## 五、POST、超时及取消边界

在 Node 辅助服务模式下，通过 sdk.axiosx.post 向 /__test__/echo 发送 JSON {"hello":"OpenDesk"}，核实真实回显与后台 HTTP 请求；页面单 GET 按钮不承担 POST 验收。
使用 /__test__/delay?ms=2000 验证网页 GET；MAIN/Worker axiosx 另设短 timeout 检查各自超时错误。
特别注意：axiosx 当前公开 facade 不接受逐请求 AbortSignal。网页 fetch 在编辑 URL 或重置时的 AbortController 中止，不证明独立 SDK 请求被取消；关闭显示/停止等待也不能算后台 HTTP 中止 PASS。
连续网页 GET、切换 URL、重置后，旧结果不得写入当前 DOM。用实际原生浏览器逐次复现；SDK 的取消与 OUTCOME_UNKNOWN 边界按已有服务合同独立记录。
