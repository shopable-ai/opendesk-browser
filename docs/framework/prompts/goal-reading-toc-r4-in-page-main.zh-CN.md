## 三、冻结 UI 要求（未经用户复核不得改变）

- 原网页靠右区域的紧凑白色/暗色卡片，轻描边、圆角；顶部 `CONTENTS` 和三个仅图标按钮：一级、当前章节、完整目录。保持原型的紧凑行距，目录文字单项最多 **两行**，超出截断，悬停/可访问名称给出完整文本。
- 当前标题使用左侧蓝色细线表达，不添加大面积彩色背景。**无搜索框、说明文字、上一节/下一节、底部留白区**。
- 悬浮目录不遮挡网页正文、操作区、ChatGPT 输入框。窄屏优先收纳/显隐，适配大网页和不同滚动容器；具体挂载方案由真实站点测量确定，但视觉须保持接近原型。
- 三个视图只控制展开深度，**不**改变阅读范围、更换回答或触发正文滚动。点击章节才执行定位；正文自然滚动只更新当前项高亮。
- 兼容明暗、200% 缩放、键盘、aria-pressed/aria-current、prefers-reduced-motion。所有用户可见提示要简短，避免永久占用卡片空间。

## 四、P0-A 多 H1、分框与边界（必须防回归）

**绝对禁止**使用 `h2,h3...h6` 而忽略所有 H1；禁止因为“文章 H1 通常被省略”就把该规则应用到会话。

- 单篇文章：如果能可靠识别页面题名 H1，可以在目录中省略**这个确定的题名节点**，但必须索引正文内部出现的其他 H1。文章从 H2 开始，也能把首层 H2 作为目录一级。不能全局或按数量过滤 H1。
- AI 会话：一个回答可含多 H1，多条回答各自也可能 H1；每条逻辑回答/版本独立维护 heading 栈，同一回答经确认的多个 DOM 片段延续同一 heading 栈，不跨不同消息/版本套父子关系。
- 用户看到多个内容框时，不等于多个逻辑消息：仅当实际目标网站有可验证的归属证据，才能把同一回答的多个内容片段合并。没有证据则保守显示独立对象或“不确定”，不得按视觉相邻、文案相似度猜合并。
- ChatGPT、知乎、多回答页面需分别提供适配器，不能使用原型 `data-source-group` 作为真实页面选择器。不预设某个稳定 message ID 已存在；每个适配器以本机目标版本 DOM 实测为准，有退化/失效保护。
- 重复 H1、重复“总结”、两个 heading 具有相同 `id`、无 id、H2 后 H1、跳级 H3 等，都不能丢目录或误跳。私有身份绑定元素/来源/回答/版本；**不得改写网页原来的 DOM id、location.hash、history、已有锚点或消息 HTML**。
- 跳过 pre/code 内伪标题、隐藏/装饰节点和本工具自身。多框与代码围栏并非必然因果；流式 DOM 结构变更需重新验证，而不随意推断补全文本。

## 五、P0-B 正文点击定位与性能

- 识别真正的滚动根（窗口或内层滚动容器）；点击精确标题时滚动至可见区域，计算固定顶栏与可用视口。不得以调用 `scrollIntoView` 作为唯一成功条件；结束时复核来源、版本、目标节点可连接及实际位置。
- 用户滚动、点击其他章节、切换会话、关闭工具时取消旧跳转。正文滚动只做单向更新目录高亮；避免跳转与 scroll spy 相互循环。
- SPA 会话切换、增量/流式生成、回答重新生成、历史懒加载、折叠/隐藏内容、嵌套滚动区、来源页面卸载都要有生命周期策略；不能无限自动滚动加载历史内容，更不能跳到旧 ID 对应的不同消息。
- 使用限定范围的 MutationObserver/IntersectionObserver 或等价可证明方案，增量去重、节流/资源释放。长会话 100+ headings 的更新、滚动/CPU/内存有实测结果；不要每个流式 token 全文扫描和大规模重建。
- Content Script 和 TOC 视图隔离样式与事件，不扩大网站攻击面。任何网页 DOM 文本不通过 `innerHTML` 不安全注入，遵守 MV3/CSP/权限生命周期，插件卸载/停用后必须彻底清理注入节点与监听。

## 六、实现次序、最低真实验收和回报格式

1. 阅读/核对当前 main 与原型，画出通用索引器、站点适配器、目录视图、滚动定位的文件/接口图。复用当前入口与能力，不另建第二套 Page SDK/自动化内核。
2. 先完成最小功能闭环：通用文章 DOM 测试页 → 生成 H1..H6 TOC → 三种视图 → 点击滚动 → 高亮跟随 → 切换/销毁。
3. 然后处理**多 AI 回答和多 H1**：至少覆盖一个回答三个片段，其中前两片段均有 H1；第二条独立回答包含自己的 H1/H2；重复“总结”、重复 DOM id、标题缺失和不确定边界。
4. 依次对可访问的真实 ChatGPT、知乎页面测试：记录实际 DOM 结构、适配成功点、权限和限制；无法安全访问的站点标注 **NOT TESTED**，使用静态仿真并保留真实站点待验项，不假报通过。
5. 运行既有项目检查、`npm test`、`npm run build`、生产包验证；检查 Chrome 实际加载路径、扩展版本和 profile，避免加载旧 build 干扰。
6. 真实 Chrome 分别验证文章外层滚动、ChatGPT 风格内层滚动、多个 H1、多个逻辑回答、同名标题、代码块伪标题、滚动中断、缩放、深色和窄屏，无控制台错误，截图留证。
7. 当前原型的 36 条独立浏览器检查仅作为设计底线；正式实现必须增加仓库可重复执行的测试与真实扩展验收。发现缺陷立即修复并复测，不以测试文档代替代码完成。
8. 最终只在 `main` 提交、合入/推送，提交前重新核对并行修改。输出 commit SHA、文件清单、功能树完成状态、检查命令/结果、真实 Chrome 测试环境与证据链接、未测项和下一轮缺口。质量目标独立评估争取 ≥95/100，**没有证据不得自评 95+ 或宣布完成**。

## 七、验收重点检查表

- [ ] 普通文章的明确页标题 H1 可不在 TOC，但正文另一个 H1 仍存在；只有 H2 的文章不会空目录。
- [ ] AI 回答 A 内的两个 H1 均在一级目录；回答 B 的 H1 也在，同名小节可各自定位。
- [ ] A 跨三个展示框，第二 H1 在第二框，后续 H2/H3 在第三框；章节层级不跨消息串联。
- [ ] 人工插入两个重复 DOM id，目录不丢项、跳转正确、原网页 DOM id 不被改写。
- [ ] 三种视图切换不带动正文；点击目录滚动到真实目标；滚动正文仅更新蓝线。
- [ ] 生成中、改写内容、SPA 切换、历史未加载、关闭/权限撤销时不串来源、不留旧 DOM 监听。
- [ ] 极简卡片无底部导航/多余文字、目录最多两行、窄屏不遮挡、性能可接受。
- [ ] 原型、源代码自动测试、真实 Chrome 扩展与实际站点测试，分别有明确证据等级。
