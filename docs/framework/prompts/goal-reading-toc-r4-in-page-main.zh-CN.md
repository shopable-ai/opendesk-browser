## 二、产品形态、功能树与不可改变的架构决策

### 2.1 产品定位（不可漂移）

OpenDesk Browser 仍是**一个 Chrome MV3 扩展**；TOC 是安装在 Side Panel **「工具」Tab** 的一项官方参考工具（开发者亦可从本地文件安装），**不是再安装一个 Chrome 扩展，不新建一级工作台 Tab，不把网页 TOC 移入 Side Panel 才能使用**。

- **安装与管理发生在 Side Panel「工具」**：从本地 `.opendesk-tool.json` 导入 → 检查版本、来源、能力、适用站点 → 用户确认安装/启用 → 出现在已安装工具列表 → 设置当前站点/允许的网站 → 停用/卸载/更新。
- **一个工具、两个展示入口（共用一套索引）**：在 Side Panel「工具」打开「阅读目录」时，可在工具自身紧凑界面查看当前网页目录并点击章节定位；同时可选择在 ChatGPT、知乎、文章等原网页显示 R3 极简卡片。两种展示均操作宿主同一内容索引与导航接口，**不得重复实现两套标题解析、跨消息归组或滚动引擎**。不强制 Side Panel 常开，网页内目录也可独立运行。
- **Side Panel 关闭不应导致已启用 TOC 失效**：TOC 是独立于 sandbox iframe 开合的受信网页功能，受用户安装/启用/网站范围控制；仅关闭工具 UI 不等于停用。
- **安装是用户控制的状态变更**：导入、预览包不运行；未经用户确认不安装、不开启网站读取；授权在安装或首次启用/扩权时处理，已批准范围内正常运行不反复弹窗。扩权或撤权后按既有权限恢复机制处理。
- **后期工具市场是安装来源，而不是第二种工具执行引擎**：本轮只做可扩展合同/入口约定，不搭建在线商店、不让远端网页静默安装或执行 JavaScript。

### 2.3 必须先审计的现实限制和升级边界

现有 `opendesk.sidebar-tool.v1` 由 `src/ui/sidebar-tools/package.js` 严格校验，其权限白名单**目前只有** `storage.local`、`currentPage.read`、`tasks.open`。其中 `currentPage.read` 经 `currentPage.info` 实际仅提供当前网页**标题和 URL**，不是 DOM、Markdown 或目录。现有工具 UI 在 opaque-origin sandbox iframe 中，关闭或切换工具时销毁 iframe，无法依靠它在网页上常驻。**直接导入一个带 TOC HTML/JS 的工具包并不会让网页出现目录。**

R4.1 必须就地增加最小、明确可审计的**宿主托管 TOC 能力**，例如经设计审阅后的窄能力 `page.toc`（具体接口名可调整，但须提供合同、验证和测试）；这是一项“获取已授权网页的有限标题目录快照 / 精准跳转 / 启停受信网页目录”的能力，**不是**“读任意 DOM / eval / 注入脚本 / 获得 chrome.tabs”能力。第三方包无论声称什么，都不得绕过用户授权、安装实例验证或使用该能力执行自己的代码。

优先保持 `opendesk.sidebar-tool.v1` 现有包可照旧安装和使用，不得为了 TOC 破坏已发布工具。若需新增 manifest 字段/包格式，先给出 v1 兼容性与迁移测试，选择最小增量；站点启用范围可以作为宿主安装元数据而不是任意 JS。目录服务必须允许关闭 Side Panel 后独立受控运行，不能借 sandbox iframe 生命周期驻留。官方 TOC 工具的目录数据由宿主内容索引生成，不依赖外部服务。

参考分层：

```text
Side Panel「工具」：安装/审核/启停/站点策略/版本 + 紧凑目录查看与跳转
        ↓ 受信管理接口与持久安装记录
扩展宿主：TOC 能力授权器 + 站点范围 + 标签/文档身份/撤销
        ↓ 受控消息（仅已授权 TOC 操作）
网页可信 Content Script：提取章节 → 渲染紧凑目录 → 点击定位
        ↕ 状态（不得要求 Side Panel 运行）
当前网页
```

工具 sandbox 的 `OpenDeskTool.request(...)` 可用于请求经过审核的有限 TOC 快照/定位/状态/开关等窄操作；禁止把网页 Element、函数、原始任意 JS、全局 chrome/DOM 句柄直接交给该 sandbox。消息须校验 toolId、实际安装包与 capabilities、发送者、tabId/documentId/frameId、来源 origin、请求会话和数据大小；页面来源变化/工具卸载即撤销旧请求。所有不受信网页内容以 textContent/等价安全方式渲染。

### 2.4 安装方式和后期市场的兼容路径

**本轮 P0 真正交付两条路径**：

1. **本地导入**：`工具 → ＋导入 → 选择官方参考 TOC 包 (.opendesk-tool.json) → 审阅申请的 TOC 能力和网站范围 → 确认安装 → 在工具列表打开 TOC/启用网页卡片/管理`。必须附带可复现的目录 `examples/sidebar-tools/reading-toc/` 或与现有示例一致的更合适路径、构建配置、可导入产物和 README；必须通过实际打包器和浏览器安装回归。
2. **官方便捷安装**：在**同一个「工具」Tab** 提供一个官方推荐条目「阅读目录」和「安装」动作，走与文件导入**完全相同的包校验、能力审阅、安装存储、启用和卸载流程**，不得偷偷安装特权模块。该条目可先来源于扩展内置静态资源；无需联网和独立 Chrome 扩展。若本轮新增 UI 会影响主干其他并行任务，应选择最小非破坏性插入方式并保留完整导入路径。

未来（P1）工具市场：目录/搜索/详情、签名或可信来源、SHA-256/内容完整性、版本差异、新权限升级确认、撤销/失败回滚、可审计来源。**市场只是获取相同格式工具包的安装通道**；不得依赖普通网页无提示安装 Chrome 扩展，不得把网络返回的任意 JS 直接当作 content script 执行，也不得用“关闭工具后自动安装远端版本”绕过审阅。本轮做好契约与扩展点即可，市场服务器和远程自动更新不开发。

**可安装性与能力边界必须说清楚**：安装工具包表示安装其声明的 UI、配置和经过宿主授权的能力，并不赋予包向网页安装任意代码的权限。TOC 的网页内容读取、章节渲染和跳转是由扩展发行包预置的可信宿主服务提供，安装/启用只是授权和激活这项受限服务；未来第三方工具如需新的原生网页能力，必须先由扩展版本提供经过审核的能力合同，市场不能依靠上传 JSON 绕过代码审查。需明确文档中哪些是本轮“已实现/待实施”，哪些属于未来市场设计。

**产品状态机**：
`未安装 → 导入/官方条目预览（无执行） → 已安装且未启用 → 用户选择允许的网站并启用 → 自动在这些已授权页面显示 → 用户停用/撤权/卸载后立即撤销 → 更新审阅后保留允许保留的数据或明确迁移`。
支持“当前网站”以及明确授权的其他/全部适用网站范围，需避免一个导入包在用户不知情的情况下遍历所有标签内容；系统已有 `<all_urls>` 也**不等于工具已经得到页面内容授权**。若产品选择“安装并启用”合一按钮，仍应在同一审核步骤明示将启用的网站范围。

## 三、冻结 UI 要求（未经用户复核不得改变）

- 原网页靠右区域的紧凑白色/暗色卡片，轻描边、圆角；顶部 `CONTENTS` 和三个仅图标按钮：一级、当前章节、完整目录。保持原型的紧凑行距，目录文字单项最多 **两行**，超出截断，悬停/可访问名称给出完整文本。
- 当前标题使用左侧蓝色细线表达，不添加大面积彩色背景。**无搜索框、说明文字、上一节/下一节、底部留白区**。
- 悬浮目录不遮挡网页正文、操作区、ChatGPT 输入框。窄屏优先收纳/显隐，适配大网页和不同滚动容器；具体挂载方案由真实站点测量确定，但视觉须保持接近原型。
- 三个视图只控制展开深度，**不**改变阅读范围、更换回答或触发正文滚动。点击章节才执行定位；正文自然滚动只更新当前项高亮。
- 兼容明暗、200% 缩放、键盘、aria-pressed/aria-current、prefers-reduced-motion。所有用户可见提示要简短，避免永久占用卡片空间。

## 四、P0-C1 多 H1、分框与边界（必须防回归）

**绝对禁止**使用 `h2,h3...h6` 而忽略所有 H1；禁止因为“文章 H1 通常被省略”就把该规则应用到会话。

- 单篇文章：如果能可靠识别页面题名 H1，可以在目录中省略**这个确定的题名节点**，但必须索引正文内部出现的其他 H1。文章从 H2 开始，也能把首层 H2 作为目录一级。不能全局或按数量过滤 H1。
- AI 会话：一个回答可含多 H1，多条回答各自也可能 H1；每条逻辑回答/版本独立维护 heading 栈，同一回答经确认的多个 DOM 片段延续同一 heading 栈，不跨不同消息/版本套父子关系。
- 用户看到多个内容框时，不等于多个逻辑消息：仅当实际目标网站有可验证的归属证据，才能把同一回答的多个内容片段合并。没有证据则保守显示独立对象或“不确定”，不得按视觉相邻、文案相似度猜合并。
- ChatGPT、知乎、多回答页面需分别提供适配器，不能使用原型 `data-source-group` 作为真实页面选择器。不预设某个稳定 message ID 已存在；每个适配器以本机目标版本 DOM 实测为准，有退化/失效保护。
- 重复 H1、重复“总结”、两个 heading 具有相同 `id`、无 id、H2 后 H1、跳级 H3 等，都不能丢目录或误跳。私有身份绑定元素/来源/回答/版本；**不得改写网页原来的 DOM id、location.hash、history、已有锚点或消息 HTML**。
- 跳过 pre/code 内伪标题、隐藏/装饰节点和本工具自身。多框与代码围栏并非必然因果；流式 DOM 结构变更需重新验证，而不随意推断补全文本。

## 五、P0-C2 正文点击定位与性能

- 识别真正的滚动根（窗口或内层滚动容器）；点击精确标题时滚动至可见区域，计算固定顶栏与可用视口。不得以调用 `scrollIntoView` 作为唯一成功条件；结束时复核来源、版本、目标节点可连接及实际位置。
- 用户滚动、点击其他章节、切换会话、关闭工具时取消旧跳转。正文滚动只做单向更新目录高亮；避免跳转与 scroll spy 相互循环。
- SPA 会话切换、增量/流式生成、回答重新生成、历史懒加载、折叠/隐藏内容、嵌套滚动区、来源页面卸载都要有生命周期策略；不能无限自动滚动加载历史内容，更不能跳到旧 ID 对应的不同消息。
- 使用限定范围的 MutationObserver/IntersectionObserver 或等价可证明方案，增量去重、节流/资源释放。长会话 100+ headings 的更新、滚动/CPU/内存有实测结果；不要每个流式 token 全文扫描和大规模重建。
- Content Script 和 TOC 视图隔离样式与事件，不扩大网站攻击面。任何网页 DOM 文本不通过 `innerHTML` 不安全注入，遵守 MV3/CSP/权限生命周期，插件卸载/停用后必须彻底清理注入节点与监听。

## 六、实现次序、最低真实验收和回报格式

**P0 安装闭环是开工顺序的门槛**：实现者应先确认现有 Tools Tab 导入协议/iframe 生命周期和插件宿主能力扩展点，在正式功能编码前完成工具包、安装状态和受信网页 TOC 的接口设计；不能把 Side Panel 的工作推到最后并声称“以后接入”。以下原有网页索引实施步骤仍然必须完成。

**第一条真实 E2E 必须贯穿完整产品路径**：正式 Chrome 加载 OpenDesk Browser → Side Panel「工具」导入官方 TOC 工具包并批准能力/站点 → 可见“阅读目录”已安装 → 点击“打开”可在工具内看到当前网页的目录并点击导航 → 在已授权普通文章和 ChatGPT 风格页面显示 TOC → 关闭 Side Panel 后目录仍可用 → 刷新、切标签后依然按站点策略运行 → 停用时网页目录消失 → 重启 Chrome 恢复启用 → 卸载后无孤立 DOM/残存监听/越权读取。官方便捷安装要走相同后半流程。

**不得只造一个静态 `index.html`/页面演示；必须提交合法可导入的 TOC 工具包及完整源码和打包入口。** 不得把 TOC 实现成网页用户手工复制一段 JS 后才能启动的脚本。兼容所有旧工具和现有最高 12 工具配额/包大小/存储边界；若修改上限必须有预算与回归证据。

1. 阅读/核对当前 main 与原型，画出通用索引器、站点适配器、目录视图、滚动定位的文件/接口图。复用当前入口与能力，不另建第二套 Page SDK/自动化内核。
2. 先完成最小功能闭环：通用文章 DOM 测试页 → 生成 H1..H6 TOC → 三种视图 → 点击滚动 → 高亮跟随 → 切换/销毁。
3. 然后处理**多 AI 回答和多 H1**：至少覆盖一个回答三个片段，其中前两片段均有 H1；第二条独立回答包含自己的 H1/H2；重复“总结”、重复 DOM id、标题缺失和不确定边界。
4. 依次对可访问的真实 ChatGPT、知乎页面测试：记录实际 DOM 结构、适配成功点、权限和限制；无法安全访问的站点标注 **NOT TESTED**，使用静态仿真并保留真实站点待验项，不假报通过。
5. 运行既有项目检查、`npm test`、`npm run build`、生产包验证；检查 Chrome 实际加载路径、扩展版本和 profile，避免加载旧 build 干扰。
6. 真实 Chrome 分别验证文章外层滚动、ChatGPT 风格内层滚动、多个 H1、多个逻辑回答、同名标题、代码块伪标题、滚动中断、缩放、深色和窄屏，无控制台错误，截图留证。
7. 当前原型的 36 条独立浏览器检查仅作为设计底线；正式实现必须增加仓库可重复执行的测试与真实扩展验收。发现缺陷立即修复并复测，不以测试文档代替代码完成。
8. 最终只在 `main` 提交、合入/推送，提交前重新核对并行修改。输出 commit SHA、工具包位置和真实导入方式、安装与自动启用状态、文件清单、功能树完成状态、检查命令/结果、真实 Chrome 测试环境与证据链接、未测项和下一轮缺口。质量目标独立评估争取 ≥95/100，**没有证据不得自评 95+ 或宣布完成**。

## 七、验收重点检查表

**工具形态与安全 P0**
- [ ] 真实 Side Panel「工具」可导入已构建 TOC `.opendesk-tool.json`，安装预览、权限审核、启用、停用、卸载和版本升级可用；未确认前不执行包内容。
- [ ] 安装工具后打开工具可看到当前网页目录、点击导航；同一个目录也能选择显示在**网页内**，并非只有 iframe；关闭 Side Panel 不会停用已启用的页内目录。
- [ ] 官方便捷安装入口使用相同审核/安装/升级存储逻辑，无第二种静默安装路径，无新的 Chrome 扩展。
- [ ] 工具包中的 JS 不可直接在网页执行或访问未经批准的 DOM、chrome API；新 capability 窄授权且伪造请求、失效文档、网站切换、恶意包均无法越权。
- [ ] 未批准的网站、撤销网站权限、禁用工具、卸载或更换来源后，不再留有可操作的目录；正常重新启用无需反复申请权限。
- [ ] 其他既有工具包、任务运行和工具切换不回归；工具包数据与 TOC 页面服务生命周期隔离。
- [ ] 提供将来官方工具库/市场复用的包签名/完整性/来源和更新合约设计，但不声称在线市场已上线。

**阅读与定位 P0**

- [ ] 普通文章的明确页标题 H1 可不在 TOC，但正文另一个 H1 仍存在；只有 H2 的文章不会空目录。
- [ ] AI 回答 A 内的两个 H1 均在一级目录；回答 B 的 H1 也在，同名小节可各自定位。
- [ ] A 跨三个展示框，第二 H1 在第二框，后续 H2/H3 在第三框；章节层级不跨消息串联。
- [ ] 人工插入两个重复 DOM id，目录不丢项、跳转正确、原网页 DOM id 不被改写。
- [ ] 三种视图切换不带动正文；点击目录滚动到真实目标；滚动正文仅更新蓝线。
- [ ] 生成中、改写内容、SPA 切换、历史未加载、关闭/权限撤销时不串来源、不留旧 DOM 监听。
- [ ] 极简卡片无底部导航/多余文字、目录最多两行、窄屏不遮挡、性能可接受。
- [ ] 原型、源代码自动测试、真实 Chrome 扩展与实际站点测试，分别有明确证据等级。

**交付标准：真实源码 + 自动回归 + 生产构建 + Chrome 证据 + main 提交。** 不只交付一段建议或新提示词。若由于当前执行环境不能访问用户 Mac 或真实账号，先完成可以验证和提交的代码，将本机任务明确标成待本地 Codex 验收，并附最短本地执行步骤与专用验收提示词。
