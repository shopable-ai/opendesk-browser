### 4. P2：从目标“第一”反推最小产品闭环，而不是手写 JSX

对 TOP 5 每个输出“真实用户一句话需求 → 用户能直接看到的操作 → OpenDesk 现成模块 → 还缺的最小功能 → 必须通过的测试 → 允许的营销”。要特别区分：
- 一次真实 AI Agent 成功 ≠ JS 可单独重复运行。
- Revision 保存 ≠ Task Verified ≠ Available ≠ Installed。
- WebCodex 手工文本请求/回填 ≠ 真实官方模型工具自动连接。
- Node/Mock 协议响应 ≠ Chrome 真实 RunId/ResultId/权限执行。
- Stop 受管 DOM ≠ 回滚网站已产生的真实业务副作用。
- Cloud R5 通用任务组件成功 ≠ 真实 Chrome 多任务长期 Runner 完全验证。

选择最接近且最有用的一个任务，优先沿用 examples/tasks/demo-form.html 或合法模拟的卖家后台测试样本：AI/Codex 修改候选 → 源码/站点/参数审阅 → 原 Candidate/Verify/Available/Install → 断开模型与开发环境 → 同一固定版本独立运行至少 2 次 → 真实结果、Stop、撤权与数据边界。记录 sourceHash、manifestHash、packageHash、真实 Chrome 文档身份、runId/resultId/原生回执。测首次 AI 费用+后续 20 次运行综合成本，不能只宣传“后续零模型”却忽略前期费用。

有并行 SDK、依赖、Native、AI/模型、安装、Cloud 专职 Agent 的共享代码不重复实现。独立 Demo 和研究可做；若真实缺陷必须动共享源，先查 Owner/冲突并在无冲突时做最小修复，执行现有受影响测试。

### 5. P3：真排名与反例审查

每个候选设置预先固定的公平任务、相同设备/版本/数据，分冷启动、热运行、失败恢复、重复运行总成本、成功率。竞品可以采用它自己的最佳自然工作流；无法亲测就 NOT_TESTED，不能判失败。至少保存原始单次计时、手工动作、模型调用与 Token/成本来源、实际运行身份、错误及录像/截图。对比要覆盖整个使用成本，不能用“单次成功演示”估算可靠性第一。
