## 2. 第一优先：补齐安全 Native Host，构成可运行闭环

审计、修复并在真实 macOS 上验证现有 native-agent/native-host.mjs（已经在仓库中，不要重建另一个进程）：
- 仅通过 Chrome 的原生 manifest \`allowed_origins\` 指定 extension ID 唤起；拒绝错误 origin/扩展 ID，拒绝非预期平台；
- 对 stdio 使用四字节 little-endian UTF-8 字节长度 framing、60KiB 上限、严格 JSON 响应和 stdout 纯协议；stderr 诊断不含密钥/脚本；
- 进程**同时**作为单一 Unix Socket IPC broker，不再二次启动旧 Demo 的 broker.mjs；socket 要在每次 Chrome 启动时显式创建，退出时只删除自己确实拥有的 socket inode；
- Unix Socket 私有目录(0700)，socket 0600，客户端凭据 0600，密钥等长 timingSafeEqual 验证，版本及握手身份校验；
- 有界客户端数、在途请求数、每连接写缓冲、验证请求 schema、超时与错误语义；
- 执行已经被转发但 Host 断连 / ACK 超时的请求不得自动重放；
- 定义 CLI 无 Host、无 Sidebar、Native 扩展权限未授权、host ready 超时状态的稳定错误码；
- setup/update/doctor/cleanup 实际安装 manifest、Node wrapper、固定 extension ID、私有安装资产，不覆盖 \`org.opendesk.browser_core_demo\` 等旧 Demo。
- **安全审计后再运行**；不执行仓库中的任意不审查脚本。

## 3. 第二优先：修复原有新候选中的真实接口缺口

源码/Node/CI 实测发现问题才修复；严禁重建 RunHost、Controller、Worker、Authority、Task DB。
- Host 通过现有注册文档（registrationId、port 与 sender）转发，未就绪返回 E_HOST_NOT_READY，零任务槽占用。
- draft 无 Save 即执行；saved 强制 scriptId/revision/contentHash 一致；返回 runId 不等于脚本已完成。
- target.current 必须来自存活 Sidebar 当前窗口。run.start 带最近可信目标：windowId、tabId、frameId、documentId、URL、origin，启动前重新核对；target 缺少、变更、网站未授权全拒绝。
- Agent / UI 启动共用 @slot，Stop/retirement/Result 仍来自正式 Controller。
- 当前 SW storage.local requestId/digest/runId journal：同 ID 同数据不产生第二次副作用；不同数据冲突；丢 ACK 后能通过已有持久 Run journal 按 requestId 恢复观测（只读且通过现有 Authority，不新建执行旁路），否则报告 OUTCOME_UNKNOWN，绝不自动再次 Run。
- 检查 Host close、Chrome 重启后 unknown 的边界；ledger 达容量时明确 fail-closed。
- 独立认证 CLI、Native manifest origin、Extension、Host registration、已有能力 permission、具体 origin grants，不能把 native 接通当网页授权。
- 不实现 untrusted external \`chrome.scripting.executeScript\` 路由或广义任意 DOM eval。

## 5. 真实 macOS Chrome + Codex 端到端

用实际浏览器加载同一分支 build 的扩展，获取实际 \`chrome.runtime.id\`，不得用旧 Demo ID。以真实 Options 用户点击授予 nativeMessaging。网站 grant 由真实 Sidebar/Chrome 用户操作完成。安装/启动/诊断：
node native-agent/cli.mjs setup --extension-id <real-extension-id>
node native-agent/cli.mjs doctor
打开同一个扩展 Side Panel，实际 Native Handshake；doctor 显示 extension ID、handshake 与活着的 Host。
node native-agent/cli.mjs bridge.status
node native-agent/cli.mjs target.current
准备 request.json，明确用输出的 target + registrationId；draft:
node native-agent/cli.mjs run.start --file /absolute/path/draft-request.json --request-id unique-1
node native-agent/cli.mjs run.get --file /absolute/path/run-get.json
参数文件的请求和响应字段以实际 CLI 合同为准。第一次先核对 Host 是否已正确安装、原 Native manifest 是否冲突，再启动。
- draft 真实网页 Run / DOM 可观察业务效果。
- saved 保存 r1/r2 时运行 pinned r1，不因 Save 变更。
- A/B 同 URL 不串 tab；切 tab 不漂移；导航 documentId stale；权限撤销拒绝；新端口/new tab/current window 后重新获取 target，不修改业务脚本 hash。
- 真正的 requestId 相同同 digest 不重复，改变源码/参数/目标冲突；丢 ACK、Socket/Native 断连是 OUTCOME_UNKNOWN、绝不自动重放；已获知 runId 可通过持久 Run/Result 跟踪。
- 外部与 Sidebar 竞争同一 RunHost 的 slot；Stop/Worker retirement/资源 released；真实用户关闭 Sidebar 后无存活 Host 请求明确拒绝。
- 关闭重开 Chrome、扩展重新加载、重建 Tab、新 CFT HTTP 端口后先 doctor + target.current 再 Run，不用历史假 target。
- 执行后 native-agent/cli.mjs cleanup，并确保无残留 socket / Manifest，仅移除自己的 Host。
- 退出/关闭 Native Host 和 Codex，本扩展 Sidebar **不安装 Host**仍可以运行已有 Available Task，确保独立用户闭环。
- Chrome 原生测试必须使用有真实扩展安装/允许脚本/浏览器用户输入的证据；拒绝人工 DOM 赋值、模拟 isTrusted/伪造 native ack、未授权 executeScript。
- 与 PR #7 的集中授权 UI 以及 PR #9 的最新 Sidebar UI 联合测试，不能覆盖其他工作流源文件。
