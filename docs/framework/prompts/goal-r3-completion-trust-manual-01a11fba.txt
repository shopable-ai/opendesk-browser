先提供无须阅读源码的操作清单。若我要求你直接演示，则用受控 CFT、独立 profile、真实可见窗口、可信原生键鼠，沿真实 Sidebar 文件选择器操作。禁止个人 profile、agent DOM赋值、synthetic events、隐藏导入 API、伪造 ack、改数据库和放松 target 合同。原生驱动授权按当次受控 PID/归属核查，不能沿用已退出的PID。不替我反复运行已证明且输入不变的场景。

使用 R3 备份包/fixture 时明确是复核旧冻结候选；使用最新包时另绑定新身份，不用旧结果代替新验收。

手工检查至少说明动作、看什么、通过条件和异常含义：
1. 导入 JSON 后先不运行：应出现草稿和源码视图，无页面执行效果；切换辅助源码后仍运行完整产物。
2. Page：捕获标准页后试运行，查看精确结果和唯一 proof；重复不叠加。捕获后 reload/hash变更要重新捕获，否则应拒绝。
3. Controller：关闭遮挡面板、滚动到搜索区，输入参数 {"keyword":"OpenDesk"} 后运行草稿；网页“结果：OpenDesk”，计数每次只加1；结果记录与这次 run/result 对应，terminal/released。可见 UI 不能单独证明所有身份字段，说明在哪里看这些字段。
4. Page UI：运行 main 后应有 launcher/panel、JSON文案、图片；UI_OPEN 后再点击业务按钮。
5. 面板创建后，通过网页“当前网页标题/更新网页标题”改标题；输入 "  OpenDesk UI  "，点击按钮，结果精确为新标题及 input:"OpenDesk UI"。这一步检验真实缺陷修复。
6. 空串、纯空白：error+焦点，不产生新成功；旧成功可能保留，不当新结果。
7. Enter、快速连续点击：busy时禁用，结束恢复，结果对应本次输入；肉眼检查不能严证调用次数或全部定时器清理，应说明证据边界。
8. 等待未完成时关闭/退出，再过120ms，不能出现晚到结果；关闭后 launcher 可重开、退出后两host消失；重复 main 不叠加旧实例。导航后不能自动重放。
分支宽屏/缩放/BFCache等未测项单列，不能混入核心 PASS。
