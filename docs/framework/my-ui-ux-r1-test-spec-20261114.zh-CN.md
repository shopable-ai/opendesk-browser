## 1. 本阶段的判定与证据规则

- 2026-11-15 参数抽屉补充：本次仅同步正式 `TaskRunSheet` 与 HTML/React 预览的遮罩关闭及焦点恢复。关闭后草稿保留，内部点击/内部拖出不误关；WebFlow 关闭不发准备、执行或取消请求。定向 Node 10/10 和两种离线浏览器预览通过，真实已安装侧栏为 `NOT_TESTED`；不扩大为整页设计实施或完整矩阵。
- 按最新反馈只迭代原独立 HTML 与规范；本次重做计划列表、新建/编辑和任务管理，验证图标语义、字段校验、检查/保存、管理搜索/启停筛选/复制说明/卸载及跨页保稿。添加/目录和参数入口仅复验受影响保留路径；文件只读读取沿原候选记录，不冒充本次重跑。原 60px 行与“参数与运行”继续保留；不重复无关历史检查，不启动产品环境、构建、安装或完整回归。
- 区分 `SPEC_CHECK`（本轮文档核查）、`SOURCE_INSPECTED`（源码存在）、`OFFLINE_RECORDED`（已有独立模拟记录）与 `NATIVE`（同候选真实侧栏/网页/回执）。每项结果记录 PASS / FAIL / NOT_TESTED / OUT_OF_SCOPE 与原因；不同证据层不相互代替。
- 后续产品验证先从实际默认宽度、正常缩放及一条最短任务主链开始。每组检查须说明由什么改动触发、证明哪个用户行为/安全保护、未运行留下什么缺口。只选择相关检查，不以本表所有行或根 `npm test` 为默认前置。
- 真实候选记录扩展 ID/加载路径、开发服务及 applied revision、相关 dirty 源码/产物指纹、浏览器/视口、操作及业务回执。当前活动网页与已固定运行目标、请求已提交与真实结算分别记录。
- 自动化沿 `ego-browser` 默认入口；普通标签页/HTML 不能冒充原生 Side Panel，真实权限手势、OS IME、Stop 和调度未验证须保留 NOT_TESTED。失败先分产品、断言/驱动和环境，再决定最小修复。
