## 迁移哪些核心能力

以下是迁移主线，详细旧文件、目标路径和任务顺序沿用冻结的 [file-tasks.md](/Users/shopme/Documents/Codex/2026-10-02/opendesk-design-audit-continuation-01a0fc85/outputs/file-tasks.md) 与 [migration-complete.md](/Users/shopme/Documents/Codex/2026-10-02/opendesk-design-audit-continuation-01a0fc85/outputs/migration-complete.md)。目标路径代表计划位置，不能据此声称已实现。

1. **网页自动化 API。** 来源 `ChromePage.ts` 中的 ChromePage、ChromeElement、Keyboard，包括导航、读取、查找元素、输入、点击、等待、页面函数、Cookie、截图和文件上传。迁入 `src/framework/ChromePage.js`、`src/compat/src-bex/`，通过已有 target、PagePort 和页面 agent 执行。逐项保留或按已批准合同修正返回值、参数和错误行为；每个任务绑定自己的目标网页。
2. **脚本执行与生命周期。** 来源 `background.ts` 的控制脚本入口、`UtilScrpt.wrapAsync` 及 ChromePage.evaluate。将控制脚本和页面函数分别接入已批准的执行方式，归入 `src/run-host.js`、`src/scripting/` 和现有权限/运行记录。控制脚本可 await 操作、返回或抛错；停止、超时、导航和宿主关闭都有明确结算。旧后台 eval、共享 global page 和默认 active tab 按合同替换，不能直接照搬。
3. **网页 SDK 与双向回程。** 来源 `assets/js/core/brige.js`、`axiosx.js`、`appStorage.js`、`appLocal.js`，以及 `custom_event.js`、`my-content-script.ts`、`background.ts` 的转发和回调。接入同一个 broker、authority、存储和固定页面回调，保留受支持的旧调用形式。网页可以独立调用获授权的短服务并 await 结果，不要求先运行控制脚本。
4. **公共服务、工具和资源。** 按来源账本承接存储、网络、JSON 工具、服务探测、常量与实际被消费的资源，公开存储寿命、命名空间、错误和兼容变化。资源须有真实消费者及许可依据。业务专属、远程或原生设备能力按原合同登记去向和支持范围。
5. **现有底座与入口接线。** 修改已有 `src/sw.js`、`src/run-host.js`、`src/platform/**`、页面 agent、manifest、构建入口与工作台。移出公共运行流程对采集模板、收费、行数据和封存的依赖；脚本版本、结果、文件和下载使用同一套公共存储及运行记录。工作台和示例插件调用这套迁移后的接口。

旧来源保持只读。本轮只做通用框架，采集业务完整迁移、优化和发布仍在后续阶段。

## 怎样判断迁移正确

沿用 [来源和 API 账本](./source-compatibility-ledger.json) 的 72 项来源处置和 48 项 ChromePage 相关成员，并覆盖独立的网页 SDK、服务和资源合同。每个迁移项都要关联：旧文件/符号及原行为、新文件/实际调用链、保留或修正的语义、真实测试和未支持范围。旧代码中的已知缺陷须按兼容差异说明修复，不能将修复写成“原样兼容”。

验收至少能回答这些具体问题，完整必选集仍以冻结 test-spec 为准：

- **网页操作是否保留约定语义？** 输入框原值为 Base，调用 type 追加 Alice 后得到 BaseAlice，返回 Typed；click 返回 clicked。元素查询的 null/空数组、host 快照和 Worker 上下文限制分别验证。不能只测页面看起来变了。
- **异步返回是否正确？** evaluate 的函数形式按合同等待 Promise、返回 0/false/undefined 或传回错误；旧字符串形式的 true/忽略参数语义单独验证，业务数据中的 PageBrigeCode 不能被误当协议错误。
- **网页 SDK 是否真正可用？** 从注入 SDK 的网页调用 AppStorage、AppLocal 和 axiosx，经扩展服务回到原 Promise，验证返回形状、错误和一次结算；在没有控制脚本运行时也能调用已授权短服务。服务已产生效果但回程失败时，不重做未知写操作。
- **目标和任务是否隔离？** 两个任务分别操作不同 tab/frame/document，不随活动标签页改变。导航后旧元素和等待失效，新页面重新核验身份与授权。重放、撤权、停止和连接丢失按原故障用例验证。
- **完整入口是否使用同一框架？** 在真实工作台选择网页、编辑脚本和参数、保存并运行选定版本；运行 A 时保存 B 或删除脚本不改变在途 A。返回结果与错误持久化，重开可读，下载完成且文件 hash 一致。禁用采集后同样通过。

停止的承诺按执行范围区分：停止后关闭新操作准入并终止控制 Worker；已发出的页面动作或网络写入可能继续，页面函数死循环没有通用 terminate 保证。界面和验收不得把它表述为可随时撤销所有执行效果。

## 怎样推进

1. **先补齐迁移所需的执行前提（F1/T10）。** 沿用已批准后端及 classic Blob 的局部证据，证明实际用户控制代码、受限页面操作、等待/异常、隔离/停止，以及页面函数的授权、精确文档和返回结果。使用有界测试运行器；记录哪些迁移能力依赖该项。保留旧加载失败，不要求四种方式全部成功。测试程序错误、能力实测失败与尚未测试分开。
2. **通过独立复核后，按文件任务迁移和接线（F2/T01–T13）。** 先满足依赖，再承接上述核心 API、SDK 和公共服务，接入现有底座与实际工作台。临时测试 adapter 归并或删除；不得交付两套权限、路由、运行日志或数据库。每完成一项都更新来源/API 对应与行为证据。
3. **在同一最终包上完成迁移验收（F3）。** 运行全部原必选的兼容、双向通信、脚本版本、导航、权限、故障、真实存储、下载与资源清理用例，经独立代码和功能复核后冻结公共 SDK 和交接。原型能运行、文件已复制、构建成功或工作台单条流程成功，均不等于迁移完成。

## 执行边界与停止

完整范围、写入位置、冻结设计、兼容差异、必选用例和审批门继续按 [goal-constraints.md](./goal-constraints.md) 及其引用执行，本次调整不取消既有工作台或可靠性要求。主线对照依据见 [migration-focus.md](./migration-focus.md)。

原生 Goal 处于运行状态时，持续完成已授权、可逆且在原范围内的工作。必需能力真实失败、必要前提确实缺失或独立审批不能通过时，按原始停止规则保存证据并暂停；不造替代后端、不扩大研究。“尚未测试”本身不构成缺失前提。

以原生 Goal 实际状态为准，用户暂停后不自行恢复；不恢复或消息启动旧审计 Goal、旧实施任务或旧②B。全部框架必选验收及独立复核通过后才宣布迁移完成，随后停止，不进入 F4 或发布。
