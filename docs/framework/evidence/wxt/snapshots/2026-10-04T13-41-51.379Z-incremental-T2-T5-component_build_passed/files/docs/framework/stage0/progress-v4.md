现有工程已有 authority/broker、目标、存储和下载等公共底座文件。它们仍需按冻结设计改造和接入实际入口：SW 当前只接环境检查，RunHost 仍依赖采集模板。计划中的 ChromePage 外观、src-bex session 适配和网页 SDK 拟迁文件尚不存在。

## 实际验证了什么

- **控制脚本执行原型：** 真实 Chrome 中执行输入的 async 函数体，打开参数指定网页并返回标题/地址；输入 BaseAlice、点击、等待、读取通过。用户异常、语法错误、未授权导航、等待中停止、超时和部分伪造/全局修改场景已取得局部证据。[报告](../../tests/prototypes/user-control-v2/evidence/chrome-149/report.json)
- **页面函数执行原型：** 真实 Chrome 中取得授权开关、精确 document、code/file、两个执行环境的包装后 Promise/error/undefined，以及撤权和旧文档竞争的局部证据。原生错误返回和 host 权限撤销的失败分别保留，版本矩阵与独立复核未完成。[报告与限制](./prototypes/user-scripts-v2/checkpoint.md)

这些原型回答 T10 的执行方式问题，尚未验证迁移后的完整 ChromePage、网页 SDK 或工作台。
