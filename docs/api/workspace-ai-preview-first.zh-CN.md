# Workspace：本地 AI 修改，浏览器查看预览

> 适用：OpenDesk Browser 的本地文件工作区。页面源码在 `src/native-agent/workspace.html`，构建后的扩展入口为 `native-agent/workspace.html`。正常请通过目录 CLI 或扩展现有入口打开，不必手工填写 `workspaceId`。

## 1. 产品定位

**首选工作流：本地 AI / Codex 修改真实文件 → Workspace 读取并预览 → 用户核对结果。**

Workspace 是本地文件的**查看、预览和确认入口**，不是第二套 IDE、AI 编程平台或自动化执行引擎。现有的「源码」「对照」「保存 / 另存为」「ChatGPT 对话编辑」已经实现，继续保留供临时修补、人工比对和特殊流程使用；**不把它们当作日常默认步骤，也不继续扩展复杂编辑器功能**。

## 2. 日常五步

1. **连接目录。** 已完成 OpenDesk Go Native Host 配对、Chrome 扩展与目录 CLI 安装后，在要处理的目录内执行：

   ```sh
   cd "/absolute/path/to/my-project"
   opendesk browser dev .
   # 已配置 npm 全局入口时也可使用：opendesk-dev .
   ```

   CLI 默认连接当前目录并打开已有 Workspace 标签页。初次配对、只读接入和能力要求以 [R17 CLI 指南](../framework/local-directory-cli-r17.zh-CN.md) 为准；不要为浏览文件额外注册 Codex MCP、启动另一套服务。

2. **查看内容。** 在已连接的工作区选择目录和文件。默认「预览」视图就是主要入口；打开 Markdown / HTML 查看静态渲染，打开代码文件查看文本。不需要先切换到「源码」修改，也不需要点击「保存」。
3. **让本地 AI 修改文件。** 在本机 Codex 或已有编辑器中，对明确授权的真实项目文件进行修改并保存。Workspace 本身不负责向 AI 自动下发编辑任务，也不会因为 AI 修改文件而自动执行网页操作。
4. **重新读取并确认。** 回到 Workspace，对已打开的文件点击 **「重读磁盘」**，然后检查「预览」。文件清单发生变化时点击左侧 **「刷新」**。不要拿页面中缓存的旧内容判断 AI 是否已经保存成功。
5. **仅在需要时运行。** 如果项目确实是 OpenDesk Controller 或 Page USER_SCRIPT，另在 Sidebar 或已授权 MCP 中**明确运行**，并检查相应回执；这与 Workspace 查看文件是两回事。参见 [Sidebar 本地项目](sidebar-local-projects.zh-CN.md)。

## 3. 选对预览方式

| 内容 | 在 Workspace 中怎么查看 | 注意 |
| --- | --- | --- |
| Markdown | 打开文件，默认「预览」 | 基础 Markdown 渲染，不承诺完整 GFM/MDX 支持 |
| HTML | 打开文件，默认「预览」 | 隔离的**静态** HTML；脚本、事件处理、外部资源不在此执行 |
| JavaScript / TypeScript / TSX | 打开文件看源码文本 | 不会当作应用运行，也不会在扩展内编译项目 |
| 已启动的 Next.js / Vite 应用 | 切到「本机应用」，输入实际本机服务地址并「连接预览」 | 先自行启动项目已有 dev server；页面不会安装依赖或启动进程；若 iframe 被站点策略阻止，使用「独立打开」 |

「显示到目标网页」仅把**当前文件的静态预览**放到选定网页，不是业务程序执行、项目安装或 AI 自动化。真正的网页自动化仍走原来的 Controller / Page 执行与网站授权。

## 4. 已有编辑功能：保留，但按需使用

- 只有确实要临时手工修补时，才切换「源码」或「对照」，修改后**明确点击「保存」**；此按钮保存的是 Workspace 内的草稿，并非“让 Codex 保存”。
- 默认的本地 AI 修改流程不需要在 Workspace 再点击「保存」；应该点击「重读磁盘」。若 Workspace 中已有未保存草稿，重读时可能提示外部文件变化，**会保留草稿供比较**；核对后再决定采用磁盘版本或另存为，不自动覆盖 AI 已保存的文件。
- 「ChatGPT 对话编辑」仅适用于确实需要在已有 ChatGPT 网页对话中进行结构化读取、提案审阅和人工保存的场景。日常本地 Codex 编辑**不需要**这条额外流程。
- 长期只读目录仍不可写；`workspaceId` 只是定位键，不是文件访问权限。实际读写必须通过仍有效的本机连接及目录授权。

## 5. 不需要再开发的内容

不为日常流程新增 Monaco/多标签 IDE、AI 对话面板、代码智能补全、自动保存、自动运行脚本、项目启动器或第二套热更新/目录监听服务。只有出现**真实的预览错误、外部文件刷新异常、授权或写入冲突误导**时，才做影响最小的修复和定向测试。

## 6. 常见问题

- **看不到工作区 / 显示离线**：核对已配对的 Go Native Host、CLI 是否仍在运行，并点击「刷新连接」；历史目录名称不代表实际目录授权。
- **AI 已保存但预览没变**：对已打开文件点击「重读磁盘」；新增/删除文件再点击目录「刷新」。有未保存草稿时先比较，不直接丢弃。
- **只能阅读不能保存**：检查是否以 `--read-only` 接入，或目录是否已有长期只读授权；不能通过页面按钮绕过 Native 权限。
- **本机应用预览空白**：先检查已有开发服务是否已启动，地址是否为允许的 localhost / `127.0.0.1`，或用「独立打开」判断是否被禁止 iframe 嵌入。
