# 仓库协作规则

## Git 分支与工作树治理（默认单主线）

- 默认不创建新的 Git 分支或工作树。普通开发、修复、文档、测试和只读分析，应直接在用户指定的目标分支上完成。
- 只有用户明确要求创建分支时，才允许创建新分支。为了“方便”“隔离”或遵循通用代理习惯，不构成本仓库自动建分支的理由。
- 创建分支前必须先检查现有本地分支、远端分支和工作树，优先复用已有且目标一致的分支，避免产生 `codex/*`、`agent/*`、`docs/*`、`fix/*` 等重复临时分支。
- `main` 是计划中的唯一长期主分支。仓库尚未完全收敛到 `main` 时，应继续使用用户明确指定的当前目标分支，不得静默切换、合并或删除旧分支。
- 如果用户明确授权创建临时分支，默认一个任务最多创建一个，并在开始前写明目标分支。任务完成后必须在同一交付流程中完成合并、验证、推送（如用户要求）以及本地分支、远端分支和附属工作树的清理。
- 不得为了只读检查、简单文档修改、小型修复或测试验证单独创建分支。
- 删除分支前必须证明其有效内容已进入目标分支，并核对本地与远端状态；不得使用强推覆盖并发更新。
- 始终保留用户已有的未提交、已暂存、未跟踪和忽略文件。未经用户明确授权，不得通过 stash、reset、restore、clean 或强制删除来腾空工作区。
