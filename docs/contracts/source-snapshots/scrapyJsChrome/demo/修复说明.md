# selector.next() 在 popup 中调用修复说明

## 问题
在 `popup_crawl.js` 中调用 `selector.next()` 时，点击"下一个表格"按钮没有正常返回数值。

## 原因
代码存在**双重包装**问题：

```javascript
// ❌ 错误 - 双重包装
const script = "return await page.eval('selector.next()');";
const result = await executeInPage(script);
```

- `executeInPage` 内部已经会调用 `page.eval`
- 脚本里又包了一层 `page.eval`
- 导致返回值无法正确传递

## 解决方案

```javascript
// ✅ 正确 - 直接调用
const script = "selector.next()";
const result = await executeInPage(script);
```

## 如何测试

### ⭐ 方法 1：点击按钮测试（推荐）

这是**最简单和最可靠**的测试方法：

1. 打开包含列表的网页（如搜索结果页）
2. 打开扩展 popup
3. 点击 **"定位 表格"** 按钮
4. 点击 **"下一个表格"** 按钮
5. 查看表格数据是否正确更新
6. 查看浏览器控制台的日志输出

```
[executeNextSelector] Executing selector.next()...
[executeNextSelector] Result: {...}
✅ 表格数据已更新
```

### 方法 2：在目标网页的 DevTools 测试

如果你想直接测试 `selector.next()`：

1. 打开包含列表的网页
2. 打开扩展 popup
3. 点击 **"定位 表格"** 按钮（初始化 selector）
4. 在**目标网页**上按 F12 打开 DevTools（注意：是网页的 DevTools，不是 popup 的）
5. 在网页的控制台中运行：

```javascript
// 直接调用
selector.next()

// 查看 selector 状态
selector.lists.length  // 检测到的表格数量
selector.currentIndex  // 当前索引
```

### ⚠️ 不推荐：在 popup DevTools 测试

在 popup 的 DevTools 中运行测试函数可能会遇到环境错误：

```
❌ Error: 当前环境不支持执行该脚本
```

**原因：**
- popup DevTools 运行在 popup 窗口的上下文中
- `selector.next()` 需要在目标网页的上下文中运行
- 这两个是不同的 JavaScript 执行环境

如果你看到这个错误，请使用**方法 1** 或**方法 2**。

## 常见问题

**Q: 在 popup DevTools 中运行测试函数报错 "当前环境不支持执行该脚本"？**

✅ **这是正常的！** popup DevTools 和目标网页是不同的执行环境。

**解决方法：**
1. **推荐：** 直接点击 popup 中的按钮测试
2. 或者在**目标网页**的 DevTools 中运行 `selector.next()`

**Q: selector.next() 返回 null？**
- 先点击 "定位 表格" 按钮初始化
- 确保页面有明显的列表结构
- 可能已经到最后一个表格了

**Q: 点击 "下一个表格" 按钮没反应？**
- 查看浏览器控制台（不是 popup 的）的错误信息
- 确保目标页面不是 `chrome://` 开头的系统页面
- 尝试刷新页面后重新操作
