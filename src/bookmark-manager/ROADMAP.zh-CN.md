## 1. 定位

从「收藏链接」逐步发展成「管理私人知识 → 帮助重新阅读和行动 → 形成可选择公开的知识网络 → 服务发现」。第一批先完成用户看得懂、可恢复、可靠的 Chrome 原生书签管理，不把尚无证据的 AI、社区、广告、后台采集塞入首页。

### 页面与边界

- **一棵文件树**：文件夹和书签是同一个父子结构，不再独立成两个功能区。一个搜索框、一行操作「☆ 收藏当前页 / ＋书签 / ＋文件夹」，下方同一树内折叠、展开、编辑、移动、删除。只保留一条「书签管理」标题，不额外加产品口号。
- P0 数据真相是当前 Chrome Profile 内的 `chrome.bookmarks`，不是 OpenDesk 复制的书签数据库；Chrome 自带根目录、受管节点不可编辑，敏感删除有确认。
- 真实书签读取与写入在经审计的第一方扩展 UI 内，用户明确授权可选的 `bookmarks` 权限。动态安装/AI 生成工具不得依靠同名工具 ID、装包或 iframe 读取完整私人书签树。
- 侧栏交互不依赖右边额外评审画布；原型右侧区域仅用于设计讲解。

## 2. 功能宇宙（价值/代价/阶段独立评价）

| 功能领域 | 用户真正解决的问题 | 最小有效功能与实验 | 建议阶段 | 风险/决策 |
| --- | --- | --- | --- | --- |
| 原生书签管理 | 方便收藏、查找、归档和打开 | 单树 CRUD、搜索、授权、Chrome 变化、误删确认 | **P0** | 先交付可靠性，不复制数据 |
| 收藏后的阅读行动 | 收藏后再也不阅读 | 手动标记待读、每周复习清单、复习/归档状态 | P1 | 不为提醒开发第二调度器 |
| 重复/老化诊断 | 同一内容多份、很久没用 | 用户主动查重、按收藏时间排序、手动复核建议 | P1 | 不默认删除，也不把“未见访问”判为没打开 |
| 失效链接诊断 | 链接打不开、已迁移 | 用户触发限速检查、区分 404/受限/超时、建议寻找新地址 | P1 | 网络请求可能泄露访问意图；403 ≠ 死链 |
| 个人使用洞察 | 哪些收藏可能值得重新看 | 可选本机历史授权、最近打开/访问估计、透明时间窗口 | P1/P2 | 使用历史数据只用于明确的用户功能；本地优先 |
| AI 目录重构 | 旧文件夹乱、重复、难搜索 | 先给出迁移草案（旧路径→新路径）、变更列表、逐批确认、可恢复证据 | **P2** | 不自动批量移动；需提供失败恢复 |
| 知识树/学习路径 | 收藏无法形成系统认识 | 用户选择主题→知识地图（基础/进阶/延伸、相关/冲突、时间演化）→下一个阅读建议 | P2 | 溯源和解释推荐依据，不把推测当事实 |
| 内容语义与工作流 | 不只是链接，还想产出 | 用户选定文章→摘要/问答/实践步骤/复习计划；复用现有 Workflow/Task | P2 | 默认不批量抓网页或上传私人内容 |
| 智能推荐 | 发现相关的可靠公开内容 | 用户主动搜索主题、公开内容候选、来源/日期/推荐理由 | P2 | 需要质量评估与负反馈 |
| 自愿社区/共享目录 | 向相似兴趣的人学习 | 用户显式公开自己选定的书签/文件夹或话题；公开订阅、收藏、评论、举报 | P3 | 私人书签及兴趣重叠不可自动公开 |
| 专家咨询与服务市场 | 收藏一篇技术文章后需要实操协助 | 基于用户主动选择的话题，展示专家名录、课程、模板、问答服务 | P3 | 真实性、评价、防刷榜、纠纷/支付 |
| 企业/团队知识库 | 团队重复整理同一批知识 | 共享空间、角色、审阅、知识地图、组织检索 | P3 | 数据隔离、权限、删除/导出合同 |
| 智能广告定向 | 根据私人收藏和访问频率卖广告 | **不应在 Chrome 扩展内这样实现** | **NO-GO** | Chrome Web Store Limited Use 禁止用收集或派生的用户数据做个性化广告，即使选择同意也不解决该禁止 |

阶段只表达候选先后，不等于开发承诺、市场排名或已获得收入；价值需要真实用户实验验证。

## 3. 两条需要特别区分的 AI 产品链

**A. AI 整理工作流**：用户选中范围 → 本地统计/候选分类 → 按可解释规则提出新树 → 展示所有移动/重命名/合并对象 → 用户明确确认 → 通过受信任 Chrome API 顺序执行 → 记录变更与失败恢复。小规模先行，不许静默整理整库；可选云模型只传用户明确选中的数据范围。

**B. 知识成长工作流**：用户选择领域 → 将所选书签与公开参考资料映射到主题和前置知识 → 生成可追溯的结构图与阅读次序 → 用户收藏/计划/输出 → 周期性复习。过去的研究、当前可验证信息、未来方向应分层标注置信程度；相关性不等于真实性。

## 4. 商业模式的优先顺序

1. **免费基础工具**：不强迫登录、不付费才能访问自己的 Chrome 书签；保留 P0 完整 CRUD。
2. **可选择的个人增值订阅**：隐私优先的智能诊断、批量建议、知识树、复习计划、模型额度；价格尚须实验验证。
3. **团队工作空间**：共享目录、组织权限、知识更新监测、企业知识服务。
4. **公共内容/服务市场**：作者主动公开目录、课程、咨询、服务；按公开清单发现、透明佣金、赞助标记、评价与举报。
5. **非定向赞助**：仅在政策允许时研究公开分类下非个性化赞助位，不使用扩展所取得的私有收藏/访问记录（含摘要、派生标签及画像）匹配广告，也不向广告平台传这些数据。

**禁止将浏览记录、收藏网址、阅读频率或衍生标签用于个性化、兴趣定向/再营销广告**。Chrome Web Store 的 Limited Use 限制适用于原始数据及聚合、去标识、衍生数据，明确禁止利用扩展数据进行个性化广告；用户勾选同意不能自行豁免。来源：
- https://developer.chrome.com/docs/webstore/program-policies/limited-use
- https://developer.chrome.com/docs/webstore/user_data

## 5. 隐私与可观测原则

- `bookmarks`：P0 首次进入工具时主动点击授权；不上传内容。
- `history`：**P0 不请求**。日后必须有独立的用户可见功能及单独授权，只留最小本地统计和随时清除入口。Chrome 本机历史不等于跨设备完整访问事实，清理/无痕/新 Profile 不可误判为用户从未阅读。
- 失效检测：必须用户主动开始或后来明确配置，披露会产生外部网络请求；只汇总必要状态，不默认把私人 URL 发第三方扫描服务。
- AI：用户明确选择内容、知晓发送目标及用途，默认本地/仅元数据方案；删除/撤权/取消必须能阻止后续传播。
- 社区：只公开由用户主动发布的对象；不从私人重合度反向推测身份、好友或个人敏感类别。公开目录质量/版权/恶意链接需审核机制。
- 商业：自愿、透明标记、易关闭。不允许付费流量改变私人书签排序或把推广包装成系统/AI 推荐。

## 6. 下一步可证伪的产品实验

- P0：真实用户能在 320px Side Panel 中，首次授权后 60 秒内收藏当前页、创建目录并把旧书签移入；拒绝授权不暴露书签。观察操作次数与失败率，而不是使用总功能数假定覆盖率。
- P1：招募真实有一定收藏量的用户，比较“本地查重 + 周计划”和原有 Chrome 书签管理；检验 7 天内重新打开率、误删/误分类投诉及任务完成率。
- P2：让用户从 30 条书签中审阅 AI 整理提案；观察建议接受率、误分类率、撤销成功率、用户是否感到失去控制。
- P3：只用参与者主动公开的目录，验证是否产生真实阅读互助、课程咨询成交和有质量的复用；不从私人浏览记录做用户发现。
